# Agent 笔记：插件在设置的两块区域里自己做界面

状态：提议中

## 先说结论

设置窗口里有两块区域交给插件自由创作：插件详情「设置」标签的正文，以及插件用 `page` 声明的侧栏页的正文。侧栏入口本身（名称、所属分组、位置）仍然只能声明。

区域里的内容只用**描述模式**：插件后端返回一棵与界面框架无关的 JSON 界面树，宿主用 Viva 控件画。需要自由绘制时（依赖图、配色预览、构建看板），在树里放一个**画布节点**。插件一次发来整个场景（矩形、路径、文字、位图、分组），宿主保存下来，每帧自己画。悬停、按下、键盘焦点、平移、缩放、悬停提示都由宿主在本地处理，只有点击、控件修改这类语义事件才发回插件。

设置窗口里不再嵌网页，网页只留给工具窗口。不管内容是什么，框外的一切都归宿主管；写入设置必须经过 Core 校验，而且只能写本插件声明过的设置。

可以操作的原型：

- [`docs/design/plugin-canvas-scene.html`](../../../../docs/design/plugin-canvas-scene.html)：画布节点的交互、预算、故障回退和消息计数。
- [`docs/design/build-execution-settings.html`](../../../../docs/design/build-execution-settings.html)：「构建、执行、部署」页在大量插件注入时的布局，见[构建、执行、部署设置页在大量插件注入时的结构](../../implemented/feature/2026-11-18-build-execution-settings-at-scale.md)。

## 问题

现在这两块区域只能显示 Core 按清单生成的声明式设置行（`settings[]`）。插件作者做不了字段联动、「测试连接」按钮、图形预览这类界面，例如数据库连接向导、依赖冲突图或配色预览。

现有的原生声明 `native-ui.schema.json` 引用了 macOS 共享控件名（如 `LitheSettingsSelect`），切换到 Viva 后已经不适用，而且它只用于工具窗口。

如果不先划边界，插件会想改别的设置页、弹自己的对话框、改窗口底部按钮。那样宿主就没法统一管理设置窗口，也无法保证 `${setting:}`（把设置值代入启动参数的模板）的安全。

2026-11-12 的版本让插件在这两块区域里用自绘网页。实测一个最简网页在 macOS 上额外带来三个系统进程，约 60 到 70 MB（数字见备选方案）。设置窗口一页可能有好几个插件区域，用户还会来回切页，这个开销太大。

## 提案

### 两块区域

| 区域 | 入口由谁决定 | 内容由谁画 |
| --- | --- | --- |
| 插件详情「设置」标签 | 宿主固定 | 插件，用描述模式，可以含画布节点；没有自定义内容时显示声明式设置行 |
| 侧栏插件页（「语言与框架 › <语言>」「构建、执行、部署 › <构建系统>」） | 插件在清单里声明 `page`，分组和位置由宿主按[设置页分类](../../implemented/feature/2026-10-15-macos-settings-hierarchy.md)决定 | 同上；同一页有多个插件声明时，用已有的贡献者切换（`settings_surfaces.go` 的 contributorIDs），每个插件只画自己那一块 |

### 描述模式（界面树）

插件后端（用现有的 Node 或 Rust SDK）返回一棵 JSON 界面树。宿主用 Viva 控件把它画出来，再把点击、提交等事件发回后端，后端返回补丁或新的树。

- 词汇与界面框架无关：布局（列、行、网格、分组、分隔线）、内容（文本、标题、宿主图标、徽标、链接）、控件（按钮、开关、文本框、数字框、单选、多选、文件或目录选择、列表、树、表格）、画布节点。
- 树里画布以外的部分，样式只开放主题 token（宿主主题里命名好的颜色、字号、间距档位）：语气色（普通、弱化、强调、警告、危险、成功）、字号档、粗细、间距档、宽度（填满或按字符数）。不开放任意颜色、字体和绝对坐标，这样深浅色、缩放、无障碍和输入法由宿主统一保证。
- 这套 schema 替换 `native-ui.schema.json`。工具窗口的 Tree/List/Form 也改用同一套词汇，桌面端在 `plugin_native.go` 现有的渲染代码上改造。
- 输入框不会每按一次键都调用后端，只在回车、失焦或提交时发一次 change 事件。

### 画布节点

画布节点是界面树里的一种节点，内容是一个**保留场景**：插件描述“画面里有哪些东西”，宿主保存这份描述并负责每一帧的绘制。与之相对的是即时绘制，也就是每一帧都由插件发绘图指令，这种方式不采用（见备选方案）。

下面的字段名都是示意，和原型一致，正式名字在 Core 契约 PR 里定。

```json
{
  "type": "canvas", "id": "deps", "label": "依赖图", "height": 360,
  "viewBox": [0, 0, 1200, 640], "pan": true, "zoom": [0.4, 3], "on": ["viewport"],
  "nodes": [
    { "type": "path", "id": "e:liba", "d": "M190 20C234 20 216 80 260 80", "stroke": "$line", "width": 1.5 },
    { "type": "group", "id": "guava31", "x": 260, "y": 60, "w": 190, "h": 40,
      "on": ["click"], "label": "com.google.guava:guava 31.1，因冲突未使用",
      "tooltip": "范围：compile\n未使用：被 33.0 取代",
      "hover": { "fill": "$hover" }, "pressed": { "scale": 0.97 }, "sel": { "stroke": "$accent", "width": 2 },
      "children": [
        { "type": "rect", "w": 190, "h": 40, "radius": 8, "fill": { "light": "#fdf0ef", "dark": "#3a2726" }, "stroke": "$err", "dash": [4, 3] },
        { "type": "text", "x": 12, "y": 28, "style": "strong", "maxWidth": 168,
          "runs": [{ "text": "guava", "color": "$text" }, { "text": "  31.1", "color": "$err" }] }
      ] }
  ]
}
```

**节点种类**

| 节点 | 内容 | 说明 |
| --- | --- | --- |
| `rect` | 位置、大小、圆角、填充、描边、虚线、阴影档位 | 填充可以是线性渐变 |
| `path` | SVG 的 `d` 字符串、填充、描边 | 圆弧（`A` 命令）由宿主转换成三次贝塞尔，再交给 Viva 的 PathBuilder |
| `text` | 锚点、对齐、字号档、文字片段 `runs`（每段可以有自己的颜色）、`maxWidth` | 宿主用自己的界面字体和等宽字体测量和排版，超过 `maxWidth` 显示 …；插件不能指定字体 |
| `image` | 插件包里的位图路径 | 只读，只能来自插件包 |
| `group` | 变换、裁剪、命中区域 `w`/`h`、子节点 | 可点击、悬停样式、提示都挂在分组上 |

每个节点有稳定的 `id`，补丁按 `id` 定位。

**颜色**有三种写法：

- 主题 token（`$text`、`$accent`），跟随深浅色。依赖图这类普通界面用这种。
- 深浅两套值（`{ "light": …, "dark": … }`），宿主按当前主题挑一个。构建看板的系列色用这种。
- 固定颜色，不跟随主题。只在画布里允许，用于配色预览这类要展示颜色本身的内容。

**交互分工**

| 由宿主在本地处理，不跨进程 | 发回插件 |
| --- | --- |
| 悬停、按下、选中的样式（插件预先声明 `hover`、`pressed`、`sel`） | `click`：点了哪个节点 |
| 键盘焦点和焦点框 | 界面树控件的 `change` |
| 平移、缩放、缩放按钮 | `viewport`：平移或缩放停下 400 ms 后发一次，场景用 `on` 声明了才发 |
| 悬停提示（节点的 `tooltip` 字段） | |

插件收到事件后按节点 `id` 回补丁：`set` 改属性，`replace` 换一棵子树，`scene` 换整个画布，`ui` 换界面树里的一个节点（例如点了冲突节点后，在右侧详情里放一个「排除」按钮）。插件也可以主动推送补丁，例如进行中构建的实时进度。

**输入和滚动**

- 画布里没有文本框。需要输入时用界面树里的控件；输入法、选择、复制粘贴都由宿主控件负责。
- 滚轮归设置页滚动，避免画布“吞掉”滚动。⌘/Ctrl + 滚轮或双指捏合缩放画布，拖动空白处平移。缩放按钮由宿主画，插件只声明 `pan` 和 `zoom` 范围。

**无障碍**

可点击的节点必须有 `label`（读屏软件读出的名字），否则整个场景被拒绝。Tab 键进入画布后在可点击节点之间移动，Enter 或空格触发 click，焦点框由宿主画。

**预算**

| 项 | 上限 | 超出时 |
| --- | --- | --- |
| 每个画布的节点数 | 2,000 | 拒绝场景，回退 |
| 每个画布的场景大小 | 256 KB | 拒绝场景，回退 |
| 插件推送的应用频率 | 每秒 30 次 | 多出的按节点合并，只保留最新值 |
| 每次调用 | 2 秒超时 | 回退 |

回退是指框里显示错误，改为显示插件在清单里声明的设置行；窗口其他部分照常可用，这些设置行照样能改，用户可以点「重试」。

**搜索**

画布里的文字不进设置搜索：宿主不理解它的含义，也不应该为了搜索去渲染每个插件。插件在清单里给页面声明 `keywords`（API-19，文字按 API-37 本地化），侧栏搜索命中关键词后打开对应页和对应贡献者。

**首版不做**：模糊、滤镜、混合模式、径向渐变、自定义字体、动画。以后需要时可以加声明式过渡。

**编号**：画布节点是界面树的一种节点，和界面树一起算 API-13 的扩展；页面关键词算 API-19，插件文字本地化用 API-37。不新增编号。

### 宿主强制的边界

- **只画在框里。** 裁剪和滚动归宿主。弹出层只能由宿主控件打开（下拉、文件选择），并且锚在框内。插件不能弹对话框、发通知，也不能改标题、标签页、底部按钮、别的设置页或别的插件。
- **只写自己的东西。** 写入走 Core：Core 按清单校验 id、类型、范围和作用域（API-19 `settings.update`）。插件没法写宿主偏好或别的插件的设置。修改工具的真实配置（例如在 `pom.xml` 里加排除项、改 Maven 的 `settings.xml`）走本插件自己的函数，并遵守[设置反映工具真实配置](../../implemented/architecture/2026-10-25-settings-native-configuration-editing.md)：显式 Apply、冲突保护、写后重读。
- **保存归宿主。** 控件绑定到设置 id，改动只生成草稿，由宿主保存，窗口底部写明写入目标（设置文件或 `app/pom.xml` 这类工具文件）。点宿主的「应用」时，设置由 Core 提交，工具配置由插件函数写入并重新读取；点「取消」时宿主丢弃草稿，把已保存的值发回插件让它重画。提交结果的生效方式（restart、immediate、reload、nextRun）照旧由宿主分发。
- **生命周期跟着区域走。** 区域显示时才发 open 调用后端；切走、换贡献者、关闭窗口、停用或卸载插件时，取消未完成的调用并关闭区域，插件的推送也随之停止。每次调用都有超时。
- **失败只影响这一块。** 后端出错、超时、崩溃或场景超出预算时，按上面的方式回退，窗口其他部分照常可用。
- **文案分两种。** 宿主自己的文案（应用、取消、错误、回退提示、缩放按钮的提示）走 `shared/i18n`；插件画出来的文字属于插件内容，由插件自己做本地化（API-37 包内语言文件）。

### 正确做法

- 数据库插件在「设置」标签用界面树画一个连接表单，「测试连接」按钮调用本插件函数。用户点宿主的「应用」后，Core 校验并写入插件声明的 `host`、`port`。
- Maven 依赖分析插件在「构建、执行、部署 › Maven」页用画布节点画依赖图。悬停、平移、缩放都在宿主本地完成。用户点了冲突的 guava 31.1，插件回一个 `ui` 补丁，在详情里放「排除」按钮。点「排除」生成一条写入 `app/pom.xml` 的草稿，底部显示写入目标。点「应用」后插件写入文件、重新读取，宿主显示新的依赖图。
- 主题插件在「设置」标签用画布节点画配色预览，预览里用固定颜色。“变体”分段控件绑定设置 `dusk.variant`：切换只生成草稿，插件按草稿重画预览；点「取消」后预览恢复。

### 不要这样做

- 不要让插件在框外画任何东西，也不要在宿主里按插件名加专用页面分支。插件需要新页面时只能用 `page` 声明。
- 不要绕过 Core 直接写偏好目录或 `.lithe/plugin-settings.json`。那样会跳过校验，`${setting:}` 就可能把未校验的值带进启动命令。
- 不要在画布以外的界面树里开放任意颜色或像素坐标。需要像素级控制的内容放进画布节点。
- 不要把悬停、拖动、每帧重画发给插件处理。悬停和按下的样式由插件预先声明，宿主本地切换。
- 不要在画布里自己做文本框或键盘输入，用界面树的控件。
- 不要在设置窗口的插件区域里嵌网页。

## 考虑过的备选方案

### 只保留声明式设置行，不允许自由绘制

吸引力在于宿主最好管：样式统一、没有网页引擎、无障碍有保证。用户在 2026-11-12 否定了这一点：有些插件确实需要自己绘制（图形预览、可视化编辑），只给设置行会把它们挡在外面。画布节点在描述模式里满足了这个需求。

### 设置区域用自绘网页（2026-11-12 提议，2026-11-18 放弃）

插件提供包内的 HTML 页面，Viva 用 `canvas.NativeView(id, rect)` 在区域里挖一个洞，放进系统网页引擎（macOS 是 WKWebView，Windows 是 WebView2，Linux 是 WebKitGTK）。加载规则、内容安全策略和 bridge 沿用工具窗口的实现。吸引力在于插件作者能直接用 Canvas、WebGL、SVG，什么都能画。

放弃的原因：

- 内存。在 macOS 上实测一个最简页面，额外带来三个系统进程。两次测量分别是 WebContent 41、42 MB，GPU 22、12 MB，Networking 6、5 MB，合计约 69、59 MB。画布节点只在宿主进程里多存一份场景，通常几 KB 到几十 KB，没有额外进程。Windows 的 WebView2 还没测。
- 设置窗口一页可能有多个插件区域，用户会频繁切页；每次都要启动和销毁网页进程。
- 原生视图挖洞后，宿主的下拉弹层必须画在更高一层，否则会被网页盖住；三端网页引擎的行为也不一致，Linux 差异最大。

工具窗口不受影响：那里的网页已经实现，只在窗口显示时存活。

### 即时绘制的远程画布（不采用）

插件后端每一帧都发绘图指令，宿主画出来，再把所有鼠标和键盘事件转发回去。2026-11-12 用户决定不考虑，原因是每次交互都要跨进程往返（拖动会卡）、文字输入和输入法要宿主重做、插件作者还得学一套新接口。

保留场景的画布节点和它的区别：

- 悬停、拖动、缩放在宿主本地处理，只有语义事件跨进程，没有每帧往返。
- 输入仍然用界面树的控件，宿主不用重做输入法。
- 场景词汇和 SVG 接近（矩形、路径的 `d`、文字、分组变换），插件作者不需要学新东西。

### 把插件进程的原生窗口嵌进框里

插件自己开一个原生视图，由宿主重新挂到设置窗口里。看起来最自由，但各平台嵌入方式完全不同，插件进程也能借此操作宿主窗口，安全边界守不住。不采用。

### 在宿主进程里运行 WASM 绘制

插件提供 WASM 模块，在宿主进程里调用 Viva 的绘图接口。省掉了跨进程往返，但插件代码会跑进宿主进程，资源和崩溃都难隔离，还要再维护一套 WASM 运行时和接口版本。不采用。

## 验收标准

- 同一个插件在「设置」标签和侧栏页里分别显示界面树和画布节点，并能通过宿主的「应用」写入它声明的设置；Core 拒绝未声明 id、越界值和错误作用域。
- 画布节点的五种节点、三种颜色写法在浅色和深色下都正确显示；圆弧正确转换；文字超过 `maxWidth` 时截断。滚动设置页、打开下拉弹层、切换标签页时，画布的位置和裁剪都正确。
- 悬停、按下、平移、缩放、悬停提示不产生跨进程消息；平移停下后只发一次 `viewport`；点击只发一条 `click`。
- 节点数或场景大小超出预算、可点击节点缺少 `label`、调用超时、后端崩溃时，框里显示错误并回退到声明式设置行，这些设置行照样能改，窗口其他区域可以继续操作。插件推送超过每秒 30 次时按节点合并。
- 键盘能用 Tab 在可点击节点间移动，用 Enter 或空格触发；读屏软件读出 `label`。
- 打开任意插件区域时都不启动网页进程（macOS 上没有新的 `com.apple.WebKit` 进程）。
- 停用、更新、卸载插件或关闭设置窗口后，没有残留的后端调用和推送。
- 运行 `scripts/desktop/verify/verify-runtime-bundle-immutability.sh`，确认插件包和应用包在整个流程中没有被写入。
- `native-ui.schema.json` 不再出现在 Core 契约里，工具窗口改用新 schema 后行为不变。

## 风险

- Viva 画布的绘制性能。2,000 个节点在平移和缩放时每帧重画，需要先在 Viva 里测帧时间，必要时按分组缓存。平移和缩放属于高频交互，遵守[可调整界面的性能边界](../../implemented/architecture/2026-09-13-resizable-ui-performance-boundaries.md)。
- 文字度量在三端不同，插件不能依赖文字的精确宽度。用锚点、对齐和 `maxWidth` 截断减少影响，插件文档要写明这一点。
- 画布节点要映射到各平台的无障碍树。需要先确认 Viva 能不能为自绘区域提供自定义无障碍元素；不能时先在 Viva fork 补上，不在 Lithe 里绕过。
- 圆弧转三次贝塞尔有精度误差。大半径、接近整圆时要拆成多段。
- 替换 `native-ui.schema.json` 会让现有声明原生工具窗口的插件失效。需要在契约更新记录里写清楚，并同步更新官方插件。
