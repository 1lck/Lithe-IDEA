# Agent 笔记：原生窗口标题显示项目与文件

状态：已实现

## 先说结论

窗口的系统标题写明当前显示的内容：编辑器显示文件时为“项目 – 文件”，焦点在终端、工具页或没有文件时只显示项目，应用没有项目时显示应用名。这样任务栏预览、Alt+Tab 与窗口菜单可以区分多个项目窗口。Windows 与 Linux 显示文件，macOS 只显示项目（文件名由窗口自己的标签栏承担）。

## 问题

多个项目窗口在任务栏上都只显示应用名，用户只能根据缩略图判断要切换的窗口。只改应用内的标题栏，不能让系统窗口切换器得到相同信息。两个同名项目（例如同一仓库的两个检出）也需要能区分。

## 决策

- **标题格式。** 项目名与文件名之间使用 IntelliJ 同样的 en dash 分隔（`" – "`）。文件取焦点所在编辑组中当前文档的文件名。
- **只显示项目的情况。** 焦点组显示终端、工具页或没有文档时，标题只显示项目名。
- **同名项目附加父目录名。** 当其它打开的项目名称相同时，项目名后附加上一级目录名，使两个检出可以区分。
- **平台差异。** macOS 标题只包含项目名，窗口的标签栏已经显示文件。

## 考虑过的备选方案

- **只更新网页标题。** 未采用。网页标题不是原生窗口标题的可靠同步契约。
- **把工具名称或最近编辑文件放进标题。** 未采用。会让标题频繁变化，并且工具页只显示项目是既定的产品选择。
- **从持久化缓存中猜测项目列表。** 未采用。缓存可能包含已关闭的窗口，也无法证明目录归属。

## 后果

- 任务栏与 Alt+Tab 中可以直接辨认项目和活动文件。
- 标题只描述当前焦点的内容，切换焦点时会随之变化。
- 长路径和重名项目的标题可能被系统的显示宽度截断。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/workbench/ -count=1`：覆盖标题计算与同名项目的后缀规则。
- 在 Windows 与 macOS 真实窗口中验收：切换项目、切换文件、进入终端后标题只显示项目，任务栏和 Alt+Tab 可区分两个同名项目。
