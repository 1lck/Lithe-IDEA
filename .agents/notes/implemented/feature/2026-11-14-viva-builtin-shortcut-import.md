# Agent 笔记：Viva 内置快捷键导入

状态：已实现

## 先说结论

快捷键导入直接放在 IDE 的 Go 客户端中，用户在设置的快捷键页面选择来源文件，预览后确认创建独立方案。按 2026-11-14 用户明确要求，这项迁移能力不再通过插件实现，也不新增 Rust 导入模块；此决定是 `develop-lithe` 共享规则默认归 Rust Core、工具格式默认归插件的明确任务例外，不扩大到其他功能。旧客户端通过插件导入的方案已归档，不再决定当前 Viva 客户端的快捷键导入入口。

## 问题

迁移快捷键是一次性使用的 IDE 基础能力。为它安装插件、协商能力并启动后台程序增加了用户步骤和维护边界，而当前客户端已经有可编辑的快捷键和独立方案。用户要求重新设计一套 Go 实现，因此不复制旧插件源码、清单、测试和命令协议，也不让宿主依赖旧插件仓库。

## 决策

- `desktop/internal/keymapimport/` 持有独立的来源解析、动作映射、按键规范化和冲突规划。带注释的 JSON（JSONC）使用 `hujson`，XML 使用 Go 标准库；按键最终交给 `shortcuts.Decode` 检查，确保预览可表达的按键与 Viva 实际监听的一致。
- 首期由用户明确选择 VS Code/Cursor 的 `keybindings.json` 或 IDEA 的键位 XML；不扫描安装目录，不推测 IDE、Profile 或父方案的默认键。XML 声明父方案时明确提示只导入显式覆盖。来源没有可导入项时不创建空方案。
- 有条件规则、连续按键、需要参数的命令、鼠标规则或不支持按键的动作整项跳过并列出原因；未知动作明确跳过。来源规则不会被推广成全局快捷键。VS Code 的减号移除规则只说明跳过，不用它删除 Lithe 的键。
- 冲突规划以完整的当前动作表和有效绑定为基线。同次导入允许交换两个动作的按键；占用未修改的默认键会在预览中列出让位项，显式清空相应默认键。若占用用户自定义键，或两个导入动作争用同一按键，整次导入禁止应用，不能部分保存。
- 来源由独立的所选文件只读 adapter 做有界读取与确认前的身份、字节核验。macOS 文件选择器只授予所选文件访问权限，不能先用 `os.OpenRoot` 打开其父目录；在“文稿”等受保护目录下，打开未获授权的父目录可能停在系统隐私检查。Unix 使用非阻塞只读打开并核验 regular-file 身份，拒绝文件被替换为管道或符号链接。每文件最多 1 MiB、最多 4096 条规则、每动作最多八个键；JSON 嵌套最多 32 层，XML 最多 16 层并拒绝 DTD 和实体声明。读取和解析由 Viva 页面管理的后台任务（Effect）持有，取消、关闭和过期结果不发布。
- 保存复用既有 Rust Core 方案规则，先在后台的局部值完成 `saveAs` 和 `update`，确认来源和当前设置仍与预览基线一致后，只发布一次完整方案。新方案不会修改原方案；用户可通过方案选择器切回。此处没有新增 Core 命令或插件 API。
- 原始文件字节和只读快照只在本次弹窗的内存中存活，不落盘，不新增下载、解压、生成或可复用缓存。源文件和 app bundle 始终只读，不改变签名或 Sparkle 增量更新基线。失败和不完整导入提示通过既有设置错误边界记录，不包含源路径或文件内容。

正确示例：导入“跳到行”的 `Ctrl+Alt+G`，确认后启用独立方案，切回旧方案后仍使用旧绑定。不要这样做：把 `Ctrl+K Ctrl+G` 截成 `Ctrl+K`，或忽略 `when` 条件后把键变成全局动作。

## 考虑过的备选方案

- 继续接入旧插件：需要安装、进程和协议接线，与用户要求的内置迁移体验不符，不采用。
- 新增 Rust Core 来源解析模块：原先考虑过，但用户明确要求使用与 Viva 本体一致的 Go 实现；本次撤回所有新增 Rust 代码，保留既有方案机制。
- 猜测缺失默认键和继承方案：文件通常只包含自定义差异，推测默认值可能引入错误行为。首期只处理实际读取的显式绑定，并公开限制。
- 直接覆盖当前方案：难以回退，而且中途失败可能留下部分状态。采用独立方案和单次发布。

## 后果

用户无需插件即可导入，解析器没有后台进程和独立分发成本，两个平台使用同一份 Go 代码。代价是来源格式的兼容维护随 IDE 本体发布；首期不包含自动发现、参考默认键、父方案继承、条件和连续按键转换。该内置入口不改变已发布插件契约，也不自动卸载用户插件或删除远端仓库。

## 验证

- `desktop/internal/keymapimport/import_test.go` 覆盖 JSONC、XML、来源修改、格式与读取限额、条件与连续键跳过、显式解绑、默认键让位、自定义冲突、交换与确定性。
- `desktop/internal/settingswindow/keymap_import_test.go` 覆盖预览不写入、确认创建独立方案、切回旧方案、取消与过期结果、重名与来源变化不部分发布，以及 Viva 页面预览和取消。
- 使用 `.agents/skills/write-stable-tests/scripts/run-go-tests-with-timing.mjs` 记录逐项计时；运行 i18n、Agent Note、运行时发行目录只读和功能矩阵检查。
- 无头页面与单元测试不能代替 macOS/Windows 原生文件选择器和真实按键验收，矩阵保持 `pending`。

## 原生实测与修复

2026-11-14 使用与生产相同的 Viva 窗口、导入流程及工作台，原生验证入口仅将偏好和日志注入独立目录，并固定打开隔离文档。系统文件选择器实际从 macOS“文稿”读取 JSON/XML，未授予父目录额外权限。

实测发现两个此前被无头驱动的强制刷新和临时目录掩盖的问题：文件选择器返回后没有唤醒空闲页面；`configfile.Capture` 先打开父目录，超出了选择单个文件的授权范围。前者有修复前失败的 `TestBuiltinKeymapImportFilePickerCompletionWakesIdlePage`；后者有原生运行栈停在 `os.OpenRoot` 的证据，以及父目录无读取权限、所选文件仍可读的 Unix 回归。现在开始导入和文件选择器返回都会请求刷新，读取只打开所选文件。

修复后实际导入并验证 VS Code `Ctrl+Alt+P` 打开 Find Action、`Ctrl+Alt+G` 打开跳行并跳到第 42 行；重启后方案和新按键仍有效。切回默认方案后，新按键不再触发，`Command+L` 恢复跳行。IDEA XML 的 `Ctrl+Alt+J` 在重启后成功跳到 `73:1`。这只是所测常用操作和本机 macOS 的证据，不代表所有 IDE 命令或 Windows 原生流程已验收。

原生实例的三个 bundle 文件在完整流程前后哈希一致，两个来源文件未改变，用户真实 `settings.json` 字节未变。本次创建的实例、临时选择文件、生成的测试入口和测试应用注册均清理，用户原有 Lithe 实例保留。
