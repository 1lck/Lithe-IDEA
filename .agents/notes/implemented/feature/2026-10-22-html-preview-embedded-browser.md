# Agent 笔记：HTML 预览是内嵌的单页网站预览

状态：已实现

## 先说结论

HTML 预览把当前编辑的 HTML 文件放进一个内嵌的网页视图中显示，页面通过自定义协议 `lithe-site` 加载，并由 Core 决定每一个请求的结果：编辑器中未保存的文件内容、站点中的其它文件、目录的 `index.html`，或拒绝访问隐藏文件与密钥。页面的存储只在内存中，随页面关闭而消失。预览的范围与 VS Code 的 Simple Browser 相近，完整浏览器以后作为插件实现，不加在预览中。

## 问题

若用 `file://` 加载 HTML，页面的模块脚本、`fetch` 和 `XHR` 会被浏览器的安全策略拒绝，`/assets/app.js` 这类路径也会指向磁盘根目录。若允许页面读取任意本地文件，恶意的 HTML 就能借同源请求读走 `.env` 等凭据。

## 决策

- **页面由自定义协议提供。** 文件通过 `lithe-site://site/` 加载，给页面一个同源、安全上下文的站点，模块脚本、`fetch`、锚点和以斜杠开头的路径都按本地开发服务器的方式工作。
- **请求由 Core 解析。** Core 决定每个请求返回哪一段内容：当前文件使用编辑器中的文本，使未保存的修改可见；站点中的其它文件只读；目录请求返回其 `index.html`；隐藏文件与密钥文件返回 403。
- **页面不能借同源请求读取机密。** 隐藏文件（以点开头的路径分量，如 `.env`、`.git`）与被 Core 判定为密钥的文件一律拒绝。
- **页面存储只在内存中。** Cookie、本地存储、缓存和 Service Worker 不写入磁盘，并且在不同预览和不同站点之间隔离。不支持这种隔离的平台拒绝打开页面。
- **导航规则。** 主框架留在站点内。用户点击的外部链接交给“跟随”（系统打开）；页面打开的新窗口若位于站点内，则在原页面中加载；指向站点外的新窗口最多每隔一段时间才跟随一次。框架可以加载网页、数据与 blob 地址。
- **文本变化时重新加载。** 编辑器的文本变化会重新加载当前页面，并尽量恢复原来的滚动位置。

## 考虑过的备选方案

- **`loadFileURL` 加载磁盘文件。** 未采用。来源仍是 `file://`，模块脚本和 `fetch` 仍被拒绝，并且无法显示未保存的修改。
- **在本机启动 HTTP 服务。** 未采用。需要管理端口和进程生命周期，并让同机其它进程访问到工作区文件。
- **允许页面中的 `file://` 访问。** 未采用。任何 HTML 都能读取用户的整个磁盘。

## 后果

- 预览行为接近真实网站，用户可以直接在编辑器中调试前端页面。
- 当前 Viva 预览比完整浏览器小：没有地址栏、缩放、页内查找、开发者工具、对话框、下载和打印；这些功能以后由插件提供。
- 访问规则是唯一的泄露防线，修改时不能放宽隐藏文件与密钥的拒绝规则。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/webpreview/ -count=1`：覆盖站点请求的解析与隐藏文件的拒绝（如 `.env` 返回 403）。
- 在真实窗口中验收：未保存的编辑在预览中可见，目录链接可以加载其中的脚本，点击外部链接会交给系统打开。
