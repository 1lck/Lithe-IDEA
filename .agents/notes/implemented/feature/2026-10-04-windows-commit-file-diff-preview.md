# Agent 笔记：提交差异的完整上下文与块级包含边界

状态：已实现

## 先说结论

文件差异的完整上下文、块的边界和块级包含都以 Git 自己的补丁为事实来源。完整上下文取值必须限制在安全上限内，并把 Git 的块间上下文固定为 0，否则 Windows 的有符号 32 位整数会溢出，让同一段源码被重复显示。块包含的边界由 Git 的连续增删脚本决定，不能用 hunk 的上下文范围代替。桌面端的差异视图只消费 Core 返回的完整补丁。

## 问题

整文件差异的上下文行数若取 Git 接受的最大值，xdiff 合并相邻修改时会计算两倍上下文并溢出，把多处修改拆成互相重叠的整文件 hunk，行号反复回到 1。块级包含若按 hunk 的上下文范围划分，会把附近未勾选的修改一起暂存。

## 决策

- **完整上下文使用固定安全值。** 完整文件视图的上下文行数使用 `1_073_741_823`，不能使用 Git 接受的 `2_147_483_647`。
- **块间上下文固定为 0。** 读取完整文件差异时，Core 显式传入 `--inter-hunk-context=0`，避免用户配置在旧版 Git for Windows 中重新触发溢出。这个设置不能在视图层去重掩盖。
- **块边界来自 Git 连续增删脚本。** 同一个 hunk 中的两处修改必须能分别包含。
- **只读快照不写入仓库。** 查看差异时使用系统临时目录里的独立 Git 管理目录和索引，不在仓库 `.git` 中创建临时目录，也不改变真实暂存区。临时目录由 Core 的上下文对象独占，正常返回和错误返回都会清理；Unix 下创建时即为 0700 权限。
- **字节保真的回退通道。** 当显示投影无法安全重建补丁（例如 CR 或文件末尾缺少换行标记、UTF-8 解码有损）时，块操作不得依赖显示用的补丁；回退只能使用未经解码的原始补丁，并在写入前以固定上下文重新读取比较，不一致时拒绝写入。
- **无法安全分块时保留整文件操作。** 重命名、二进制、稀疏或截断的补丁只提供整文件的包含入口。

## 考虑过的备选方案

- **用最大上下文值读取全部内容。** 未采用。Git 的内部计算会溢出，产生重复的整文件 hunk。
- **在视图中按行去重。** 未采用。掩盖了补丁本身的错误，行号和块身份仍然错误。
- **用显示投影的补丁校验回退。** 未采用。显示投影会丢掉 CR 的变化，校验会误拒绝所有块回退。

## 后果

- 完整文件差异的行号单调递增，块包含有可靠的输入。
- 写入回退依赖原始补丁的字节保真，需要额外的读取和比较成本。
- 块级包含在桌面端尚未实现，当前 Viva 差异视图以 `desktop/internal/workbench/gitreview_diff_view.go` 为准。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/core/ -count=1`：覆盖完整上下文读取路径，且用户配置的 `diff.interHunkContext` 不改变结果。
- 在已有文件的多个不相邻位置修改后，验证完整补丁只有一个 hunk，左右源行各出现一次。
