# Agent 笔记：Windows Git Log 单文件差异预览

状态：已实现

## 先说结论

Windows 的 Commit Files 点击文件后使用独立页面，一次显示一个文件的差异。
页面保留当前比较的完整文件集合，左右箭头切换文件，上下箭头导航差异；
到当前文件最后一处后继续按下箭头，会进入下一文件的第一处差异。
标签跟随当前文件，采用 IDEA 的 `Repository Diff: 文件名`，提交标识显示在页面内。
源文件跳转必须使用预览所属仓库，不能因为活动项目不同而打开同名的另一份文件。
并排文本预览把两侧行号集中在中间，并显示差异连接带和各侧差异标记。
并排页面保留独立行流，连接带跟随两侧实际滚动位置变化并绘制在行号背景中。
Git 提供增删脚本，Monaco 只负责只读代码控件；统一视图仍使用原 Diff 组件。

## 问题

原预览复用了多个文件纵向排列的页面，点击文件后只保留匹配路径的补丁。
它缺少差异导航和文件导航，也无法在同一预览中访问其他文件。
离散提交可以多次修改同一路径，因此路径本身不足以区分每份比较。

## 决策

Git 模块负责保存比较快照（一次读取所得的全部补丁和提交身份），
`commitFilePreview` 只区分前端页面，不改变共享 Core 的 Git 协议。
`CommitFileDiffPreview` 按文件 key 显示单个条目，导航只修改缓冲区里的当前 key。
例如 `C:a.ts` 和 `A:a.ts` 是两个可分别导航到的版本，不要按 `a.ts` 去重。
完整提交、工作区和其他多个文件的比较继续使用已有页面。

并排页面使用 `IndependentCommitDiff` 和 `mountIndependentCommitDiff`（当前页面的布局与资源所有者）。
两个 Monaco 0.55.1 只读编辑器分别显示旧、新行流，不使用 DiffEditor，不补齐另一侧缺失的行。
Git 的补丁顺序和历史行号仍是事实来源，`planIndependentCommitDiff` 只投影已有行并记录连续增删边界，
不重新比较文件，也不补造稀疏补丁缺失的源码。统一视图和多文件页面保留原有共享 Diff 所有者。

上下导航使用这些边界；下箭头在文件末尾切换下一条目，等待语言准备与模型更新完成后定位第一处差异。
整个集合末尾禁用，不循环；上箭头仍只导航当前文件。首次定位意图绑定本次切换快照，只执行一次。
左右箭头直接切文件不携带定位意图。等待更新时禁用导航和源跳转，清除旧连接、行号与装饰；
迟到的语言准备结果必须检查当前请求版本和卸载状态。高频滚动、尺寸不进入 React 或缓冲区状态。

页面采用 macOS Diff 与 IDEA Islands 的明暗背景、40px 工具栏、22px 图标按钮和三态差异颜色。
两侧差异概览与透明常显纵向滑块分别放在最左、最右外侧，轨道宽度 12px、滑块 8px。
轨道占用独立布局空间，不显示代码，避免左侧代码开头被概览和滑块遮挡。
代码区、行号区与轨道滚轮统一采用两倍灵敏度；它是本页面加快滚动的产品选择，
不是 IDEA 的固定倍数。滑块拖动仍按真实可滚动范围映射，键盘方向键按用户实际行高移动。
纵向滑块只设置 Monaco 公开滚动偏移；命中和拖动生命周期复用 `startDocumentResizeSession`。
横向滑块保留 Monaco 原生控件，`scrollBeyondLastColumn: 0` 关闭文件末列后的附加空白。
左右横向独立滚动；纵向滑块、滚轮、键盘和查找按 Git 差异边界同步对应行，保留各侧真实滚动范围。
单文件并排和统一视图隐藏补丁的 `@@` 标题，只保留真实内容行；不改变补丁数据、行 ID 和暂存块身份。
内容本身以 `@@` 开头时仍显示。底部使用公开 padding 留出五个实际行高，不补造模型行或源行号。
两个编辑器保留原生选择、复制、查找、语法高亮与用户字体/行距，关闭补丁投影中的诊断、符号与选择概览。

整行差异使用 Git 连续增删边界；词级差异复用 BSD-3-Clause 的 jsdiff 8.0.2 `diffWordsWithSpace`。
每块最多 8192 字符和 512 编辑步骤，整份预览最多处理 128000 字符，超限保留整行差异。
有词级结果的修改块采用 IDEA 的中间底色：正文修改色占 40%、页面底色占 60%，
词级替换两侧都使用完整修改底色，纯新增、纯删除片段分别使用增删底色；中央行号和连接面保持完整修改色。
明暗配色采用 Islands 对应编辑器方案的 DIFF 背景和概览色，代码边界使用背景色而非概览色。文字仍在原生装饰之上，
不改变语法前景色或文字透明度；关闭词级或预算超限时保留完整整行底色。
这是一项呈现增强，不将 Git 的行级脚本重新交给字符算法推断。锁文件固定来源和校验，未新增运行时下载、
资源目录或可共享缓存；现有资源复用清单已覆盖 Bun 下载缓存，node_modules 仍是各工作树独立可变状态。
词级和空白开关由页面保存，切文件后保持。仅完整补丁可折叠连续上下文，展开恢复真实行；
Ctrl/Cmd+F 先展开全部上下文，再调用原生查找，以免查找漏掉被折叠文本。

左右版本标题复用现有锁图标，按条目保存真实父提交与目标提交：
单提交采用第一父提交，连续范围采用 baseRef/targetRef，离散选择保留各自版本身份。
`null` 父版本表示空树；缺少版本元数据的旧快照使用“上一版本”，不猜测 hash。
重命名分别显示旧、新路径，统一视图纵向显示两个标题。
分隔条布局事件只修改页面 CSS 列宽，标题跟随实际编辑器宽度，不发布 React 或缓冲区状态。
中央区域为左右历史行号预留真实宽度，SVG 连接面跨过两列行号，并绘制在数字后面。
默认三位行号每列只留 12px 总边距，中间曲线宽度 16px，随用户字体的实际字符宽度调整。
代码与中央区域使用同一整数布局边界。连接面只填底色，上下描边按代码边界的半像素中心绘制，
不描共享边缘的垂直线，避免连接面与代码区接缝多出一条线或上下错位。
行号区的上下边界保持水平直线，仅两列行号之间的分隔区域绘制曲线，不能从代码边缘就开始弯曲。
新增在旧侧、删除在新侧的零行范围画横跨可见代码区的双像素边界线，接到对应行号区和曲线。
修改的两侧在各自实际区间画上下单像素边界，保留整行底色和词级高亮；不增加空白行或可滚动宽度。
不移动 Monaco 内部 DOM，不覆盖可选择代码。稀疏补丁的源行号 110 显示为 110，但点击选择的是
对应模型行；左右行号支持单击整行及反向 Shift 扩展，不能把源行号当作模型索引。
中央分隔条复用现有文档拖动所有者，键盘方向键调整宽度，Home 恢复均分；窗口狭窄时裁剪中央区域，
编辑器和连接带尺寸均不得为负。版本标题的列宽随局部布局 CSS 更新。

纵向滚动参考 IDEA 的差异边界同步，以主侧视口约三分之一处为锚点，保留行内像素偏移。
投影变化时缓存文件起点、每个差异块起止点和文件终点，每次滚动二分查询对应行；不按全文比例映射。
例如右侧新增十行时，对应旧侧停在插入边界；经过该块后，两侧共同上下文重新对齐。
不为短侧补空白行，也不扩大它的滚动范围；横向偏移不联动。连接带按两侧实际视口偏移动态绘制。
差异块边界采用 IDEA 的微小方向保护，避免映射停滞时行内偏移使另一侧前后抖动。
同步有重入保护；替换两个模型、配置行高、布局和显式双侧导航时暂停同步，不能观察新旧混合模型。

文本/布局变化时缓存变化块的像素边界及概览标记；每帧二分筛选可见变化，只绘制可见行号和连接面，
不扫描全文，不重新建立概览 DOM。折叠、换行与字号产生的新像素边界仍来自 Monaco 公开坐标 API。
卸载取消动画帧、语言请求、观察器、全部监听与拖动，再销毁两个编辑器及两个模型。

Jump to Source 使用最后聚焦侧的光标，把补丁行号转换成新版本源行号。
删除的行定位到邻近保留行；整个文件已删除时禁用源跳转。
例如预览属于 `C:/parent/nested`，即使活动项目是 `C:/parent`，也要打开 nested 内的文件。
不要用显示行号直接打开源码，也不要从全局项目根目录猜测仓库位置。
历史版本和当前工作区之间没有额外的行号重映射；工作区后续修改或删除可使位置偏移或打开失败。
图片、二进制及无文本差异条目仍允许下箭头进入下一文件；没有文本光标时禁用源位置导航。

参考 IDEA Community `fb72b4df43aba102479eb0502d20b03586b9c5b8`：
`platform/vcs-log/impl/resources/messages/VcsLogBundle.properties` 的 Repository Diff 标题，
`VcsLogEditorDiffPreview.kt` 的文件名选择，以及
`platform/diff-impl/src/com/intellij/diff/impl/DiffRequestProcessor.java` 的
Previous/Next Difference、OpenInEditor、Prev/Next Change 动作顺序。
同一处理器的 `goToNextChangeImpl` 使用 `ScrollToPolicy.FIRST_CHANGE`，作为跨文件定位依据。
这些是页面交互依据，不表示移植 IDEA 的完整差异引擎。
中间行号参考同一 revision 的 `TwosideTextDiffViewer.java` 左侧镜像布局；
连接带参考 `DiffDividerDrawUtil.java` 的可见区域裁剪、空范围及两侧独立像素边界，
曲线边界参考 `DiffDrawUtil.java`。浏览器层采用 Monaco 0.55.1 的公开 API，
零行边界及修改块上下边界参考 `DiffDrawUtil.LineHighlighterBuilder` 和 `drawChunkBorderLine`；
修改正文的中间底色参考 `TextDiffTypeFactory.TextDiffTypeImpl.getIgnoredColor` 的 0.6 混色因子，
以及 `SimpleDiffChangeUi.createHighlighter` 在有 inner fragments 时启用 ignored 底色；
细滑块参考 `DefaultScrollBarUI.kt` 的 10px 非小型轨道与绘制内边距，不照搬 Swing 的事件逻辑。
纵向同步参考 `SyncScrollSupport.java`、`BaseSyncScrollable.java` 和 `SimpleDiffViewer.MySyncScrollable`；外侧滚动条方向参考
`tools/util/side/TwosideTextDiffViewer.java` 的 `VERTICAL_SCROLLBAR_LEFT`。不移植 Swing 组件。
Islands Dark 从 `IslandSchemeDark.xml` 继承 Darcula 差异色；Islands Light 使用 `expUI_lightScheme.xml` 的 Light 方案。
词片段分类参考 `SimpleDiffChangeUi` 和 `DiffUtil.getDiffType`；五行底部留白参考 `EditorSettingsState.kt` 的
`editor.virtual.lines` 默认值及 `EditorSizeManager.java` 的额外行高计算。

## 考虑过的备选方案

- 在旧纵向页面加按钮：仍会同时渲染多个同路径提交区段，无法满足一次显示一个文件的需求。
- 切换文件时重新请求 Git：增加等待和迟到结果风险，丢失离散提交版本身份。
- 新写文本/词级差异算法：Git 已提供行级脚本，jsdiff 提供成熟词级增强，不重复实现比较算法。
- 将跨文件后的初始差异位置写入持久缓冲区：会让重新打开或手动切换文件继承旧跳转意图。
- 保留 DiffEditor 的公开配置：能改颜色与滑块，但公开 API 不能关闭补空白行，也不能把左纵向滚动条放在外侧。
  用户对照图明确要求动态连接带，因此需要独立页面布局，而不是继续叠加 CSS。
- CSS 移动 Monaco 内部行号或镜像整个编辑器：会使代码、选择、查找、弹窗和鼠标命中坐标不一致；
  采用两个独立只读代码控件，以公开 API 提供文本选择和坐标，页面只负责外围布局。
- 完全自绘代码文本：会重复实现长文件可见区、语法、复制和连续选区。本次复用完整只读 Monaco 控件，
  布局与连接几何放在局部页面中；未来可替换控件，但必须保持公开坐标和选择接口。
- 两侧设置同一个 scrollTop 或按总高度比例同步：在长短不同的差异块之后会错行；采用差异边界映射。

## 后果

一个固定预览标签可以浏览整个比较集合，也能保留同路径的多个提交版本。
代价是缓冲区保存完整集合，即使当前只显示一个文件；Git API 本来就返回完整集合。
历史预览继续采用现有补丁上下文范围，不在前端补造缺失的源码。
代价是并排页面需要自己维护连接几何与外侧纵向滑块；这些资源与单文件页面一同卸载。
词级超限退回整行高亮，展开上下文会更新只读模型，模型 URI 和资源数量保持不变。
macOS 本次不修改，双端功能矩阵保持目标产品运行验收待验证的状态。
