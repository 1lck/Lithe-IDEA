# Agent 笔记：Windows 单文件差异预览与 Commit 块包含

状态：已实现

## 先说结论

Windows 的 Commit Files 点击文件后使用独立页面，一次显示一个文件的差异。
页面保留当前比较的完整文件集合，左右箭头切换文件，上下箭头导航差异；
到当前文件最后一处后继续按下箭头，会进入下一文件的第一处差异。
到当前文件第一处后继续按上箭头，会进入上一文件的最后一处差异；跨文件后 Commit 列表同步选中并显示对应行。
标签跟随当前文件，采用 IDEA 的 `Repository Diff: 文件名`，提交标识显示在页面内。
源文件跳转必须使用预览所属仓库，不能因为活动项目不同而打开同名的另一份文件。
并排文本预览把两侧行号集中在中间，并显示差异连接带和各侧差异标记。
并排页面保留独立行流，连接带跟随两侧实际滚动位置变化并绘制在行号背景中。
Git 提供增删脚本，Monaco 只负责只读代码控件；通常的统一视图使用原 Diff 组件，整文件新增只显示新增行流。
Commit 面板点击文件也使用同一页面，增加块级包含复选框、回退双箭头与刷新；包含状态直接来自 Git 暂存区。
两处工具栏的词级高亮、空白符和视图切换位于左侧，最右侧显示当前文件的差异数；Commit 还显示已包含块数。

## 问题

原预览复用了多个文件纵向排列的页面，点击文件后只保留匹配路径的补丁。
它缺少差异导航和文件导航，也无法在同一预览中访问其他文件。
离散提交可以多次修改同一路径，因此路径本身不足以区分每份比较。

## 决策

单文件工具栏的显示选项与文件导航放在同一左侧操作区，弹性空白之后只显示差异统计。
窄窗口只让左侧操作区横向滚动，统计保留在右侧独立区域，不能随按钮一起滚出视口。
Git Log 的差异数来自当前编辑器已完成的比较；Commit 有可包含块时，总数与 included 使用同一组 Git 连续增删块，
避免统一视图合并比较结果后出现 included 大于差异总数。不使用文件总数、增删行数或 Git hunk 数；
加载、切换文件和图片/二进制预览时不显示虚假的“无差异”。Commit 的已包含数沿用暂存区块状态，
部分包含块也计入；勾选及刷新后统计随块状态更新。按本次用户要求，全部包含时仍显示 included 数量。
没有可安全分块的数据时，完全包含文件按全部差异已包含计数；部分包含但无法确定块数时不编造 included 数量。
参考 Community `fb72b4df43aba102479eb0502d20b03586b9c5b8` 的
`platform/diff-api/resources/messages/DiffBundle.properties`、
`platform/platform-resources-en/src/messages/ActionsBundle.properties` 和
`platform/vcs-impl/src/com/intellij/openapi/vcs/changes/actions/diff/lst/LocalTrackerDiffUtil.kt`：
英文使用 `Highlight Words`、`Show Whitespaces`、`Unified viewer`、`Side-by-side viewer`，
差异状态区分 `No differences`、`1 difference` 和 `N differences`，Commit 追加 `, N included`。
空白符开关保持同一操作名，通过选中状态表示开关；词级关闭仍保留整行底色，不新增高亮策略。

Git 模块负责保存比较快照（一次读取所得的全部补丁和提交身份），
`commitFilePreview` 只区分前端页面，不改变共享 Core 的 Git 协议。
`CommitFileDiffPreview` 按文件 key 显示单个条目，导航只修改缓冲区里的当前 key。
例如 `C:a.ts` 和 `A:a.ts` 是两个可分别导航到的版本，不要按 `a.ts` 去重。
完整提交、普通工作区和其他多个文件的比较继续使用已有页面；Commit 单文件入口由独立工作区所有者接入同一呈现。

上下差异导航在当前文件边界双向继续，不循环；比较未准备好时两种跨文件入口都禁用。
向前进入首个差异，向后进入最后一个差异；并排与统一控件在比较完成后只消费一次定位请求，普通刷新保留当前位置。
Commit 文件列表观察当前工作区活动预览的仓库及相对路径，更新对应行的选择并展开其仓库、分组和祖先文件夹，
随后用已有虚拟列表滚动到该行。不要模拟点击文件行重新打开 Diff，也不要移动编辑器焦点或改变 include 状态。
同一文件的状态刷新不重新滚动；历史 Diff、加载中快照和不属于列表的仓库不更新列表选择。
参考 Community `fb72b4df43aba102479eb0502d20b03586b9c5b8` 的
`platform/vcs-impl/src/com/intellij/openapi/vcs/changes/ChangeViewDiffRequestProcessor.java` 与
`platform/vcs-impl/src/com/intellij/openapi/vcs/changes/ui/TreeHandlerDiffRequestProcessor.kt`：
跨文件移动更新变更树的选择，已有多选包含目标文件时保留多选；树按实际变更身份定位节点。
文件加载成功并通过原有活动缓冲区、请求代次和顺序校验后才发布新预览，因此失败、关闭或迟到请求不能移动文件列表选择。

Commit 的工作区所有者 `useCommitDiffReview` / `createCommitDiffReview` 读取 HEAD 到磁盘和 HEAD 到暂存区的完整补丁。
例如同一个三行上下文 hunk 中有两处修改，勾选第二处只将第二处写入暂存区；不能把 hunk 的上下文范围当作提交块。
块边界使用 Git 连续增删脚本，补丁构造复用 `gitGutterChangeHunk`，上下文来自暂存区，不夹带附近未勾选的修改。
已有暂存插入导致后续行号偏移时，按 HEAD 到暂存区的边界计算真实索引位置；块内只暂存了部分行时显示三态复选框。
取消勾选只恢复该块的 HEAD 内容，保留其他已暂存块。新增或整文件删除以一个完整文件块处理，复用现有整路径操作，
不向空暂存区应用缺少文件元数据的普通 hunk。重命名、二进制、稀疏/截断补丁保留整文件复选框，不能假装支持精确块操作。
解析器为显示去掉 CRLF 的 CR 或 EOF（文件结尾）缺少换行标记时，必须保留有损标识。
这类补丁不能再作为精确的块包含事实，也不能重建可写 hunk；新旧 Diff 都退回整文件包含入口。
例如磁盘是没有末尾换行的 `B`，不能提交重建的 `B\n` 后把它显示为完全包含；整文件暂存由 Git 保存实际字节。
暂存修改跨越当前可见块边界时禁用该块写入，避免顺手撤掉不在当前块内的暂存内容。

文件行勾选来自实际 `file.staged`，有剩余磁盘修改时显示部分包含；点击部分包含的文件框可包含其余修改。
Commit 面板点击文件固定打开 HEAD 到磁盘比较，避免已包含一块后下一次点击只看见暂存块。
右标题为“当前版本”（显式暂存预览使用“暂存区版本”），左标题使用 HEAD；新增/删除仍仅显示真实存在的一侧。
如果磁盘恢复到 HEAD、暂存区仍有不同内容，改为展示 HEAD 到暂存区并标明“暂存区版本”。
这只是显示回退，不改变实际写入目标或把暂存补丁当作磁盘补丁；没有安全块时仍保留文件标题和整文件框。
整文件框的三态来自 `file.staged/file.worktree`，不能由可分块列表推导；二进制和重命名也必须保持部分包含。
这里不保存第二套提交选择，也不在提交前把勾选文件全部 `git add`；现有工作区提交流程只提交暂存区内容。
块写入和其刷新期间持有待完成标识，阻止提交按钮读取中间状态；预览关闭后，标识仍到已发出的写入结束才释放。
状态映射中找不到文件的备用入口也必须解析真实仓库并保存工作区目标；否则仅有正文而没有块级操作所有者。
已打开或恢复的旧单文件 Commit 预览缺少目标时，按原文件 key 中的显示路径解析仓库，不能将嵌套仓库的相对路径套到外层根目录。
补全元数据后才启用块写入；迟到的解析结果必须核对原缓冲区比较身份，不能覆盖新选中的文件。

左侧双箭头沿用已有回退契约：恢复该块到暂存区版本，只撤销未暂存内容，已勾选内容保持不变。
双箭头点击后直接回退对应未暂存修改块，不弹确认框，也不读取“丢弃前确认”设置；
这是用户明确确认的产品规则，适用于新旧 Diff 块级箭头。设置说明明确仅覆盖文件或仓库级丢弃，
文件列表、文件夹多选和整仓库丢弃的原确认调用链保持不变。
完全已包含块、新增/删除等无安全磁盘 hunk 的块禁用回退。
工作区所有者在写入前重新读取完整快照；快照变化、关闭或进入提交审查时不应用旧补丁，显示刷新结果并要求重新操作。
Git 事件在读取中到达时合并为后续读取，不能只丢弃旧结果就遗漏最后一次改动；无关仓库事件不触发刷新。
只读工作区快照使用系统临时目录里的独立 Git 管理目录和索引，不能在仓库 `.git` 中创建临时目录。
Windows 即使忽略临时子目录，也会报告父 `.git` 目录变化；读 Diff 后触发刷新、刷新再读 Diff，会不断作废结果，
导致正文已经出现而双箭头与块级包含框始终等不到快照。不要用关闭监听或发布过期结果遮掩这个循环。
例如查看文件只在系统临时目录创建一次性索引；实际提交仍使用原有仓库内提交上下文，以保持提交引用语义。
临时快照目录由 Core 的上下文对象独占，正常返回和错误返回都随对象销毁清理；不复用到其他请求或工作树。
Unix 使用创建时的 0700 权限，不能先以公共权限创建再 chmod；即使临时根目录可被其他账户遍历，
HEAD、索引中的文件名和对象 ID 也只能被当前用户访问。Windows 保持用户临时目录的继承权限。
Git 的共享对象与引用只作为读取输入，真实暂存区不得改变；系统临时位置由运行环境提供，不从安装目录推导。
该目录不属于打包资源或资源复用清单，不影响发行包哈希、签名或增量更新基线。
读取失败保留旧内容并显示错误，只有 Git 状态成功确认文件已干净才关闭标签。普通自动刷新保持用户滚动位置。
并排操作位于中央两列行号外侧，不覆盖代码；它们跟随各自实际滚动坐标。统一视图复用 Monaco 的公开 gutter widget，
不插入动作空行，也不改动内部 DOM。只创建当前可见区的并排控件，卸载清除观察器、监听、控件和暂存区操作所有者。
行号按钮固定在列的左边缘，动作空间只由按钮内边距预留；容器不能再加内边距，否则绝对定位按钮会向中央溢出。
两个只读控件关闭整行光标底色；源跳转提示由工具栏按钮承载，不给整个内容宿主设置原生 title 气泡。
参考 Community 的 `SimpleLocalChangeListDiffViewer.kt`、`LocalTrackerDiffUtil.kt` 和 `PartialCommitInclusionModel.kt` 的
块包含、标题文件复选框与三态列表；Lithe 的包含事实由 Git 暂存区拥有，不移植 IDEA 的本地 tracker 或提交排除数据库。

并排页面使用 `IndependentCommitDiff` 和 `mountIndependentCommitDiff`（当前页面的布局与资源所有者）。
两个 Monaco 0.55.1 只读编辑器分别显示旧、新行流，不使用 DiffEditor，不补齐另一侧缺失的行。
Git 的补丁顺序和历史行号仍是事实来源，`planIndependentCommitDiff` 只投影已有行并记录连续增删边界，
不重新比较文件，也不补造稀疏补丁缺失的源码。通常的统一视图和多文件页面保留原有共享 Diff 所有者。
整文件新增复用独立代码控件的单流布局，隐藏不存在的旧侧、连接带和分隔条，只显示实际新文件行号。
新增底色覆盖行号、代码、轨道及底部留白，避免原生空旧模型被绘成灰色删除行和外圈；不伪造旧文件文本。

上下导航使用这些边界；下箭头在文件末尾切换下一条目，等待语言准备与模型更新完成后定位第一处差异。
整个集合末尾禁用，不循环；上箭头仍只导航当前文件。首次打开、左右切文件和跨文件后的落点均为第一处改动。
定位意图由只读组件保存，等待本次模型与比较完成后只执行一次；同路径重新打开新比较会重新定位，
词级/空白、字号和主题调整不会重新抢走用户位置。等待更新时禁用导航和源跳转，清除旧连接、行号与装饰；
迟到的语言准备结果必须检查当前请求版本和卸载状态。高频滚动、尺寸不进入 React 或缓冲区状态。

页面采用 macOS Diff 与 IDEA Islands 的明暗背景、40px 工具栏、22px 图标按钮和三态差异颜色。
两侧差异概览与透明常显纵向滑块分别放在最左、最右外侧，轨道宽度 12px、滑块 8px。
轨道占用独立布局空间，不显示代码，避免左侧代码开头被概览和滑块遮挡。
左侧轨道与面板边缘、右侧轨道与代码视口各留 4px 间隙，右侧代码在轨道前裁剪；
窄列时留白随可用宽度缩减，不能出现负宽度。间隙是本页面布局选择，并非 IDEA 固定尺寸。
代码区、行号区与轨道滚轮统一采用编辑器配置所有者提供的两倍灵敏度，普通编辑器和笔记本代码区共用；它是加快滚动的产品选择，
不是 IDEA 的固定倍数。滑块拖动仍按真实可滚动范围映射，键盘方向键按用户实际行高移动。
纵向滑块只设置 Monaco 公开滚动偏移；命中和拖动生命周期复用 `startDocumentResizeSession`。
横向滑块保留 Monaco 原生控件，`scrollBeyondLastColumn: 0` 关闭文件末列后的附加空白。
左右横向按同一像素偏移同步；纵向滑块、滚轮、键盘和查找按 Git 差异边界同步对应行，保留各侧真实滚动范围。
单文件并排和统一视图隐藏补丁的 `@@` 标题，只保留真实内容行；不改变补丁数据、行 ID 和暂存块身份。
内容本身以 `@@` 开头时仍显示。底部使用公开 padding 留出五个实际行高，不补造模型行或源行号。
两个编辑器保留原生选择、复制、查找、语法高亮与用户字体/行距，关闭补丁投影中的诊断、符号与选择概览。
并排和统一预览通过 Monaco 公开 guides 配置关闭缩进及括号引导线，保留语法颜色。

整行差异使用 Git 连续增删边界；词级差异复用 BSD-3-Clause 的 jsdiff 8.0.2 `diffWordsWithSpace`。
每块最多 8192 字符和 512 编辑步骤，整份预览最多处理 128000 字符，超限保留整行差异。
有词级结果的修改块采用 IDEA 的中间底色：正文修改色占 40%、页面底色占 60%，
词级替换两侧都使用完整修改底色，纯新增、纯删除片段分别使用增删底色；中央行号和连接面保持完整修改色。
明暗配色采用 Islands 对应编辑器方案的 DIFF 背景色，独立轨道的增删改标记与对应背景共用颜色，
不再使用另一组概览前景色。这是用户要求的页面颜色选择。文字仍在原生装饰之上，
不改变语法前景色或文字透明度；关闭词级或预算超限时保留完整整行底色。
通常的统一视图仍复用原生 DiffEditor，必须在本预览范围内把 Monaco 的公开增删行、字符和行号栏颜色变量
接到同一组 Islands 底色，字符边框透明；否则新增文件会落回默认黄绿色、删除落回默认红色。
不覆盖活动语法主题，不修改其他编辑器的颜色；统一视图的修改按原生增删分段呈现。
原生统一 Diff 通过公开 `renderIndicators: false` 关闭行号旁的增删符号；独立行号只绘数字。
这是一项呈现增强，不将 Git 的行级脚本重新交给字符算法推断。锁文件固定来源和校验，未新增运行时下载、
资源目录或可共享缓存；现有资源复用清单已覆盖 Bun 下载缓存，node_modules 仍是各工作树独立可变状态。
词级和空白开关由页面保存，切文件后保持。Windows Commit、Git Log 和统一 Diff 页面不再自动折叠
连续上下文，完整补丁的全部真实行直接显示，避免出现 hidden lines 打断浏览和对应行滚动。
底层独立布局仍保留折叠投影兼容能力，页面不启用；Ctrl/Cmd+F 调用原生查找。

左右版本标题复用现有锁图标，按条目保存真实父提交与目标提交：
单提交采用第一父提交，连续范围采用 baseRef/targetRef，离散选择保留各自版本身份。
`null` 父版本表示空树；缺少版本元数据的旧快照使用“上一版本”，不猜测 hash。
重命名分别显示旧、新路径，通常的统一视图纵向显示两个标题；新增仅显示新版本、删除仅显示旧版本的一组标识与路径。
单边标题参考 Community `OnesideTextDiffViewer.createTitle` 按实际一侧选择标题、`OnesideContentPanel.setTitle` 只承载一组标题。
分隔条布局事件只修改页面 CSS 列宽，标题跟随实际编辑器宽度，不发布 React 或缓冲区状态。
中央区域为左右历史行号预留真实宽度，SVG 连接面跨过两列行号，并绘制在数字后面。

## 考虑过的备选方案

- 在旧纵向页面加按钮：仍会同时渲染多个同路径提交区段，无法满足一次显示一个文件的需求。
- 切换文件时重新请求 Git：增加等待和迟到结果风险，丢失离散提交版本身份。
- 新写文本/词级差异算法：Git 已提供行级脚本，jsdiff 提供成熟词级增强，不重复实现比较算法。
- 将首次定位意图写入持久缓冲区：会使偏好切换或重绘反复定位，覆盖用户后续滚动；组件只按比较身份消费一次。
- 保留 DiffEditor 的公开配置：能改颜色与滑块，但公开 API 不能关闭补空白行，也不能把左纵向滚动条放在外侧。
  用户对照图明确要求动态连接带，因此需要独立页面布局，而不是继续叠加 CSS。
- CSS 移动 Monaco 内部行号或镜像整个编辑器：会使代码、选择、查找、弹窗和鼠标命中坐标不一致；
  采用两个独立只读代码控件，以公开 API 提供文本选择和坐标，页面只负责外围布局。
- 完全自绘代码文本：会重复实现长文件可见区、语法、复制和连续选区。本次复用完整只读 Monaco 控件，
  布局与连接几何放在局部页面中；未来可替换控件，但必须保持公开坐标和选择接口。
- 两侧设置同一个 scrollTop 或按总高度比例同步：在长短不同的差异块之后会错行；采用差异边界映射。
- 忽略所有 `.git` 父目录事件或在持续失效时直接发布旧快照：可能漏掉仓库替换、外部暂存与真实更新；
  让只读快照不写入被监听的仓库元数据，保留监听和迟到结果保护。

## 后果

完整文件上下文使用 `FULL_FILE_CONTEXT_LINES = 1_073_741_823`，不能使用 Git 接受的最大值 `2_147_483_647`。
Git 的 xdiff（补丁生成引擎）合并相邻修改时会计算两倍上下文；Windows 的有符号 32 位整数会溢出，
将多处修改拆成互相重叠的整文件 hunk（补丁区块）。这会让同一源文件内容重复显示、行号反复回到 1，
也会使块包含失去安全的完整文件输入。工作区、HEAD 到磁盘快照和暂存区读取共用安全上限，Core 还会在实际 Git
参数中显式加入 `--inter-hunk-context=0`，避免用户配置在旧版 Git for Windows 中重新触发溢出；不能在视图层去重掩盖补丁错误。

一个固定预览标签可以浏览整个比较集合，也能保留同路径的多个提交版本。
代价是缓冲区保存完整集合，即使当前只显示一个文件；Git API 本来就返回完整集合。
历史预览继续采用现有补丁上下文范围，不在前端补造缺失的源码。
代价是并排页面需要自己维护连接几何与外侧纵向滑块；这些资源与单文件页面一同卸载。
词级超限退回整行高亮，展开上下文会更新只读模型，模型 URI 和资源数量保持不变。
macOS 本次不修改，双端功能矩阵保持目标产品运行验收待验证的状态。
