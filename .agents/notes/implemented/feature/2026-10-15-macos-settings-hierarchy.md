# Agent 笔记：设置页分类归属规则

状态：已实现

## 先说结论

设置侧栏有七个一级分组：外观与行为、插件、版本控制、构建/执行/部署、语言与框架、工具、AI；最后是一级页面“关于”，它不是设置分组，但更新相关的设置（自动检查、更新渠道、发布源）只放在它的更新卡片里。每个设置页必须属于其中一个分组，分组关系只写在设置模型的 `parents` 表中，侧栏、面包屑和“打开设置时展开所属分组”都从这张表推导。新增设置页前先按下面的归属规则选分组，不要再加一级入口。

## 问题

分组关系如果同时写在侧栏、展开逻辑和面包屑三处，新增页面很容易只改一处，出现“侧栏在 A 组、面包屑写 B 组”的不一致。仓库里原本也没有规则说明新页面该放哪里，每次都靠评审时口头约定。

## 决策

### 归属规则

| 分组 | 放什么 |
| --- | --- |
| 外观与行为 | 应用本身的外观、编辑器显示与输入、快捷键，以及应用自身网络请求的代理设置 |
| 插件 | 插件的安装、启用和插件自带的选项；一级页面，不属于任何分组 |
| 版本控制 | 分组本身是目录页；每个版本控制系统一个子页，目前只有“Git”（GitHub 账号、变更标记、行尾 Blame、变更列表、Git 日志上限和 Git 控制台）。2026-11-21 之前这些开关直接放在“版本控制”自己的页面上；以后加 SVN 等系统时，新增一个子页，不往 Git 页里塞 |
| 构建、执行、部署 | 分组本身是目录页；固定子页“工具链”（插件声明的全部工具，包括项目 JDK）和“调试器”（单步过滤等调试设置）；插件声明的构建工具页、编译器页按种类排在后面，以及运行配置、服务运行和框架、构建工具注入的配置 |
| 语言与框架 | 没有固定子页；插件声明的语言页、框架页（语言服务开关、Spring Boot 等框架配置）排在下面，有子页时它成为分组，分组本身是目录页 |
| 工具 | 终端、搜索（搜索和替换文件大小预算）、控制台（运行、构建和测试控制台的输出编码）、可信位置（本机可信文件夹列表，与工具链共用偏好目录的 toolchains/global.json，#2207 加入）等通用工具；控制台和可信位置 2026-11-21 前在“构建、执行、部署”下；插件带来的专用工具可以放进对应工具页。日志与诊断不属于设置，它是独立的日志窗口 |
| AI | 与 AI 有关的全部配置：MCP、Skill、全局指令、AI 提交信息、Agents、AI 服务商 |
| 关于 | 应用本身是什么、怎样拿到新版本：版本信息、更新卡片（自动检查更新、更新渠道、发布源、立即检查）、交流群和项目链接（开源仓库、问题反馈、Rust Core、Viva 上游）；一级页面，固定在侧栏最后，除更新卡片外不放设置项 |

插件带来的设置默认放进“插件”页；只有它新增的是某个分组本来就该有的能力（例如新的版本控制系统）时，才放进那个分组。插件可以在清单中把页面注册到“语言与框架”或“构建、执行、部署”下，这些页面由插件声明推导，宿主不为具体语言或构建工具写专用页面。

「外观与行为 → 编辑器」的自动补全开关控制客户端何时弹出语言服务器与插件提供的补全候选。该偏好由客户端持久化，默认开启，关闭后仍可按 Ctrl+Space 请求补全。补全内容仍由原有的语言服务和插件提供。

### 二级折叠

AI 分组内，Agent 可加载的资源（指令、技能、Hooks、MCP 配置）收进可折叠的“资源库”，与 AI 服务商、Agents、AI 与提交并列。二级折叠由子分组声明，页面仍归父分组所有，面包屑为“AI › 资源库 › 页面”。只有同类资源达到三个以上页面时才新增二级折叠。

“构建、执行、部署”下插件声明的页面按种类（构建工具、编译器）归类：每个有页面的种类在侧栏只占一行，行尾是页面数，不展开；点开是和「工具链」「调试器」一样的分栏页，左侧列出这一类的全部页面和提供插件，可以按名称或插件筛选，右侧是选中页面的设置。再次打开时回到这一类上次看的页面。插件页只在侧栏搜索命中时才单独出现在侧栏，点结果在分栏页里打开。“构建、执行、部署”目录页每个种类只写前 3 个名称并计数其余，条数只写在设置窗口的 `kindNames` 常量里，不要为某个插件或种类单独改。这些插件页是额外的聚合入口：同样的设置仍然留在插件详情的「设置」标签，不从那里移走。详细结构见[构建、执行、部署设置页在大量插件注入时的结构](2026-11-18-build-execution-settings-at-scale.md)。

“语言与框架”下插件声明的页面直接作为子页列在侧栏。凡是自己有页面的分组（设置模型里 `ownsPage` 为真：“版本控制”“构建、执行、部署”和“语言与框架”），点侧栏这一行会打开自己的页面并展开分组，子页上方面包屑里的分组名可以点回这个页面。“版本控制”的页面是目录：标题下一句说明，再列出每个版本控制系统一行（图标、名称、它包含哪些设置），单击打开该子页；目录页不放任何开关。它和“构建、执行、部署”目录页共用同一个列表绘制（`directory`），不要另写一套。“语言与框架”的页面是目录：每个插件页一行，写页面名称和提供插件，语言页另写第一个提供插件的语言服务状态；单击或回车打开该页，方向键只移动；列表虚拟化，只绘制可见行。没有插件贡献页面时说明页面从哪里来，并给“浏览插件市场”入口。打开的语言页不重复目录行已经写的内容：只有一个插件贡献时直接是它的设置，没有插件选择器，也没有语言服务状态卡；两个以上插件贡献同一页时才显示选择器，和“构建、执行、部署”的分栏页一致。2026-11-21 之前 `content()` 没有处理这个分组自己的页面，点它只显示“新桌面端暂未提供此页面”；给 `ownsPage` 加分组时，要同时在 `content()` 里给出它的页面。

### 开发者怎么做

- 新设置页：在设置分类中增加页面，并把它加入所属分组的 `parents` 表；补充搜索词与文案。不需要再改侧栏、展开逻辑和面包屑。
- 新分组：只有上表没有任何一行能容纳时才新增，并先更新本笔记。

### 不要这样做

- 不要把页面直接加到一级页面列表里绕开分组；一级页面只留给插件和“关于”。
- 除更新卡片外，不要把设置项放进“关于”；更新卡片也不要再复制一份到其它分组，例如在“外观与行为”下重新开一个更新页。
- 不要在设置视图中再写按页面分支的分组判断。
- 不要为某个语言或构建工具新增设置分类，让对应插件在清单中注册页面。

### 页面宽度

设置页内容区随窗口宽度伸缩，页面不要自带固定的最大宽度，否则调大设置窗口后右侧会出现空白。需要限制宽度的是单个控件，不是整页。

## 考虑过的备选方案

- **完整实现三级树。** 未采用。目前“构建工具 → Maven”“服务运行”“框架支持”没有对应的独立页面，为凑树形结构拆页面或放空页会增加没有内容的入口。
- **“外观与行为 › 更新”独立成页，“关于”只放一张不可编辑的更新卡片。** 2026-11-18 起不再采用。两处显示同一个当前版本和检查状态，用户要在两页之间来回找渠道和发布源；用户决定把整套更新设置迁入“关于”，删除独立更新页。
- **“版本控制”保持一级页面，Git 的开关直接放在上面。** 2026-11-21 起不再采用。用户决定让“版本控制”和“语言与框架”一样显示总览，Git 的设置搬进“Git”子页；以后加其他版本控制系统时，各自一个子页，目录页一眼能看出有哪些系统。代价是从侧栏进 Git 设置多点一次；Git 控制台和 Git 日志里的设置按钮直接打开 Git 页，不受影响。
- **“控制台”“可信位置”放在“构建、执行、部署”下。** 2026-11-21 起不再采用。用户决定移到“工具”：这两页不是构建或运行配置本身，控制台编码对所有控制台生效，可信位置决定项目以什么方式打开，都属于通用工具设置。“构建、执行、部署”目录页因此只列工具链、调试器和插件声明的种类，打开它也不再读取可信文件夹。
- **规则只写在 `AGENTS.md`。** 未采用。入口文件只保留指向本笔记的提醒，详细规则放在笔记中，避免多份规则漂移。

## 后果

- 一级入口减少到七个，AI 相关页面集中；分组关系只有一个来源。
- 旧的设置位置会变化，已有用户需要重新找一次。
- 插件页面的归属由插件声明决定，宿主不需要为新插件修改分组。
- “版本控制”与“语言与框架”“构建、执行、部署”一样先给目录再进子页；外部入口（Git 控制台、Git 日志的设置按钮）直接打开子页，不经过目录。
- 更新设置和版本信息在同一页，找“我现在是哪个版本、从哪里更新”只看一处；代价是“关于”不再是纯展示页，页面更长，项目链接要往下滚才能看到。

- `scripts/desktop/desktop-go.sh test ./internal/settingswindow -count=1`：验证侧栏、面包屑、搜索展开与“关于”排在 AI 之后；`TestBuildKindIsOneRowThatOpensItsPage` 等验证插件页的种类行与分栏页；`TestLanguagesPageListsItsPagesAndOpensThem`、`TestLanguagesPageWithoutPluginPages` 验证“语言与框架”目录页、它的面包屑链接和空页面；`TestLanguagePageDoesNotRepeatItsDirectoryRow` 验证语言页不重复目录行；`TestVersionControlPageListsGitAndOpensIt`、`TestGitIsTheOnePageOfTheVersionControlGroup` 验证“版本控制”目录页、Git 子页和面包屑；`TestToolsGroupHoldsTerminalSearchConsoleAndTrustedLocations`、`TestBuildDirectoryListsOnlyItsOwnPages` 验证工具分组的四个子页和构建目录页只列自己的子页。
