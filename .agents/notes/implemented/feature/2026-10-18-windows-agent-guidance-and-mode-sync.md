# Agent 笔记：Windows Agent 计划、推理与模式同步对齐 macOS

状态：已实现

## 先说结论

第 12 期把 macOS 已有的三项对话呈现接入 Windows：Agent 上报的执行计划、与回复分开的思考过程文本，以及 Agent 自行切换模式后的选择器同步。三项都只消费 ACP 上游事件，不在 Windows 侧推断或补造状态；没有计划就不渲染计划栏，没有思考文本就不会出现空的思考行。

## 问题

第 11 期完成后，Windows Agent 对话已经能在工具窗口和编辑区之间移动，但 `agent_thought_chunk` 仍会被并入回复正文，ACP 的 `plan` 与 `current_mode_update` 事件被直接丢弃。用户看到的是：推理文字混进回答、Agent 汇报的计划不可见、Agent 自行退出计划模式后权限选择器仍停在旧值。macOS 已经有完整的呈现和解析语义，本期按 macOS 对齐，而不是另做一套 Windows 样式。

## 决策

- 思考文本使用独立的 `reasoning` 消息角色。收到 `agent_thought_chunk` 时先冲刷待合并的正文缓冲，再追加思考，保证思考与回复交替时顺序正确且文本不混合。
- 思考行按 macOS 呈现为安静的一行摘要：流式时显示小号进度和“思考中…”，结束后显示“思考过程”；折叠时不显示正文预览。展开后是最大 240px 的 Markdown 卡片，流式时跟随到底部。
- 搜索命中时思考行强制展开，搜索期间点击标题不会收起；清空搜索后回到手动偏好或流式默认状态。
- 计划在每次 `plan` 更新时整体替换。空条目数组是合法清空；顶层结构非法时忽略整次更新，保留上一份计划；单条缺少内容或状态不在 `pending/in_progress/completed` 内时丢弃该条，不默认成待办。
- 计划栏固定在活动统计栏上方，折叠时显示单行“计划 1/3”和当前步骤；展开后最多 180px 滚动。已完成使用成功色勾选并加删除线，进行中在 Agent 响应时使用虚线圆环、轮次结束后使用半填充圆环，待办使用空心圆。
- `current_mode_update` 只同步 `category == "mode"` 的已有配置项，并且要求目标 id 已在该项的 choices 中；未知 id 不写入、不回发请求。
- 历史导出把思考标记为 `Thinking` 并以引用块保留；历史消息数继续只统计对话轮次，不计工具与思考行。
- 功能矩阵把计划、推理、模式同步和 Agent 入口可发现性四行从 `missing` 推进到 `implemented / pending`，真机验收仍待执行。

## 考虑过的备选方案

- 继续把思考并入回复：实现最少，但会破坏思考与正文的流顺序，也无法独立折叠、搜索或导出。
- 折叠时保留思考首行预览：信息更多，但与 macOS 的安静摘要行不一致，长思考会把对话列表挤乱。
- 把非法计划状态默认成 `pending`：能少丢几条，但会把上游协议错误伪装成合法待办；macOS 明确丢弃该条。
- 用 `option.id === "mode"` 兜底匹配模式项：能兼容个别历史配置，但会把仅同名、非 mode 分类的配置误当成权限选择器。
- 为 Windows 单独设计计划卡片或思考面板：自由度更高，但会与 macOS 形成两套交互，后续还要分别维护。

## 后果

- 计划、思考和模式只来自 Agent 上报；上游没给就不显示，不提供本地伪造的默认值。
- 非法计划更新不会清空用户正在看的计划；只有合法空计划才会移除计划栏。
- 思考行不参与活动统计和历史消息计数，导出时也不会与回复混淆。
- 第 12 期不新增 ACP 请求，也不改变 Rust host 的事件转发。
