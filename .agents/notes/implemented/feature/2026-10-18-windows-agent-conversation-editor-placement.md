# Agent 笔记：Windows Agent 对话在编辑区标签与工具窗口之间的放置

状态：已实现

## 先说结论

Windows 的 Agent 对话现在可以从右侧工具窗口移动到主编辑区，再原路移回。移动的是同一个 ACP 会话，不是复制一份聊天：连接、消息、标题和未发送草稿都由窗口级单例共享。编辑区标签使用 `agent-conversation://<sessionID>` 这种确定性虚拟路径，因此重复打开只聚焦已有标签；标签关闭或点击反向位置按钮后，工具窗口重新显示对话。工具窗口在编辑区占用会话时改为历史列表，避免同一会话出现两个可输入的输入框。

## 问题

第 10 期完成后，Windows 的 Agent 面板已经能保留每个 Agent 的会话并等待设置确认，但对话只能待在右侧工具窗口。macOS 参考实现允许把同一会话放进编辑区标签，并保持：

- 编辑区使用居中的聊天列和按需展开的会话详情栏；
- 工具窗口在对话移走后继续承担历史管理；
- 两个位置显示同一标题、同一会话和同一份未发送草稿；
- 重复打开不创建第二个会话或第二条连接；
- 关闭标签等价于把对话移回工具窗口，而不是断开 Agent。

Windows 编辑器原本已有 `agent` 缓冲区类型，但它渲染的是旧的本机 API Key AI 聊天，不是新的 ACP Agent 面板；直接复用会让两套 Agent 语义混在一起。

## 决策

- 新增独立的 `agentConversation` 缓冲区类型，路径固定为 `agent-conversation://<encoded sessionID>`。路径是标签身份，重复调用只会激活已有标签。
- `AgentPanel` 增加 `placement`、`sessionID`、`isActive`、`onMoveToToolWindow` 和 `onTitleChange`。工具窗口和编辑区共用同一组件与同一个 `agentConnection()` 单例，没有第二份连接或消息状态。
- 编辑区列最大 `716px`，输入框最大 `700px`；右侧会话详情栏通过标题栏按钮开关。宽屏时详情栏占独立列，窄屏时以覆盖层出现。
- 会话详情只展示连接已经上报的数据：标题、Agent 与版本、工作区、会话 ID、消息/轮次数量、上下文占用和模型配置。MCP 服务器与变更行数没有后端数据时不编造，直接说明尚未上报。
- 未发送文本和附件从组件本地状态提升到 `agent-surface.store`，按会话 ID 保存。工具窗口和编辑区因此读写同一份草稿；切换会话仍各自保留。
- 编辑器标签像终端和 WebView 一样常驻挂载，普通标签切换只隐藏，不卸载。否则每次切走都会丢失滚动位置并触发“关闭标签”的清理逻辑。只有当前可见标签的 `isActive` 为真时才允许它选择共享连接，避免隐藏标签争抢会话。
- 工具窗口检测到 `editorSessionIDs` 非空时显示历史列表。选择历史行会聚焦该会话已有标签，或为尚未放置的会话新开标签。
- 关闭编辑区标签会清除放置记录并打开工具窗口；项目切换导致的批量卸载不会强行弹出 Agent 面板。
- 编辑区放置只在本次运行内有效。现有工作区会话持久化只恢复文件、终端和 WebView 标签，本次没有把 ACP 会话标签写进磁盘。

## 考虑过的备选方案

- 复用旧 `agent` 缓冲区类型：改动更少，但会把本机 API Key 聊天和 ACP Agent 混成同一类标签，后续无法独立演进，也会让旧聊天把新标签当作上下文。
- 在编辑区再建一个 Agent 连接：界面看起来一样，但两个进程各自持有会话，标题、草稿和权限都会分叉，违反“同一个会话移动位置”的要求。
- 把对话主体抽成新的无状态组件：结构更纯，但第 11 期需要同时处理设置页、历史页、搜索、选项卡和连接生命周期，改写面过大；在当前阶段给 `AgentPanel` 增加放置维度更可控。
- 关闭标签只清空标签、不打开工具窗口：实现简单，但用户会以为对话丢失；macOS 的语义是移动位置，因此这里选择返回工具窗口。
- 编辑器标签按需挂载：能少挂几个组件，但标签切换会反复卸载输入框和滚动区域，也无法可靠区分“切走”和“关闭”。

## 后果

- 同一会话只保留一个可输入界面：放在编辑区时工具窗口是历史页，放回工具窗口时编辑区标签关闭。
- 编辑区标签和工具窗口共享连接状态与草稿；任一位置的发送、停止、权限处理和模型切换都会立即反映到另一位置。
- 隐藏的编辑区标签仍保留组件状态，但不会轮询额度或抢占当前会话。
- 会话详情栏不提供 MCP 和 Changes 的本地伪造数据；等 Agent 上报后再扩展。
- 重启应用后 ACP 会话标签不会自动恢复，仍可从历史列表重新打开。
