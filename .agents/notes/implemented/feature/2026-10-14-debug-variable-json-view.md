# Agent 笔记：调试变量的 JSON 与树形查看

状态：已实现

## 先说结论

调试的变量面板可以在树形视图与格式化 JSON 视图之间切换。JSON 是从调试适配器返回的字段生成的只读快照，不是对目标程序执行序列化，也不承诺等同于业务接口的 JSON。大对象、循环引用或不可用的字段用标记说明，不假装已经完整读取。

## 问题

多层对象和列表需要反复展开才能找到末端值。只复制调试器返回的摘要文字（如 `User@123`）得不到完整字段；而调用目标进程中的序列化函数或 `toString()` 可能执行用户代码、改变程序状态或让暂停的会话卡住。

## 决策

- **只读取调试适配器的字段。** 继续使用调试适配器协议的 `variables` 请求，字段、类型和对象引用归调试器所有。
- **快照由独立的投影逻辑生成。** 读取、编码和限制在快照中完成，不改变树的展开状态与分页缓存。
- **只在 JSON 可见时读取。** 切回树视图或离开面板会取消读取；恢复运行、切换会话、栈帧或作用域后，旧结果会被拒绝。
- **循环引用按路径判断。** 只有在当前路径上重复出现的对象引用才视为循环，两个字段引用同一对象不算循环。
- **不解析摘要字符串。** 不可展开的摘要保留为字符串，不伪造结构。
- **数字精度。** 超过精确整数范围的值保留文本，避免丢位。
- **取消只结束当前快照。** 超时与取消只结束本次快照的等待，不取消整个调试会话，以免影响监视表达式等其它检查。

## 考虑过的备选方案

- **调用目标的 `toString()` 或序列化库。** 未采用。依赖目标项目，并可能执行用户代码。
- **默认展开所有树节点。** 未采用。仍然依赖大量层级和滚动，也改变用户原有的树状态。

## 后果

- 暂停后第一次打开 JSON 视图会额外请求字段，代价是一次读取。
- JSON 不包括未加载的全部根变量，也不保证第三方调试器的逻辑集合视图。
- 复制内容是调试快照，不能直接当作业务请求的完整载荷。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/workbench/ ./internal/core/ -count=1`：覆盖调试变量与调试状态。
- 在真实调试会话中验收：树与 JSON 双向切换、复制、恢复运行后旧快照不再显示。
