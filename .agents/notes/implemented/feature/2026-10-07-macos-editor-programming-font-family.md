# Agent 笔记：代码编辑器可选择编程字体族

状态：已实现

## 先说结论

代码编辑器的编程字体族是用户设置，默认值仍是随发行包提供的 JetBrains Mono，因此未改设置的用户看到的效果不变。候选列表只包含等宽字体族；终端、输出窗口和提交说明输入框继续使用打包字体。用户选中的字体被卸载或缺字时，显示回退到打包字体，设置项仍保留用户原值。

## 问题

用户希望更换默认的编程字体。字体会被三类排版系统消费（系统字型名、网页编辑器的 CSS 族名、Diff 的单字符宽度度量），因此不能只加一个下拉框。编辑器的 Diff 横向宽度与行号栏宽度依赖等宽字体的假设，比例字体会让它们错位。

## 决策

- **只列等宽字体族。** 判定只看实测：`i`、`W`、`0` 三个字形的宽度必须相同，不依赖字体的“等宽”声明。打包的 JetBrains Mono 固定排第一。
- **设置只保存族名。** 设置项保存一个族名，默认值为 `JetBrains Mono`。规范化（去空白、空值回落默认）不检查字体是否安装；是否可用由平台层判断，所有渲染入口先解析族名，无法解析时回退打包字体。
- **网页侧传 CSS 族名并带回退栈。** 编辑器字体栈为 `"所选族", "JetBrains Mono", monospace`，网页与原生界面使用同一套回退。
- **字体列表只在进程内缓存。** 枚举与等宽探测结果只保存在内存中，新装字体需要重启应用后才会出现在候选列表中。
- **缺字时提示但不阻止选择。** 探测字符覆盖（拉丁字母与界面标点必须覆盖；中文只在中文界面要求），缺字时在设置中显示说明，打包默认字体不显示该提示。
- **终端与输出不跟随编辑器字体。** 终端、输出窗口与提交说明保留打包字体，与 IDEA 的 Editor font / Console font 分工一致。
- **字体设置的界面选择复用共享控件。** 可搜索的选值控件复用已有的设置选值组件，不另建第二套下拉。

## 考虑过的备选方案

- **允许全部字体，另加“只显示等宽”开关。** 未采用。比例字体会让 Diff 的单字符度量失效，需要先重做横向宽度与行号栏测量。
- **使用系统字体面板。** 未采用。外观与产品共享下拉体系不一致，也无法只列等宽族。
- **把字体列表持久化到磁盘。** 未采用。若要持久化，必须写到平台存储目录而不是安装目录。

## 后果

- 编辑器字体可以按用户习惯更换，默认行为不变。
- 只支持等宽字体；字重缺失时按系统最接近的字重降级，不会合成字重。
- 首次枚举字体有一次性的停顿，应放到后台完成，而不是持久化缓存。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/settingswindow ./internal/bundledfont -count=1`：覆盖设置页与打包字体的回退。
- 在真实窗口中验收：切换字体后编辑器、Diff 的行号与横向滚动一致；卸载字体后回退到打包字体；终端字体不变。
