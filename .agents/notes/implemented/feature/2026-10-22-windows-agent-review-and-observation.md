# Agent 笔记：Windows Agent 修改审阅、粘贴文件与观测统计

状态：已实现

## 先说结论

Agent 上报的差异只是证据，不能直接当成可覆盖整个文件的快照。Windows 撤销必须同时检查完整原文、编辑器脏状态、工作区路径与磁盘字节身份；明确创建的文件只能移入回收站。图片粘贴写入应用缓存，统计只保存有界的数字汇总，发行目录保持只读。

## 问题

工具报告可能是片段、重放或重复更新。直接覆盖文件可能丢失用户修改；只统计最新 ACP 用量又会把上下文占用误当成会话累计。图片若仅依赖内存 URL，发送后历史引用会失效。

## 决策

- 修改审阅按文件汇总精确差异版本。保留动作只确认对应版本前缀，后续差异重新出现；断连和重放保留确认，关闭会话标签才释放。
- 撤销在平台文档 adapter 内使用保存锁与预期字节身份，拒绝工作区外路径和末端重解析点。明确创建才允许移除，先暂存并核对实际对象，再交给 Windows 回收站；失败尝试恢复，不能覆盖并发重建文件。
- 片段撤销的唯一性检查包含重叠匹配，精确文本和换行归一化都从首个匹配起点加一继续搜索。例如 `ababa` 中的 `aba` 有两处匹配，必须拒绝撤销，不能挑第一处覆盖。
- Windows 路径解析保留 `canonicalize()` 的扩展路径用于工作区和字节身份检查，只在 Shell 回收站边界转换盘符与 UNC 路径。转换后再次解析必须指向同一目标；超出旧 Shell 长度限制、设备命名空间或尾部点空格导致别名变化时拒绝并恢复暂存文件，不可直接删去前缀后操作另一个文件。
- 正确示例：文件仍等于上报的完整新内容时，按原编码恢复。错误示例：把工具的十行摘录当成整个文件，或删除已经被用户改写的创建文件。
- 文件粘贴读取 Windows 的文件列表格式 CF_HDROP；图片按格式、数量、单张与批次大小限制写入平台缓存。失败或过期粘贴只删除自身文件，已接收附件为历史保留。
- 会话累计与最新上下文占用分别记录。工具计时取活动区间并集，重复工具 ID 不增加次数；历史重放不重复累计。模型调用统计保留上游未知值及下界说明，构成估算明确标注。
- 累计数字按工作区、Agent、会话隔离，最多 200 条。缓存不保存消息、原始请求、配置文本、密钥和凭据存在标记。

## 考虑过的备选方案

- 直接反向应用文本差异：简单，但无法识别外部改动和片段歧义，故加入完整证据与原生身份保护。
- 直接删除新建文件：无法恢复误删，所以采用受保护暂存与原生回收站。
- 累加每条 usage 更新：容易重复计算上下文快照与历史回放，所以累计只接受本地轮次及去重观测。
- 定期按年龄删除粘贴图片：可能破坏仍被历史引用的文件，因此仅清理能证明属于失败或放弃操作的文件。

## 后果

用户可以安全审阅和撤销有完整证据的修改，并查看断连后仍保留的数字汇总。代价是缺少原文、路径可疑或磁盘发生变化时必须拒绝撤销；已接收图片缓存可能长期保留，历史引用的回收需要独立所有权设计。

## 验证

- `windows/tauri` 中运行 `bun run typecheck` 与 Agent 前端测试，覆盖片段歧义、精确创建、外部变化、重放、统计去重和重叠计时。
- `./.agents/skills/write-stable-tests/scripts/test-stability-windows.ps1 -Scope WindowsRust` 覆盖平台文档路径、身份检查与受保护移除。
- 交互式 Windows 会话运行 `./scripts/windows/test/test-windows-agent-recycle.ps1`：使用真实 Shell 回收一个独占临时工作区中的中文文件名，检查回收站条目与字节，再仅恢复和清理该工作区的条目。原生调用有 15 秒期限，Shell 恢复轮询有 10 秒期限，报告含验收与清理耗时；常规 Rust 套件跳过此显式验收。
- `node scripts/resources/test-reuse-worktree-resources.mjs` 验证图片缓存不能跨工作树复用，缓存不属于发行资源。
- 桌面验收必须检查实际文件字节、原生回收站路径和发行资源前后哈希；单元测试不替代这些运行时证据。
