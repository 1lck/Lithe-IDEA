# Agent 笔记：声明式原生插件界面契约

状态：已实现

## 先说结论

插件可以声明树、列表、表单和面板工具栏动作，由宿主用共享控件呈现，开发者只提供数据与函数，不编写样式。声明本身不能携带颜色、字体或脚本。结构、所有权和预算的校验由 Rust Core 完成，宿主的呈现层不复制这些规则。当前 Viva 桌面端只有 Core 侧的校验入口（`desktop/internal/core/plugin_native.go`），还没有渲染原生插件界面。

## 问题

文本窗口无法表达节点选择和业务动作，网页界面则要求插件作者自己维护控件和样式。插件作者需要一种既不写样式、又不能执行第三方界面代码的声明方式。

## 决策

- **声明只描述结构。** 首版支持一棵树、一个列表，或一个表单及其面板动作。声明不能携带颜色、字体或脚本。
- **Core 负责校验。** 初始声明与刷新数据的结构、所有权（哪个插件、哪个面板）与预算都在 Core 校验，宿主不复制这些规则；无效的刷新结果保留上一份有效节点并显示错误。
- **表单只接受声明。** 表单可以包含输入框、选择器、复选框和按钮，控件的 ID、值类型、选项、动作引用与预算由 Core 校验。宿主恢复已保存的字段值时，要剔除已删除的字段、变更类型的字段和失效的选项。
- **提交只在明确时机发生。** 文本输入只保存本地值，回车提交；选择器与复选框在改变后提交。提交通过已有的非选择类函数调用，不新增后端接口。
- **动作限定在面板内。** 工具栏动作只显示图标，标题作为悬停提示与无障碍名称；动作不能按插件或动作 ID 推断图标。
- **会话与生命周期。** 原生面板与网页使用同一套会话登记表。插件停用、替换或关闭项目时取消请求；隐藏窗口时释放请求，重新打开时从已有的状态存储恢复选择和展开状态。
- **只读资源边界。** 状态只写入平台提供的可写存储，不改变已安装的插件包或应用的发行目录。

## 考虑过的备选方案

- **要求所有插件提供网页页面。** 未采用。网页只作为可选方式，不满足免写样式的需求。
- **执行插件提供的界面代码。** 未采用。增加二进制兼容、签名和隔离问题。
- **一次实现任意组件组合。** 未采用。超出首版范围，先验证最小完整路径。

## 后果

- 同一份树与动作声明可以直接使用宿主的统一样式。
- 首版每个面板只匹配一个已检测的构建实例，完整刷新最多 2000 个节点，尚无按需加载子节点。这些限制由契约明确规定，不能默默选择第一个实例。
- 动作只能在面板内使用，不能据此宣称已经具备全局命令。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/core -count=1`：覆盖 Core 侧的契约校验与会话接口。
- `scripts/desktop/verify/verify-runtime-bundle-immutability.sh`：检查原生界面的资源路径不写入发行目录。
- 渲染层接入后，需要在真实窗口中验收树、列表、表单与动作的深浅主题、焦点与隐藏重开。
