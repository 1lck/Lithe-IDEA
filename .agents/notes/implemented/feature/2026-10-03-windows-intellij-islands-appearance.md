# Agent 笔记：项目颜色渐变与项目标识

状态：已实现

## 先说结论

项目的颜色渐变和头像颜色由同一个函数决定：对项目根目录路径计算 64 位 FNV-1a 哈希，再映射到色板序号。头像、项目菜单和渐变必须取同一个序号，不能为某一处另起一套配色。色板和渐变的具体颜色属于主题数据，不能写死到所有主题里。

## 问题

用户把 Lithe 与 IntelliJ 并排使用，项目颜色不一致会被直接看到。若把 Islands 的颜色写成全局默认值，第三方主题会被强行染色，高对比主题的可辨识度也会下降。项目颜色又不能每次启动随机变化，否则同一项目的颜色会让人失去辨认依据。

## 决策

- **颜色序号由路径哈希决定。** 使用项目根目录路径的 64 位 FNV-1a 哈希对色板数量取模。哈希自行实现，不使用标准库的 `hash/fnv` 路径，因为它在每个最近项目的每一帧都会执行。
- **头像与渐变共用序号。** 项目头像、项目菜单和渐变都读取同一个 `identityColorIndex`。
- **颜色属于主题。** 色板取自当前主题，其它主题只继承布局与圆角，颜色由主题自身推导。
- **不做按项目持久化的颜色。** 颜色完全由路径决定，不需要额外的存储。

## 考虑过的备选方案

- **按 IntelliJ 的做法轮流分配颜色并持久化。** 未采用。需要新增项目级存储，而且与 macOS 的路径哈希方案不一致。
- **用 Canvas 或遮罩层绘制渐变。** 未采用。需要与面板布局同步重绘，违背可调整面板的性能边界。
- **把 Islands 颜色设为全局默认。** 未采用。会覆盖第三方主题的设计意图。

## 后果

- 同一个项目路径在不同界面中颜色一致。
- 路径变化（移动项目目录）会改变项目颜色。
- 第三方主题只获得推导出的近似颜色，不是逐像素复刻 IntelliJ 的渐变。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/workbench/ -count=1`：覆盖颜色序号与渐变的计算。
- 在深浅主题下检查最近项目列表、标题栏与项目菜单的颜色是否一致。
