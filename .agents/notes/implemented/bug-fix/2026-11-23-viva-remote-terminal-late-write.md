# Agent 笔记：远程终端退出后的写入确认

状态：已实现

## 先说结论

远程 shell 可能在一次输入请求等待确认时退出。终端退出会清空输入队列，随后到达的写入确认应直接结束发送循环。判断终端是否结束与更新队列在同一次加锁中完成。

## 问题

桌面发送器复制一段输入后释放锁，等远端响应。这段时间内，终端输出请求可以先返回并清空输入。随后处理成功响应时，发送器从已清空的队列移除原来的字节数，导致桌面客户端崩溃。

## 决策

在处理写入确认、更新输入队列之前，重新持有终端状态的锁并检查退出状态。只在终端仍运行时移除已确认的字节，继续发送排队的输入。

## 考虑过的备选方案

- 把移除的字节数截到队列当前长度。这样虽能避免切片越界，发送循环仍会把终端退出后的确认当成可以继续的工作。
- 持锁等待远端写入确认。这样会让终端退出和新的输入都需要等待远端，破坏终端退出与输入处理的独立性。

## 后果

终端退出可以立即释放积压输入。延迟的确认在发送器再次拿锁时被丢弃，正常的分块输入和重试沿用原流程。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/workbench -run '^TestRemoteShellStopsWhenWriteIsAcknowledgedAfterExit$'` 固定先退出、后确认的顺序。修复前复现切片越界，修复后发送器退出，终端拒绝新输入，正常退出不报告失败。
