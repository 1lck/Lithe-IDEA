# Agent 笔记：在当前工作区完成插件启用

状态：已实现

## 先说结论

工作区推荐里的「查看插件」直接打开插件市场，推荐多项时显示完整目录。启用语言服务器插件后，已打开、语言已识别的文件在原标签开始同步。用户可以在当前项目继续编辑。

## 问题

多项推荐沿用了普通插件设置入口，新窗口显示已安装的插件。打开文件时若没有语言服务器提供者，插件启用后也没有新的打开事件来请求服务器。安装恰好发生在首次查询已读到旧插件列表时，同语言的启动去重还可能吞掉新的请求。

## 决策

插件市场入口显式区分未指定搜索和空搜索。插件状态变更通过现有启动入口处理已打开文件，每种语言最多请求一次。首次启动使用旧列表并且未找到提供者时，才处理期间积存的注册表刷新请求。窗口和项目关闭、用户取消、以及正在运行的会话沿用原生命周期。

## 考虑过的备选方案

等待用户再次打开文件会延迟语言能力。启用任何插件都重启项目语言服务会重复导入工作区，并中断正在运行的会话。已有打开文件提供了按需启动所需的信息。

## 后果

启用后会查询已打开文件对应的语言，有服务的语言可以立即准备。已运行的服务器继续服务，真实启动错误仍通过现有诊断反馈。完全未知扩展名的旧标签需要再次打开来识别语言。

## 验证

运行 `./scripts/desktop/desktop-go.sh test ./internal/workbench -run TestPluginEnable`，覆盖现有文件接管及安装与旧查询交错。运行 `./scripts/desktop/desktop-go.sh test ./internal/settingswindow -run TestOpenMarketplaceWithoutSearch`，覆盖首次打开窗口和窗口已打开两种情况。

## 适用范围

适用于 Viva 工作台的插件管理、现有文档同步和设置窗口的插件市场入口。
