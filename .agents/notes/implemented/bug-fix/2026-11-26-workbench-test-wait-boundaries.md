# Agent 笔记：工作台测试按操作等待并限制等待时间

状态：已实现

## 先说结论

工作台测试只为当前断言等待必要的后台结果。绘制和菜单选择不再等待整个应用的后台任务；确实需要全部任务完成时，等待和清理都有本地截止时间。这样既保留真实 Git 集成覆盖，也能在失败时说明还剩哪些任务，而不是等整个测试包超时。

## 问题

#2425 的对照显示，main 与彩虹分支都会超过累计 180 秒，不能据此判断最后一个 Git 用例挂死。旧 `settle()` 无期限等待全部后台任务，`settleChain()` 的六轮和 `settleUntil()` 的十二轮只限制轮数，无法限制单轮耗时。单纯选中引用也会等待无关的仓库查询。

固定十二轮还会拒绝合法的较长任务链。另一方面，只有本地分支的强删测试仍创建 bare 远程和第二个克隆，增加了与断言无关的进程成本。

## 决策

- `sendClick` 只发送输入并绘制立即结果；调用方随后等待被测操作的完成状态。例如选中引用直接检查选择结果，删除分支等待 `busy` 结束并检查真实 Git 结果。已有通用 `click` 保留六轮刷新语义，避免一次改变所有测试的假设。
- `settleUntil` 使用窗口唤醒事件推进并检查明确条件，不用固定轮数。不要把真实 Git 命令放进被反复检查的条件；先等操作完成，再执行一次真实仓库断言。
- 保留的全任务等待及六轮刷新共用生产已有的三十秒 Git I/O 期限，清理仍限八秒，普通条件等待仍为八秒。完整分组中的合法多仓库提交超过八秒，因此全任务期限对齐原生 I/O；旧实现没有全任务期限，测试包期限不变。Git 分支写操作同样使用已有三十秒操作期限。原先点击内部的无限等待发生在八秒 `await` 之前，因此旧八秒并没有约束完整写操作。
- 工作队列用可取消等待的 `taskGroup` 替换 `sync.WaitGroup`。每批非空任务持有独立的完成通道；归零只关闭该批通道，后续新任务不能让旧等待者错过完成。取消只停止等待，不取消任务；不为等待创建额外 goroutine。它只负责 Go 工作线程同步，不承接 Core 的业务状态规则。
- fixture 初始化等待仓库、日志或嵌套仓库的必要状态；远程行为继续使用真实本地 bare 仓库和第二克隆。纯本地强删只创建本地历史。
- 条件完成后仍须绘制其失效帧；要点击弹窗里的控件，还须等待会改变控件位置的内容。例如 Build options 同时等待配置值和运行时行，不能只看忽略路径已加载，否则弹窗随后重新居中，旧坐标会点空。提交并推送（包括 linked worktree）等待真实审阅结果，单次本地提交等待其 busy 结束，再检查仓库；不为断言等待其他仓库后台任务。
- 清理仍先关闭项目并取消其资源，再用八秒期限等待任务退出。超时报告运行数、待投递结果数和工作台状态，再关闭驱动。该期限不能强制终止不响应取消的任意后台实现；底层进程仍须遵守自己的取消与进程树清理契约。

## 考虑过的备选方案

- 增大整个包的超时：不能修复无限等待或说明真正未完成的操作。
- 将阻塞等待放进额外 goroutine 并只超时调用方：会遗留无法回收的等待者。
- 将全部 Git 用例改成模拟数据：会丢失远程引用、强删保护和跨仓库回滚的真实边界。
- 把所有点击改为异步返回：会改变无关测试的既有刷新顺序。本次只替换能指出具体完成状态的夹具路径。

## 后果

不再为引用选择等待无关任务，也不会因超过十二个后台回合而误判失败。工作队列每个非空批次增加一个通道，闲置时不新增线程或轮询。真实 Git 仍有集成成本；定向组通过不代表整个工作台在 180 秒内完成，也不代表原生窗口验收完成。

- `TestLogReferenceSelectionDoesNotWaitForUnrelatedTask` 用受控任务阻塞应用工作队列；旧点击等待其截止时间而失败，新实现保留任务未完成并立即选中引用。
- `TestHarnessPredicateWaitFollowsMoreThanTwelveTurns` 推进二十个受控后台回合；旧十二轮 helper 失败，新实现完成。
- `task_group_test.go` 控制等待者注册、任务追加、归零、立即复用与取消的先后顺序，并为所有等待者设置截止时间及清理。
