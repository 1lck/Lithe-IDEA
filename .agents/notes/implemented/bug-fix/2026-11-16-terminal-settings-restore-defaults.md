# Agent 笔记：恢复默认设置必须通知终端设置所有方

状态：已实现

## 先说结论

设置窗口的全局「恢复默认设置」必须重置回滚行数和光标，而不只是默认 Shell 与行为开关。显式恢复需要通知设置所有方，即使未知保存值在页面上已显示成默认值；普通打开页面仍不能改写设置。

## 问题

此前页脚遗漏两处终端重置调用，两个设置函数又以归一化后的值比较，无法清除显示为默认的未知值。

## 决策

沿用窗口已有的 force 参数约定：普通控件传 false，显式恢复传 true；已关闭会话始终拒绝写入。回滚恢复还清除未提交的输入草稿，避免旧输入在后续绘制时重新覆盖默认。

正确做法是通过既有设置回调交给工作台保存，不直接写偏好文件或更改运行中 Shell。不要在页面初始化时修正未知值，也不要让普通未变化选择产生重复回调。回滚默认值继续使用 DefaultScrollback；工作台仍负责以零值保存默认语义。

## 考虑过的备选方案

没有为两项设置另建 reset API，因为窗口已有强制通知约定；没有直接替换整个 Values，因为这会绕过设置所有方及其他设置的生命周期。

## 后果

代价只是在显式重置时调用既有回调，无新增状态、线程或持久化格式。

## 验证

terminal_reset_test.go 在真实 Viva Driver（无头窗口驱动）中点击页脚，检查非默认与未知值的回调、显示、草稿及关闭后的边界。terminal_reset_visual_test.go 生成明暗主题、中英文的重置前后截图。

## 适用范围

范围仅 desktop/internal/settingswindow 的终端设置和页脚；不改变 Core、插件、Shell 配置或默认值。Linux 无头结果不替代 macOS/Windows 原生验收。
