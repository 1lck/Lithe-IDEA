# Agent 笔记：保存工具链后刷新构建提供者

状态：已实现

## 先说结论

独立构建提供者（在后台常驻、执行插件构建或测试请求的进程）在启动时绑定工作环境。
项目工具链或全局默认值保存后，下一次请求重新启动提供者，不要求用户重启桌面端。
正在执行的请求仍交给旧进程，排空后再关闭；无变化的保存不会触发重启。

## 问题

原来进程复用只比较插件设置，不比较宿主保存的工具链。即使设置页已显示新程序，
仍可能由旧进程执行下一次测试任务。

## 决策

宿主在确认写入后推进工具链修订，现有进程复用键同时记录该修订。
与语言服务器共享的提供者仍由语言服务器管理，不能通过这条路径另起一份。

## 考虑过的备选方案

没有选择保存时关闭所有构建会话，因为这会取消正在执行的任务；也没有在测试请求中特判具体语言，
因为同一个常驻进程也会为模型、依赖等其他请求服务。

## 后果

保存时没有额外的工具探测。代价是作用域内的独立提供者会在下次使用时重新解析并启动，
即使某个提供者不依赖刚变更的工具。

## 验证

在 `desktop/internal/workbench/build_provider_restart_test.go` 用合成提供者验证项目 pin 保存、已有请求排空
和重复保存。在 Windows 的同一原生窗口中先用旧工具执行，再保存新工具并重跑，核对两次实际启动的路径。

## 适用范围

Viva 两端共用的宿主进程管理。Core 的选择规则、插件契约和界面文案不变。
