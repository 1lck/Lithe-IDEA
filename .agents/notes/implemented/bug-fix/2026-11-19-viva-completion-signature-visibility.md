# Agent 笔记：补全名称和长签名的显示空间

状态：已实现

## 先说结论

补全列表优先给候选名称留出宽度，便于区分前缀相同的函数。签名在列表中放不下时，选中项的完整内容会在列表底部换行，超出详情区域时可以滚动。方向键切换候选时同步更新详情。

## 问题

固定宽度的补全弹窗在同一行压缩名称和签名。两个候选可能只显示相同的名称前缀，调用参数和返回类型也可能藏在省略号后。

## 决策

- 工作台使用实际字体测量候选，行内省略、详情触发和参数文档换行均使用扣除边框和内边距后的宽度。参数文档的卡片高度包含边框。
- 列表放不下选中项的全部文字时，在有界高度的详情区域展示完整文字。超长文本交由 Viva 虚拟列表按块换行，滚动条可直接定位到后面的内容，键盘焦点留在编辑器。
- 补全根据光标上下的可用高度限制候选行数，键盘导航始终能带入当前选中项。参数信息同时避开补全弹窗和当前编辑行。窗口空间只够一个弹窗时保留补全列表。

## 考虑过的备选方案

- 给所有弹窗改用更大的固定宽度。窄窗口和更长的签名仍会遇到截断。
- 在每个候选行换行显示签名。可见候选行数会随内容变化，用户逐项浏览时需要追踪位置。
- 用一个换行控件排版超长签名。控件会在首帧同步排版整段文本，压缩可见高度也无法减少这部分耗时。

## 后果

常用函数名可以直接在列表中辨认。详情会临时占用额外高度，光标附近空间有限时会少显示几项候选。超长详情的虚拟列表在接近文本块边界时可能多换一行。
