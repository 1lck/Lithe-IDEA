# Agent 笔记：远程重连、文件写入和会话恢复的安全边界

状态：已实现

## 先说结论

远程连接恢复后必须重新判定信任，文件保存必须由服务端检查工作区边界，保留会话的令牌必须先比较实际目标再发送。本次实现了这些检查，并限制文件读取、目录响应和监听队列的资源用量；保存的外部写者竞态仍仅得到缓解。SSH 身份日志尚有磁盘增长风险，整组改动保持 Draft，不能直接作为发行验收结论。

## 问题

断线前的信任、保存连接的 ID 和 SSH 别名都可能在下次连接时过期。客户端先检查路径再写入也无法阻止主机上父目录变成符号链接。无限读取、大目录和无界监听队列会让单个工作区耗尽资源。

## 决策

- 断线立即撤销运行许可；只有新会话的信任读取可以恢复许可，过期异步结果不能重新授权。
- 保存携带工作区根和预期文件版本。服务端相对目录句柄定位，拒绝根以下的父目录和叶符号链接；旧服务没有相应能力时拒绝保存。
- 暂存前后复查精确版本并协调 Lithe 写者，新建文件原子拒绝覆盖。POSIX 无法按版本原子替换已有文件，不遵守锁的外部写者仍有检查到替换的窗口。
- 从同一实际 SSH 连接取得身份，再选择恢复凭据。例如别名从主机甲改到乙时，应新建会话并保持安全模式；不要按别名发送甲的令牌。
- 无法核验的路由不自动恢复，旧凭据保留；宿主只在 Core 明确消费过凭据时删除记录。
- 读取、响应和监听队列同时检查字节与数量预算；监听溢出要求重扫，不能默默丢失后继续声称状态完整。
- 容器工作树保存完整 SSH、WSL 与容器路由，不能在重新打开时退化为本机容器。

## 考虑过的备选方案

- 预读 `ssh -G` 再覆盖连接选项：两次执行可能得到不同路由，不能证明实际认证身份，未采用。
- 仅对主机名加哈希：不能区分别名改绑、账户和最终容器状态，未采用。
- 自动恢复失败就删除原凭据：目标不匹配不代表原会话已结束，未采用。
- 把读取日志的 64 KiB 上限视作磁盘上限：OpenSSH 仍可持续写入，不能作为资源风险已修复的证据。

## 后果

失去信任或身份变化后仍可浏览，但运行项目代码需要重新确认。代理连接可能需要每次确认信任。严格拒绝符号链接保存会影响此前依赖该行为的工作流；用户需直接打开目标文件夹。

SSH 身份日志的持续写入与生命周期、安装包内新增路径验证尚未解决。服务状态标记不是硬件身份，复制账户状态到相同路径的克隆也会复制身份。Windows、真实 ProxyJump 和完整容器工作流尚未验收。
