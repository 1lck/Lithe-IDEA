# Agent 笔记：手动补全的光标与语言服务器启动

状态：已实现

## 先说结论

手动补全属于触发时的文档版本和光标位置。语言服务器还在探测或启动时，工作台保留这次请求，待文档同步后按原有流程合并候选。探测确认没有会话时，工作台可以直接询问插件。

## 问题

只移动光标不会改变文档版本。若独立插件这时返回旧候选，弹窗可能出现在新光标下面，接受候选时却修改原位置。服务器尚未登记的启动阶段也会暂时查不到会话，提前选择独立插件会遗漏稍后可用的服务器候选。

## 决策

- 独立插件请求进入工作台已有的语义请求队列。光标移动、文档编辑、切换标签或下一轮补全可取消它。展示或接受候选前，核对当前文档版本和光标位置。
- 手动请求在等待语言服务器时保留触发位置。会话启动成功后沿用文档同步和双来源候选合并。未启动会话时重新判定来源，只在当前位置仍有效时尝试独立插件。
- 自动补全开关继续只影响输入触发的候选。仍使用原有插件和语言服务器契约。

例如，同时注册两种补全来源的文件打开后立刻按 Ctrl+Space，应在同步完成时看到两边的候选。在这个等待过程中移动光标后，原位置的候选应被丢弃。

## 考虑过的备选方案

- 只比较文档版本。这个检查能拦住编辑后的回包，但光标移动不会改变版本。
- 在服务器启动时立刻展示插件候选，再补充服务器结果。这会让同一轮补全的列表和当前选中项在用户准备接受时变化。沿用现有合并流程可以在候选到齐后交付一份列表。

## 后果

纯插件仍可手动补全，已开始探测的语言可能需要等到来源明确后才显示候选。等待期间每个工作台只保留最近一次手动补全，关闭文档或光标变化时释放请求。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/workbench -run 'TestManualProviderCompletion|TestManualCompletion'`。合成插件控制回包时间，覆盖移动光标后按 Enter、语言服务器启动后合并候选，以及探测未找到服务器时的独立插件回退。
