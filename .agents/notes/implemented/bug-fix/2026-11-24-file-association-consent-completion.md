# Agent 笔记：文件关联必须等待系统确认完成

状态：已实现

## 先说结论

macOS 设置默认应用时，必须等待公开异步接口的完成回调，再读取实际默认应用。一次选择多个格式应处理整批，普通单项失败不能阻止其余格式；系统是否逐项要求确认仍由系统决定。返回设置窗口后只读刷新，保留勾选和上一轮失败反馈。

## 问题

初版文件关联（`c086a0b1b`，#2361）在同步设置返回成功后立即检查默认应用，把尚未观察到的新值转换成“找不到应用”（-10814），并在首项失败时终止整批。用户日志中的快速失败和下一轮基线冲突与此路径一致；日志没有证明系统确实找不到已安装的 Lithe。Windows 的候选注册也在单项写入失败后直接结束，返回系统设置后没有自动读取结果。

## 决策

macOS 通过 `NSWorkspace.setDefaultApplication` 等待完成，按统一内容类型（UTType，系统识别文件格式的标识）合并后缀别名。默认查询与候选注册的修订依据系统事实，不使用同应用标识的启发式安装路径。Windows 保持当前用户注册表与系统默认应用设置流程，不写受保护的 UserChoice。

普通单项错误保留原生原因和失败后缀后继续。取消、超时或未结束的系统确认停止后续提交；迟到回调只使用自己持有的原生内存，同一进程最多保留一个未结束的系统请求。操作结束后的回读独立限时，窗口激活也只触发读取。

正确示例：`.java` 和 `.jav` 共用一个系统类型，只发一次请求，完成后读取实际默认应用。不要在提交接口返回后立即合成 -10814，也不要因用户取消一次等待而释放系统回调仍会访问的内存。完整行为约束见[系统文件关联](../feature/2026-11-23-system-file-associations.md)。

## 考虑过的备选方案

- 保留同步设置并增加固定等待：无法知道系统确认何时结束，也无法可靠处理用户拒绝。
- 强制所有格式只显示一次系统授权：公开接口没有整组授权参数，不能作此承诺。
- 通过修改 Windows UserChoice 直接设置默认：绕过系统保护，不能作为可靠注册流程。

## 后果

整批不会因一个普通失败而提前结束，界面也能区分“候选已注册”和“默认已生效”。代价是必须管理异步确认生命周期；系统已显示的确认无法撤回，宿主超时后仍可能生效，因此回读和重试提示必须说明这一点。

## 验证

- `scripts/desktop/desktop-go.sh test -race -tags 'vivahead lithevisual' ./internal/fileassociations ./internal/core ./internal/settingswindow -run '^Test(FileAssociations|VisualFileAssociations$)' -count=1 -timeout=60s`：定向通过；自动回读测试临时移除 `OnActivate` 时失败、恢复后通过。
- 原生只读与内容类型别名测试不修改默认应用；幂等探针只对已经生效的同一默认应用重复提交一次，完成回调成功且默认值不变。它们不代表批量写入或授权已经验收。
- 签名发布包的 macOS 批量写入、拒绝与超时后回读，以及 Windows Go 原生构建、注册、系统确认和卸载仍待目标系统验收，功能矩阵保持 `pending`。
- `scripts/agent-notes/verify-agent-notes.sh`：校验 Note 格式、路径与链接。

## 适用范围

适用于 `desktop/internal/fileassociations/`、`desktop/internal/settingswindow/file_associations_view.go` 和设置窗口的激活回调。不改变 Core 的格式目录与冲突计划，也不改变既有单文件编辑入口。
