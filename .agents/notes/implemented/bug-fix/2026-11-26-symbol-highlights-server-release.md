# Agent 笔记：语言服务退出后的符号高亮恢复

状态：已实现

## 先说结论

语言服务停止时，只取消该服务提供的符号高亮请求，其他服务或单文件查询的高亮保持不变。所属服务停止后，仍打开的编辑器保留恢复目标，在服务能力和文档同步恢复后重新查询，无需用户移动光标。文档关闭或项目退出时必须彻底释放目标。

## 问题

原先单个服务退出和项目切换共用整体清理入口，清理请求时也忘记了当前文档。后续恢复入口失去查询目标，静止选区的高亮无法恢复；其他语言服务退出也会误清当前高亮。

## 决策

工作台按服务身份撤销所属请求，取消在途操作并更新请求代次以拒绝旧答案，只保留打开的文档，不保留旧服务。保留目标的查询键使用无效修订，确保下一次服务能力通知或文档同步完成会重新检查当前选区。恢复复用已有事件，不增加定时轮询。

语言服务可能在请求标识绑定前就返回结果。共享清理入口只保留仍有活跃请求匹配的早到结果；取消的请求和关闭的文档不再匹配，其他服务仍在使用的答案不会被误丢。

### 正确做法

- 当前文件由服务 A 提供高亮，服务 B 停止时保留 A 的请求。
- A 停止时撤销旧请求；A 重新同步后从当前选区查询，旧答案不能覆盖新请求。
- 文档关闭和全部服务释放时清除文档引用及所有待执行工作。

### 不要这样做

- 在共享语义弹窗重置入口里无条件清空高亮目标，它也会被单个服务退出调用。
- 为恢复高亮保留旧服务实例，或等待用户再次点击作为恢复机制。

## 考虑过的备选方案

每帧从当前文档重查会掩盖目标丢失，并增加无交互时的工作，因此不采用。让全部清理入口保留文档会延长已关闭文档的生命周期，也不采用。

## 后果

服务停止和编辑器关闭具有不同的清理边界。恢复仍遵循现有请求去重、文档成员检查和过期答案保护；新增状态只借用仍打开的文档，所有关闭路径必须释放它。
