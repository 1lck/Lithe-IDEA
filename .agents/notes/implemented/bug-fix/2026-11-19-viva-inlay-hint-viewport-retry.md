# Agent 笔记：Viva 内联提示请求失败后的视口重试

状态：已实现

## 先说结论

编辑器请求内联提示遇到临时错误时，会对同一视口自动重试一次。服务连续失败后，编辑器等到视口、文档版本或服务刷新事件变化时再请求。等待期间保留当前文档已有的提示。

## 问题

语言服务器可能在编辑过程中撤回请求，响应也可能无法解码。原来这两种情况都会把整个视口登记为已取回。停留在相同位置等服务恢复时，编辑器会一直跳过该视口的请求。

## 决策

- 每个可见范围批次成功返回后才缓存覆盖范围。一个分段失败时，丢弃这次批次收集到的结果，保留上一份已绘制的提示。
- 首次失败后通过画布调度一次延迟帧。重试仍失败便等待输入、文档版本或服务刷新事件。刷新从新批次开始，过期批次的结果直接丢弃。

## 考虑过的备选方案

- 把失败当作空结果缓存，编辑器将失去自动恢复机会。
- 失败后立即重新请求，服务持续失败时，每次响应都会引出新的请求和帧。

## 后果

短暂失败会增加一次视口请求。服务器恢复较慢时，旧提示会一直保留到下次成功刷新、文档版本变化或编辑器关闭。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/workbench -run '^TestLSPInlayHints'` 使用合成服务和虚拟时钟验证自动恢复、连续失败后停止，以及收到服务刷新后的恢复。
- `TestVisualLSPActions` 检查同一视口中一次失败前后的绘制，覆盖深浅主题与中英文。
