# Agent 笔记：Viva 调试会话的进程退出与取消清理

状态：已实现

## 先说结论

调试适配器可能直接退出，不能只等调试协议的结束事件才清理。宿主必须同时观察原生进程退出，并在停止时解除管道写入、等待正在创建的 Core 会话返回后销毁它。旧会话迟到的结果不得修改新会话。启动计划、可执行目标和调试参数由原 Rust Core 根据插件声明生成；客户端不再发空参数。

## 问题

调试适配协议（DAP）负责调试语义，但进程崩溃时不保证发送 `terminated`。把 Go 内存管道作为子进程标准输入，会让 `exec.Cmd` 创建输入复制任务；输入源没有关闭时，进程已经退出也可能卡住 `Wait`。

停止与创建并发时，先销毁再收到创建成功会留下 Core 会话。后台复用局部结果变量，再让界面回调读取它，也会产生数据竞态。

## 决策

- 使用原生文件管道作为适配器标准输入，宿主拥有并关闭父进程端；取消和有界写入超时都关闭管道。
- 同时观察进程退出与协议结束。清理幂等，立即停止进程和写入，再等待启动任务结束后销毁 Core 记录；等待退出观察器回收。
- 会话 ID 跨项目唯一，界面结果按项目、会话身份和代次核对。投递给界面的结果使用独立值快照。
- 正确示例：用户点击停止，创建调用迟到成功，清理任务随后销毁该 ID。不要先销毁尚不存在的 ID 就认为完成。

### 真实启动准备与事件时序

启动前读取已安装插件的原始清单，把它交给 Core 的进程计划、目标可执行文件查找计划和启动参数接口。界面提供显式适配器选择；当前源文件、工作目录、原生查找结果作为事实传入，程序路径和默认参数按插件的 targetBindings（目标字段绑定）生成。配置明确给出程序路径时，路径不可运行就是失败，不能悄悄回到自动候选。此批读取插件默认值和当前文件；完整 Run 编辑器、用户项目覆盖和 Java 调试目标仍未接入。

文件检查、通用 macOS 开发工具查找和进程创建均在后台。macOS 在 PATH 缺失时交给 xcrun 查找所选开发工具目录，不写死 Xcode 路径或 LLDB 工具名。运行时入口先逐段验证包路径，再交给工具链解析和 Core 的 launch 模板实例化；不在 Go 拼接运行时参数。该 serverProcess 4 路径只有内部契约测试，尚未因此扩大宿主声明或声称运行时插件完整准入。

原生进程句柄原子发布，停止可以发生在后台进程创建之前。启动任务、接收、断点和检查操作各自串行完成 Core 调用、发送帧和发布界面结果，避免不同 goroutine（并发任务）重排同一会话的传输。启动完成后，清理只销毁真正创建过的 Core 会话，再等待原生退出并删除本次会话独占的可写状态目录。目录由原生 `MkdirTemp` 分配，位于插件可写根 `.state/<plugin-id>/<version>/desktop-debug-<session>/`，不会与另一应用进程的会话计数器碰撞；包和应用安装资源只读，不影响签名或增量更新。

真实 LLDB 可以先发送暂停或结束事件，再确认启动请求。Core 的确认只能把仍处于 launching 的状态改为 running，不能覆盖更新的 paused/terminated；成功确认仍报告操作完成。正确做法是保留用户已经看到的暂停状态，不要用稍后收到的确认把目标显示成运行中。共享 fixture `Lithe-core-rust/rust/fixtures/debug/launch-event-order.json` 固定这条边界。

## 考虑过的备选方案

只等待 DAP 结束事件无法覆盖崩溃；把无界 `Wait` 放进后台任务也不能解除输入复制任务。继续使用内存管道会增加一个需要额外管理的复制任务，因此这里使用原生管道。取消后只丢弃界面结果也不够，仍须回收 Core 会话和进程。

## 后果

异常退出和停止可以释放本次会话，旧错误不会污染重启后的界面。代价是宿主需要维护启动完成和退出观察器的同步信号；写入超时会关闭会话管道，不能继续复用。当前还未完成完整 Run 配置编辑、attach、TCP、Java 语言服务器调试、变量和步进；真实 LLDB 流程不代表这些能力已验收。
