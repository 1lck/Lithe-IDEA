# Agent 笔记：项目树目录读取使用独立 I/O 限时

状态：已实现

## 先说结论

项目树读取会访问文件系统并查询 Git，不能沿用纯计算请求的两秒限时。
桌面端为每批目录读取保留三十秒上限，关闭项目仍立即取消请求。
同级忽略目录的跟踪文件检查属于独立 Rust Core 仓库；本文对应的主仓库修改不改变 Core 固定版本，也不把本地 Core 优化当成已经合入的能力。

## 问题

Windows 0.8.0 的项目树把目录读取超时统一显示为项目目录不可用，虽然目录和 Git 均正常。
诊断项目的十个忽略目录触发逐项 Git 检查，单独复现耗时 2.412 秒，超过原请求限时。

## 决策

- `desktop/internal/workbench/filetree.go` 仅对目录列表使用独立 I/O 限时，仍通过项目 context 取消，并复用既有过期结果隔离。
- Git 忽略与跟踪规则留在外部 Rust Core，桌面端不复制或解释 Git 忽略策略。
- Core 批量查询优化与桌面端 I/O 生命周期修改分别提交，依赖升级前保持原固定版本和契约。

## 考虑过的备选方案

- 重开项目或重新安装 Git：不改变稳定复现的查询数量和限时。
- 全局提高纯计算限时：会扩大无关调用的等待范围。
- 无界等待或在 Go 重写忽略规则：分别失去故障上限、破坏共享逻辑归属。

## 后果

慢磁盘上的目录读取可以完成；永久阻塞仍由有限超时和关闭项目的取消边界约束。
本地诊断包通过 `LITHE_CORE_RUST_DIR` 链接任务目录的 Core 优化，并保留原始修订、补丁和构建身份；它的性能数据不能代表本次主仓库 PR 已包含 Core 优化。

## 验证

先确认 Go 的 `TestProjectTreeDirectoryReadsAllowNativeIO` 在修复前失败，再验证修复后通过，并检查 `TestProjectTreeDirectoryReadCancelsWhenProjectCloses`。
实际项目读取、独立 Core 优化及本地诊断包的验证分别记录，不能混用；测试报告随本地构建保存。

## 适用范围

Viva 桌面端项目树和所链接 Rust Core 的索引目录决策；不改变项目文件、Git 配置或安装目录写入规则。
