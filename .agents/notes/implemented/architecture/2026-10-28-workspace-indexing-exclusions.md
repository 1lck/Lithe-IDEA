# Agent 笔记：目录索引排除与项目树可见性分离

状态：已实现

## 先说结论

目录能否在树里浏览，与是否进入 Lithe 自有索引是两种不同的策略。
手动排除及 Git 自动排除由 Rust Core 判断，两端只存储项目偏好并触发刷新。
语言服务拥有自己的扫描器；Java 导入排除不能当作整个 Java 资源扫描已停止的证据。

## 问题

目录标记原本是显示角色，用户把目录标记为已排除后仍可能进入搜索缓存。
复用隐藏名单可以减少扫描，却会同时让用户无法在树里找到目录，违反浏览需求。

## 决策

索引策略使用独立版本，版本变化使旧缓存失效，并令在途扫描拒绝发布。
每个工作区运行实例持有独立的租约，即同一根仍在使用的凭据；扫描版本与
释放句柄分开。Git watcher 只更换扫描版本，同根的其他工作区关闭时不能使
当前工作区退役。显式配置替换本 owner 的句柄，成功返回前保留旧句柄，失败
恢复旧租约；已经交给并发成功调用的句柄不能被另一次失败回收。策略校验和
句柄发布在同一个临界区完成。最后一个 owner 释放后才清理根的库存和缓存。
配置失败也须恢复最后一次成功发布的策略，而不只是租约令牌。配置安装身份与
扫描版本分开，watcher 更换扫描版本仍保留安装身份；这样配置期间被 watcher
替换的未发布策略也能回滚。回滚创建新扫描版本，不重新激活旧扫描；另一个
调用已经成功接受的新策略则保留，避免失败调用撤销并发成功结果。
macOS 扫描期间修改开关或标记时，发布库存前比较当前策略并补扫，直到结果与
当前项目偏好一致，不丢弃刷新期间的新设置。跨项目及同根重开时，配置调用按
完成顺序串行；旧调用迟到成功须先释放其句柄，失败须丢弃，不能覆盖新项目的
策略、加载状态或错误。关闭项目后尚未完成的安装同样由原调用回收。
Core 的扫描代际取消经 Swift 桥接和远程路由原样保留；当前工作区遭其他 owner
刷新时复用新代际重扫，不把取消误报成目录不可用，也不反复强制退休对方的代际。
任务取消或工作区关闭后立即停止重试。库存准备、Git 刷新及会话恢复的异步边界
之后还须核对已应用快照 UUID，不能在较新库存发布后再次提交旧文件集。
会话恢复的完成状态归工作区生命周期所有；恢复期间库存 UUID 改变不能让已完成
的恢复重新变成未执行，否则下一次重扫会重开用户已经关闭的旧会话标签。
首次完整库存的发布与树是否已经显示分开跟踪；首次扫描不完整，或被增量库存
替换时，由第一个有效完整库存承担项目服务和本地历史基线的首次初始化。
同一策略用于初次扫描、文件名和内容搜索、符号候选以及保存直更。
例如 `vendor` 被手动排除时，`vendor/examples` 的自动包含例外不能绕过它。
不要把浏览展开返回的文件重新加入项目库存，否则手动展开会暗中取消排除。

Git 忽略语义交给本机 Git 的 `check-ignore`；查询同层目录时批量提交，
再用 `ls-files` 保护已跟踪后代。单个被忽略文件不会被升级成目录排除。
关闭自动排除保留手动标记与包含例外；应用存储不写入 `.gitignore` 或 `.iml`。

两端开关统一放在“设置 › 版本控制 › Git”，紧接程序与凭据设置，删除独立索引
页面及项目环境页中的重复入口。开关仍绑定当前工作区，Git 页切到全局配置或
选择子仓库都不改变它的范围；无项目时只显示禁用控件，不创建偏好。作用范围、
取消排除例外和语言服务限制放入同一说明提示，读取或保存错误仍直接显示。

已排除目录的标记子菜单只保留“取消排除”，避免在仍受排除策略约束时直接改成
源码、资源等角色。手动排除与 Git 自动排除使用同一菜单规则；取消后恢复普通
目录可用的标记选项。普通文件夹只改变角色，不创建包含例外；只有明确的取消
排除动作才创建例外：取消手动排除恢复记忆角色，取消 Git 自动排除保留当前角色。
修改任何普通角色都保留已有例外，只有明确手动排除删除该目录自身的例外。
不能用历史记忆角色覆盖自动排除前仍有效的源码、资源等角色。
不能猜测旧例外的产生原因，因此不自动删除
历史例外。继承手动排除的子目录仍须到对应父目录取消排除。
树中的排除状态使用目录图标及提示表达，目录后代仍可浏览；文件名文字保留
独立的 Git 状态颜色，不把整个排除子树统一染色而遮盖修改或冲突状态。

排除目录的文件仍可打开编辑。语言服务工作副本不自动打开这些文件；
已有工作副本在策略变化后关闭并清除其诊断。Java provider 合并导入排除配置，
但构建系统显式声明的模块和依赖仍由构建工具决定。Java 会话保留插件初始化时
原有的导入排除项，每次初始化、配置查询和动态通知都重新合并当前策略；取消
Lithe 排除不能清除插件规则，也不能把上一次合并结果作为下一次的原始配置。

Windows 附加目录按目标路径选择最近的工作区根，标记、包含例外和角色显示都
读取该根的项目偏好。根集合和租约由工作区运行时拥有；切换 Project、Git、
Search 或文件树卸载只清理呈现，不释放策略。移除根、关闭或替换工作区才
回收租约，原生窗口销毁同时回收已安装和迟到安装的租约。树中展开的目录只
查询状态，不成为新的工作区根。改名、删除按所属根迁移偏好，跨根移动则把角色、
排除和包含例外转移到目标根，同时保留两根各自的 Git 开关。不要用主根的设置
处理附加根。
最近根归属同样用于 Windows 编辑器的语言服务门禁：先验证文件属于哪个已打开
根，再计算相对目录；工作区之外的文件不提交项目排除查询。启动与取消仍保留
原工作区的生命周期身份，不能为了查附加根策略就替换主根 scope。增删根集合
也会清理并重新评估已打开的工作副本，不能只在下次打开文件时才使用新归属。
跨窗口偏好更新统一处理 storage 和本窗事件，按根过滤并合并后重读当前值。
后台扫描必须贯穿工作区身份；缓存 pane 优先使用其 WorkspaceStoreScopeContext，
不能在异步边界重新取活动工作区，否则切换项目会把旧根查询交给新 owner。
Windows 同根的另一个 owner 刷新扫描版本时，配置请求可重读偏好后重试两次；关闭或
移除根仍立即终止，不能把暂时的代际替换直接变成搜索错误，也不能无限重试。

多根库存、搜索与替换请求显式携带当前工作区的根集合。父根到达另行登记的嵌套
根时停止索引遍历，由嵌套根按自己的偏好生成候选。例如打开 `main` 与
`main/nested`，只在后者排除 `archive`，父根不能再把该目录加入候选或读取内容。
这一边界进入缓存身份，保存和 watcher 直更也保留同样的边界；移除嵌套根后，
父根恢复扫描。失效的无关附加根不应阻断当前根的限定搜索；尚未移除的缺失嵌套
根仍保留归属边界，避免目录重建后从父根回填。不能从 Core 全局策略表推断根成员，否则另一个窗口的策略或关闭
后保留的退役记录会改变当前窗口的结果。只过滤最终结果也不够，因为文本已经
被读取并驻留索引。
同一搜索请求的目录范围同时过滤文件名、类型、符号和内容来源，并在结果上限与
分页游标之前应用，不能让范围之外的候选占满一页。

远程传输尚未接入索引排除，因此 Git 页显示不支持并禁用开关；不能把这一状态
显示成 Git 解析失败，更不能声称远程手动排除已经生效。项目树也不提供无效的
排除动作或显示已排除图标；已有偏好保留，待能力接入后再解释。
Windows 设置页同样先检查能力，不向本机 Core 提交远程根。设置解析及存储错误
返回稳定分类，界面通过共享中英词条呈现；损坏数据保留原值，不以默认值覆盖。
目录标记的读取也使用同一稳定错误分类，树提示不能直接展示 JSON 或存储异常的
英文字符串。Windows 原生路径的标记、祖先约束、包含例外与记忆角色按路径身份
匹配，外部仅修改目录名大小写后仍能取消排除；远程及大小写敏感根维持区分。
内容搜索的首次请求、加载更多和库存状态失败同样保存类型化的索引错误，呈现层
再按当前应用语言读取词条，不能把 `Error.message` 中的内部错误码直接展示。
这样已有错误随语言切换更新，无须再次搜索；加载更多失败仍保留已取得的结果，
读取损坏偏好也不写入默认值。上游搜索诊断继续原样显示，搜索失败标题由共享
i18n 提供，不在模型中另拼英文前缀。
已有结果时继续显示列表，并在其旁呈现紧凑的错误及重试入口，不能只依赖空状态
组件。失败后暂停自动翻页，用户明确重试后才恢复请求，避免滚动观察反复触发失败。
macOS 同样在适配器返回类型化失败，状态保留失败分类，呈现时再通过共享 i18n
读取当前应用语言。不要缓存已经翻译的错误字符串，否则语言即时切换后会保留旧文案。首次配置失败
保留项目身份并显示重试，重试重新读取偏好；读取失败不允许写入默认值。
刷新失败保留已加载树。释放 Workspace 模块须使整个重建代际失效，不能只
拒绝已经开始的配置，否则等待库存的任务仍可能安装新租约。
工作区切换须先等待旧模块图关闭，再重新绑定 Workspace 资源所有者，最后
开始新投影代际。旧模块和新项目共用长期存在的界面投影；只在配置完成时
检查代际不能防止旧模块稍后释放刚开始的新项目。同根连续打开也要按独立
操作身份拒绝迟到准备结果，不能只比较根路径。
应用动作使用的打开代次由工作区会话在同步打开时建立，不能借用投影资源的代次。
等待旧图清理、重新绑定和首次开始库存会改变投影代次，但不能让刚点击的 Run、
Java 保存或语言启动请求变成旧操作。同根重开、关闭及停止会话仍使打开代次失效。
稳定身份不代表库存已就绪：Run 继续以完整快照 UUID 判断 ready，没有快照时只
绑定配置并保留延后动作，不能将空文件列表当作可运行库存。

Git 元数据事件使用索引专用重评估，不递归请求第二次 Git 刷新。只有有效
库存变化或先前不完整库存恢复完整时，才再次发布项目快照；普通 commit、
stage 等无库存变化的事件不重载项目服务。
Git 规则变更信号独立于可见文件路径：隐藏的 `.gitignore`、位于打开子目录之外的
仓库级规则，以及与普通文件同批的元数据都须保留该信号。扫描发布前同时检查
规则事件版本，扫描期间到达的新规则须补扫；同批普通文件仍发送内容更新和文件
通知。异步角色写入失败只能回滚自己仍拥有的设置版本，不能覆盖较新的取消排除
或 Git 开关操作。Windows 读取策略失败也不能中断树刷新或 Maven 待重载状态；
策略未知时暂缓源文件通知，等待后续成功刷新。

语言服务的文档提交、诊断接受和就绪队列发送与策略撤回使用同一会话同步边界。
锁顺序为索引边界、发送顺序、会话状态；库存扫描先在这些锁之外准备。就绪时还
须重查排队文件的资格，防止策略已安装、会话撤回尚未执行时发出旧事件。路径
判断解析符号链接，删除事件使用最近仍存在的祖先，避免同一文件的 URI 别名
绕过排除。

Windows 所有存活本机运行实例保持轻量监听。原生注册以窗口、运行实例和注册 ID
区分持有者；路径规范化后共享底层监听，最后一个持有者关闭才释放。同根重开
建立新运行实例，关闭后的迟到安装须回收。仓库子目录同时观察到仓库根之间的
祖先规则目录，linked worktree 继续使用原生 Git 返回的独立及公共元数据路径。
普通隐藏文件过滤不能吞掉 `.gitignore` 信号，混合批次先失效再分发文件通知。

`workspace.refreshIndexing` 验证已有 owner/令牌后只推进扫描代际，不安装新租约。
Windows 原生宿主按根合并事件，失效版本先递增，再交给后台任务和查询共用的
刷新队列。刷新期间的新事件不能由旧结果清除；等待有期限，最多处理三轮，
失败保留 dirty 状态，由下一次查询、激活、窗口焦点或显式刷新再次尝试。
首次配置进行中也登记根，避免安装前收到的事件丢失。查询返回前重查失效版本。
活动工作区改变前同步登记前端刷新任务，使库存、搜索和文档准入等待同一任务。
偏好变化与刷新完成使用不同事件，完成事件不能重新写偏好或触发无限刷新。

后台刷新不建立全文索引；只有运行中的语言服务需要目录判断时才扫描目录。
完成后，已挂载编辑器由原来的 hook 接回文档所有权，工作区控制器只重查未挂载
的源码 buffer。最初就被排除、尚未启动语言服务的 buffer 也要重新准入；没有
LSP provider 的文件跳过，单个 provider 失败不能中断后面的文档。工作副本重开
等待在途关闭，打开后再同步期间的新编辑；补同步失败保留已打开的 owner，使
后续编辑仍可重试并能正常释放 attachment。每个异步边界检查运行实例、根成员、
buffer、挂载状态及 attachment；不重启整个语言服务。
全局 Git 忽略文件仍通过激活、焦点和显式刷新补偿，不持续监听任意外部配置。
本轮不新增“恢复跟随 Git”菜单，也不迁移已丢失的历史角色和例外。

## 考虑过的备选方案

- 复用隐藏路径：会隐藏目录，不能满足浏览与编辑需求。
- 自行解释 Git 通配符：无法完整复现嵌套规则、否定规则和已跟踪内容。
- 只过滤搜索结果：无法减少目录访问、文本读取和索引驻留量。
- 禁用整个语言服务：会影响未排除源码；采用工作副本门禁及 provider 能力提示。

## 后果

原有隐藏名单仍独立生效。新策略不会让隐藏目录重新出现。
内置隐藏规则被用户通过 `!` 条目取消后，该条目须继续传到 Core 库存和 watcher
过滤，不能在某一层重新加入已取消的内置隐藏项。显示该目录也不代表取消其
Git 索引排除。本地历史的单条通配符匹配不使用工作区索引的嵌套根边界；
构造独立规则时显式保留空边界，不把索引策略变成本地历史规则的来源。
重命名和移动同样不能从索引候选枚举历史文件。工作区对选中的源、目标调用一次
历史迁移，Core 根据历史存储的元数据迁移精确路径及目录后代，保留相对后缀；
例如排除 `archive` 后重命名为 `archive-old`，已有 `archive/notes.txt` 的记录仍须
出现在新路径。不要为了迁移历史重新扫描排除目录或把后代加入索引库存。
目录标记由树与索引配置共用同一个存储读取和结构校验器，错误类型放在无运行时
依赖的模块。搜索不能自行 `JSON.parse` 并在字段缺失时安装空标记，否则树与搜索
会对同一份损坏数据作出不同决定，原始解析错误也会绕过本地化。
自动规则的决策缓存按需建立，因此状态中的目录集合不是完整的文件系统清单。
Git 失败必须保留手动排除并报告失败，不能报告成无忽略规则。
Java 的导入配置仅属部分支持；Rust 与 Go 分别合并原生目录列表与有序过滤规则，
配置源保持原样，取消排除后恢复原值。原生动态重扫效果仍需运行时验收。
同一 provider 同时使用嵌套对象与点分键时，递归合并对象，保留无关兄弟字段；
冲突叶子由点分键覆盖，更具体的点分前缀最后应用，再叠加当前目录排除。
Python/Basedpyright 的项目配置可以覆盖语言服务器配置，因此不改写其项目配置，
界面明确提示不能保证扫描排除。其他 provider 保持运行。

上游依据：
- [rust-analyzer 配置](https://rust-analyzer.github.io/book/configuration#rust-analyzerfilesexclude)：相对路径，不支持通配符。
- [gopls directoryFilters](https://go.dev/gopls/settings#directoryFilters)：最后匹配规则优先，并保留上游默认过滤。
- [Basedpyright 服务设置](https://docs.basedpyright.com/latest/configuration/language-server-settings/)：项目配置可以覆盖 exclude。

独立语言服务启动及工作副本不继承旧排除。新的活动策略仍会取消在途启动。
