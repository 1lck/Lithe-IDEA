# Agent 笔记：设置读取真实来源并确认写回

状态：已实现

## 先说结论

设置页应让用户看到工具当前实际使用的非敏感配置，在同一处编辑，确认后写回明确的配置来源，再重新读取并显示结果。不能只显示一个“自动”占位符，也不能保存到工具不读取的另一份偏好里。本文落地的是开发和评审准则，不表示所有既有设置页已完成迁移；修改某页时才按其真实能力补齐实现和验证。

## 问题

占位符不是输入框的值：用户看不清实际配置，编辑时还得重新抄写。把本地草稿当作已生效配置、把工具配置另存到应用偏好，或写完不重新读取，都会出现“界面保存成功、工具仍用旧值”的错觉。失焦和离页自动提交还可能把刚恢复默认的值重新写回。

## 决策

### 先查来源，再显示当前值

平台适配器负责读取环境、文件和上游工具的配置接口，遵循其真实优先级；Core 只处理已有契约内的确定性规则，视图不能直接读写文件。页面打开默认只读，不创建文件、不补写默认值、不启动后台同步。

非敏感字段直接填入当前可读取的值，并用紧凑状态标记显示来源路径、作用范围和是否继承。说明仍放在现有 ⓘ 中，不新增解释段落。没有配置文件但有官方默认值时可以回显默认值，必须标成“默认/继承”，不能因此产生一条显式覆盖；读取失败不能假装是空值。

例如 Maven 应识别当前启动方式指定的配置和上游优先级；没有显式选择时发现用户级 `~/.m2/settings.xml` 与安装级 `conf/settings.xml`，用户级配置覆盖安装级同项。回显的是当前选中来源的可编辑原值，并区分合并后生效值；本地仓库还要考虑有效配置和上游默认值，不能仅检查目录是否存在。不要把示例路径硬编码为所有平台的事实。上游依据为 [Maven Settings Reference](https://maven.apache.org/settings.html) 与 [Configuring Maven](https://maven.apache.org/guides/mini/guide-configuring-maven.html)。

### 编辑、确认、保护写入、重新读取

1. 输入只修改草稿。写入原生配置前，用户通过明确的“保存/应用”确认目标路径、范围和变更；已有明确表达目标的保存动作可以承担确认，不强制增加重复弹窗。取消、打开页面、失焦和离页均不写原生配置。
2. 保存检查读取时的版本或内容标识，原文件已被其他程序修改时提示冲突并保留草稿，不能盲目覆盖。使用上游成熟编辑接口或已有适配器，只更新目标字段，保留其他字段、注释（格式支持时）、权限和敏感内容，采用受保护的原子替换。
3. 保存成功后从真实来源重新读取并回显。若有更高优先级配置覆盖、工具需要重连或重载，明确显示真实生效状态，不能把草稿直接当作生效值。失败保留草稿并呈现错误。
4. 外部重载和“恢复默认值”更新编辑基线，即输入草稿所对应的原配置快照。提交前再次核对基线，不能依赖稍后才到达的界面通知，否则立即失焦、关闭页面仍会恢复旧值。对原生配置的重置也属于需确认的写入，确认说明恢复哪一层；不能删除整份共享配置或所有凭据。

正确做法：发现 Maven 的用户设置，在明确标注来源的输入框中显示仓库路径；用户改动并确认后，仅修改该来源的对应项，再读取显示实际结果。错误做法：只用 `~/.m2/repository` 当占位符，用户编辑后仅保存一份 Maven 不读取的应用偏好，或者每次失焦就覆盖整份 XML。

### 敏感字段与只读来源

配置文件可能混有密码、Token、私钥及带凭据的地址；“文件可读”不代表整份内容可以明文回显。只将确认非敏感的字段放进普通控件；秘密保持不变或走独立安全输入和凭据存储，不将脱敏占位符写回、不在日志、预览或测试数据里泄露。

发行包、安装目录和无写入权限的配置保持只读。需要改变继承值时，明确让用户选择受支持的可写覆盖层，不自动提权，也不绕过发行包只读规则。真正属于 Lithe 的偏好仍可写入应用存储，但须标明作用范围，不能伪装成工具原生配置。

## 考虑过的备选方案

- 只提示默认路径、要求用户重新填写：省去读取逻辑，但无法证明显示值与工具一致，也增加误操作，因此不作为非敏感配置的默认交互。
- 所有字段每次按键或失焦立即保存：省掉一次确认，却容易破坏共享配置、保存未完成输入或复活重置前草稿；原生文件编辑不采用。
- 把整份配置复制到应用存储再接管：制造第二份真源和升级兼容成本。优先复用上游解析与编辑能力；确需隔离运行时配置时，沿用已有专门契约并清楚标注范围，不冒充原文件编辑。

## 后果

用户能在设置页完成读取、编辑、确认和核对结果，不必猜测应用是否真的影响工具。实现需要维护来源、有效值和草稿的区别，并处理并发修改与读取失败；这些复杂性由已有配置适配器和功能模型承担，不下放给视图。现有页面逐项修复，不能仅更新本文就将功能矩阵标为已验证。

## 验证

- 修改设置页时覆盖：标准来源发现、当前值回显、继承值未修改不产生覆盖、编辑取消不写入、确认后仅修改目标字段、保存后重新读取、重开后仍一致。
- 补充敏感字段不泄露、外部修改冲突、文件缺失或无权限、写入失败保留草稿，以及恢复默认后立即失焦、切页或关闭不写回旧值。测试使用临时目录或隔离存储，不读取或修改开发者真实配置。
- 按目标平台执行原生交互测试和真实工作流；单元测试通过不能替代整页验收。记录未完成的设置页迁移，不把政策当运行时证据。
- 运行 `./scripts/agent-notes/verify-agent-notes.sh`；有产品实现改动时执行对应测试、`./scripts/architecture/verify-service-boundaries.sh`、`./scripts/macos/verify/verify-runtime-bundle-immutability.sh` 和功能矩阵检查。
