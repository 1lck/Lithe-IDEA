# Agent 笔记：Viva 编辑器的代码操作、参数信息与内联提示

状态：已实现

## 先说结论

代码操作、参数信息和内联提示由标准语言服务器协议提供。Rust Core 校验请求、响应及文档版本，Viva 负责编辑器交互和文件写入。对于折叠的文档，编辑器把可见行拆成多个连续区间，分别请求提示。

## 问题

语言服务器的回复和正在编辑的文本可能属于不同版本。代码操作还可能先编辑几个文件，再要求语言服务器执行命令。滚动和折叠则会不断改变需要显示提示的行。

## 决策

- 按 Core 返回的操作 ID 接收结果。对于先到的完成事件，等同 ID 的提交确认后再处理。请求期间替换文档或更改版本时，丢弃旧结果。
- Core 校验服务器给出的文档版本。Viva 再核对当前同步状态和视图修订，在后台准备编辑。关闭工作区、取消或目标变化时，后台任务负责按旧内容恢复本次已经写入的文件。恢复时核对写入后的字节，保留同时发生的外部改动。
- 代码操作附带的命令在相关编辑内容同步到语言服务器后发送。参数信息使用服务端能力声明触发，并根据服务端返回的结果更新，避免用宿主的括号规则猜测不同语言的参数范围。
- 折叠块两侧的可见行分别请求。提示排版依赖不可变文本快照，并在视图修订匹配时安装。涉及超长单行时，继续分页绘制源码，该行省略内联提示。

## 考虑过的备选方案

- 按方法名匹配提前到达的完成事件。同一文档的前后两次操作会共用方法名，导致旧编辑误用新请求的修订。
- 从首个到最后一个可见逻辑行发出单次请求。折叠一千行后，这个区间仍包含一千行，隐藏结果可能先耗尽提示额度。
- 在字符表面叠放浮层或向文本插入空格。折行、选区和鼠标命中依赖同一几何，覆盖层不能可靠匹配，插入空格还会污染实际文档。

## 后果

编辑缓冲区和磁盘上的文件都可以参与代码操作。外部进程同时改写目标文件时，保护写入可能拒绝编辑或回滚，并记录对应失败。多段可见提示减少折叠区的工作量，语言服务器需要分段返回。
