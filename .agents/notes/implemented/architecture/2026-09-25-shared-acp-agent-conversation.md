# Agent 笔记：共享 ACP Agent 对话

状态：已实现

## 先说结论

Agent 对话默认关闭，打开某个项目的 Agent 面板时才启动本机 Agent。每个项目的每种 Agent 只有一个对话连接，一个连接里可以有多个会话；会话历史由 Agent 自己保存；Lithe 负责显示，并单独保存收藏、自定义标题和可恢复的隐藏状态。供应商管理允许 Codex 在自定义 API Key 和本机 ChatGPT 订阅间切换；Claude 仍只支持 API Key。订阅额度放在输入框上下文的右侧，不新增页面。Agent 需要的 Node.js 由用户自己安装，Lithe 只负责检测；ACP 适配器由 Lithe 提供一键安装，安装时用的是用户本机的 npm。ACP（Agent Client Protocol，编辑器与 Agent 之间的对话协议）连接和进程管理写在同一个 Rust crate 里，Mac 与未来的 Windows 只各自实现界面。

## 问题

如果两端各写一套 ACP 连接、权限回复与进程清理，协议行为容易分叉。若在应用启动时就启动 Agent，不用这个功能的用户也要承担内存和进程开销。Agent 会请求执行工具，权限必须由用户确认。

实测还发现两个会直接影响用户的问题：

- codex-acp 1.13.1 在"刚发出消息就取消"时会丢掉这次取消。它此时已经拿到本轮 ID，但 Codex 还没把这一轮标记为进行中，于是中断请求返回"没有进行中的一轮"。结果是这条消息的请求永远不返回，本轮在后台继续跑完并消耗额度，下一条消息还会被塞进这一轮。
- 打开 codex-acp 的 `APP_SERVER_LOGS` 调试日志后，网关请求头（包括明文 API Key）会写进日志文件。

## 决策

- **Claude 错误使用短重连预算**：真实 401 和 503 均在约一秒收到首次错误，但 Claude Code 默认十次重试的退避等待（失败后延长下一次请求前的等待）累计约三分钟。交互式 API Key 会话改为临时故障总共五次尝试，四次间隔为 0.5、1、2、4 秒；首次失败后的重连阶段最多二十秒，超时仍遵守已有十秒取消确认边界。无效密钥、权限、参数、模型和额度错误直接返回；已产生回复、推理、计划、工具或授权请求的轮次不能整轮重放。正常工作不设整轮绝对上限，重连后出现实际进度会退出短重连阶段，不把工具执行或用户审批限制在二十秒。
- **复用公开错误能力，Host 只控制交互预算**：依据 [Claude Code 官方环境变量说明](https://code.claude.com/docs/en/env-vars)，原生重试预算统一适用于错误，还可能遵照供应商的 `Retry-After` 长时间等待。SDK 环境与程序化 `settings.env` 两层设置 `CLAUDE_CODE_MAX_RETRIES=0`、`CLAUDE_CODE_RETRY_WATCHDOG=0`、`CLAUDE_CODE_DISABLE_NONSTREAMING_FALLBACK=1`，新建与历史恢复相同。Host 协商固定 ACP 适配器的公开 AIR `sessionFailure` 扩展（结构化失败类别和恢复动作）；它把终止失败放在 `end_turn` 响应元数据中，必须先转换为请求失败，不能误报成功。扩展也避免把 CLI 合成错误文本当成模型回复。旧式 JSON-RPC 错误使用公开 `errorKind`。部分网关的 400/402 被上游归到通用服务错误，兼容检查只允许固定 CLI `API Error:` 前缀中的永久 HTTP 状态否决重连，不能凭文本启用重试，更不能扫描模型正文或私有 CLI 日志。未知旧式错误立即返回。实测重复发送前必须中断已失败的 SDK 请求，否则五个 ACP 尝试会产生九个 HTTP 请求；中断已终止且没有进度的请求后，本地服务实际收到五次。仍保留上游会话和历史所有权，不写或回滚历史。模型 404 的原生解析可能立即探测两次，不是 Lithe 自动重连，不承诺所有错误只产生一次 HTTP 调用。不要新增鉴权预检、修改安装的第三方包或自行实现另一套 Claude Agent。
- **Codex API Key 同步预算，保留原生恢复**：Codex 的 HTTP 重试和流恢复是两层预算，默认连续 503 在本地服务实际产生三十次请求。使用原生配置 `request_max_retries=0`、`stream_max_retries=4`，关闭无界连接重试；首次调用加四次恢复合计五次。仅尚无工作的重连最多二十秒，另保留十秒取消确认。已有回复、推理、计划、工具或授权进度后，原生恢复不再受 Host 二十秒期限或第二份五次计数取消；上游仍按已配置的有限预算恢复，最终失败与永久错误继续终止，不限制正常工作。公开原生错误类别或 HTTP 状态证明是永久错误时立即停止；普通 HTTP 429 在原生 CLI 中可能直接耗尽，因此仅在尚无实际工作时补短等待后的重发，并与原生共用五次计数。已出现实际工作，或其他原生终止错误，都不能整轮重发。订阅模式保留原生登录刷新，自定义 ACP 不注入 Codex 配置。
- **Codex 兼容入口只补配置与错误信息**：固定适配器覆盖自定义网关配置，`CODEX_CONFIG` 中的重试字段会丢失；混用点号路径和整个表又会受到原生 HashMap 应用顺序影响，不能靠偶尔成功认为已生效。因此单次连接创建一方标准输入/输出转发 helper（只传输公开 App Server 协议），在创建、恢复和分叉会话时补齐原生预算，其他配置照传。AIR 重连警告会丢掉原生错误信息，helper 将结构化 `codexErrorInfo`、原始说明、当前轮次和通知序号保存在失败标题内的 JSON 信封；Host 只在协商后的失败元数据中解码，正常消息原样传递，不扫描模型文本或私有日志。公开通知序号去重、原生当前轮次判断拒绝迟到错误，界面只显示原始说明。`<system-temp>/lithe-codex-retry-<UUID>/` 由该连接持有，结束进程树或启动失败后删除，无密钥内容；临时目录由平台解析，不写安装包、用户配置或第三方文件，不影响签名与 Sparkle delta。资源注册表将它排除，不能跨工作树复用。适配器未来直接保留这些原生配置并转发错误信息后，应移除此兼容 helper，保留预算和契约测试。
- **重连状态由实际事件驱动**：Host 发出带唯一轮次标识和尝试次数的 `turnRetrying`，macOS 在尚无工作时显示“正在重连 2/5…”并继续累计耗时；已有工作后的原生恢复省略 `maxAttempts`，只显示“正在重连”，不能编造调用上限。首次恢复警告后五分钟显示等待较久的提醒，继续等待只关闭提醒，不重发；后续警告不能推迟提醒。实际输出恢复后切换回复或推理状态；有效计划更新（包括清空计划）也证明重连已恢复，界面退出重连并清空次数，保留轮次计时和忙碌，不覆盖已有回复、推理、权限或停止状态。无法解析的计划不触发此清理。完成、失败、取消、断连清空次数；迟到通知不能复活已结束轮次，取消优先于重连，取消确认前不解锁。Claude 的下一次尝试必须等前次失败且无进度；Codex 的流恢复仍由原生执行。后续接入其他 ACP，应先核对它是否提供结构化失败、明确重连事件及可配置预算；只支持 ACP 不代表可以控制它的内部重试。未经适配的 Agent 保留原生策略，正常轮次不设绝对上限，不能对所有 Agent 盲目套五次 prompt 重放。
- **思考强度名称**：强度选项使用上游英文名称，例如 Low、Medium、High、Xhigh、Max、Ultra，不经过通用本地化。子菜单、设置行当前值和模型底栏复用同一个呈现入口，避免同一强度在不同位置显示中英文混合。菜单标题“思考强度”和其他配置仍按界面语言显示；不改上游选项 ID、可选范围或确认流程，也不手工补齐当前 Agent 未提供的强度。
- **权限模式呈现**：菜单和底栏保留 Agent 上游名称，例如 Claude 的 Manual、Accept edits、Plan、Auto、Bypass permissions；模型和思考强度也使用上游名称。名称不能进入全局翻译表，否则 `Plan` 会碰到其他界面的“计划”翻译，导致个别选项与其余名称混用语言。Claude 与 Codex 按已知权限 ID 共享对应图标，Claude 继续显示上游实际提供的编辑、计划等额外选项。依据 [Claude 权限模式说明](https://code.claude.com/docs/en/permissions)，说明可按界面语言呈现，但保留实际 Agent 的审批与环境约束，不把 Codex 的沙箱说明直接套到 Claude。只改变显示，不修改选项 ID、数量、顺序或权限命令；上游确认继续决定当前值。未知选项保留其原文和默认图标，不按列表位置猜测权限，也不把 Claude 的五项折叠成三项。不新增状态、资源或运行时写入。
- **Agent 菜单标志与勾选**：输入框的 Agent 下拉菜单为每个选项显示 16 点品牌图标，复用底栏同一套只读资源与内存染色。原生单选控件（Picker）将当前选项的勾选状态与品牌图像分别呈现，避免选中项用勾选图标替换品牌。控件直接绑定面板已有的选择值与切换动作，不在 View 里再存一份当前 Agent；图标和勾选以实际选择为准，不改变连接、会话或权限语义。
- **侧栏入口图标**：Agent 使用 Lithe 原创的“对话气泡 + 星光”线性 SVG，由工作台 renderer 显式绑定，避免落入通用模块图标而让用户误认成插件管理。图标作为固定源资源随应用打包，复用现有模板着色与选中态；不下载、不生成运行时文件，不影响安装包的只读边界。面板内 Codex/Claude 标志仍表示具体供应商。
- **安装包图标解析**：Agent 品牌图标从应用的 `Contents/Resources/Lithe_Lithe.bundle` 只读加载；资源包或图标缺失时使用默认标志。不要在已安装的 `.app` 中直接调用 SwiftPM（Swift 包管理器）生成的 `Bundle.module`：它只查应用旁的资源包和编译目录，找不到会直接终止进程，开发机器残留的构建资源还会掩盖问题。开发和测试入口保留 SwiftPM 回退；安装版不使用编译目录，也不通过启动时复制资源来修补发行包，避免改变代码签名和 Sparkle 增量更新基线。
- **底栏品牌标志**：参考 [CC GUI 的紧凑入口](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/blob/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/components/ChatInputBox/selectors/ProviderSelect.tsx) 与[品牌组件](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/blob/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/components/shared/ProviderModelIcon.tsx)，Claude 使用彩色星芒，Codex 使用主题单色结形标志。上游 Web 入口为 16 像素；Lithe 原生工具栏使用 18 点视觉尺寸、28 点点击区域，模型入口保留较小的同品牌标志。Claude 的 `#D97757` 与既有 `@lobehub/icons 5.8.0` 彩色组件一致。轮廓复用既有 SVG，欢迎区和历史页继续使用模板着色。SwiftUI 的前景色在原生 Menu 转换图像时可能丢失，因此底栏通过只读 SVG 的透明度蒙版在内存中生成带颜色的原始图像，不依赖原生控件替模板补色。图像缓存身份包含资源包、尺寸和颜色，深浅主题切换不会拿到旧色，也不修改其他视图共用的模板。正确做法是按品牌和主题选择颜色；不要复制 SVG 路径、改写源图或把染色图写进 bundle。该派生图像只在应用内存中存活，不新增磁盘缓存、下载或跨工作树复用资源，不影响代码签名和 Sparkle delta。
- **共享实现**：`rust/lithe-agent-host` 使用官方 `agent-client-protocol` SDK。一个 `AgentHandle` 对应一个项目的 Agent 进程和 ACP 连接，负责初始化、网关登录、会话新建/列出/加载、消息、权限、取消和进程树清理。Mac 通过 Rust Core C ABI（`lithe_agent_open_json`、`lithe_agent_send_json`、`lithe_agent_close`）调用；Windows 以后直接依赖同一个 crate。命令和事件的 JSON 形状由 `shared/fixtures/agent/acp-events-v1.json` 固定。
- **按需启动，跟着项目走**：`LitheAgentConversationModule` 是内置可选模块，默认禁用。每个项目有自己的模块运行时，所以会话天然属于项目。切换标签或窗口不会结束任何会话，后台项目的这一轮会继续跑完；只有关闭项目、关闭功能或退出应用时才停止 Agent。后台项目的会话在等待权限时，项目标签上会显示提醒点。
- **API Key 按上游公开接口传递**：Lithe 通过 ACP 的标准输入输出（stdio）通道把凭据传给适配器，不进入 Lithe 启动适配器的命令行参数、环境变量或文件，也不设置 `APP_SERVER_LOGS`。Codex 使用 Responses，在初始化时声明 `auth._meta.gateway = true`，通过 `gateway` 登录传服务商地址和 `Authorization: Bearer <key>`；没有该登录能力就报错。Claude 使用 Anthropic Messages，通过上游公开的 `_meta.claudeCode.options` 在 `session/new` 与 `session/load` 同时传入地址、API Key 和模型；由上游适配器与 Claude SDK 管理其内部原生凭据转换。SDK 的环境配置和程序化 settings 两层都显式指定同一路由，并清除旧 Bearer、OAuth、自定义请求头、云平台路由与 `apiKeyHelper`，防止用户或项目设置覆盖所选服务商。缺少凭据时直接报错，二者都不静默回退到账户订阅。
- **Claude SDK 子进程的凭据边界**：上面的保证只覆盖 Lithe 启动 ACP 适配器这一层，不覆盖整个子进程树。当前固定版本的 Claude SDK 会把对象形式的 `options.settings` 序列化为 Claude Code CLI 的 `--settings` 命令行参数，因此 `settings.env.ANTHROPIC_API_KEY` 会出现在该 CLI 子进程的参数里；开启 SDK debug 还可能把完整参数写进调试文件。同用户进程和诊断工具可以读取这些参数，不能把这一实现描述为全进程树都不暴露 Key。原 gateway 路径也把带 Key 的自定义请求头放进程序化 settings，本次路由修复没有消除这项上游暴露。后续独立评估把 Key 仅放在 `options.env`、settings 仅保留非敏感路由；采用前必须验证用户和项目 settings 中旧 Key 的覆盖优先级，以及新建、历史恢复和切换服务商都使用所选凭据，不在当前修复中直接删去凭据覆盖层。
- **Codex 订阅是 Agent 绑定方式**：供应商管理增加“Codex 订阅”选项，但不往提交信息共用的 HTTP 服务商注册表写一个假供应商。已有配置缺少认证类型时仍解释为 API Key；订阅绑定不保存 provider ID，启动时不读取该服务商的 Key、URL 或默认模型。只在当前子进程中指定官方 `openai` 路由并清除继承的 API 覆盖，会话配置同时清空 `openai_base_url` 并指定官方 `chatgpt_base_url`，防止本机旧地址继续覆盖订阅路由；额度探测也使用同样的覆盖。保留用户的 `CODEX_HOME`、MCP 和 Skills。本机 Codex 拥有账号存储和刷新，Lithe 不读取或复制其订阅凭据。已有账号直接复用；未登录先提示，用户点击才通过 ACP `chat-gpt` 方法打开官方浏览器登录。等待有五分钟期限，取消停止连接并停留在可重试状态，避免 idle 空态自动重连；认证通知与请求响应先后不作为成功依据，必须等上游确认账号。账号退出或邮箱改变时断开旧连接，不静默改计费来源。订阅错误不附加未经脱敏的上游 stderr，因为 Lithe 并不知道其凭据值。
- **额度复用官方查询能力**：核对 [codex-acp v1.13.1](https://github.com/agentclientprotocol/codex-acp/blob/v1.13.1/src/CodexAcpServer.ts) 的扩展方法后，确认它提供连接级认证状态推送，但没有结构化额度接口；`/status` 只有显示文本，token 统计也不是订阅窗口。因此共享 host 短暂启动已检测到的本机 `codex app-server`，用官方 `account/rateLimits/read` 查询，禁止创建线程或发送 prompt。查询前后读取账号并与 ACP 提供的邮箱比较；没有邮箱时不能确认归属，只显示未知。上游 ACP 没有稳定账户 ID，同邮箱切换组织仍是当前身份校验的限制。每连接最多一分钟一次、不并发，查询二十秒超时；连接取消或查询结束清理整个进程树。将来 ACP 暴露结构化额度后用同一连接替换此探测，不长期维护第二套认证或私有 HTTP API。
- **额度显示和资源边界**：参考 PR #870 保留真实窗口时长、未知不当零、失败显示过期的原则，不整合其独立页面和日志扫描。输入框上下文栏右侧显示使用率最高的窗口，例如 `5h · 已用 68%`；悬停列出各额度窗口、重置与更新时间。窗口按实际上报时长标注，primary 可以是七天。面板可见且应用活跃时每分钟刷新，回复结束也请求一次受限刷新；历史页、隐藏面板停止定时请求。短暂失败保留并灰显旧值，断连与身份失败清除旧额度。API Key 模式没有额度查询。快照只在连接内存中存活；未增加下载、缓存文件或可复用工作树资源，CLI 仍使用自身用户目录，安装目录和发行 bundle 只读，不影响代码签名或 Sparkle delta。
- **历史以 Agent 为准**：会话列表来自 `session/list`，打开旧会话用 `session/load`，由 Agent 回放历史。Lithe 不自己保存聊天记录。Agent 进程重启后，旧会话必须先加载才能继续发消息。导出按 [ACP 会话加载契约](https://agentclientprotocol.com/protocol/v1/session-setup) 等待完整回放后返回的 `session/load` 响应；Swift 接收到 `sessionLoaded` 时先刷新缓冲文本，再生成导出快照，不靠固定延迟猜测回放完成。
- **历史页与本地管理**：参考 [CC GUI 历史页](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/tree/main/webview/src/components/history) 使用面板内返回、搜索、统计和分隔列表。搜索只查询标题和 ID，数量只统计已加载的用户/Agent 消息，不扫描 CLI 文件，也不伪造上游未提供的消息总数。`AgentHistoryFeatureModel` 通过 `AgentHistoryPersisting` 保存收藏、标题覆盖和隐藏标记；macOS adapter 使用既有偏好设置，键为 `lithe.agent-history.v1.<workspace-agent-digest>`，按标准化工作区与配置 Agent ID 隔离。变更前重新读取，避免另一窗口的旧快照覆盖最近注释；解码或保存失败明确显示，不重置损坏状态。移除仅隐藏本地列表，提供“已移除的会话”筛选与恢复，不宣称删除 Agent 原始会话。单条和批量移除都先弹出确认框，取消不写元数据；确认操作使用弹窗出现时的会话 ID 快照，避免把后续选择变化带入删除。进入历史页保留对话视图和输入草稿，不停止正在进行的轮次。
- **导出与资源所有权**：导出为用户选择位置的 Markdown，包含用户、Agent 和工具消息，工具输入/输出/内容一并保留。未打开会话复用现有、有请求期限的 ACP 加载路径，逐个加载，不改变选中标签；加载失败不写部分导出；只有会话成功创建或完整加载后才标记历史快照可复用，消息非空不能证明完整性。失败或断连留下的部分回放必须重载，已完整加载的快照在断连后仍可导出。取消与模块关闭释放等待 continuation（异步结果回调），原加载请求可自然结束。正在回复或加载中的会话不导出。导出 Task 由历史功能模型拥有并在模块停止时取消、等待结束；平台 adapter 拥有保存对话框与原子文件写入，最大 32 MiB。偏好设置与用户导出都不是构建缓存，不新增下载、不跨 worktree 复制；见 `scripts/worktree-resources.json`。它们不写发行 bundle、不影响代码签名和 Sparkle delta。
- **配置菜单间距**：模型和设置选项使用较小的最小行高，权限选项保留标题与最多两行说明需要的空间；行内容较高时允许自然增高，不用固定行高裁剪文字。权限面板按实际内容高度收紧，测量值在最大可视高度处截断并只更新弹出面板的局部状态，避免滚动时反复调整面板大小；长列表继续由原生滚动容器承载，不能把行距变小却保留旧面板高度，或为了紧凑隐藏上游选项。名称和权限语义由既有呈现规则及 ACP 确认流程决定，布局不改写选项 ID 或当前值。
- **上下文用量以上游为准**：输入框顶部参考 CC GUI 显示圆环与整数百分比，悬停显示一位小数百分比及已用/总容量 token。提示复用工作台已有的悬停浮层与面板局部 scope（浮层可绘制的范围），圆环和百分比共用完整命中区域，鼠标进入立即显示在指示器上方，移开或面板退出时关闭；不依赖系统原生 `.help` 的延迟提示，避免宿主视图内看不到详情。使用现有 ACP `usage_update.used/size`，共享 host 已按 SDK 原样转发，不另接 Codex 私有事件、不扫描历史文件、不根据文字长度或模型名推算。计费用量是累计消耗，不是当前上下文容量，不能混用。用量按会话保存，每条有效更新替换之前值，压缩后允许下降；没有上报、容量为零或无效数据在会话状态中仍保持未知；展示层按 CC GUI 使用 0% 占位，悬停仅提示“上下文: 0.0%”，真实零使用量也使用相同简短提示，不编造已用 token 或总容量。断连、确认模型改变、重新加载会话清除旧数据，权限或思考选项改变不清除。超过容量时保留上游数值与百分比，仅圆环限制为一整圈。数据只是内存会话状态，不写入 bundle 或新增缓存资源。
- **停止必须等上游确认**：只发送一次 `session/cancel`，撤销本轮权限请求，界面进入“正在停止”。收到原 prompt 的结束响应后才能发送下一轮。旧方案只屏蔽迟到的 prompt 响应，却不能阻止上游把新消息并入旧轮次，也不能识别没有轮次编号的迟到通知。因此改为十秒确认期限：超过期限则明确报错、停止该 Agent 的进程树，保留界面记录，用户重连后通过 `session/load` 恢复。正常取消不重启进程。这不是伪装成正常结束，用户会看到恢复原因；同一 Agent 进程里的其他会话也会断开，不能静默自动重试消息。
- **会话配置由上游提供**：面板连接完成后准备空会话，让用户发第一条消息前就能选择模型、权限模式、思考强度。选项、分组和当前值均来自 `session/new`、`session/load`、配置更新通知及 `session/set_config_option` 的响应；不硬编码模型列表。每次启动 Agent 连接前，通过既有本机配置端口读取完整配置；地址、默认模型、协议、认证方式和密钥必须来自同一次读取，避免旧导入地址搭配新密钥，也避免旧模型继续成为新会话的默认值。导入供应商的非密钥字段按原 ID 更新，保留 Agent 关联、提交信息的服务商选择和用户的 HTTP 许可；手动服务商不受本机配置影响。模型读取独立于完整 API 配置：Codex 没有自定义服务商或 API Key 时仍能读取顶层 `model`，不能把其他 TOML 表里的同名字段当成默认模型；凭据校验失败时也更新面板的模型回退显示。API Key 模式仍校验凭据；订阅模式绕过这条服务商模型同步路径，使用 Codex 自己的模型目录。仅刷新本机配置仍不够：codex-acp 1.13.1 会把不在实际模型目录中的配置值临时补进选项。共享 host 保留上游同时返回的旧式模型目录，并协商其版本化推荐值扩展（`jetbrains.air.recommendedValue`）；当前值不在实际目录中时，优先使用同时存在于目录和选择器的推荐值；推荐值缺失、不兼容或版本过旧时，按目录顺序选择第一个在选择器中可用的官方模型。两种修复都通过标准 ACP 配置请求并等待上游确认后再发布会话，保留官方返回的完整选项，由上游移除临时补入的无效模型；两次请求共用创建会话的有界超时。配置中有效的模型、历史会话和用户文件不被自动改写；目录缺失、格式不兼容或没有可选交集时保留标准 ACP 行为，不猜默认模型、不按版本名或描述筛选。手动新增 Codex 供应商的编辑器初始值使用官方 `gpt-6.1-sol`，编辑已有供应商仍保留其已保存模型。ACP 模型菜单使用该 Agent 已有的品牌 SVG，不使用通用 CPU 图标；显示标签仍由上游确认的当前值决定。请求完成前禁止重复配置和发送，失败保留之前确认的值并显示错误。适配器没暴露的配置不画假控件，也不替用户改变网关地址或全局 CLI 配置。
- **通用供应商的模型需要显式填写**：通用 AI Providers 的 Add Provider 入口允许切换 Responses、Chat Completions 和 Anthropic Messages，因此初始模型保持为空，填写有效模型后才允许发出请求。不要把 Codex 编辑器的默认模型填入通用入口，也不要在协议切换时按模型字符串清理用户输入；即使用户手动填写 `gpt-6.1-sol`，该值仍由用户拥有。这样避免未确认的 Codex 默认值进入 Claude 会话或提交信息请求，代价是通用入口需要显式填写模型。
- **会话配置准备期间的显示**：本地供应商默认模型只是启动输入，不是当前会话的已确认模型。切换到尚未初始化的 Agent 时，工具栏从连接启动、准备空会话到默认模型修正完成，连续显示“正在加载会话设置”；加载历史也等待该会话自己的配置，不先闪现本地默认模型或另一个会话的选项。进程报告 ready 只表示连接可用，不能当成模型目录已就绪。已有连接和已确认会话在来回切换时直接复用，不额外加载；创建或加载失败、需要登录、连接失败以及上游不提供配置时退出加载状态，保留真实错误和既有默认模型回退。发送按钮和回车发送都遵循准备状态。这是原生界面根据现有连接事件推导的显示行为，不新增 ACP 状态、模型缓存、资源目录或运行时 bundle 写入。
- **关闭最后一个标签后准备新会话**：连接已 ready 时，关闭最后一个会话由连接模型立即调用既有 `prepareConversation()`，发起一次新建请求，不等待视图重新出现或连接状态再变化。准备中的创建请求复用已有 token，重复关闭或准备不会重复创建；旧确认不能重新选中已关闭的会话。保留“正在加载会话设置”的显示与发送限制，收到新会话确认后才恢复模型选择和发送。还有其他标签时直接选中最后一个标签，断连时不创建；这只移除本地标签，不删除上游历史。不要仅为解除阻塞取消准备状态判定，否则会重新闪现未确认的本地默认模型。
- **工具证据与文档保护**：工具详情合并上游的部分更新，展示类型、输入、输出、文件位置和修改前后文本；权限卡复用已收到的工具证据，区分允许和拒绝。显示文本每段限制 32 Ki 字符，内容和位置各限制 100 条，避免大工具输出堵住界面；截断处标记 `[...]`。点击项目内文件交给现有编辑器导航，不在视图中直接读写文件。磁盘刷新、脏缓冲区保护和 Git diff 沿用文档/Git 模块。Agent 从项目目录启动，不需要先附加当前文件才能读写磁盘；未保存的编辑器快照是后续独立能力。
- **未发送的空会话不能当成历史恢复**：为了提前显示配置，界面会先创建空会话，但 Codex 在首条消息前还没有把会话内容写入磁盘（rollout），旧进程关闭后用原 ID 加载会报 `no rollout found`。连接模型只跟踪本连接新建、未成功提交消息且未出现在上游历史中的会话；断开时移除这些会话的本地标签和临时记录，重连后通过原有准备流程新建。已有消息、上游列出或成功加载的会话继续恢复，不根据“当前消息列表为空”推断历史不存在，也不按错误字符串给真实历史自动新建替身。这个操作不删除用户的上游历史文件；代价是未发送会话的临时配置选择需要在新连接重新确认。
- **历史加载失败不清空记录**：回放时保留原会话快照，成功后使用上游回放，失败或连接退出时恢复之前记录并丢弃不完整的回放片段。旧连接事件任务被取消后不再消费缓冲事件。
- **并发权限与中断状态**：同一会话的多个权限申请按到达顺序排队，答复一个后展示下一个，取消时一起撤销。轮次或连接结束时，没有收到最终状态的工具标记为中断，不再无限显示运行中。
- **本机与自定义供应商**：面板设置保留本机 CLI 读取入口，并支持添加、编辑、启用和确认删除自定义供应商。自定义编辑器接受 Codex TOML/auth JSON 或 Claude settings JSON，但只提取 API 地址、模型和 API 密钥；其余 CLI 选项仍由本机文件决定，编辑器明确提示这一范围。TOML/JSON 元数据复用共享 Core 的现有 AI 解析器，不在 Swift 重新实现 TOML；原文仅存在编辑草稿，密钥由 Mac 适配器提取并交给现有安全存储。解析响应和错误不含密钥、原文或解析器诊断。配置编辑器沿用源码/SQL 编辑器的纯文本策略，关闭智能引号、破折号替换与自动纠错，避免合法配置在输入时被系统改坏。保存错误固定在滚动区外的按钮上方，不能把错误藏到长配置底部；已有弯引号导致 TOML 失败时明确提示改用直引号。供应商元数据复用既有 AI 服务商列表，添加、编辑、启用不改变提交信息的服务商选择；删除会同时移除列表里的供应商及其密钥，界面先说明影响并要求确认。
- **本机导入按来源隔离**：Codex 与 Claude 的导入凭据标识必须包含各自来源，重复导入只更新同一来源的供应商并保留其身份，不能用共享标识查找或移除另一来源。旧版本遗漏字符串插值会使后一次导入覆盖前一条记录，出现 Claude 图标显示 Codex 模型；预检只看绑定是否存在，不能证明凭据可用。macOS 加载设置时修正旧标识，保留供应商身份、提交信息选择和正确绑定，并解除内置 Agent 指向另一种本机来源或已被覆盖移除的供应商的错误关联；已被覆盖的配置无法可靠恢复，用户需显式重新选择，不按模型名或图标猜测来源，也不自动切换到订阅。即使标识已被提交供应商刷新修正，错误关联仍要检查。自定义供应商和自定义 Agent 的有效关联不改动。正确做法是只导入 Codex 时让未关联的 Claude 保持未配置；不要用界面替换图标掩盖两个 Agent 共享错误记录。修复只写既有设置存储，不读取、复制或修改用户的 CLI 密钥，不新增运行时资源，不影响安装包签名与 Sparkle delta。`AgentProviderImportTests` 用内存设置覆盖双向导入、重复导入、旧设置修复和重载。
- **本机配置按连接读取完整快照**：`AgentLaunchConfigurationResolver` 在连接前协调配置端口与设置存储。读取到快照后，用它同步所绑定供应商的非密钥字段，并直接将快照中的密钥交给当前连接，不能再调用凭据解析器读取第二次。本机配置缺失时拒绝启动旧路由；只有模型可读时仍更新模型回退显示，缺失密钥时同步最新地址后明确报错。正确示例：CLI 从供应商 A 切到 B，下一次连接同时使用 B 的地址和密钥，供应商 ID 与关联保持不变；不要只更新模型后把 B 的密钥发送到 A，也不要通过重新导入改变提交信息的供应商选择。该快照只活在当前调用和连接内存中，非密钥字段写入既有偏好设置；不新增缓存、下载、日志、监听器或跨工作树资源，不写 CLI 文件或发行目录，不影响签名和 Sparkle delta。代价是现有连接需要用户空闲重连才能采用外部配置变化，不在后台监听文件或切换计费来源。
- **切换连接**：当前项目的 Agent 正在响应、加载会话、创建会话、等待权限或确认配置时，拒绝切换；空闲时先等待旧连接关闭，再绑定供应商并重连。编辑或删除当前项目正在使用的自定义供应商也遵循这个顺序。保存操作在等待旧连接关闭前记录供应商快照，写入密钥前同步核对共享注册表；若另一窗口已删除或修改该记录，旧保存操作必须失败，不能重新创建供应商或覆盖新配置。检查、密钥写入和元数据发布之间不得异步等待。密钥写入失败不会发布新配置，删除密钥失败会保留供应商供重试，重连使用原配置。现有本机凭据文件损坏或版本不支持时，写入和删除必须报错并保留原始文件，不能按空文件覆盖。其他项目已经建立的连接继续完成自己的工作，在下一次连接时读取最新供应商；不得为了全局设置变化中断后台项目的轮次。切换保留面板记录，恢复已保存会话仍通过上游历史加载。
- **Agent 管理（Agent 面板内的设置）**：
  - **支持的 Agent 目录**：写在 `lithe-agent-host` 的 `catalog.rs`，Agent ID、npm 包名和固定版本都与 ACP 官方注册表一致。首批是 Codex（已用真实服务商验证）和 Claude（标为"未验证"）。只有重新验证过的版本才会提升。
  - **环境检测**：通过登录 shell 读取 `PATH`，所以 nvm、fnm 装的 Node 也能找到。检测 Node 和 npm 的版本，每个 Agent 各有最低 Node 版本（Codex 20、Claude 22），版本不够时只提示。
  - **一键安装**：用用户的 npm 把固定版本的适配器装到 `Application Support/Lithe/agents/<id>`。先装到临时目录，确认可执行文件存在后再替换旧目录，所以失败或取消不会破坏已经能用的旧版本。
  - **复用用户本机的 Agent CLI**：两个适配器都自带一份 Agent 的原生程序，都是可选依赖，单个平台约 200–370 MB，而用户本机本来就有。所以安装时加上 `--omit=optional`（Codex 装完约 18 MB）。启动时在登录 shell 的 PATH 里找到用户的 CLI 交给适配器：Codex 用 `CODEX_PATH`（最低 0.156.0），Claude Code 用 `CLAUDE_CODE_EXECUTABLE`（最低 2.1.280，对应 SDK 的 `claudeCodeVersion`）。CLI 找不到时可由 npm 安装；版本过旧时先确认当前 PATH 命令的安装来源，再通过原安装器更新。来源展示在预检项中，npm/Homebrew/原生安装可以按验证结果提供升级按钮，未知来源只给手动指引。所有安装与更新只在用户明确点击时运行，Node.js 和 npm 仍由用户自己安装。CLI 过旧不阻止安装适配器，只有 Node.js 或 npm 不可用才阻止。
  - **CLI 更新保留安装来源**：以 PATH 中实际命令及其真实文件为准，不能仅看到用户装了 npm 就把所有 CLI 交给 npm。Homebrew 通过自己报告的 Cellar/Caskroom 位置和已安装记录确认归属，保留 cask/formula 及 `claude-code@latest` 等渠道；npm 必须确认当前 global root、包名、bin 声明和链接都指向同一 CLI，另一套 Node 环境不能代更新；Claude 标准原生 launcher 使用上游 `claude update`。未知来源、损坏链接、缺少原安装器或安装记录时拒绝自动覆盖，明确提供手动指引。更新后重新读取登录 shell 的 PATH 并验证最低版本；更新命令退出成功但实际 CLI 仍过旧也应失败。安装器可能在首次下载失败后重试成功，却保留非零退出状态，因此正常结束的命令无论退出状态如何，都要检查实际版本。只有新安装或数字版本严格提升且达到最低要求时，才能把非零退出降为“已成功、带警告”，返回有界日志并在界面折叠展示；原本可用但版本没变、降级、仍过旧或找不到命令时继续报错。不能根据日志中的“successfully upgraded”字样猜测成功，也不能把取消、超时或启动失败改判成功。读取来源只使用有界的本地查询，不更新包管理器索引、不改变用户配置。Homebrew 和原生下载归原安装器拥有，仅显示“正在更新”与耗时，不伪造字节进度；它们的全局安装和缓存不注册成可复制的工作树构建资源，排除清单与测试同步维护。
  - **兼容的 CLI 仍可手动更新**：最低版本只证明适配器能够运行，不能证明 CLI 已包含刚发布的模型。macOS 的 CLI 预检行在通过检查、折叠时也显示更新按钮，是否可点仍由已确认的安装来源决定；未知来源或 npm 环境不匹配继续只给手动指引。正确做法是允许用户把仍兼容的旧 CLI 交给原安装器升级，保留 PASS 状态；不要为了显示按钮提高最低版本或把兼容安装误报为故障。完成后刷新检测版本，并提示用户重连以获取上游模型目录，不自动中断现有会话，也不在 Lithe 中补写新模型名称。该入口复用原管理操作的进度、取消、超时与单操作限制，没有新增缓存或发行包写入。
  - **下载进度以 npm 的真实传输为准**：安装与 CLI 升级通过现有 Core 事件回调报告已接收软件包字节数、最近采样速度、耗时和等待时间。npm 没有提供整次安装的总量，且会继续发现依赖，所以不显示总体百分比。内嵌的 Node 观察模块只统计 HTTP 响应进入流缓冲区的字节，不添加消费数据的监听器，也不重写下载、代理、重试、校验或缓存行为。模块通过内存中的 data URL 加载，启动后先恢复用户原有 `NODE_OPTIONS`，防止 npm 子脚本继承观察器；不生成辅助文件或新的可复用缓存。正确做法是显示“已下载 25 MB、75 KB/秒、已用时 300 秒”；不要把 npm 静默时的日志时间或整个共享缓存大小当成下载进度。Core 事件只携带数字和阶段，界面按操作标识丢弃迟到事件，完成、失败或取消后清除进度。
  - **Rust Core 命令**：`agent.status`、`agent.install`、`agent.uninstall`、`agent.installCli`，复用现有信封的取消和超时。
  - **Key 和模型的传法**：API Key 经 ACP stdio 传给适配器。Responses 使用 `gateway` 的 `Authorization: Bearer`；Claude 使用公开会话参数中的原生 API Key 配置，由 SDK 发出 `x-api-key`。Codex 的模型用 `CODEX_CONFIG`，Claude 的模型用 `ANTHROPIC_MODEL` 并在会话 options 中显式提供。服务商配置里的"模型"必须传给 Agent：实测某个网关禁用了 Codex 的默认模型，不传模型时 Agent 只会回复一条网关报错。
  - **设置放在面板里，只有 Agent 管理一页**：Agent 的开关、预检清单（Node、npm、CLI、适配器、本机配置）、适配器和 CLI 的一键安装都在 Agent 面板右上角的设置视图里，不进全局设置窗口。布局仿照 Codeg 和 CC GUI：左侧图标栏，右侧标题加分段切换各个 Agent。
   - **本机配置保留 CLI 所有权**：每个 Agent 通过本机配置行读取用户自己 CLI 的地址、模型和密钥（Codex 读 `~/.codex/config.toml` 和 `auth.json`，Claude 读 `~/.claude/settings.json` 和 `~/.claude.json`），生成的服务商配置绑定到该 Agent。本机模式的密钥不复制进 Lithe 的设置或安全存储；每次连接时从同一份用户文件快照读取地址、模型与密钥。修改 CLI 配置后，新连接自动采用完整的新配置；已经建立的连接保留原路由，用户可在空闲时点击刷新完成重连，不中断其他项目的轮次。需要独立配置时使用上面的自定义供应商编辑器，不改写 CLI 文件，也不改变提交信息使用的服务商选择。
   - **关闭时仍能找到入口**：工作台始终保留 Agent 的静态入口声明，首次安装没有模块配置、手动关闭后也能打开面板。模块仍默认禁用，入口读取不调用 factory，不创建连接；禁用模块的通用贡献目录和其他模块的入口规则保持原样。未配置的面板立即显示原因和“打开 Agent 设置”操作，用户在面板内开启开关，无需修改本机配置文件。开启后复用运行时入口，按 ID 避免重复；关闭后保留面板和入口。不要把默认开关改为启用来修复发现入口的问题，否则会改变所有用户的后台启动行为。
  - **提示文案本地化**：Rust 返回的 `issues` 只决定能否安装；界面显示的原因由 Swift 按结构化状态（Node 版本、npm、CLI 版本）重新生成，这样中英文都能显示。
- **面板始终显示完整布局**：功能关闭或没有配置 Agent 时，面板照样显示会话标题、消息区和输入框，用户可以输入；发送时先校验（功能是否开启、是否有已配置的 Agent、模块是否启动完成），不通过就在输入框上方给出提示并提供进入设置的按钮，不会启动任何进程。
- **文件拖入对话框**：参考 CC GUI 普通文件的路径引用交互，原生输入框接受 Finder 和项目树的文件 URL，显示可移除标签，并支持文件选择器。一次最多 32 个引用，按拖入顺序去重；切换会话清除旧文件草稿，发送失败保留文字和引用。功能模型把引用与文字一起排队，Rust Host 用上游 ACP SDK 的 `resource_link` 发送，Agent 自己读取文件并遵守现有权限。文件 URL 是这次消息的原生上下文，不作为跨平台项目标识持久化。正确做法是发送“说明这两个文件”加两个引用；不要在 View 里读文件、复制进缓存或拼装隐式文件内容提示词。图片目前同样作为文件引用，没有缩略图或多模态字节上传；这避免了与本次需求无关的内存、大小和格式策略，后续需要图片输入时再按上游能力协商。
- **对话面板**：停靠在编辑器右侧，与 Maven 共用右侧槽位。输入框下方可以切换 Agent，列出的是已经绑定服务商或 Codex 订阅的 Agent；打开的会话以标签形式排列。每个 Agent 第一次被选中时才建立连接；项目里所有 Agent 的权限提醒会合并显示到项目标签上。
- **选择状态由面板直接观察**：切换 Agent 时，解析当前连接的视图必须直接观察 `AgentConversationFeatureModel`，连接内的模型与权限则由 `AgentConnectionModel` 发布。不能只观察外层 AppModel 再读取可选模块，否则选择已经改变，品牌、模型列表与发送目标仍可能停留在旧连接。正确做法是让 `AgentConfiguredConversationView` 持有观察关系，并按 Agent ID 重建连接视图；每个 Agent 的原连接和会话继续保留。不要靠通知整个工作台或重启进程来刷新选择，这会增加无关重绘或中断后台会话。代价是视图明确分为项目选择与连接内容两层；新增菜单必须继续使用同一选择源。该修复只调整内存观察，不新增文件、缓存或下载资源，也不写发行 bundle。
- **对话区的视觉与交互**：按 CC GUI 参考设计使用单行会话标题、居中的品牌标志、上下文栏和底部工具栏。只有多会话或用户主动展开时才显示标签条，避免空会话标题重复。空态不放进滚动列表，否则无法在剩余高度内居中。输入区复用 `LitheSplitPaneView`，尺寸约束跟随可用高度，拖动只更新局部容器。搜索只筛选当前已加载消息，不请求 Agent 或改动历史。品牌 SVG 来自参考项目锁定的 `@lobehub/icons` 5.8.0，以静态源资源随 SwiftPM bundle 打包并携带 MIT 许可，不新增运行时下载或可复用缓存。配置选择器按参考项目的底栏设计：权限与模型入口位于输入区底部，模型弹出面板提供本地名称/ID/分组搜索、品牌图标、蓝色选中行和绿色勾选，不显示模型说明；权限弹出面板保留上游名称，只对说明使用界面语言。思考强度、速度及其他上游配置放到模型面板底部的子菜单，未提供时不显示。选项数量和权限语义仍以 ACP 为准，不照截图补选项。选择后收起面板，已生效值仍由上游确认拥有；响应期间允许预选下一轮配置，底栏呈现预选值，真正提交配置等待确认时禁止再次配置。弹出与搜索状态只在视图内保存，会话切换重建选择器以清除旧会话的弹出状态；不重建输入框或清空草稿。模型面板使用共享 `litheDropdown`，设置子选项通过 `LitheMenu(opensToSide: true)` 作为它的原生子窗口展开。共享菜单呈现器按触发行定位、在屏幕右缘向左翻转并管理关闭；不把子选项拼入主面板，也不另写鼠标全局监听或位置缓存。上下文百分比使用 Agent 上报的用量，缺失时展示 0% 占位与“上下文: 0.0%”简短提示；占位不作为已上报用量写回会话状态。
- **长会话的底部跟随由原生滚动容器管理**：消息区继续使用按需创建屏幕附近行的 `LazyVStack`，不为了规避卡顿把整段历史一次性展开。权限卡片通过 `safeAreaInset` 让滚动容器预留底部空间；不要把卡片放回消息滚动区外的同级布局，再同时按消息 ID 调用 `ScrollViewReader.scrollTo`。完整工作区回放证明，溢出的历史、消息定位和权限区域改变可使 SwiftUI 布局持续占用主线程；仅延后一轮定位、换底部哨兵或直接操作原生滚动位置，都不能单独消除卡点。`AgentTranscriptScrollAnchor` 只在内容、视口大小或权限占用的原生内边距改变时合并安排一次原生底部跟随，不监听懒布局估算的内容高度来继续滚动，也不向业务模型发布几何数据。底部计算计入 `contentInsets`，避免高权限卡片遮住最新回复；内边距由原生观察者直接读取，不请求 SwiftUI 重新测量历史。用户主动滚离底部时保持浏览位置，回到底部或发送新消息后恢复跟随；搜索暂停跟随，会话切换和卸载取消旧操作并移除观察者。该组合使用 macOS 13 已有 API，不提高最低系统版本；新系统的默认滚动锚点也在回放中通过，但无需为此维护两套按版本切换的实现。只持有视图内状态，无文件、缓存或发行资源写入。
- **进程与诊断**：启动时把 Agent 可执行文件所在目录放到 `PATH` 最前面。npm 把 `codex-acp` 和 `node` 装在同一个目录，而 Mac 图形应用拿不到登录 shell 的 `PATH`。关闭时先向整棵进程树发 SIGTERM，并记录树里的每个进程 ID，稍等后再对仍存活的进程发 SIGKILL，因为 codex-acp 的 app-server 会比外层进程晚几秒退出。API Key 模式下 Agent 意外退出时，报错里附上 stderr 最后 20 行，其中的 Key 会被替换掉；订阅模式仅显示受控错误，不附加账号工具的原始输出。

正确做法：新平台的界面通过平台适配器把 fixture 里的命令交给 `lithe-agent-host`，并把工具权限选择交给用户。

不要这样做：在 Windows React 层重新实现 JSON-RPC 协议；在打开 IDE 时就启动 Agent；取消尚未确认就解锁发送；把取消超时伪装成成功而不提示用户重连；把 API Key 通过环境变量或命令行传给 Agent；替用户下载一份他本机已有的 Agent CLI。

未知值不猜说明，也不补选项。

原先把 180pt 侧栏拼在主面板右侧，再给整个横向容器画背景，会把子菜单上方
空白染成整块矩形；按底部对齐也会让不同配置行共用错误位置。现在复用共享

### 响应期间预选下一轮配置

macOS 的审批模式、模型和思考强度在等待、推理、输出、工具执行及停止确认期间继续允许点击。用户此时选择的是下一轮的配置；正在运行的一轮以及尚未处理的工具授权继续使用原配置。底栏立即显示预选值，悬停说明“修改将在下一轮对话生效”。空闲时的直接修改仍等上游确认后才改变显示。

参考 [CC GUI 的输入栏选择器](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/blob/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/components/ChatInputBox/ButtonArea.tsx)在生成期间继续提供模式和模型回调，以及 [发送入口](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/blob/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/hooks/useMessageSender.ts)读取用户选择。Lithe 保留已有共享 Host 的忙碌边界：响应期间不发送 `setConfigOption`，只由当前会话的功能模型保存每个选项最后一次预选；重新选择已确认值取消该项预选。视图不另存配置队列，也不改本机 CLI 配置。

正常结束、取消确认或本轮请求失败后，功能模型先提交模型，再按最新上游选项顺序提交剩余配置，每个请求确认后才提交下一个。换模型可能改变思考强度和速度目录，因此每一步都重新校验；拒绝、发送失败、能力消失或返回值未确认时，清除剩余预选，恢复已经确认的值并显示配置错误。等待全部确认期间继续阻止发送，不自动提交用户草稿。停止请求本身不能解除等待，也不能让新配置进入尚未结束的一轮。

正确做法：当前轮使用模型 A，用户选择 B 和 High；本轮结束后确认 B，再用 B 的最新目录确认 High，下一条消息才使用新值。不要这样做：仅移除控件的禁用条件并立即请求 `session/set_config_option`，或把本地预选直接覆盖到已确认配置中；前者可能影响当前工具授权且会被 Host 拒绝，后者会把失败当成成功。

预选按项目、Agent 和会话隔离；切换标签不丢失，后台完成只提交该后台会话的配置。新的上游配置或模式通知只更新已确认状态，不覆盖用户的有效预选。断连清除未确认预选和请求关联，迟到确认不能恢复它们。代价是本轮结束与下一轮发送之间可能多出数次配置确认，且不兼容的新模型选项需要用户重新选择。该能力目前只接入 macOS；Windows 不据此标记完成。状态仅保存在会话内存中，不新增下载、缓存或工作树可复用资源，不写发行包，不影响代码签名和 Sparkle delta。

### 思考、计划、斜杠命令与模式通知

共享 Host 一直把 ACP 会话更新（`SessionUpdate`）原样转发，以前 Swift 只消费消息、工具、标题、配置和用量，其余直接丢弃。参考 CC GUI 的可折叠思考块、计划面板与 `/` 命令补全后，macOS 现在消费下面四类标准更新；Host、C ABI 和 fixture 形状都不变，只在 fixture 中补样例并由 Rust 测试确认它们能被官方 SDK 原样往返。

- **思考（`agent_thought_chunk`）**：存为独立的 `thought` 角色消息，不并进 Agent 回复。流式缓冲按角色记录，角色切换先刷新上一段，所以“思考 → 回复 → 工具 → 思考”保持原顺序。只有正在流式输出的最后一段思考默认展开，后续回复或工具到达后自动收起，用户手动展开的状态保留；搜索时临时展开匹配的思考，优先于已有的手动折叠选择；搜索期间不允许再次收起命中文字，清空搜索后恢复手动选择，不把搜索结果写回折叠偏好。手动偏好由 `AgentTranscriptView` 在视图局部内存中按会话 ID 与消息 ID 保存，再以绑定传给思考行；搜索先过滤消息，会移除并重建行，因此不能让行内状态成为偏好的所有者。切换会话保留各自选择，关闭会话或移除实际消息时释放对应偏好，销毁对话视图时一并释放；不写入功能模型、共享 Host、历史文件或安装目录，不影响代码签名和 Sparkle delta。`AgentThoughtTranscriptTests` 直接挂载实际对话容器，通过原生鼠标事件和完整渲染快照覆盖搜索移除/重建、命中时临时展开和会话切换。导出 Markdown 用引用块写出思考，便于和回复区分；历史消息数仍只统计用户与 Agent 回复。活跃思考块的标题显示“思考中…”，底部等待行改为“回复中…”并保留本轮计时，避免重复提示；取消时仍显示“正在停止…”。
- **计划（`plan`）**：ACP 规定每次都发完整计划，所以整体替换，不做合并；空列表清除计划，格式错误的更新忽略，最多保留 100 条。计划条状态只认 `pending`、`in_progress`、`completed`，未知状态的条目丢弃而不是猜测。点击底部“任务”打开计划与进度；没有计划时显示该会话的工具列表，不编造计划。`session/load` 回放会自然恢复计划。
- **斜杠命令（`available_commands_update`）**：按会话保存上游列表，最多读取前 200 条；同名命令只保留首条定义，保证命令行身份唯一。断连时清空每个会话的旧命令，重连加载后等待新进程重新上报，避免显示已经失效的能力。输入框以 `/` 开头且命令名中还没有空白时弹出过滤结果，前缀匹配排在包含匹配之前；选择后只把 `/name ` 填入草稿，命令文本仍作为普通 prompt 原样发送，由 Agent 自己解释。实测 codex-acp 1.13.1 把 Skill 以 `$name` 形式放进同一个命令列表，而它的命令解析会跳过 `/$name`，Skill 需要以 `$name` 提及。因此名字以 `$` 开头的命令补全为 `$name `；输入 `$` 只列 Skill，Agent 没有上报 Skill 时 `$` 仍是普通文字。Lithe 不扫描 SKILL.md 或命令目录，也不内置命令表，避免和 Agent 的真实能力不一致。方向键和 Tab 导航依赖 macOS 14 的 `onKeyPress`；macOS 13 保留鼠标选择和 Return 补全。Return、Esc、方向键与 Tab 共用视图局部的补全状态，Return 在命令名未完整时只补全、完整时发送；Esc 先关闭补全，再次 Esc 才停止回复，编辑草稿后重新显示匹配。补全高度由输入区内部的局部布局容器按剩余空间限制，先保留一行可编辑文字；最小输入区放不下一整行命令时，列表浮在输入框上方，通过锚点偏好在整个对话布局中绘制，让鼠标点击范围不被较小的输入面板限制；沿用工作台悬停提示的局部 overlay 模式，不新增全局位置状态或鼠标监听。输入区的最小高度包含上下栏、可编辑行和外边距，附带文件时再预留附件行；这个值只在附件有无改变时通过视图偏好更新，不跟随拖动逐帧发布。不要让固定高度的命令列表参与分隔条的最小尺寸计算，也不要把逐帧几何尺寸发布到会话模型。
- **模式通知（`current_mode_update`）**：Agent 自己切换模式（例如退出计划模式）时，只更新 `category == "mode"` 且包含该值的配置选项，不向上游回发设置请求；选项中不存在的模式 ID 忽略，不显示原始 ID。

正确做法：新的更新类型先在 fixture 中加入样例，让 Rust 往返测试证明它是合法 ACP，再在平台功能模型中解析。不要这样做：在视图中直接解析原始更新；为了显示命令列表而自己维护一份 Claude 或 Codex 命令表。

这些状态只保存在会话内存中，不新增日志、下载、缓存或可复用工作树资源；安装目录和 bundle 仍只读，不影响代码签名和 Sparkle delta。

### 每轮耗时与上报 token

发送后用单调时钟（不受系统日期调整影响的计时源）开始测量，包含建会话、加载历史、工具执行和权限等待。界面状态旁的秒数表示本轮已经过的时间，不声称是模型内部推理时间。只让可见等待行每秒重绘，不每秒发布整个会话。正常完成、请求失败和断连固定耗时；取消仍等上游确认才结束。每轮末尾保留统计，标签切换不会重置，失败发送和历史回放不编造记录。

状态文案必须使用已经观察到的进度。准备会话显示“正在准备对话”，发送后尚无新输出显示“等待 Agent 响应”；只有收到思考片段才进入推理状态，普通回复和本轮活跃工具分别显示输出与执行状态，待授权和停止状态优先。已加载历史中的未完成工具不算新一轮的活跃工具。推理片段行已经显示实时标题时，状态行保留原有“输出中”提示，避免重复的“思考中”标题。

固定的 `codex-acp` 1.13.1 在未协商类型化错误扩展时，已经通过 `session_info_update._meta.codex.error` 上报 `willRetry` 和 `turnId`。该更新通常没有标题，不能先要求 `title` 再读取元数据。macOS 功能模型只在当前会话仍响应、未停止且上游明确 `willRetry: true` 时显示“Agent 正在重试”；不把原始错误、请求地址或重试次数从文本中猜出后放进界面。新的有效输出或工具事件清除重试显示，本轮完成、失败或断连后清理；已观察到的上一轮重试 ID 不得污染下一轮。只保存必要状态和有界的当前/前一轮 ID，不保存原始错误正文。这些字段仍通过共享 Host 原样透传，Windows UI 尚未完成同等消费，不能把 macOS 测试写成 Windows 已验证。

正确做法：收到明确重试通知后改变当前状态，继续保持会话忙碌，用户仍可停止。不要这样做：仅凭静默 180 秒就显示“正在重试”，或为了改善文案缩短整个请求期限、重新发送 prompt、读取供应商私有日志。等待长只能证明还没有新进度；重试和网络恢复继续由上游拥有，正常轮次无绝对上限，十秒取消确认边界保持不变。状态仍只在会话内存中，未新增缓存、下载、日志或发行包写入，不影响签名和 Sparkle delta。

正常轮次与用户授权不设总时长限制。连续五分钟没有新的实际进度时，共享 Host 只发出静默提醒；继续等待不重发请求，停止仍遵循十秒取消确认。授权等待通过 SDK 拥有的独立任务处理，不能阻塞后续消息、其他会话或连接退出。具体取舍见 [长任务与静默提醒](../bug-fix/2026-10-08-agent-turn-lifetime-and-quiet-notices.md)。

Host 发出 `turnCancelling` 时已经拒绝该会话的待处理权限。macOS 收到事件后必须立即清空该会话的授权卡片并刷新权限提醒，不能只依赖用户点击停止时的清理，否则自动超时后仍会显示失效的授权按钮。其他会话的授权和提醒继续保留；正在停止的会话仍保持忙碌并继续计时，直到收到终止事件。功能模型测试直接注入取消事件，覆盖权限队列清理、迟到权限忽略、取消完成前禁止发送，以及后台会话取消不影响当前会话。

共享 Host 开启官方 SDK 已有的可选 `usage` 解析，并随 `turnFinished` 原样透传。缺失、空值或非法数据不能阻止这一轮结束。输入/输出使用确切上报值，悬停显示总量、推理及缓存明细，没有上报就只显示耗时。

不要用上下文百分比、文字长度或订阅额度推算 token，也不要把不同供应商的报告统一称为单轮累计账单。[固定的 codex-acp 1.13.1](https://github.com/agentclientprotocol/codex-acp/blob/v1.13.1/src/CodexAcpServer.ts) 使用 `lastTokenUsage` 生成完成报告，[ACP 自身也有单轮与会话口径冲突](https://github.com/agentclientprotocol/agent-client-protocol/issues/1860)。正确做法是标注“Agent 上报，统计口径由 Agent 决定”，并保留上游数字；不要跨轮累加或做差来制造总消耗。

统计仅在会话内存中保存，不新增日志、下载或缓存资源。安装目录和 bundle 继续只读，不影响代码签名和 Sparkle delta。成功重新加载上游历史会重建消息，因此不会把旧本地测量绑定到新回放的消息上。

## 考虑过的备选方案

### Codex 直接复制 Claude 重放，或只设置 CODEX_CONFIG

前者会在原生重试之外再增加循环，可能重复工具并放大调用次数；后者被固定
`codex-acp` 1.13.1 的 `mergeGatewayConfig` 覆盖。上游最新公开实现仍覆盖整个
供应商表，单纯升级不能证明预算已生效；点号字段与整个表混用又依赖原生无序
覆盖的应用顺序。隔离或改写用户 `CODEX_HOME` 会改变 Skills、MCP、历史和指令，
手改已安装适配器则破坏安装基线并被重装覆盖，均未采用。

当前复用完整原生 App Server，只在公开配置边界补缺失字段，并保留 AIR 遗失的
结构化错误；代价是每个 API Key 连接多一个 Node 转发进程和独占临时 helper。
普通 429 的原生恢复缺口只在无工作时补齐，已有输出和工具绝不使用此重发。
正确做法是每次升级用本地 Responses 服务核对真实请求次数、流式恢复和清理；
不要仅检查写入了数字五，或把原生重试与 Host 重试分别当成五次。

### 两端各用平台语言实现 ACP

界面开发起步更快，但连接、取消、权限和进程树清理都要写两遍，长期维护成本高。社区的 Swift SDK 也会带来第二套协议栈。

### 直接修改 Agent 历史文件来支持收藏、重命名和删除

这样看似能复刻参考项目的全部动作，但会让 Lithe 再实现各 CLI 的私有目录、文件格式、并发写入和索引，绕过 ACP 的所有权边界。当前采用 Lithe 自己的轻量注释以及可恢复隐藏，代价是 CLI 本身的名称和记录不受影响；未来 ACP 提供对应正式能力时再评估迁移。

### 整体复用 Codeg

Codeg 是一个完整的 ACP 产品，可以参考，但它的工作台、状态和发布方式不适合嵌进 Lithe。直接用官方 SDK 可以复用协议实现，同时保留 Lithe 自己的模块生命周期。

### 项目失活时结束会话

这是上一版的做法，但点一下另一个窗口也会结束正在进行的对话。它不符合"会话属于项目"的使用习惯，已经撤回。

### Lithe 自带 Node.js，或用 `npx` 按需拉取适配器

Zed 就是这么做的。但会装 Agent 的用户本机通常已经有 Node。自带 Node 会让安装包变大，也多出一份需要维护更新的运行时。`npx` 会在第一次打开面板时悄悄联网下载，用户不知道装了什么。因此只检测 Node，不自带；适配器由用户点击后才安装，而且固定版本。

### 用户自己用 `npm -g` 装适配器

多数用户不知道"适配器"和 Agent 的命令行工具是两个东西，比如装了 `claude` 不等于装了 `claude-agent-acp`。全局安装还可能碰到权限问题，版本也不受控制。

### 取消超时后结束会话，或定时重发取消

定时重发取消针对单个适配器缺陷，不能成为通用协议策略，因此不采用。单纯超时结束并清空会话会丢上下文，也不采用。当前选择保留记录、显式报错并重连加载的有界恢复：代价是重启连接，但能保证下一轮不与未结束的旧轮混在一起。

曾使用十分钟整轮上限保护完全不返回的请求，但真实编码任务会持续执行超过这个时间，导致正常工作被强制中断，因此已移除。静默只触发提醒；用户停止、上游明确故障、连接退出和会话关闭仍有各自的取消与清理边界。

### Claude 使用通用 gateway、手工修改适配器或另建 HTTP 代理

Claude ACP 0.81.2 的 gateway 模式会将 `ANTHROPIC_AUTH_TOKEN` 设成占位值 `acp-proxy`；0.84.0 仍使用同样逻辑。原生 CLI 请求头实验显示它与真实 `x-api-key` 同时发送，而部分服务商优先校验 Bearer，结果是有效密钥也收到 401。额外自定义 Authorization 未能覆盖占位值，单纯升级同样无法消除此原因。

上游已经公开 `NewSessionMeta.claudeCode.options`，且恢复会话同样接受它。实测不走 gateway、通过这条接口传 SDK 原生 API Key 配置时，同一固定适配器能够完成回复，只发正确的 x-api-key。因此采用此接口完整复用上游 Agent、权限、工具、取消和历史；不修改下载后的第三方文件、不维护供应商专用分支、不增加本地 HTTP 代理。代价是凭据路由需要在每次新建和恢复会话时携带，升级适配器时必须验证这条公开扩展。

正确做法：在共享 Host 的 `session_routing` 中生成两层一致的会话配置，并让新建、历史恢复共用它。不要只清理启动环境或只给 session/new 配置；用户 settings 后加载会覆盖环境，历史恢复也会重新创建 SDK Query。手工修改用户级 npm 包会被重装覆盖，新增代理则增加本可避免的监听端口和生命周期，不采用。

路由仅在连接内存中保存，不产生下载、缓存或生成资源，工作树复用清单无需新增资源；不写发行 bundle 或安装目录，不影响代码签名和 Sparkle delta。

### 环境变量传 Key、或把 `CODEX_HOME` 指到 Lithe 目录

`OPENAI_API_KEY` 这类环境变量只适用于官方地址，也更容易泄露。隔离 `CODEX_HOME` 会让 Agent 读不到用户自己的 MCP 服务器、Skills 和全局指令；而一旦设置了网关，请求本来就不会用到用户的账号登录，所以没有必要隔离。

### 用 npm 日志或另写下载器提供进度

删除一个硬编码的旧模型名无法适应下一次模型变化，按描述为空过滤会误伤合法选项，固定新模型名会绕过上游推荐。上游 [codex-acp 的 AIR 扩展](https://github.com/agentclientprotocol/codex-acp/blob/main/src/AirExtension.ts) 已能提供推荐值，旧式模型目录仍能区分临时补入的配置值，因此复用这些信息并等待 ACP 确认；不修改第三方适配器，也不再另起一个 CLI 进程查询模型。

npm 的进度选项只面向终端，HTTP 日志通常在请求完成后才输出，无法解释长时间下载；轮询用户共享缓存也会把其他 npm 进程的写入误算进来。另写下载器会重复 npm 的代理、重试和缓存边界。因此采用一个只观察实际流字节的 Node 模块，保留 npm 完整安装行为；代价是必须用本地 HTTP 测试保护 Node 观察点和流的背压（消费者来不及处理时暂停接收）语义。

### 不识别来源，失败后给 npm 加 `--force`

这会覆盖 Homebrew 等安装器管理的命令链接，留下两个安装器争用同一文件，也可能让更新的是一份 CLI、PATH 运行的是另一份。统一迁移到 npm 还会改变用户的发布渠道。当前采用文件身份与原安装器记录确认后再更新：查询开销稍大，但能够保留安装方式；未识别的来源宁可显示手动步骤，也不猜测和覆盖。识别规则采用上游公开目录/命令，目录或包管理器输出变化时应补充契约与本地 fixture 测试。

### 可操作的活动栏与文件审阅

活动栏原先只有计数，用户无法从“任务 / 运行中 / 编辑”查看内容。现在三项通过共享 `litheDropdown` 面板展示当前会话的计划、待执行或执行中的工具、按上报路径合并的文件修改；搜索不改变统计，切换会话关闭旧面板。面板定位、关闭和外观复用已有共享控件，差异片段选择使用 `LitheSettingsSelect`，避免新增系统 popover 或独立下拉样式。参考 [CC GUI 的活动面板](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/tree/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/components/StatusPanel) 的交互，继续使用 ACP 已上报的状态。“运行中”不声称这些工具都是子代理，也不重新请求上游数据。

三个面板的宽度跟随活动栏，空态只显示一行居中提示，标题由下方入口承担。
参考版本的 `StatusPanel.less` 使用等宽浮层和中性选中背景，`TodoList.tsx`、
`SubagentList.tsx` 与 `FileChangesList.tsx` 都直接展示内容，不重复面板标题。
因此不再使用固定 340pt 宽度，也不在计划或工具列表外再套一层带标题的卡片。
计划和工具列表复用现有渲染器的嵌入模式，保留状态、证据展开和有界滚动；
编辑的批量操作集中在顶部右侧，文件行保持打开、差异查看与回撤入口。
例如点击空的“任务”只出现短提示，切换“编辑”直接更新同一原生面板。
不要为了靠近参考截图把它改成占用对话高度的常驻区域，或另写全局点击监听。

宽度由活动栏的局部布局读取，不写入会话模型或持久化存储。取舍是宽屏中的
列表更宽，但内容高度仍按已有上限滚动；普通对话中的计划卡片和工具分组仍可
独立折叠。`AgentActivityPresentationTests` 用真实窗口事件验证深浅主题、窄宽
等宽空态、切换与关闭、三种长列表滚动至末项，以及编辑动作和锚点拆除清理。
该布局不新增下载、缓存或磁盘资源，也不改变安装包、签名或 Sparkle 增量基线。

“编辑”支持打开文件、复用已有比较界面查看差异、保留单轮文件修改和回撤单个文件或全部文件。Agent 已经保存文件，所以“保留全部”只确认当前版本，不重复写盘。确认保存在该会话的内存里，后续新增工具修改以已确认版本为起点；旧工具的证据若被更新则重新展示，避免旧确认隐藏新内容。同一标签断连、重连和历史回放时继承这些确认；加载失败恢复原会话，加载成功仍核对完整版本或已确认前缀。关闭会话才释放这些状态，Lithe 不新建聊天历史或可复用缓存。行增减数只采用上游版本兼容的统计，缺失时不从字符串或片段估算。

ACP 差异可能是完整文本，也可能是 Claude 上报的片段。界面分开展示每段，标明来源；超出行数比较预算时展示前后文本，超出既有文本上限时标记不完整并禁止回撤。不能把片段拼成虚假的整文件基线。也不能仅凭 `oldText: null` 删除文件，因为上游会用相同值表示插入片段或缺失旧内容；只有显式创建元数据才允许把原创建文件移入废纸篓。Codex 使用差异中的创建类型，Claude 使用固定适配器转发的 SDK `FileWriteOutput`（写文件工具的结构化结果）；它明确区分 `create` 与 `update`，并提供完整的新文本和可用的旧文本。Write 优先用这份完整文本，保留片段会丢掉的末尾换行；旧文本缺失的 `update` 不得被当作创建。新增样例进入共享 fixture，由官方 SDK 往返校验。

回撤由连接模型持有可取消任务，逐个确认成功的文件；失败和较新的版本留在列表。关闭连接会取消并等待任务完成，切换会话不把结果写入新会话。AppModel 在动作前同步原生编辑器的待处理输入，拒绝脏缓冲区和仍在回复的会话；Mac 适配器校验工作区及父目录链接边界，保留末端路径交给文档适配器拒绝符号链接，不能先跟随链接再操作另一个文件。恢复按上报文本逆序处理，片段只允许唯一的非空精确匹配。写盘复用文档适配器的编码、字节身份及原子冲突检查；恢复删除要求路径仍不存在，撤销创建通过携带预期字节身份的受保护废纸篓端口，与原生保存共享同一写入锁。批量回撤不是文件系统事务，发生冲突时停止并保留尚未处理的条目。

外部程序不参与原生保存锁，所以移入废纸篓后还必须核对实际移出的对象类型和字节身份；不匹配时恢复原路径并返回冲突。如果外部程序又创建了同名文件，恢复不能覆盖它，两个版本都保留并提示废纸篓内的恢复路径。废纸篓文件由系统拥有，冲突恢复或用户手动恢复后结束该生命周期；不增加运行时缓存、工作树共享资源或安装包写入，也不改变签名和 Sparkle 增量基线。相比移入前再读一次，提交后的核对能发现最后一次检查与实际移动之间的外部替换；仍不承诺任意外部程序停止写入已打开的文件句柄。没有实现受保护移除的适配器直接拒绝，不能降级为普通 Trash。

正确示例：第一轮修改已保留，第二轮修改后仅撤销第二轮；用户在片段之外追加文字时保留追加内容，片段冲突或出现多个匹配时停止。错误示例：把 Agent 截断的 `newText` 当作磁盘内容直接覆盖，或回撤时删除用户后来新建的同名文件。这些做法会丢失用户数据。

重连也遵守同一个例子：A→B 已保留，回放后 B→C 的回撤只能恢复 B；已回撤的上报记录不会重新出现。创建 a.txt 后若它变成指向 b.txt 的链接，即使 b.txt 内容相同也拒绝，不能把 b.txt 移入废纸篓。原生编辑器先保存了新内容时，移除必须返回冲突，不能把保存成功的用户版本确认成回撤成功。

这里复用已有 ACP Host、文档读写与比较界面，不复制参考项目的桥接协议或另建文件快照服务。代价是证据不足的文件可以打开和确认，但不能自动回撤；多次上报的差异按段审阅，不承诺完整会话净差异；恢复已删除文件只能依据上报文本使用 UTF-8，无法还原未知的原编码或文件元数据。所有写入都来自用户显式回撤，目标仅为工作区；固定资源继续只读，不增加安装目录写入、签名变化或 Sparkle 增量基线变化。Windows UI 仍以功能矩阵中的独立状态为准。

## 后果

两端共享同一套协议和清理逻辑。功能关闭或没打开面板时，不会有 Agent 进程。一个项目的每种 Agent 只建立一个对话连接，会话再多也一样。订阅额度额外使用有界的短时官方查询进程，不新增常驻服务。

代价：

- Rust C ABI 和 fixture 成为兼容面，两端界面仍要分别维护。
- 用户需要自行安装 Node.js，适配器可以在面板内安装。
- codex-acp 丢失取消时，最多等待十秒后需要用户重连；同一进程的其他会话也会断开。上游未持久化的最后片段可能无法完整回放，界面保留旧记录用于诊断，不能保证 Agent 保存了未完成轮次。
- Claude 短重连依赖上游的错误分类。2026-10-07 本地集成复测中，404 曾在约 1.4 秒返回最终模型错误，但额外发出重连通知；随后 70 次重复检查和完整集成检查均未复现。首轮中间错误未捕获，尚不能确定是临时故障还是分类与时序问题。保留公开协议诊断和原断言，不能把后续通过视为已解决这个偶发边界；生产 UI、真实供应商与 Windows 验收仍以矩阵中的 pending 为准。
