# Agent 笔记：共享 ACP Agent 对话

状态：已实现

## 先说结论

Agent 对话默认关闭，打开某个项目的 Agent 面板时才启动本机 Agent。每个项目的每种 Agent 只有一个对话连接，一个连接里可以有多个会话；会话历史由 Agent 自己保存；Lithe 负责显示，并单独保存收藏、自定义标题和可恢复的隐藏状态。供应商管理允许 Codex 在自定义 API Key 和本机 ChatGPT 订阅间切换；Claude 仍只支持 API Key。订阅额度放在输入框上下文的右侧，不新增页面。Agent 需要的 Node.js 由用户自己安装，Lithe 只负责检测；ACP 适配器由 Lithe 提供一键安装，安装时用的是用户本机的 npm。ACP（Agent Client Protocol，编辑器与 Agent 之间的对话协议）连接和进程管理写在同一个 Rust crate 里：Mac 通过 C ABI 调用，Windows 通过 `windows/tauri/src-tauri/src/agent.rs` 的连接桥调用，两端只各自实现界面。

## 问题

如果两端各写一套 ACP 连接、权限回复与进程清理，协议行为容易分叉。若在应用启动时就启动 Agent，不用这个功能的用户也要承担内存和进程开销。Agent 会请求执行工具，权限必须由用户确认。

实测还发现两个会直接影响用户的问题：

- codex-acp 1.13.1 在"刚发出消息就取消"时会丢掉这次取消。它此时已经拿到本轮 ID，但 Codex 还没把这一轮标记为进行中，于是中断请求返回"没有进行中的一轮"。结果是这条消息的请求永远不返回，本轮在后台继续跑完并消耗额度，下一条消息还会被塞进这一轮。
- 打开 codex-acp 的 `APP_SERVER_LOGS` 调试日志后，网关请求头（包括明文 API Key）会写进日志文件。

## 决策

- **当前项目以编辑器打开的目录为准**：用户打开仓库里的 Spring Boot 子项目时，Agent 的 `cwd` 已经正确，但模型读取外层 Lithe README 后把当前项目介绍成了 IDE。向上继承开发规则本身合理，规则的归属目录不能成为项目用途的替代答案。共享 Host 在普通消息和补充消息的同一个组装入口附带固定的项目范围说明，以 JSON 引用当前连接的 `openedWorkspaceRoot`，明确用途和结构问题先检查这个目录的 README、构建文件与源码；用户显式要求其他范围时仍遵循用户请求。新建、重连、恢复历史后的提问和受控续轮使用相同入口，不把 Git 根目录替换成工作区，也不擅自扩大工具权限。历史仍由 Agent 保存，Lithe 仅在用户消息呈现边界移除自己附加的精确上下文后缀，保留原用户文字及全部模型、工具和其他元数据。Codex 还会用首条完整 prompt 截断生成标题，所以实时标题和历史列表标题也要移除可识别的完整或截断上下文后缀；只处理 Host 自己的固定前缀，不按一般 XML 标签过滤用户标题。原生斜杠命令保留原始文本块和附件顺序，不能因为带附件就追加项目上下文，避免破坏 `/usage` 和命令参数解析。清理后为空或仅空白的自动标题以缺失值传给界面，继续使用首条用户消息、新对话或无标题回退；不要用空字符串覆盖这些回退，也不改写上游保存的标题。该说明不是文件系统沙箱，仍需真实模型验证其是否选对资料。

  参考 Zed `c403bc6af644cd0ab60c90045ac6dc3436218809` 的 `crates/agent_servers/src/acp.rs`：主目录与额外目录通过标准 ACP 生命周期参数传递；Cline `789f79e46d3ba579717e8dc8be35fe28af935b06` 的 `apps/vscode/src/core/workspace/WorkspaceRootManager.ts` 以编辑器工作区为主，再附 Git 信息；OpenCode `34d8ded0c58dd66808c1d60e081e8c66da12a896` 的 `packages/core/src/location.ts` 分别保存当前目录和仓库目录，其规则文档允许向上继承。Lithe 继续复用上游 ACP 工具与规则发现，仅补编辑器已知、模型无法从 Git 根推断的项目范围。正确做法：打开 `repo/examples/service` 后询问当前项目，先读 `examples/service/README.md`。不要这样做：强制用户把项目搬出仓库、禁止所有上层规则，或者替每种 Agent 写一套私有系统提示词和历史管理。仅修测试目录不能覆盖真实嵌套项目；使用标准文本块无需协商可选的嵌入资源能力，也不会制造一个不存在的上下文文件。代价是普通提问和补充消息多出一小段模型上下文，其 token 仍按上游实际统计。本能力只保存连接内存，不新增下载、缓存、资源目录或文件读写，不写发行包，不影响代码签名和 Sparkle delta。确定性 ACP 测试覆盖两个不同嵌套工作区、恢复、补充、附件、命令和历史呈现；真实 Agent 回归用外层 IDE 与内层 Spring Boot 的不同 README 验证读文件证据和回答，并检查恢复后仍保持范围。
- **独立历史入口，保留原管理页**：标题栏只显示当前会话标题，不再把标题变成历史下拉。时钟按钮直接打开 `AgentHistoryView`，沿用搜索、收藏、重命名、可恢复移除、复制 ID 与导出；返回后保留原连接、草稿和滚动位置。标题仍使用 `AgentHistoryPresentation.popupTitle` 的本地重命名、上游标题、首条用户消息与空会话回退规则。编辑区与工具窗口共用这一入口，不能为切换历史新建连接。

- **新建对话入口保留真实动作**：顶部 New Chat 和多会话标签栏的新建按钮调用同一现有连接动作，等待创建时禁止重复请求；仅创建请求成功进入等待状态后重置草稿。连接未就绪或未配置时显示具体原因，不让空草稿重置伪装成新建成功。输入框左下角加号始终是添加文件，不接新建对话动作。预检的 WARN/FAIL 仅默认展开，用户仍可收起，再切换 Agent 后按新 Agent 的检查结果恢复默认状态。

- **Claude 错误使用短重连预算**：真实 401 和 503 均在约一秒收到首次错误，但 Claude Code 默认十次重试的退避等待（失败后延长下一次请求前的等待）累计约三分钟。交互式 API Key 会话改为临时故障总共五次尝试，四次间隔为 0.5、1、2、4 秒；首次失败后的重连阶段最多二十秒，超时仍遵守已有十秒取消确认边界。无效密钥、权限、参数、模型和额度错误直接返回；已产生回复、推理、计划、工具或授权请求的轮次不能整轮重放。正常工作不设整轮绝对上限，重连后出现实际进度会退出短重连阶段，不把工具执行或用户审批限制在二十秒。
- **复用公开错误能力，Host 只控制交互预算**：依据 [Claude Code 官方环境变量说明](https://code.claude.com/docs/en/env-vars)，原生重试预算统一适用于错误，还可能遵照供应商的 `Retry-After` 长时间等待。SDK 环境与程序化 `settings.env` 两层设置 `CLAUDE_CODE_MAX_RETRIES=0`、`CLAUDE_CODE_RETRY_WATCHDOG=0`、`CLAUDE_CODE_DISABLE_NONSTREAMING_FALLBACK=1`，新建与历史恢复相同。Host 协商固定 ACP 适配器的公开 AIR `sessionFailure` 扩展（结构化失败类别和恢复动作）；它把终止失败放在 `end_turn` 响应元数据中，必须先转换为请求失败，不能误报成功。扩展也避免把 CLI 合成错误文本当成模型回复。旧式 JSON-RPC 错误使用公开 `errorKind`。部分网关的 400/402 被上游归到通用服务错误，兼容检查只允许固定 CLI `API Error:` 前缀中的永久 HTTP 状态否决重连，不能凭文本启用重试，更不能扫描模型正文或私有 CLI 日志。未知旧式错误立即返回。实测重复发送前必须中断已失败的 SDK 请求，否则五个 ACP 尝试会产生九个 HTTP 请求；中断已终止且没有进度的请求后，本地服务实际收到五次。仍保留上游会话和历史所有权，不写或回滚历史。模型 404 的原生解析可能立即探测两次，不是 Lithe 自动重连，不承诺所有错误只产生一次 HTTP 调用。不要新增鉴权预检、修改安装的第三方包或自行实现另一套 Claude Agent。
- **Codex API Key 同步预算，保留原生恢复**：Codex 的 HTTP 重试和流恢复是两层预算，默认连续 503 在本地服务实际产生三十次请求。使用原生配置 `request_max_retries=0`、`stream_max_retries=4`，关闭无界连接重试；首次调用加四次恢复合计五次。仅尚无工作的重连最多二十秒，另保留十秒取消确认。已有回复、推理、计划、工具或授权进度后，原生恢复不再受 Host 二十秒期限或第二份五次计数取消；上游仍按已配置的有限预算恢复，最终失败与永久错误继续终止，不限制正常工作。公开原生错误类别或 HTTP 状态证明是永久错误时立即停止；普通 HTTP 429 在原生 CLI 中可能直接耗尽，因此仅在尚无实际工作时补短等待后的重发，并与原生共用五次计数。已出现实际工作，或其他原生终止错误，都不能整轮重发。订阅模式保留原生登录刷新，自定义 ACP 不注入 Codex 配置。
- **Codex 兼容入口只补配置与错误信息**：固定适配器覆盖自定义网关配置，`CODEX_CONFIG` 中的重试字段会丢失；混用点号路径和整个表又会受到原生 HashMap 应用顺序影响，不能靠偶尔成功认为已生效。因此单次连接创建一方标准输入/输出转发 helper（只传输公开 App Server 协议），在创建、恢复和分叉会话时补齐原生预算，其他配置照传。AIR 重连警告会丢掉原生错误信息，helper 将结构化 `codexErrorInfo`、原始说明、当前轮次和通知序号保存在失败标题内的 JSON 信封；Host 只在协商后的失败元数据中解码，正常消息原样传递，不扫描模型文本或私有日志。公开通知序号去重、原生当前轮次判断拒绝迟到错误，界面只显示原始说明。`<system-temp>/lithe-codex-retry-<UUID>/` 由该连接持有，结束进程树或启动失败后删除，无密钥内容；临时目录由平台解析，不写安装包、用户配置或第三方文件，不影响签名与 Sparkle delta。资源注册表将它排除，不能跨工作树复用。适配器未来直接保留这些原生配置并转发错误信息后，应移除此兼容 helper，保留预算和契约测试。
- **重连状态由实际事件驱动**：Host 发出带唯一轮次标识和尝试次数的 `turnRetrying`，macOS 在尚无工作时显示“正在重连 2/5…”并继续累计耗时；已有工作后的原生恢复省略 `maxAttempts`，只显示“正在重连”，不能编造调用上限。首次恢复警告后五分钟显示等待较久的提醒，继续等待只关闭提醒，不重发；后续警告不能推迟提醒。实际输出恢复后切换回复或推理状态；有效计划更新（包括清空计划）也证明重连已恢复，界面退出重连并清空次数，保留轮次计时和忙碌，不覆盖已有回复、推理、权限或停止状态。无法解析的计划不触发此清理。完成、失败、取消、断连清空次数；迟到通知不能复活已结束轮次，取消优先于重连，取消确认前不解锁。Claude 的下一次尝试必须等前次失败且无进度；Codex 的流恢复仍由原生执行。后续接入其他 ACP，应先核对它是否提供结构化失败、明确重连事件及可配置预算；只支持 ACP 不代表可以控制它的内部重试。未经适配的 Agent 保留原生策略，正常轮次不设绝对上限，不能对所有 Agent 盲目套五次 prompt 重放。
- **思考强度档位控件**：按用户给定的 Effort 参考设计，模型菜单底部把纵向强度选项收成一行：左侧按用户要求统一显示 `Effort (当前档位)`，右侧用胶囊轨道、圆点和选中圆块表示上游实际档位。模型滚动区只包含完整模型目录，目录为空或长列表滚动到底时仍能访问强度。档位数量、顺序、ID 与名称都由 Agent 提供，不固定成参考图的四档，也不手工补齐 Low、Medium、High、Xhigh、Max、Ultra。点击圆点、方向键及辅助功能调整均提交同一配置动作；按用户要求，调整 Effort 后保持同一个模型弹窗，等待上游确认期间只禁用控件，确认或失败后恢复操作，不能因提交请求或进入配置等待而收起弹窗。选择模型及其他配置仍关闭菜单，点击外部、按 Esc 和会话切换继续使用共享关闭逻辑；拖动仅在控件内预览，松开后提交一次，不能把每次移动都变成上游请求。空闲时仍等上游确认才改变当前值，下一轮预选继续由既有状态机负责；禁用态不发请求，未知当前值不伪装成第一档。弹窗继续复用 `litheDropdown` 和共享外框，按用户要求，模型弹窗最小宽度设为 300pt，给模型列表与 Effort 行留下更宽松的空间；长标签与轨道仍参与内容测量，最大宽度遵守共享上限，不改成固定宽度；标题与括号按原文渲染，保证中文界面不会因翻译成更宽的字符而超出测量宽度、出现 `思考强…edium)` 截断。控件使用现有主题色和字体，不新增另一套菜单背景。代价是短模型目录的弹窗也保留 300pt 最小宽度，收益是多档强度不再占用多行并且始终可见。只新增视图内手势与焦点状态，不新增缓存、下载或发行包写入。
- **权限模式呈现**：菜单和底栏保留 Agent 上游名称，例如 Claude 的 Manual、Accept edits、Plan、Auto、Bypass permissions；模型和思考强度也使用上游名称。名称不能进入全局翻译表，否则 `Plan` 会碰到其他界面的“计划”翻译，导致个别选项与其余名称混用语言。模式入口采用纯文本与向下箭头，菜单复用 LitheMenu 的紧凑单行选项与左侧勾选；删除卡片式逐项图标、双行说明及独立滚动/尺寸测量。当前模式说明留在入口 tooltip，Claude 继续显示上游实际提供的编辑、计划等额外选项。依据 [Claude 权限模式说明](https://code.claude.com/docs/en/permissions)，说明可按界面语言呈现，但保留实际 Agent 的审批与环境约束，不把 Codex 的沙箱说明直接套到 Claude。只改变显示，不修改选项 ID、数量、顺序或权限命令；上游确认继续决定当前值。未知选项保留其原文，不按列表位置猜测权限，也不把 Claude 的五项折叠成三项。不新增状态、资源或运行时写入。
- **Agent 菜单标志与勾选**：输入框的 Agent 下拉菜单为每个选项显示 16 点品牌图标，复用底栏同一套只读资源与内存染色。原生单选控件（Picker）将当前选项的勾选状态与品牌图像分别呈现，避免选中项用勾选图标替换品牌。控件直接绑定面板已有的选择值与切换动作，不在 View 里再存一份当前 Agent；图标和勾选以实际选择为准，不改变连接、会话或权限语义。
- **侧栏入口图标**：Agent 使用 Lithe 原创的“对话气泡 + 星光”线性 SVG，由工作台 renderer 显式绑定，避免落入通用模块图标而让用户误认成插件管理。图标作为固定源资源随应用打包，复用现有模板着色与选中态；不下载、不生成运行时文件，不影响安装包的只读边界。面板内 Codex/Claude 标志仍表示具体供应商。
- **安装包图标解析**：Agent 品牌图标从应用的 `Contents/Resources/Lithe_Lithe.bundle` 只读加载；资源包或图标缺失时使用默认标志。不要在已安装的 `.app` 中直接调用 SwiftPM（Swift 包管理器）生成的 `Bundle.module`：它只查应用旁的资源包和编译目录，找不到会直接终止进程，开发机器残留的构建资源还会掩盖问题。开发和测试入口保留 SwiftPM 回退；安装版不使用编译目录，也不通过启动时复制资源来修补发行包，避免改变代码签名和 Sparkle 增量更新基线。
- **底栏品牌标志**：参考 [CC GUI 的紧凑入口](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/blob/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/components/ChatInputBox/selectors/ProviderSelect.tsx) 与[品牌组件](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/blob/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/components/shared/ProviderModelIcon.tsx)，Claude 使用彩色星芒，Codex 使用主题单色结形标志。上游 Web 入口为 16 像素；Lithe 原生工具栏使用 18 点视觉尺寸、28 点点击区域，模型入口保留较小的同品牌标志。Claude 的 `#D97757` 与既有 `@lobehub/icons 5.8.0` 彩色组件一致。轮廓复用既有 SVG，欢迎区和历史页继续使用模板着色。SwiftUI 的前景色在原生 Menu 转换图像时可能丢失，因此底栏通过只读 SVG 的透明度蒙版在内存中生成带颜色的原始图像，不依赖原生控件替模板补色。图像缓存身份包含资源包、尺寸和颜色，深浅主题切换不会拿到旧色，也不修改其他视图共用的模板。正确做法是按品牌和主题选择颜色；不要复制 SVG 路径、改写源图或把染色图写进 bundle。该派生图像只在应用内存中存活，不新增磁盘缓存、下载或跨工作树复用资源，不影响代码签名和 Sparkle delta。
- **共享实现**：`rust/lithe-agent-host` 使用官方 `agent-client-protocol` SDK。一个 `AgentHandle` 对应一个项目的 Agent 进程和 ACP 连接，负责初始化、网关登录、会话新建/列出/加载、消息、权限、取消和进程树清理。Mac 通过 Rust Core C ABI（`lithe_agent_open_json`、`lithe_agent_send_json`、`lithe_agent_close`）调用；Windows 通过 `windows/tauri/src-tauri/src/agent.rs` 直接依赖同一个 crate。命令和事件的 JSON 形状由 `shared/fixtures/agent/acp-events-v1.json` 固定。
- **按需启动，跟着项目走**：`LitheAgentConversationModule` 是内置可选模块，默认禁用。每个项目有自己的模块运行时，所以会话天然属于项目。切换标签或窗口不会结束任何会话，后台项目的这一轮会继续跑完；只有关闭项目、关闭功能或退出应用时才停止 Agent。后台项目的会话在等待权限时，项目标签上会显示提醒点。
- **API Key 按上游公开接口传递**：Lithe 通过 ACP 的标准输入输出（stdio）通道把凭据传给适配器，不进入 Lithe 启动适配器的命令行参数、环境变量或文件，也不设置 `APP_SERVER_LOGS`。Codex 使用 Responses，在初始化时声明 `auth._meta.gateway = true`，通过 `gateway` 登录传服务商地址和 `Authorization: Bearer <key>`；没有该登录能力就报错。Claude 使用 Anthropic Messages，通过上游公开的 `_meta.claudeCode.options` 在 `session/new` 与 `session/load` 传入地址和 API Key，仅新会话传入供应商默认模型；由上游适配器与 Claude SDK 管理其内部原生凭据转换。SDK 的环境配置和程序化 settings 两层都显式指定同一路由，并清除旧 Bearer、OAuth、自定义请求头、云平台路由与 `apiKeyHelper`，防止用户或项目设置覆盖所选服务商。缺少凭据时直接报错，二者都不静默回退到账户订阅。
- **Claude SDK 子进程的凭据边界**：上面的保证只覆盖 Lithe 启动 ACP 适配器这一层，不覆盖整个子进程树。当前固定版本的 Claude SDK 会把对象形式的 `options.settings` 序列化为 Claude Code CLI 的 `--settings` 命令行参数，因此 `settings.env.ANTHROPIC_API_KEY` 会出现在该 CLI 子进程的参数里；开启 SDK debug 还可能把完整参数写进调试文件。同用户进程和诊断工具可以读取这些参数，不能把这一实现描述为全进程树都不暴露 Key。原 gateway 路径也把带 Key 的自定义请求头放进程序化 settings，本次路由修复没有消除这项上游暴露。后续独立评估把 Key 仅放在 `options.env`、settings 仅保留非敏感路由；采用前必须验证用户和项目 settings 中旧 Key 的覆盖优先级，以及新建、历史恢复和切换服务商都使用所选凭据，不在当前修复中直接删去凭据覆盖层。
- **Codex 订阅是 Agent 绑定方式**：供应商管理增加“Codex 订阅”选项，但不往提交信息共用的 HTTP 服务商注册表写一个假供应商。已有配置缺少认证类型时仍解释为 API Key；订阅绑定不保存 provider ID，启动时不读取该服务商的 Key、URL 或默认模型。只在当前子进程中指定官方 `openai` 路由并清除继承的 API 覆盖，会话配置同时清空 `openai_base_url` 并指定官方 `chatgpt_base_url`，防止本机旧地址继续覆盖订阅路由；额度探测也使用同样的覆盖。保留用户的 `CODEX_HOME`、MCP 和 Skills。本机 Codex 拥有账号存储和刷新，Lithe 不读取或复制其订阅凭据。已有账号直接复用；未登录先提示，用户点击才通过 ACP `chat-gpt` 方法打开官方浏览器登录。等待有五分钟期限，取消停止连接并停留在可重试状态，避免 idle 空态自动重连；认证通知与请求响应先后不作为成功依据，必须等上游确认账号。账号退出或邮箱改变时断开旧连接，不静默改计费来源。订阅错误不附加未经脱敏的上游 stderr，因为 Lithe 并不知道其凭据值。
- **额度复用官方查询能力**：核对 [codex-acp v1.13.1](https://github.com/agentclientprotocol/codex-acp/blob/v1.13.1/src/CodexAcpServer.ts) 的扩展方法后，确认它提供连接级认证状态推送，但没有结构化额度接口；`/status` 只有显示文本，token 统计也不是订阅窗口。因此共享 host 短暂启动已检测到的本机 `codex app-server`，用官方 `account/rateLimits/read` 查询，禁止创建线程或发送 prompt。查询前后读取账号并与 ACP 提供的邮箱比较；没有邮箱时不能确认归属，只显示未知。上游 ACP 没有稳定账户 ID，同邮箱切换组织仍是当前身份校验的限制。每连接最多一分钟一次、不并发，查询二十秒超时；连接取消或查询结束清理整个进程树。将来 ACP 暴露结构化额度后用同一连接替换此探测，不长期维护第二套认证或私有 HTTP API。
- **额度显示和资源边界**：参考 PR #870 保留真实窗口时长、未知不当零、失败显示过期的原则，不整合其独立页面和日志扫描。输入框底部工具栏右侧只放一个对标 Claude Desktop 的圆环（issue #1249）：灰轨，按已用比例最高的窗口填充并着色，这样任一窗口接近上限都能一眼看到；文字摘要移入悬停详情，避免窄侧栏挤掉模型等基础信息。详情中优先列真实五小时窗口，其他窗口保留原时长，不能把 primary 强制标为五小时。仅鼠标悬停时显示灰底详情，分别展示五小时、七天已用比例、灰轨进度条与重置时间，账号保留在标题下。已用比例默认绿色，严格超过 60% 黄色、超过 90% 红色；未知不当零，过期值灰显。灰底使用既有 HoverTooltip token 与共享 workbenchHoverCard，移开鼠标自动收起；没有新增点击弹层，会话切换卸载摘要并清除旧悬停。面板可见且应用活跃时每分钟刷新，回复结束也请求一次受限刷新；历史页、隐藏面板停止定时请求。短暂失败保留并灰显旧值，断连与身份失败清除旧额度。API Key 模式没有额度查询。快照只在连接内存中存活；未增加下载、缓存文件或可复用工作树资源，CLI 仍使用自身用户目录，安装目录和发行 bundle 只读，不影响代码签名或 Sparkle delta。
- **历史以 Agent 为准**：会话列表来自 `session/list`，打开旧会话用 `session/load`，由 Agent 回放历史。Lithe 不自己保存聊天记录。Agent 进程重启后，旧会话必须先加载才能继续发消息。导出按 [ACP 会话加载契约](https://agentclientprotocol.com/protocol/v1/session-setup) 等待完整回放后返回的 `session/load` 响应；Swift 接收到 `sessionLoaded` 时先刷新缓冲文本，再生成导出快照，不靠固定延迟猜测回放完成。
- **恢复模型必须确认底层生效**：供应商默认模型只用于新会话，不能通过 `ANTHROPIC_MODEL` 固定整个 Claude 适配器进程，也不能在 `session/load` 再传 `options.model` 覆盖历史。固定 Claude ACP 0.81.2 会从最后一个真实回复读取模型并报告给界面，但这不证明 SDK 正在使用同一模型。共享 Host 在 Claude API Key 恢复响应中读取标准 `category: model` 的当前值，再用 `session/set_config_option` 重新确认；即使当前值没变或不在选择器列表里，也必须完成这次确认。成功后使用完整的配置响应发布 `sessionLoaded`，保留上游更新的思考、速度和权限选项；拒绝、确认值不一致或超时走加载失败，不解锁排队消息。加载和确认共用已有六十秒期限，不重新开始计时。正确例子是历史选择 Opus、供应商默认 Sonnet 时仍恢复 Opus；不要靠工具栏显示 Opus 就认为实际请求已经切换，也不要读写 CLI 历史、保存第二份模型状态或修改安装的适配器。无模型选择器的旧适配器与其他 Agent 保持标准加载行为。这个修复只新增内存中的请求顺序，不新增缓存、下载或可复用资源，不写 app bundle、不影响签名与 Sparkle delta。
- **历史页与本地管理**：参考 [CC GUI 历史页](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/tree/main/webview/src/components/history) 使用面板内返回、搜索、统计和分隔列表。搜索只查询标题和 ID，数量只统计已加载的用户/Agent 消息，不扫描 CLI 文件，也不伪造上游未提供的消息总数。`AgentHistoryFeatureModel` 通过 `AgentHistoryPersisting` 保存收藏、标题覆盖和隐藏标记；macOS adapter 使用既有偏好设置，键为 `lithe.agent-history.v1.<workspace-agent-digest>`，按标准化工作区与配置 Agent ID 隔离。变更前重新读取，避免另一窗口的旧快照覆盖最近注释；解码或保存失败明确显示，不重置损坏状态。移除仅隐藏本地列表，提供“已移除的会话”筛选与恢复，不宣称删除 Agent 原始会话。单条和批量移除都先弹出确认框，取消不写元数据；确认操作使用弹窗出现时的会话 ID 快照，避免把后续选择变化带入删除。进入历史页保留对话视图和输入草稿，不停止正在进行的轮次。
- **归档历史走 Agent 自己的官方接口，浏览只读**：固定的 codex-acp 1.13.1 在 `session/list` 中只列未归档线程，也没有取消归档请求；Claude Agent SDK 0.3.280 的会话信息没有归档概念。因此 Host 只为 Codex 连接提供归档历史：`codex_history.rs` 使用与 ACP 连接相同的 Codex CLI（订阅模式取已检测的 CLI，API Key 模式取中继改写前的 `CODEX_PATH`），临时启动 `codex app-server`，调用 `thread/list`（`archived: true`，provider 与 source kinds 与 codex-acp 一致，不发 0.156 不支持的 `cwd` 参数），按 codex-acp 的路径比较规则在本地筛选当前工作区并跟随游标翻页，按 ID 去重；达到 `MAX_SESSION_LIST_PAGES` 时返回 `complete: false`，界面明示只显示最近部分，不把截断当完整。该进程沿用额度探针的隔离方式：移除 API 覆盖变量、不传凭据、不改 `CODEX_HOME`，单次交换有 30 秒上限，结束或取消时终止整个进程树；上游错误文本不回传界面。浏览、刷新和搜索只发列表请求；只有用户在确认框中选择“取消归档并打开”后才发 `thread/unarchive`，成功后再走已有 `session/load`，失败时会话留在归档分组。取消归档成功事件必须先同步把会话移回活跃历史、作废此前活跃与归档列表的请求 token，并重新查询双列表，再恢复等待方；不要等异步等待方恢复后才改数组，否则成功事件紧接着到达的旧列表仍会把会话错误放回归档，断连后也可能重新插入过期记录。Swift 把上游原始归档响应与活跃 `sessions` 分开保存，以请求 token 丢弃过期结果；只有最新上游活跃列表中的 ID 才压制归档展示，不用本地已加载会话判断上游状态，也不破坏性删除归档响应。两种响应先后顺序都要在本轮完成后得到相同结果：例如 A 从活跃变归档时，即使归档先返回、A 的本地标签仍打开，也只在归档历史分组显示，已加载消息仍保留。截断提示放在分组外，不能依赖归档非空、展开或搜索命中；空结果且 `complete: false` 不能显示“没有历史”或“没有匹配”。连接断开、切换工作区或 Agent 时清空归档列表，避免串入旧结果。归档与 Lithe 的“已移除”互不相同：后者只是本地隐藏。已移除的归档行提供独立恢复按钮，只清除本地隐藏标记，保留收藏和自定义标题，不请求加载或取消上游归档；本地注释接口接受活跃或归档列表中的已知 ID，导出仍只接受可加载的活跃会话。`ready` 的 `canListArchivedSessions` 为假时（如 Claude），历史页提示该 Agent 不支持归档会话，不按 Agent 名称写分支。本能力不新增下载、缓存或资源目录，不写发行包，不影响代码签名和 Sparkle delta。
- **导出与资源所有权**：导出为用户选择位置的 Markdown，包含用户、Agent 和工具消息，工具输入/输出/内容一并保留。未打开会话复用现有、有请求期限的 ACP 加载路径，逐个加载，不改变选中标签；加载失败不写部分导出；只有会话成功创建或完整加载后才标记历史快照可复用，消息非空不能证明完整性。失败或断连留下的部分回放必须重载，已完整加载的快照在断连后仍可导出。取消与模块关闭释放等待 continuation（异步结果回调），原加载请求可自然结束。正在回复或加载中的会话不导出。导出 Task 由历史功能模型拥有并在模块停止时取消、等待结束；平台 adapter 拥有保存对话框与原子文件写入，最大 32 MiB。偏好设置与用户导出都不是构建缓存，不新增下载、不跨 worktree 复制；见 `scripts/worktree-resources.json`。它们不写发行 bundle、不影响代码签名和 Sparkle delta。
- **配置菜单间距**：模型和设置选项使用较小的最小行高，权限选项保留标题与最多两行说明需要的空间；行内容较高时允许自然增高，不用固定行高裁剪文字。权限面板按实际内容高度收紧，测量值在最大可视高度处截断并只更新弹出面板的局部状态，避免滚动时反复调整面板大小；长列表继续由原生滚动容器承载，不能把行距变小却保留旧面板高度，或为了紧凑隐藏上游选项。名称和权限语义由既有呈现规则及 ACP 确认流程决定，布局不改写选项 ID 或当前值。
- **上下文用量以上游为准**：发送按钮左侧使用共享 22pt 命中区内的 16pt 圆环，悬停通过工作台浮层显示一行百分比及已用/总容量，如 `41.8% · 125.3K / 300.0K 上下文已使用`，点击展开上下文明细。没有上报或无效容量保持未知，不再显示 0%；只有有效零使用量才是 0%。使用现有 ACP `usage_update.used/size`，每条更新替换前值，压缩允许下降，超过容量时保留上游数字、仅圆环限制一圈；计费累计量不能代替占用，也不根据模型名或文字长度推算。固定的 codex-acp 1.13.1 在 `loadSession` 中回放消息但不重新发出 `usage_update`，所以历史消息存在不等于已有容量数据。Lithe 将实际收到的报告与已确认模型选项 ID/值一并放入已有、按工作区和 Agent 隔离的有界会话统计记录；恢复完成且模型完全匹配时展示已保存的报告，新报告替换来源状态和数字，回放中明确上报的未知值也不能被旧缓存覆盖。模型改变清除报告和持久化快照，权限/思考选项不清除；断连清除实时展示，下一次恢复需重新确认模型。旧历史没有缓存时，固定 Codex 适配器通过下述原生恢复兼容通道获取真实报告；其他适配器没有报告时仍未知。不发隐式提示、不读取 Agent 私有历史文件、不修改已安装适配器。只复用用户偏好存储，不新增资源路径，不写 bundle。
- **停止必须等上游确认**：只发送一次 `session/cancel`，撤销本轮权限请求，界面进入“正在停止”。收到原 prompt 的结束响应后才能发送下一轮。旧方案只屏蔽迟到的 prompt 响应，却不能阻止上游把新消息并入旧轮次，也不能识别没有轮次编号的迟到通知。因此改为十秒确认期限：超过期限则明确报错、停止该 Agent 的进程树，保留界面记录，用户重连后通过 `session/load` 恢复。正常取消不重启进程。这不是伪装成正常结束，用户会看到恢复原因；同一 Agent 进程里的其他会话也会断开，不能静默自动重试消息。
- **会话配置由上游提供**：面板连接完成后准备空会话，让用户发第一条消息前就能选择模型、权限模式、思考强度。选项、分组和当前值均来自 `session/new`、`session/load`、配置更新通知及 `session/set_config_option` 的响应；不硬编码模型列表。每次启动 Agent 连接前，通过既有本机配置端口读取完整配置；地址、默认模型、协议、认证方式和密钥必须来自同一次读取，避免旧导入地址搭配新密钥，也避免旧模型继续成为新会话的默认值。导入供应商的非密钥字段按原 ID 更新，保留 Agent 关联、提交信息的服务商选择和用户的 HTTP 许可；手动服务商不受本机配置影响。模型读取独立于完整 API 配置：Codex 没有自定义服务商或 API Key 时仍能读取顶层 `model`，不能把其他 TOML 表里的同名字段当成默认模型；凭据校验失败时也更新面板的模型回退显示。API Key 模式仍校验凭据；订阅模式绕过这条服务商模型同步路径，使用 Codex 自己的模型目录。仅刷新本机配置仍不够：codex-acp 1.13.1 会把不在实际模型目录中的配置值临时补进选项。共享 host 保留上游同时返回的旧式模型目录，并协商其版本化推荐值扩展（`jetbrains.air.recommendedValue`）；当前值不在实际目录中时，优先使用同时存在于目录和选择器的推荐值；推荐值缺失、不兼容或版本过旧时，按目录顺序选择第一个在选择器中可用的官方模型。两种修复都通过标准 ACP 配置请求并等待上游确认后再发布会话，保留官方返回的完整选项，由上游移除临时补入的无效模型；两次请求共用创建会话的有界超时。配置中有效的模型、历史会话和用户文件不被自动改写；目录缺失、格式不兼容或没有可选交集时保留标准 ACP 行为，不猜默认模型、不按版本名或描述筛选。手动新增 Codex 供应商的编辑器初始值使用官方 `gpt-6.1-sol`；新增 Claude 专用供应商按用户选择预填 `claude-fable-5-1`（[官方模型 ID](https://platform.claude.com/docs/en/models/fable-5-1/overview)）。这只决定新增草稿的初始值，用户可以修改，编辑已有供应商仍保留已保存模型，包括尚未填写的空值。通用 AI Providers 的新增入口继续要求显式模型，不能把专用编辑器的默认值带入通用入口或本机配置读取。模型入口保留该 Agent 已有品牌 SVG，菜单选项使用左侧勾选，不使用逐项品牌或通用 CPU 图标；显示标签仍由上游确认的当前值决定。请求完成前禁止重复配置和发送，失败保留之前确认的值并显示错误。适配器没暴露的配置不画假控件，也不替用户改变网关地址或全局 CLI 配置。
- **通用供应商的模型需要显式填写**：通用 AI Providers 的 Add Provider 入口允许切换 Responses、Chat Completions 和 Anthropic Messages，因此初始模型保持为空，填写有效模型后才允许发出请求。不要把 Codex 编辑器的默认模型填入通用入口，也不要在协议切换时按模型字符串清理用户输入；即使用户手动填写 `gpt-6.1-sol`，该值仍由用户拥有。这样避免未确认的 Codex 默认值进入 Claude 会话或提交信息请求，代价是通用入口需要显式填写模型。
- **会话配置准备期间的显示**：本地供应商默认模型只是启动输入，不是当前会话的已确认模型。切换到尚未初始化的 Agent 时，工具栏从连接启动、准备空会话到默认模型修正完成，连续显示“正在加载会话设置”；加载历史也等待该会话自己的配置，不先闪现本地默认模型或另一个会话的选项。进程报告 ready 只表示连接可用，不能当成模型目录已就绪。已有连接和已确认会话在来回切换时直接复用，不额外加载；创建或加载失败、需要登录、连接失败以及上游不提供配置时退出加载状态，保留真实错误和既有默认模型回退。发送按钮和回车发送都遵循准备状态。这是原生界面根据现有连接事件推导的显示行为，不新增 ACP 状态、模型缓存、资源目录或运行时 bundle 写入。
- **关闭最后一个标签后准备新会话**：连接已 ready 时，关闭最后一个会话由连接模型立即调用既有 `prepareConversation()`，发起一次新建请求，不等待视图重新出现或连接状态再变化。准备中的创建请求复用已有 token，重复关闭或准备不会重复创建；旧确认不能重新选中已关闭的会话。保留“正在加载会话设置”的显示与发送限制，收到新会话确认后才恢复模型选择和发送。还有其他标签时直接选中最后一个标签，断连时不创建；这只移除本地标签，不删除上游历史。不要仅为解除阻塞取消准备状态判定，否则会重新闪现未确认的本地默认模型。
- **工具证据与文档保护**：工具详情合并上游的部分更新，展示类型、输入、输出、文件位置和修改前后文本；权限卡复用已收到的工具证据，区分允许和拒绝。显示文本每段限制 32 Ki 字符，内容和位置各限制 100 条，避免大工具输出堵住界面；截断处标记 `[...]`。点击项目内文件交给现有编辑器导航，不在视图中直接读写文件。磁盘刷新、脏缓冲区保护和 Git diff 沿用文档/Git 模块。Agent 从项目目录启动，不需要先附加当前文件才能读写磁盘；未保存的编辑器快照是后续独立能力。
- **未发送的空会话不能当成历史恢复**：为了提前显示配置，界面会先创建空会话，但 Codex 在首条消息前还没有把会话内容写入磁盘（rollout），旧进程关闭后用原 ID 加载会报 `no rollout found`。连接模型只跟踪本连接新建、未成功提交消息且未出现在上游历史中的会话；断开时移除这些会话的本地标签和临时记录，重连后通过原有准备流程新建。已有消息、上游列出或成功加载的会话继续恢复，不根据“当前消息列表为空”推断历史不存在，也不按错误字符串给真实历史自动新建替身。这个操作不删除用户的上游历史文件；代价是未发送会话的临时配置选择需要在新连接重新确认。
- **历史加载失败不清空记录**：回放时保留原会话快照，成功后使用上游回放，失败或连接退出时恢复之前记录并丢弃不完整的回放片段。旧连接事件任务被取消后不再消费缓冲事件。
- **并发权限与中断状态**：同一会话的多个权限申请按到达顺序排队，答复一个后展示下一个，取消时一起撤销。轮次或连接结束时，没有收到最终状态的工具标记为中断，不再无限显示运行中。
- **本机与自定义供应商**：面板设置保留本机 CLI 读取入口，并支持添加、编辑、启用和确认删除自定义供应商。自定义编辑器默认提供名称、API Key、API 请求基础地址和模型四个必填字段，Key 默认遮罩并允许用户显隐。参考 [CC Switch 的 Codex 字段表单](https://github.com/farion1231/cc-switch/blob/51ac86f1c59abfefabadebd05ec5a5415b8ad72c/src/components/providers/forms/CodexFormFields.tsx) 的字段优先方式，沿用 Lithe 原生设置控件；不添加尚无保存语义的官网、备注、测速或完整请求 URL 开关。需要粘贴配置时显式切到配置文本，继续接受 Codex TOML/auth JSON 或 Claude settings JSON，但只提取 API 地址、模型和 API 密钥；其余 CLI 选项仍由本机文件决定，编辑器明确提示这一范围。表单进入文本模式时生成正确转义的模板，文本返回表单时先通过既有解析端口的草稿读取模式再回填；空白或部分填写的地址、模型和 Key 保持空值，不因缺少密钥阻止切换，也不填入 CLI 的隐式默认值。草稿模式继续复用 Rust 的 TOML/JSON 解析和别名解析，格式损坏或不支持的协议仍保留原文和模式。保存走完整校验，不能把允许切换解释为允许保存不完整供应商。保存只解析当前模式的输入，避免隐藏的旧字段覆盖用户刚粘贴的配置。正确做法是填好字段后再选择文本检查生成值；不要在每次击键时双向覆盖两套草稿。TOML/JSON 元数据复用共享 Core 的现有 AI 解析器，不在 Swift 重新实现 TOML；原文仅存在编辑草稿，密钥由 Mac 适配器提取并交给现有安全存储。解析响应和错误不含密钥、原文或解析器诊断。配置编辑器沿用源码/SQL 编辑器的纯文本策略，关闭智能引号、破折号替换与自动纠错，避免合法配置在输入时被系统改坏。保存错误固定在滚动区外的按钮上方，不能把错误藏到长配置底部；已有弯引号导致 TOML 失败时明确提示改用直引号。供应商元数据复用既有 AI 服务商列表，添加、编辑、启用不改变提交信息的服务商选择；删除会同时移除列表里的供应商及其密钥，界面先说明影响并要求确认。
- **本机导入按来源隔离**：Codex 与 Claude 的导入凭据标识必须包含各自来源，重复导入只更新同一来源的供应商并保留其身份，不能用共享标识查找或移除另一来源。旧版本遗漏字符串插值会使后一次导入覆盖前一条记录，出现 Claude 图标显示 Codex 模型；预检只看绑定是否存在，不能证明凭据可用。macOS 加载设置时修正旧标识，保留供应商身份、提交信息选择和正确绑定，并解除内置 Agent 指向另一种本机来源或已被覆盖移除的供应商的错误关联；已被覆盖的配置无法可靠恢复，用户需显式重新选择，不按模型名或图标猜测来源，也不自动切换到订阅。即使标识已被提交供应商刷新修正，错误关联仍要检查。自定义供应商和自定义 Agent 的有效关联不改动。正确做法是只导入 Codex 时让未关联的 Claude 保持未配置；不要用界面替换图标掩盖两个 Agent 共享错误记录。修复只写既有设置存储，不读取、复制或修改用户的 CLI 密钥，不新增运行时资源，不影响安装包签名与 Sparkle delta。`AgentProviderImportTests` 用内存设置覆盖双向导入、重复导入、旧设置修复和重载。
- **本机 HTTP 需要逐供应商授权**：本机 CLI 读取入口的活动供应商提供“Allow insecure HTTP”，默认关闭。Claude 和 Codex 共用 Host 的 HTTPS 校验，不能因为只有 Claude 报错就给 Claude 绕过校验或自动信任回环地址。正确做法是在本机代理如 `http://127.0.0.1:3425/v1` 被阻止时，由用户为该供应商打开许可；许可保存在既有供应商元数据中，重新导入、连接快照刷新和应用重启后保留，另一来源不受影响。切换沿用当前项目的空闲停止与重连，并在异步停止后再次核对完整供应商快照，防止覆盖另一窗口的刷新或删除。只修改许可，不写 CLI 配置或密钥文件，不新增缓存、下载或运行时资源，不影响签名与 Sparkle delta。代价是许可随同一供应商身份保留，用户更换 CLI 地址时仍应确认是否信任。`AgentLaunchConfigurationResolverTests` 同时覆盖 Codex/Claude 的许可开关、持久化、HTTP 地址和同次快照密钥传递、来源隔离与过期记录拒绝。
- **本机配置按连接读取完整快照**：`AgentLaunchConfigurationResolver` 在连接前协调配置端口与设置存储。读取到快照后，用它同步所绑定供应商的非密钥字段，并直接将快照中的密钥交给当前连接，不能再调用凭据解析器读取第二次。本机配置缺失时拒绝启动旧路由；只有模型可读时仍更新模型回退显示，缺失密钥时同步最新地址后明确报错。正确示例：CLI 从供应商 A 切到 B，下一次连接同时使用 B 的地址和密钥，供应商 ID 与关联保持不变；不要只更新模型后把 B 的密钥发送到 A，也不要通过重新导入改变提交信息的供应商选择。该快照只活在当前调用和连接内存中，非密钥字段写入既有偏好设置；不新增缓存、下载、日志、监听器或跨工作树资源，不写 CLI 文件或发行目录，不影响签名和 Sparkle delta。代价是现有连接需要用户空闲重连才能采用外部配置变化，不在后台监听文件或切换计费来源。
- **切换连接**：当前项目的 Agent 正在响应、加载会话、创建会话、等待权限或确认配置时，拒绝切换；空闲时先等待旧连接关闭，再绑定供应商并重连。编辑或删除当前项目正在使用的自定义供应商也遵循这个顺序。保存操作在等待旧连接关闭前记录供应商快照，写入密钥前同步核对共享注册表；若另一窗口已删除或修改该记录，旧保存操作必须失败，不能重新创建供应商或覆盖新配置。检查、密钥写入和元数据发布之间不得异步等待。密钥写入失败不会发布新配置，删除密钥失败会保留供应商供重试，重连使用原配置。现有本机凭据文件损坏或版本不支持时，写入和删除必须报错并保留原始文件，不能按空文件覆盖。其他项目已经建立的连接继续完成自己的工作，在下一次连接时读取最新供应商；不得为了全局设置变化中断后台项目的轮次。切换保留面板记录，恢复已保存会话仍通过上游历史加载。
- **输入区视觉规则**：多行输入复用共享输入组件的 14pt Regular 正文与 Islands `Component.infoForeground` 提示色（深浅色均为 #73767C，来自 `StatusText` → `SimpleTextAttributes.GRAYED_ATTRIBUTES` → `NamedColorUtil`）；单行搜索继续使用 13pt；两者共用这个提示色，不能使用 ToolTip.infoForeground/text-muted 替代写作占位色。这是 Lithe 的共享多行规则，Community 没有公开截图中的 AI Assistant 专用字号，不宣称已验证其私有实现。附件与发送保留现有两个动作，共用 22pt 工具栏按钮的 hover、按下和禁用绘制，图标为 16pt。发送轮廓资源沿用 Community `915c3c26029bd2f8d35907d6faf43c4a3264c5f7` 的 `platform/collaboration-tools/shared/resources/icons/send.svg` 路径，将填充改为 1pt 描边并使用既有深浅图标色；NOTICE 标明改编，不把它冒充未修改的 AI Assistant 资源。上下文指示器移到发送按钮左侧，以共享 22pt 工具栏占位和 16pt 圆环显示，不在输入框底栏重复显示百分比；圆环按参考布局使用 2pt 内侧描边（不是 Community 私有 AI 插件源码常量），轨道与已用部分复用共享提示前景/工具窗口文字色，警示色和使用量计算不变。百分比和 token 数保留在简洁悬停提示及无障碍值，组成保留在点击明细，不绘制 hover 底色；工具栏与状态条的圆环在 Agent 首条用量上报前整体隐藏（`AgentContextUsageView.isHiddenUntilReported`），上报后出现，避免空圆环被误读为零占用；点击明细面板与无障碍值在无数据时仍显示未知说明，不把未知数据画成空的已用进度，也不显示成零用量。已上报的数据和计算规则不变。
- **Agent 管理（主设置窗口中的 AI > Agents（2026-10 起从 Tools 移入 AI 分组，见 2026-10-15-macos-settings-hierarchy））**：
  - **支持的 Agent 目录**：写在 `lithe-agent-host` 的 `catalog.rs`，Agent ID、npm 包名和固定版本都与 ACP 官方注册表一致。首批是 Codex（已用真实服务商验证）和 Claude（标为"未验证"）。只有重新验证过的版本才会提升。
  - **环境检测**：通过登录 shell 读取 `PATH`，所以 nvm、fnm 装的 Node 也能找到。检测 Node 和 npm 的版本，每个 Agent 各有最低 Node 版本（Codex 20、Claude 22），版本不够时只提示。
  - **一键安装**：用用户的 npm 把固定版本的适配器装到 `Application Support/Lithe/agents/<id>`。先装到临时目录，确认可执行文件存在后再替换旧目录，所以失败或取消不会破坏已经能用的旧版本。
  - **复用用户本机的 Agent CLI**：两个适配器都自带一份 Agent 的原生程序，都是可选依赖，单个平台约 200–370 MB，而用户本机本来就有。所以安装时加上 `--omit=optional`（Codex 装完约 18 MB）。启动时在登录 shell 的 PATH 里找到用户的 CLI 交给适配器：Codex 用 `CODEX_PATH`（最低 0.156.0），Claude Code 用 `CLAUDE_CODE_EXECUTABLE`（最低 2.1.280，对应 SDK 的 `claudeCodeVersion`）。CLI 找不到时可由 npm 安装；版本过旧时先确认当前 PATH 命令的安装来源，再通过原安装器更新。来源展示在预检项中，npm/Homebrew/原生安装可以按验证结果提供升级按钮，未知来源只给手动指引。所有安装与更新只在用户明确点击时运行，Node.js 和 npm 仍由用户自己安装。CLI 过旧不阻止安装适配器，只有 Node.js 或 npm 不可用才阻止。
  - **检查状态与适配器版本共用规则**：每次检查都显示加载状态，完成后明确反馈；整体失败显示原因并保留上次检测数据，正在检查或失败时不显示旧结果里的更新入口。CLI 查询错误通过可选 `updateCheckError` 返回有界原因，在预检内展示；同一查询的目标版本通过可选 `availableVersion` 返回，npm 使用实际发布版本，Homebrew 使用所属条目的 `current_version`，不能只丢给界面一个布尔值。CLI 折叠标题显示当前版本与升级目标，展开后分别标为“当前版本”“可更新至”，最低版本独立显示；未返回目标版本时写“无法确认”，不能从本地版本推测。适配器版本区分别显示当前版本、已核验目标和有更新时的“可更新至”。没有只读查询协议的原生安装仍显示无法确认，不能声称最新。适配器的可选 `updateAvailable` 由 Rust 使用已有依赖树中的 semver 比较已安装版本与 Lithe 核验的固定目标版本，版本相等、本地更高或不可解析时不显示 Update；预发布版本低于同版本正式版，构建元数据不算更新。保留固定目标策略，不查询并自动安装未经核验的注册表最新版。新增目录 Agent 自动复用这些规则，不按名称增加条件。
  - **CLI 更新保留安装来源**：以 PATH 中实际命令及其真实文件为准，不能仅看到用户装了 npm 就把所有 CLI 交给 npm。Homebrew 通过自己报告的 Cellar/Caskroom 位置和已安装记录确认归属，保留 cask/formula 及 `claude-code@latest` 等渠道；npm 必须确认当前 global root、包名、bin 声明和链接都指向同一 CLI，另一套 Node 环境不能代更新；Claude 标准原生 launcher 使用上游 `claude update`。未知来源、损坏链接、缺少原安装器或安装记录时拒绝自动覆盖，明确提供手动指引。更新后重新读取登录 shell 的 PATH 并验证最低版本；更新命令退出成功但实际 CLI 仍过旧也应失败。安装器可能在首次下载失败后重试成功，却保留非零退出状态，因此正常结束的命令无论退出状态如何，都要检查实际版本。只有新安装或数字版本严格提升且达到最低要求时，才能把非零退出降为“已成功、带警告”，返回有界日志并在界面折叠展示；原本可用但版本没变、降级、仍过旧或找不到命令时继续报错。不能根据日志中的“successfully upgraded”字样猜测成功，也不能把取消、超时或启动失败改判成功。读取来源只使用有界的本地查询，不更新包管理器索引、不改变用户配置。Homebrew 和原生下载归原安装器拥有，仅显示“正在更新”与耗时，不伪造字节进度；它们的全局安装和缓存不注册成可复制的工作树构建资源，排除清单与测试同步维护。
  - **所有 Agent CLI 共用更新状态与入口规则**：最低版本只证明适配器能够运行，不能证明有更新。npm 安装从已验证的更新计划读取实际包名与显式 `@latest` 发布版本，与实际更新目标一致，不能让用户 npm 的默认 `tag` 配置把检查改为 beta 等其他渠道；Homebrew 安装读取更新计划中所属 cask/formula 的过期状态，保留如 `claude-code@latest` 的渠道；查询有界，Homebrew 不自动刷新索引。npm 发布版本接受 JSON 字符串或单元素字符串数组，拒绝空数组、多项和非法版本。结构化查询只解析 stdout，stderr 单独有界收集，非致命 warning 不影响有效结果；共用原有超时、取消和进程清理路径。只有安装来源可安全更新且确认有新版本时，所有 Agent CLI 才显示 Update；npm 确认当前版本时显示“已是最新版本”；Homebrew 只显示“当前 Homebrew 索引未发现更新”，并提示可手动运行 `brew update` 后重查，不自动刷新索引。预检文案使用设置页选中的界面语言，查询失败时明确说无法确认，不显示 Update。低于适配器最低版本时保留兼容性警告与原安装器指引，但仍必须确认有新版本才能显示 Update，不能把不兼容当成更新证据。未知来源或 npm 环境不匹配继续只给手动指引。新增 npm/Homebrew Agent 只在既有目录登记包名和安装归属，检查器与界面不得再按 `codex`/`claude` 名称分支；例如 Claude 的 npm 包自动沿用相同查询，不能复制一个 Claude 专用检查器。原生安装没有通用只读版本协议时返回未知，展示无法检查更新并保留原安装器指引，不执行 `claude update` 来探测，不拿 npm 发布版本冒充原生渠道版本。[Claude 官方安装说明](https://code.claude.com/docs/en/setup)说明原生版本可选择发布渠道；因此放弃把所有来源都与 npm latest 比较的方案，代价是原生安装暂不显示已确认的可选更新入口，低于适配器最低要求的修复入口仍保留。完成后刷新检测版本，并提示用户重连以获取上游模型目录，不自动中断现有会话，也不在 Lithe 中补写新模型名称。查询可能受网络或本地 Homebrew 索引新鲜度影响，因此未知结果不宣称“已是最新版本”；不新增缓存或发行包写入。
  - **下载进度以 npm 的真实传输为准**：安装与 CLI 升级通过现有 Core 事件回调报告已接收软件包字节数、最近采样速度、耗时和等待时间。npm 没有提供整次安装的总量，且会继续发现依赖，所以不显示总体百分比。内嵌的 Node 观察模块只统计 HTTP 响应进入流缓冲区的字节，不添加消费数据的监听器，也不重写下载、代理、重试、校验或缓存行为。模块通过内存中的 data URL 加载，启动后先恢复用户原有 `NODE_OPTIONS`，防止 npm 子脚本继承观察器；不生成辅助文件或新的可复用缓存。正确做法是显示“已下载 25 MB、75 KB/秒、已用时 300 秒”；不要把 npm 静默时的日志时间或整个共享缓存大小当成下载进度。Core 事件只携带数字和阶段，界面按操作标识丢弃迟到事件，完成、失败或取消后清除进度。
  - **Rust Core 命令**：`agent.status`、`agent.install`、`agent.uninstall`、`agent.installCli`，复用现有信封的取消和超时。
  - **Windows 连接桥**：`windows/tauri/src-tauri/src/agent.rs` 直接依赖 `lithe-agent-host`，用 `agent_open`、`agent_send`、`agent_close` 三个 Tauri 命令转发 fixture 里的同一套 JSON，协议、会话和取消语义仍只有共享 crate 一份。连接 ID 由界面自己生成：界面先订阅 `agent_event` 再开连接，因此不存在“事件先于连接标识到达”的竞态；重复或为空的 ID 直接拒绝，不会顶掉在用的连接。事件只发给打开它的那个窗口，不广播给其他项目；`agent_send` 和 `agent_close` 同样注入 Webview，并在同一个注册表临界区内比对连接归属窗口，所以其他窗口即使拿到 ID 也不能驱动或关闭别人的连接。连接按窗口标签登记：项目窗口销毁时把连接移出注册表并交给阻塞池关闭，移出与“正在关闭”计数在同一个临界区完成，因此随后的应用退出既看不到这条连接、也不会漏等它；退出先在同一次加锁里停止接受新连接并取走剩余连接，同步关闭它们，再以 15 秒上限等待仍在阻塞池里的关闭，而 `AgentHandle::close` 自带停止窗口并强杀进程树，这个上限只兜底“任务还没被调度”的情况。Windows 桌面外壳是 GUI 进程、没有控制台，所以共享 host 在 Windows 上以 `CREATE_NO_WINDOW` 启动适配器，避免每开一次 Agent 都弹出一个控制台窗口。适配器安装再用一个 Agent 事件通道转发共享 host 的 `agentInstallProgress`：`platform_invoke` 同时接 Git 与 Agent 两个可选通道，按事件 kind 只投给申请它的窗口；`agent.install` 与 `agent.installCli` 不下发信封超时，npm 下载可能持续几分钟、共享 host 自己以 15 分钟为界，macOS 同样不设信封超时。
  - **Windows 面板复用共享连接，不另写一套协议**：Agent 面板挂在已有的右侧工具窗里，和通知、Maven 共用同一处可调整面板，入口是活动栏按钮、命令面板命令 `workbench.showAgent` 与快捷键，可见状态存在 `settings.agentPanel`，默认关闭：只有用户点入口才会打开面板并连接 Agent，恢复布局本身不会拉起进程。面板的全部状态都来自 `windows/tauri/src/features/agent/stores/agent-connection.model.ts` 这个按窗口与项目隔离的连接单例（会话标签、消息流、工具与权限提示、上下文用量与订阅额度共用同一份模型），传输只经 `agent-transport.ts` 调 `agent_open` / `agent_send` / `agent_close` 三个共享命令。正确做法是让面板订阅这份共享模型；不要这样做：在 React 里再实现一套 ACP 状态机、每个会话各开一个连接，或用布局持久化隐式启动 Agent。输入框的引用入口有两条：`@` 打开项目文件选择器，以及从系统或项目树拖入文件；匹配规则（引用必须位于行首或空白之后、不含空白与第二个 `@`）放在 `agent-composer-mentions.ts` 纯函数里，邮箱地址和已完成的引用不会重新弹出选择器；这里有意比 AI 聊天输入框的 `lastIndexOf("@")` 检测更严格，两处机制本来就不同（那边是 contenteditable 徽章，这里是纯文本加 ACP `file://` 引用），所以没有抽成同一份。移除 `@query` 时只在该精确 token 仍存在于草稿时才切分，用户在选择器打开后继续输入的内容不会被误删。Windows 的拖入不能只靠 HTML5 `drop`：Tauri 默认开启原生拖放（`dragDropEnabled`），WebView2 收到系统文件时只发原生事件、DOM 拿不到文件，而项目树是用鼠标事件模拟拖动。所以两条路径都按落点找到带 `data-agent-file-drop-target` 的输入区，再派发 `lithe-agent-file-drop` 事件，输入区用同一个 attach 入口处理，去重与 32 个上限只有一份。落点在原生拖放与项目树拖动里还会派发 `lithe-agent-file-drop-hover`，让输入区在两条真实路径上都有拖入高亮（HTML5 `dragenter` 只作兜底）；项目树与系统拖入都把文件或文件夹按路径引用，与 macOS 的 `dropDestination` 一致。正确做法是给新的拖入目标加落点标记并同时接这两个事件；不要为了拿到 HTML5 拖放而关闭 `dragDropEnabled`，那会让文件夹打开项目和终端拖入失效。代价是面板要跟着共享 host 的事件字段演进，Windows 与 macOS 的呈现差异必须逐项真机比对。适配器与供应商设置放在面板内的设置区（`agent-settings-section.tsx`），API Key 存安全存储 key `agent-provider-api-key/<agentId>`，启动参数由 `agent-launch.ts` 按 macOS 同一套 `agentLaunchConfiguration` 规则组装，不在前端硬编码模型或权限目录。可写运行时状态（适配器安装目录等）统一从 `windows/tauri/src/platform/app-data-directory.ts` 取平台数据目录，绝不从安装目录推导：写安装目录会改动发行基线，让 Sparkle 增量更新校验失败。这个 adapter 只做路径解析，不自己创建、清理或缓存任何文件。
  - **Windows 把旧 `ai` 聊天单独设成一条能力开关**：`capabilityForCommand` 把 `agent.status` / `agent.install` / `agent.uninstall` / `agent.installCli` 归到 `agent`，把旧的 `acp_*` / `codex_*` / `ai_provider` / `_chat` 归到新的 `aiChat`，而 `windows/tauri/src/config/backend-capabilities.ts` 里 `agent: true`、`aiChat: false`。这样面板按"共享 Agent 通道是否接通"显示，没有 Windows 后端的旧聊天入口仍然显示"待开发"，不会把请求送进 dispatcher 再拿到一个 not implemented 错误。正确做法是先定义能力再接线；不要这样做：让新旧两套入口共用同一个布尔开关，或把未接通的能力默认打开。
  - **Windows 的历史标注存在平台 store**：收藏、本地标题和“已移除”是 Lithe 自己的标注，写在平台 store（`agent-history.json`），键为“Agent ID + 工作区路径”，绝不写进发行包或 Agent 的会话文件。macOS 用的是偏好存储（`MacAgentHistoryPersistence` 的 `lithe.agent-history.v1.<digest>`），两端都只存标注、不复制转录。每次修改前先重读再合并保存，避免两个窗口互相覆盖对方的标注；筛选、搜索和批量操作只作用于当前可见行。导出前先按需重放未打开的会话（这类加载不打开标签页），全部加载成功后才写用户选定的文件：取消保存对话框不写文件，超过 32 MiB 直接报错，任何一步失败都不产出半份记录。
  - **Key 和模型的传法**：API Key 经 ACP stdio 传给适配器。Responses 使用 `gateway` 的 `Authorization: Bearer`；Claude 使用公开会话参数中的原生 API Key 配置，由 SDK 发出 `x-api-key`。Codex 的模型用 `CODEX_CONFIG`，Claude 的模型用 `ANTHROPIC_MODEL` 并在会话 options 中显式提供。服务商配置里的"模型"必须传给 Agent：实测某个网关禁用了 Codex 的默认模型，不传模型时 Agent 只会回复一条网关报错。
  - **设置归属**：Agent 开关、预检、适配器与 CLI 安装及供应商配置集中在主设置窗口的 AI > Agents（2026-10 起从 Tools 移入 AI 分组，见 2026-10-15-macos-settings-hierarchy），复用设置侧栏、搜索、面包屑和共享表单控件；对话面板的设置按钮打开此分类。Agent 面板保留首次欢迎引导、会话、历史、输入和必要的配置提示，不再嵌入另一套设置导航。
  - **设置与面板的选择同步**：设置页删除独立 `@State selectedID`，使用共享 `AppModel.selectedAgentConversationID` 与面板现有选择动作；设置采用 `LitheSettingsSelect`，功能开关采用共享带标题复选框及缩进说明，聊天底栏保持菜单，任意一处选择都更新同一 ID；本机配置、自定义供应商和订阅启用后的既有选择动作也走这个入口，避免后续连接再次覆盖 UI 选择。未配置 Agent 也能切换面板标题和底栏，显示配置提示但不自动打开设置、不启动另一个已配置 Agent；已有配置通过原会话选择/连接接口处理，保留后台轮次。预检、供应商行和 ACP adapter 文本取消背景卡片，使用共享设置分组和普通表单文字；真实输入框和下拉控件保留其共享外框；共享控件边框采用 `DarculaNewUIUtil.paintRectangleImpl` 的内外圆角路径奇偶填充，普通 1pt，焦点 2pt 向外扩展 1pt，不在 Agent 页另画描边。提示条使用共享 Islands Banner 警告色和圆角，不再用 warning 透明度近似，提示条只保留文字和警告图标，设置动作集中在对话标题栏，避免在提示条重复入口。
   - **本机配置保留 CLI 所有权**：每个 Agent 通过本机配置行读取用户自己 CLI 的地址、模型和密钥（Codex 读 `~/.codex/config.toml` 和 `auth.json`，Claude 读 `~/.claude/settings.json` 和 `~/.claude.json`），生成的服务商配置绑定到该 Agent。本机模式的密钥不复制进 Lithe 的设置或安全存储；每次连接时从同一份用户文件快照读取地址、模型与密钥。修改 CLI 配置后，新连接自动采用完整的新配置；已经建立的连接保留原路由，用户可在空闲时点击刷新完成重连，不中断其他项目的轮次。需要独立配置时使用上面的自定义供应商编辑器，不改写 CLI 文件，也不改变提交信息使用的服务商选择。
   - **关闭时仍能找到入口**：工作台始终保留 Agent 的静态入口声明，首次安装没有模块配置、手动关闭后也能打开面板。模块仍默认禁用，入口读取不调用 factory，不创建连接；禁用模块的通用贡献目录和其他模块的入口规则保持原样。未选择 Agent 前始终显示欢迎页；选择后，未配置的面板显示会话输入与设置入口，用户在主设置窗口开启开关，无需修改本机配置文件。开启后复用运行时入口，按 ID 避免重复；关闭后保留面板和入口。不要把默认开关改为启用来修复发现入口的问题，否则会改变所有用户的后台启动行为。
  - **提示文案本地化**：Rust 返回的 `issues` 只决定能否安装；界面显示的原因由 Swift 按结构化状态（Node 版本、npm、CLI 版本）重新生成，这样中英文都能显示。

- **文件拖入对话框**：参考 CC GUI 普通文件的路径引用交互，原生输入框接受 Finder 和项目树的文件 URL，显示可移除标签，并支持文件选择器。一次最多 32 个引用，按拖入顺序去重；切换会话清除旧文件草稿，发送失败保留文字和引用。功能模型把引用与文字一起排队，Rust Host 用上游 ACP SDK 的 `resource_link` 发送，Agent 自己读取文件并遵守现有权限。文件 URL 是这次消息的原生上下文，不作为跨平台项目标识持久化。正确做法是发送“说明这两个文件”加两个引用；不要在 View 里读文件、复制进缓存或拼装隐式文件内容提示词。图片目前同样作为文件引用，没有缩略图或多模态字节上传；这避免了与本次需求无关的内存、大小和格式策略，后续需要图片输入时再按上游能力协商。
- **粘贴与 `@` 引用文件**：输入框获得焦点时，⌘V 先检查剪贴板：Finder 复制的文件直接作为引用附加；只有图片、没有文字时（截图、浏览器复制图片），把图片转成 PNG，通过 `FileStorage.cacheDirectory()` 写到 `Caches/<应用存储根>/AgentPastedImages/`，再作为普通文件引用发送；有文字时照常粘贴文本。剪贴板图片没有可引用的原文件，而 Agent 要在发送后通过 `resource_link` 读取，所以这是“不复制进缓存”的唯一例外。目录由 Agent 对话功能拥有，只放用户主动粘贴的图片，每次写入时删除一周前的文件；它不在 app bundle 或安装目录内，不影响代码签名和 Sparkle delta，也不登记为跨 worktree 可复用资源。字段编辑器会在 SwiftUI 之前处理 `paste:`，所以用输入框背景中的原生视图承载本地按键监听；除了焦点状态，还必须确认事件窗口和当前可编辑的原生文本视图位于该输入框范围内，视图离开窗口或卸载时移除监听。不能只依赖 SwiftUI 的焦点布尔值：切到另一个窗口时旧值可能仍为真，会把其他输入框的 ⌘V 附件错误加入旧会话。单独输入 `@` 或全角 `＠` 时，立即从项目已加载且遵循隐藏规则的文件清单中显示最多 20 个候选，不重新扫描目录，也不启动搜索模块；如果输入时初始扫描还没结束，文件清单就绪后按工作区快照版本自动刷新候选，无需重输 `@`；继续输入关键字时仍复用 Search Everywhere 的文件搜索并合并快速输入，迟到或取消的查询不得覆盖当前候选。选中后移除 `@查询` 并附加为同样的文件引用，回车、Tab、方向键与 Esc 沿用现有补全行为，不在提示词里拼路径。默认列表复用工作区内存清单，不新增文件、缓存或发行包写入。中文输入法在 `$` 键上输入 `¥`/`￥`、在 `/` 键上输入 `、`，命令补全把它们视为同一触发符，插入的仍是 `$name`、`/name`。
- **对话面板**：停靠在编辑器右侧，与 Maven 共用右侧槽位。Agent、审批模式、模型与思考强度统一位于输入框内底部，不再重复显示标题下的 Agent 名称和框外配置栏。列出的仍是已绑定服务商或 Codex 订阅的 Agent；每个 Agent 首次被选中时才建立连接，后台会话和权限提醒保持。
- **选择状态由面板直接观察**：切换 Agent 时，解析当前连接的视图必须直接观察 `AgentConversationFeatureModel`，连接内的模型与权限则由 `AgentConnectionModel` 发布。不能只观察外层 AppModel 再读取可选模块，否则选择已经改变，品牌、模型列表与发送目标仍可能停留在旧连接。正确做法是让 `AgentConfiguredConversationView` 持有观察关系，并按 Agent ID 重建连接视图；每个 Agent 的原连接和会话继续保留。不要靠通知整个工作台或重启进程来刷新选择，这会增加无关重绘或中断后台会话。代价是视图明确分为项目选择与连接内容两层；新增菜单必须继续使用同一选择源。该修复只调整内存观察，不新增文件、缓存或下载资源，也不写发行 bundle。
- **对话区的视觉与交互**：按 CC GUI 参考设计使用单行会话标题、居中的品牌标志、上下文栏和底部工具栏。不显示会话标签条，会话切换统一从独立历史按钮进入原管理页。再次 New Chat 时复用断连时的临时会话清理：删除本次连接创建、未成功发送消息且未获上游历史确认的空会话，有消息和已加载历史继续保留。空态不放进滚动列表，否则无法在剩余高度内居中。输入区按实际草稿高度增长，`AgentConversationLayout` 只向输入区提供可用高度上限，正文占据剩余空间，不再预留可拖动的固定高面板。搜索只筛选当前已加载消息，不请求 Agent 或改动历史。品牌 SVG 来自参考项目锁定的 `@lobehub/icons` 5.8.0，以静态源资源随 SwiftPM bundle 打包并携带 MIT 许可，不新增运行时下载或可复用缓存。配置选择器按参考项目的底栏设计：权限与模型入口位于输入区底部，模型弹出面板提供本地名称/ID/分组搜索、左侧共享勾选和 hover 高亮，当前选项不强制保留另一条蓝色底色；说明保留在 tooltip。权限弹出面板保留上游名称，只对说明使用界面语言。思考强度按参考界面作为模型菜单同级分组，速度及其他上游配置仍在底部子菜单，未提供时不显示。选项数量和权限语义仍以 ACP 为准，不照截图补选项。选择模型和普通配置后收起面板，Effort 连续调整保持面板打开，已生效值仍由上游确认拥有；响应期间允许预选下一轮配置，底栏呈现预选值，真正提交配置等待确认时禁止再次配置。弹出与搜索状态只在视图内保存，会话切换重建选择器以清除旧会话的弹出状态；不重建输入框或清空草稿。模型面板使用共享 `litheDropdown`，设置子选项通过 `LitheMenu(opensToSide: true)` 作为它的原生子窗口展开。共享菜单呈现器按触发行定位、在屏幕右缘向左翻转并管理关闭；不把子选项拼入主面板，也不另写鼠标全局监听或位置缓存。上下文只显示实际报告或模型匹配的历史快照；工具栏圆环与状态条在首条上报或可恢复快照出现前整体隐藏，出现后缺失才提示尚未上报，不能显示成零用量。
- **长会话的底部跟随由原生滚动容器管理**：消息区继续使用按需创建屏幕附近行的 `LazyVStack`，不为了规避卡顿把整段历史一次性展开。权限卡片通过 `safeAreaInset` 让滚动容器预留底部空间；不要把卡片放回消息滚动区外的同级布局，再同时按消息 ID 调用 `ScrollViewReader.scrollTo`。完整工作区回放证明，溢出的历史、消息定位和权限区域改变可使 SwiftUI 布局持续占用主线程；仅延后一轮定位、换底部哨兵或直接操作原生滚动位置，都不能单独消除卡点。`AgentTranscriptScrollAnchor` 只在内容、视口大小或权限占用的原生内边距改变时合并安排一次原生底部跟随，不监听懒布局估算的内容高度来继续滚动，也不向业务模型发布几何数据。视口同时观察原生 bounds 与 frame 通知：AppKit 重设 frame 可以同步改变 bounds，却不发 bounds 通知；两类事件仍按实际视口尺寸去重合并，不能依靠延长测试等待补救遗漏通知。底部计算计入 `contentInsets`，避免高权限卡片遮住最新回复；内边距由原生观察者直接读取，不请求 SwiftUI 重新测量历史。用户主动滚离底部时保持浏览位置，回到底部或发送新消息后恢复跟随；搜索暂停跟随，会话切换和卸载取消旧操作并移除观察者。该组合使用 macOS 13 已有 API，不提高最低系统版本；新系统的默认滚动锚点也在回放中通过，但无需为此维护两套按版本切换的实现。只持有视图内状态，无文件、缓存或发行资源写入。
- **滚动条属于面板，阅读宽度属于内容**：编辑页的消息和输入区使用可用消息面板宽度 80% 的居中列，但 `AgentEditorColumn` 必须放在消息滚动容器内部，并单独约束输入区；不能再用它包住整个滚动容器，否则原生滚动条会停在文字旁边。右侧轮次导航以每条用户消息为入口，上方预览用户输入、下方预览该轮最后一段模型正文；推理与工具输出不进入预览，工具行和轮次统计行仍归属对应用户轮次。当前视口交叠的轮次显示长标记，其余显示短标记；可见区域必须扣除原生 `contentInsets` 预留的权限卡片或通知空间，并直接观察内边距变化、合并刷新，不能只等用户再次滚动。完全被卡片遮住的轮次不能保留长标记。共享滚轮路由仅接管命中正文自身或其后代的事件；同坐标的独立轮次轨道和浮动命令列表保留自己的事件，包括列表已到边界时，避免误滚正文。鼠标离开后收起装饰，保留原生滚动条。只隐藏标记外观，不隐藏导航按钮的辅助功能入口；键盘聚焦时重新显示标记，鼠标离开会清除点击留下的焦点。轨道的命中区域必须避开原生滚动条，不能用覆盖整条右侧留白的透明交互层阻挡拖动。预览复用共享悬停卡片、主题和面板调整状态，不另建浮动窗口或全局鼠标监听。
  `AgentTranscriptNavigationState` 只保留视图内的弱原生行锚点，合并原生视口通知，并仅在可见轮次集合改变时发布给导航组件；不要让每次滚动更新业务模型或通过全树几何偏好重新布局所有消息。消息仍用惰性行列表，摘要分别限于 320/640 个字符；代价是预览只展示部分文字，仍须点击阅读完整轮次。用户明确点击时允许一次 `ScrollViewReader.scrollTo`，此前必须通知同一个原生滚动容器取消排队中的底部跟随；流式消息、工具和权限更新不能抢回历史位置。自动跟随仍走原生入口，不能恢复为每次输出都按消息 ID 定位。`AgentTranscriptNavigationTests` 验证摘要归属、可见轮次与排队跟随取消，`AgentTranscriptScrollTests` 的有界子进程回放验证宽面板边缘、实际导航动作、后续工具/权限和缩放。该导航仅落在 macOS 原生界面；Windows 当前聊天容器虽有限宽列，尚无对应轮次轨道。所有状态随视图释放，无文件、下载、缓存和发行包写入，不影响代码签名或增量更新。
- **进程与诊断**：启动时把 Agent 可执行文件所在目录放到 `PATH` 最前面。npm 把 `codex-acp` 和 `node` 装在同一个目录，而 Mac 图形应用拿不到登录 shell 的 `PATH`。关闭时先向整棵进程树发 SIGTERM，并记录树里的每个进程 ID，稍等后再对仍存活的进程发 SIGKILL，因为 codex-acp 的 app-server 会比外层进程晚几秒退出。API Key 模式下 Agent 意外退出时，报错里附上 stderr 最后 20 行，其中的 Key 会被替换掉；订阅模式仅显示受控错误，不附加账号工具的原始输出。

正确做法：新平台的界面通过平台适配器把 fixture 里的命令交给 `lithe-agent-host`，并把工具权限选择交给用户。

不要这样做：在 Windows React 层重新实现 JSON-RPC 协议；在打开 IDE 时就启动 Agent；取消尚未确认就解锁发送；把取消超时伪装成成功而不提示用户重连；把 API Key 通过环境变量或命令行传给 Agent；替用户下载一份他本机已有的 Agent CLI；只按连接 ID 授权 send/close 而不校验调用窗口；退出时只清空注册表，把已经交给后台线程的关闭留在未登记状态。

对话可以移入共享编辑区标签页。位置由 EditorTabOrderFeatureModel 是否包含 agentConversation 页决定，工具窗口改用同一历史列表的伸展布局；点击历史后选择同一 AgentConnectionModel 中的会话并聚焦编辑页。重复打开只聚焦已有页，不再创建标签或连接；关闭编辑页将对话移回工具窗口，保留其他文件及未保存内容。共享标签负责关闭、排序、拖动分组和活动/非活动选中样式，不另写页面标签系统。此页呈现当前会话，历史切换更新同一页的标题与消息，不为每条历史再创建独立连接。草稿文字与附件由连接模型按会话保留，编辑器的命令补全/焦点仍属视图；位置切换和标签换焦点不清空草稿，切换会话恢复各自草稿，New Chat 使用空草稿并保留原会话的未发送内容。输入写入绑定和补全/发送同步更新草稿，避免等待视图销毁后的 onChange。
拖动入口：工具窗口渲染器通过 WorkbenchModuleUIRegistry.Renderer.openInEditor 声明“内容可作为编辑页”，宿主拖放与右键菜单只读取该声明，不按工具名特判。ToolWindowDragState 仅对声明了 openInEditor 的工具，在指针落在工作台内且不属于左右三分之一或底部三分之一停靠带时判为编辑区落点；松开即调用 showAgentChatsInEditor，不改变工具窗口停靠位置，未拖动的点击仍是切换显示。返回侧栏沿用编辑页关闭和标题栏位置按钮，侧栏布局保持原样。
编辑页布局：编辑页与工具窗口共用 `AgentChatHeader` 的单行标题及新建、位置、搜索、历史和设置菜单。消息内容、紧凑活动摘要与输入区按剩余消息面板宽度的 80% 居中，原生滚动容器保持整宽，输入框保留左右8pt内边距。框内上方直接显示默认两行、自适应增高的书写区；底部依次放附件“＋”、Agent、全部配置，以及靠右的订阅额度和发送按钮旁唯一的会话详情入口。收到真实用量后入口显示上下文圆环，未上报时显示信息图标；两个状态保持同一位置，顶部不再重复放信息按钮。会话详情通过共享 `litheDropdown` 按需展开，复用 `AgentEditorDetailsPanel` 的上下文构成与会话/Token 统计内容；窄面板也能访问全部已有统计。会话区总宽度不少于 1028pt 时，还可在设置菜单切换 264pt 右侧详情栏；这个产品断点保留消息可用空间，不限制正文列最大宽度，不再额外渲染统计页签。
唯一的会话详情入口同时展示 `AgentContextPanel` 的上下文构成，以及轮次、模型调用、TTFT/TPS、Token 与缓存命中、工具及授权耗时。内容在同一面板内滚动，未上报上下文时显示未知说明并保留统计；标题关闭按钮、Esc 和外部点击沿用共享弹层行为。数据仍来自已有聚合与持久化记录，不增加请求，不推算缺失值。弹层跟随当前会话，切换会话、隐藏工具栏或拆除锚点时关闭。两行书写区和单一底栏位于同一边框内；底栏与附件的高度一起参与自适应输入区的最小尺寸和可用高度上限计算，删除的顶部条不再参与预留空间。

Agent 回复按块级 Markdown 渲染（标题、列表、引用、表格、分割线、代码块），行内语法交给 Foundation。解析结果按原文缓存，回复视图按原文 `Equatable`，避免流式更新让已完成的回复重新解析。消息悬停显示复制按钮，标题栏菜单提供“复制对话”，导出用户消息、回复和工具单行摘要，不导出推理内容。加载历史时 Agent 会逐条重放，转录区在 `isLoading` 期间不构建行，重放结束一次渲染，避免 O(n²) 的中间状态渲染。行内加粗、斜体和代码在渲染前换成打包的 Inter-SemiBold、Inter-Italic 和 JetBrainsMono 显式字体，并清除行内呈现意图；让 SwiftUI 在自定义 Inter 上合成粗体/斜体会丢失系统中文回退，中文显示为方块。推理内容与工具组同一样式：单行摘要加圆角卡片，卡片按内容增高，超过 240pt 在卡片内滚动并在流式输出时跟随到底部，内容复用回复的 Markdown 渲染（12pt）。工具证据（输入、内容、结果）改为可换行的代码块，不再给每段套双向 ScrollView：双向滚动会把文本横向偏移导致左侧被截断，`maxHeight` 也让一行内容占满空白。展示层只识别各 Agent 通用的 shell 字段：输入里的 `command`（字符串或 `[shell, -c/-lc, 命令]`）与 `cwd`/`workdir` 显示为“$ 命令”和工作目录，结果里的 `formatted_output`/`aggregated_output`/`stdout`/`output`、`exit_code` 与 `stderr` 显示为输出、退出码和错误输出；其余结构保留原文。终端内容只有不透明的终端 ID，不显示；与解析出的输出重复的内容块去重。超过 12 行折叠，提供“显示全部”和悬停复制。

Markdown 表格的表头和正文必须完整展示：长内容在单元格内换行并撑开行高，整表过宽时保留横向滚动及共享滚动条。横向滚动容器不会提供有限宽度，单纯给文字外层设置最大宽度会先按单行测量再截断；`AgentMarkdownTableCellLayout` 因此先取得不超过 320pt 的宽度，再向文字传入该宽度并测量全部高度。短列继续按内容占宽，不把所有列强制拉到 320pt。只取消行数限制或添加 tooltip 无法满足完整阅读要求；代价是长内容增加表格高度，宽表仍需横向浏览。`AgentMarkdownTests.tableCellsGrowToShowFullHeadersAndBody` 使用实际原生渲染覆盖深浅主题、窄宽视口、长中文、加粗和无空格标识符，防止表头或正文退回省略显示；布局不向业务模型发布几何状态，也不新增磁盘资源或 bundle 写入。

复制单个表格时提供 Markdown 和 HTML 两种剪贴板表示，去掉行内样式后必须转义字面 Markdown 语法、反斜杠与 HTML 实体起始符，单元格换行和边缘空白使用数值字符引用保留，避免拆成表外段落或被表格解析器裁掉；例如代码单元格中的 `**literal**` 再次粘贴渲染后仍保留星号，不能变成加粗文字。中文加粗补偿同样不能重新解释转义或实体生成的星号；链接标签保留 Foundation 的解析结果，不能跨两个独立链接配对字面 `**`，否则 `src/**/foo.swift` 一类路径会丢失星号。文件链接只解码一次：`file://` 已有解码后的 `URL.path`，不能再调用百分号解码，也不能从这个路径删除 `#L` 锚点，否则文件名中的 `%20` 或 `#` 会改变；锚点读取自 URL 的独立 fragment。`AgentMarkdownTests` 通过表格导出后重新解析、实体星号和特殊文件名链接验证这些行为，`AgentComposerPasteTests` 挂载真实输入框验证窗口与编辑器归属。上述处理只使用内存，不新增磁盘资源或 bundle 写入。

转录行抽成按数据比较的 `AgentTranscriptRows`：外层视图会随额度、会话列表、统计等任意发布重新求值，行列表只在消息、已完成轮次、搜索词、推理展开状态变化时才重新分组和比对，滚动时不再被无关发布打断。工具调用参照 Claude 的展示：转录里是一行浅色摘要（按 ACP `kind` 统计“运行了 N 个命令，读取了 N 个文件”），展开为圆角列表，每行一个调用、点开看证据；长列表先显示 8 行。转录内的工具组不再嵌套纵向滚动视图（每组一个 NSScrollView 是滚动卡顿来源），只有活动弹窗保留四行高度的内部视口。订阅登录不经过本地代理，上下文明细和模型调用统计的说明在订阅模式下改为解释原因，而不是提示开启设置。

编辑区内消息内容与输入区共用 80% 居中内容列，输入框的左右 8pt 内边距包含在列内。`AgentEditorColumn` 通过 SwiftUI 的局部布局协议直接从父级尺寸计算列宽和居中位置，不把连续缩放结果写入状态；标题栏和消息滚动容器保持面板整宽，原生滚动条仍在面板右缘。消息滚动区会扣除原生滚动条自身的占位，因此列宽以各自实际可用宽度为准；原生回归从 SwiftUI 内容文档测量列宽与居中位置，不能用可能带额外留白的裁剪视口宽度替代。未配置页也只约束正文与输入框，标题工具栏保留整宽，否则其最小宽度会把窄列撑偏。工具窗口仍使用自身可用宽度，并为右侧导航保留间距。固定 716pt 上限和固定左右 90pt 留白均被否决：用户要求列宽随窗口按比例变化，宽窗口不应留下过多空白。80% 来自用户明确的构图要求，不是 Community 公开 AI 插件常量；代价是超宽窗口的文字行会随面板增长。

切换图标使用 Community 915c3c26 的 expui/general/previewVertically.svg 及 dark 变体，16×16；按钮尺寸、选中/hover 与工具提示复用共享 owner。图标作为固定构建资源随包只读发布，不引入运行时下载或缓存。Community 提供通用标签/图标/工具窗口规则，AI 插件的聊天迁移页面未在公开仓库找到，不把当前页面组合与字号布局冒充它的私有源码常量。

Agent 产品文案在界面层按 SwiftUI 注入的 locale 解析。Foundation 的 String(localized:) 在模型或提前构造的字符串中可能跟随系统语言，导致英文标题配中文说明；会话模型、文件错误与应用生成的配置提示因此只保留英文资源键，AgentLocalization 显式选择当前语言的 lproj，再完成格式化。启动/认证空态、设置、模型选项说明、运行状态、用量和额度提示都经过同一入口。New Chat 失败提示保留原因的英文键，到显示时才组合，切换语言不会留下旧语言文案。上游消息、模型名称、未知诊断、历史标题与导出内容保留原文，不能反向猜译用户文字。启动空态复用 settingsStrongFont、smallFont、EditorEmptyState.label、Banner.gap 及小号 ProgressView，避免独立字号和颜色；其他 Agent 空态一起使用这些规则。

标题栏的设置图标使用已有 Community settings 16pt SVG 和共享 `LitheMenu`。菜单保留重命名、复制整段对话、可恢复删除、Agent 设置与显示工具栏；编辑页另有右侧详情栏开关。重命名和删除继续由 `AgentHistoryFeatureModel` 管理，忙碌、加载或配置期间禁止删除。Show Toolbar 只控制框内上下两条操作栏；隐藏时销毁浮层锚点，保留文本、草稿与回车发送。

模型选择入口恢复到输入框内底栏，与 Agent、审批模式同行。全部配置复用同一个 `AgentSessionSelectors`，按上游目录展示并等待确认；加载期间仍显示正在准备设置，响应期间仍允许预选下一轮。不能为了压缩宽度隐藏模型选项或移除配置能力。

### 响应期间预选下一轮配置

macOS 的审批模式、模型和思考强度在等待、推理、输出、工具执行及停止确认期间继续允许点击。用户此时选择的是下一轮的配置；正在运行的一轮以及尚未处理的工具授权继续使用原配置。底栏立即显示预选值，悬停说明“修改将在下一轮对话生效”。空闲时的直接修改仍等上游确认后才改变显示。

参考 [CC GUI 的输入栏选择器](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/blob/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/components/ChatInputBox/ButtonArea.tsx)在生成期间继续提供模式和模型回调，以及 [发送入口](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/blob/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/hooks/useMessageSender.ts)读取用户选择。Lithe 保留已有共享 Host 的忙碌边界：响应期间不发送 `setConfigOption`，只由当前会话的功能模型保存每个选项最后一次预选；重新选择已确认值取消该项预选。视图不另存配置队列，也不改本机 CLI 配置。

正常结束、取消确认或本轮请求失败后，功能模型先提交模型，再按最新上游选项顺序提交剩余配置，每个请求确认后才提交下一个。换模型可能改变思考强度和速度目录，因此每一步都重新校验；拒绝、发送失败、能力消失或返回值未确认时，清除剩余预选，恢复已经确认的值并显示配置错误。等待全部确认期间继续阻止发送，不自动提交用户草稿。停止请求本身不能解除等待，也不能让新配置进入尚未结束的一轮。

正确做法：当前轮使用模型 A，用户选择 B 和 High；本轮结束后确认 B，再用 B 的最新目录确认 High，下一条消息才使用新值。不要这样做：仅移除控件的禁用条件并立即请求 `session/set_config_option`，或把本地预选直接覆盖到已确认配置中；前者可能影响当前工具授权且会被 Host 拒绝，后者会把失败当成成功。

预选按项目、Agent 和会话隔离；切换标签不丢失，后台完成只提交该后台会话的配置。新的上游配置或模式通知只更新已确认状态，不覆盖用户的有效预选。断连清除未确认预选和请求关联，迟到确认不能恢复它们。代价是本轮结束与下一轮发送之间可能多出数次配置确认，且不兼容的新模型选项需要用户重新选择。该能力目前只接入 macOS；Windows 不据此标记完成。状态仅保存在会话内存中，不新增下载、缓存或工作树可复用资源，不写发行包，不影响代码签名和 Sparkle delta。

### 思考、计划、斜杠命令与模式通知

除自行附加的项目上下文在用户历史和自动标题中的呈现过滤外，共享 Host 把 ACP 会话更新（`SessionUpdate`）原样转发，以前 Swift 只消费消息、工具、标题、配置和用量，其余直接丢弃。参考 CC GUI 的可折叠思考块、计划面板与 `/` 命令补全后，macOS 现在消费下面四类标准更新；Host、C ABI 和 fixture 形状都不变，只在 fixture 中补样例并由 Rust 测试确认它们能被官方 SDK 原样往返。

- **思考（`agent_thought_chunk`）**：存为独立的 `thought` 角色消息，不并进 Agent 回复。流式缓冲按角色记录，角色切换先刷新上一段，所以“思考 → 回复 → 工具 → 思考”保持原顺序。只有正在流式输出的最后一段思考默认展开，后续回复或工具到达后自动收起，用户手动展开的状态保留；搜索时临时展开匹配的思考，优先于已有的手动折叠选择；搜索期间不允许再次收起命中文字，清空搜索后恢复手动选择，不把搜索结果写回折叠偏好。手动偏好由 `AgentTranscriptView` 在视图局部内存中按会话 ID 与消息 ID 保存，再以绑定传给思考行；搜索先过滤消息，会移除并重建行，因此不能让行内状态成为偏好的所有者。切换会话保留各自选择，关闭会话或移除实际消息时释放对应偏好，销毁对话视图时一并释放；不写入功能模型、共享 Host、历史文件或安装目录，不影响代码签名和 Sparkle delta。`AgentThoughtTranscriptTests` 直接挂载实际对话容器，通过原生鼠标事件和完整渲染快照覆盖搜索移除/重建、命中时临时展开和会话切换。导出 Markdown 用引用块写出思考，便于和回复区分；历史消息数仍只统计用户与 Agent 回复。活跃思考块的标题显示“思考中…”，底部等待行改为“回复中…”并保留本轮计时，避免重复提示；取消时仍显示“正在停止…”。
- **计划（`plan`）**：ACP 规定每次都发完整计划，所以整体替换，不做合并；空列表清除计划，格式错误的更新忽略，最多保留 100 条。计划条状态只认 `pending`、`in_progress`、`completed`，未知状态的条目丢弃而不是猜测。点击底部“任务”打开计划与进度；没有计划时显示“暂无任务”，不把工具调用充当计划。`session/load` 回放会自然恢复计划。
- **斜杠命令（`available_commands_update`）**：按会话保存上游列表，最多读取前 200 条；同名命令只保留首条定义，保证命令行身份唯一。断连时清空每个会话的旧命令，重连加载后等待新进程重新上报，避免显示已经失效的能力。输入框以 `/` 开头且命令名中还没有空白时弹出过滤结果，前缀匹配排在包含匹配之前；选择后只把 `/name ` 填入草稿，命令文本仍作为普通 prompt 原样发送，由 Agent 自己解释。实测 codex-acp 1.13.1 把 Skill 以 `$name` 形式放进同一个命令列表，而它的命令解析会跳过 `/$name`，Skill 需要以 `$name` 提及。因此名字以 `$` 开头的命令补全为 `$name `；输入 `$` 只列 Skill，Agent 没有上报 Skill 时 `$` 仍是普通文字。Lithe 不扫描 SKILL.md 或命令目录，也不内置命令表，避免和 Agent 的真实能力不一致。方向键和 Tab 导航依赖 macOS 14 的 `onKeyPress`；macOS 13 保留鼠标选择和 Return 补全。Return、Esc、方向键与 Tab 共用视图局部的补全状态，Return 在命令名未完整时只补全、完整时发送；Esc 先关闭补全，再次 Esc 才停止回复，编辑草稿后重新显示匹配。补全高度由输入区内部的局部布局容器按剩余空间限制，先保留默认两行可编辑文字；最小输入区放不下一整行命令时，列表浮在输入框上方，通过锚点偏好在整个对话布局中绘制，让鼠标点击范围不被较小的输入面板限制；沿用工作台悬停提示的局部 overlay 模式，不新增全局位置状态或鼠标监听。输入区的最小高度包含上下栏、可编辑行和外边距，附带文件时再预留附件行；这个值只在附件有无改变时通过视图偏好更新，不跟随拖动逐帧发布。不要让固定高度的命令列表参与分隔条的最小尺寸计算，也不要把逐帧几何尺寸发布到会话模型。
- **模式通知（`current_mode_update`）**：Agent 自己切换模式（例如退出计划模式）时，只更新 `category == "mode"` 且包含该值的配置选项，不向上游回发设置请求；选项中不存在的模式 ID 忽略，不显示原始 ID。
- **即时通知（`notice`）**：共享 Host 启用固定 SDK 的 `unstable_session_notices` 能力，并声明 `clientCapabilities.session.notices: {}`，让适配器通过独立事件发送警告。macOS 每个会话只保存最新一条通知，用现有 `LitheBanner` 展示和关闭；通知不计入回复、历史导出或轮次统计，下一条 prompt 成功提交及断连时清除。上游通知字段限制为标题 256 字符、详情 4096 字符，未知严重程度和空标题忽略。

Claude ACP 0.81.2 会在默认 Auto 不可用时回退到 `acceptEdits`，但把启动警告延迟到第一次 prompt 才发送。用户可能此前已确认切到 Plan，所以仅把通知从聊天消息移出来仍会误报。该版本没有通知错误码，因此只在 `claude-acp` 连接中识别结构化 warning 标题 `Auto mode unavailable`，结合 Agent 已确认的模式决定是否仍适用；模式不再是 `acceptEdits`，或已确认切换模型，就清除这条通知。配置预选、请求尚未确认和失败都不能把现存有效警告清掉。通知先于会话创建/加载确认时，确认配置后再核对。其他通知保留原内容和严重程度，不能凭回复正文里的英文句子猜通知类型。依据是上游固定版本的 `src/session-mode.ts` 与 `src/session-notices.ts`；不修改用户已安装适配器、不升级依赖版本。

正确示例：用户在首次发消息前切到 Plan，迟到的 Auto 启动警告不会成为聊天回复，也不会声称当前仍在 Accept edits。不要这样做：每次点击选择器立即删掉警告，或按英文字符串清理所有回复；前者会掩盖配置失败，后者可能删除模型真正回答的内容。代价是这个兼容识别依赖固定适配器的结构化标题，升级时必须复验；Windows 尚未接入共享 Host 对话 UI，不因此标为已实现或已验证。

配置请求处理中收到的新降级通知先保留，等同一 token（请求标识）的配置结果或失败确认后再核对实际模式。上游选择 Auto 或换模型时可能先通知降级、随后发布配置；不能用旧的 Plan 值提前丢掉这条新警告，也不能因随后确认新模型就清掉它。等待期间如果同一会话收到更新的有效通知，旧的暂存警告立即失效；例如先降级警告、后工具错误，配置成功或失败都必须保留工具错误。反过来先工具错误、后降级警告时，新警告仍等待配置结果，再按实际模式显示。格式无效或其他会话的通知不改变这一顺序，避免配置重放把旧警告变成“最新通知”。旧通知仍由已确认的配置变化清理。

通知和权限卡片共用直接挂在 `ScrollView` 上的 `safeAreaInset`（为底部卡片预留原生滚动空间），优先显示需要用户操作的权限卡，答复后再显示仍有效的通知。两张卡叠加时，窄面板中可能占满消息视口，所以不能直接堆叠；通知标题最多两行、详情最多三行，悬停可读完整原文。原生回放等待可观察的底部跟随结果再断言，不用一次布局回调代替完成信号。

原生 `/model` 或模型拒绝后的上游切换没有本地请求 token，仍会依次发出模式降级、新通知和完整模型配置。连接模型因此在观察到 Auto→Accept edits 时记录转换前的通知身份；紧接着的第一份完整配置只清理转换前的旧通知，保留转换中新产生的通知，然后释放转换记录。记录按会话隔离，新消息提交和断连也清理，不新增计时器或持久化数据。正确做法是把本次降级原因保留到用户能看到，同时让后续再次换模型清掉它；不要把“发生模型变化”直接等同于“屏幕上的所有通知都已过期”，也不要永久豁免这条警告。

正确做法：新的更新类型先在 fixture 中加入样例，让 Rust 往返测试证明它是合法 ACP，再在平台功能模型中解析。不要这样做：在视图中直接解析原始更新；为了显示命令列表而自己维护一份 Claude 或 Codex 命令表。

这些状态只保存在会话内存中，不新增日志、下载、缓存或可复用工作树资源；安装目录和 bundle 仍只读，不影响代码签名和 Sparkle delta。

### 每轮耗时与上报 token

发送后用单调时钟（不受系统日期调整影响的计时源）开始测量，包含建会话、加载历史、工具执行和权限等待。界面状态旁的秒数表示本轮已经过的时间，不声称是模型内部推理时间。只让可见等待行每秒重绘，不每秒发布整个会话。正常完成、请求失败和断连固定耗时；取消仍等上游确认才结束。每轮末尾保留统计，标签切换不会重置，失败发送和历史回放不编造记录。

状态文案必须使用已经观察到的进度。准备会话显示“正在准备对话”，发送后尚无新输出显示“等待 Agent 响应”；只有收到思考片段才进入推理状态，普通回复和本轮活跃工具分别显示输出与执行状态，待授权和停止状态优先。已加载历史中的未完成工具不算新一轮的活跃工具。推理片段行已经显示实时标题时，状态行保留原有“输出中”提示，避免重复的“思考中”标题。

固定的 `codex-acp` 1.13.1 在未协商类型化错误扩展时，已经通过 `session_info_update._meta.codex.error` 上报 `willRetry` 和 `turnId`。该更新通常没有标题，不能先要求 `title` 再读取元数据。macOS 功能模型只在当前会话仍响应、未停止且上游明确 `willRetry: true` 时显示“Agent 正在重试”；不把原始错误、请求地址或重试次数从文本中猜出后放进界面。新的有效输出或工具事件清除重试显示，本轮完成、失败或断连后清理；已观察到的上一轮重试 ID 不得污染下一轮。只保存必要状态和有界的当前/前一轮 ID，不保存原始错误正文。这些字段仍通过共享 Host 原样透传，Windows UI 尚未完成同等消费，不能把 macOS 测试写成 Windows 已验证。

正确做法：收到明确重试通知后改变当前状态，继续保持会话忙碌，用户仍可停止。不要这样做：仅凭静默 180 秒就显示“正在重试”，或为了改善文案缩短整个请求期限、重新发送 prompt、读取供应商私有日志。等待长只能证明还没有新进度；重试和网络恢复继续由上游拥有，正常轮次无绝对上限，十秒取消确认边界保持不变。状态仍只在会话内存中，未新增缓存、下载、日志或发行包写入，不影响签名和 Sparkle delta。

正常轮次与用户授权不设总时长限制。连续五分钟没有新的实际进度时，共享 Host 只发出静默提醒；继续等待不重发请求，停止仍遵循十秒取消确认。授权等待通过 SDK 拥有的独立任务处理，不能阻塞后续消息、其他会话或连接退出。具体取舍见 [长任务与静默提醒](../bug-fix/2026-10-08-agent-turn-lifetime-and-quiet-notices.md)。

Host 发出 `turnCancelling` 时已经拒绝该会话的待处理权限。macOS 收到事件后必须立即清空该会话的授权卡片并刷新权限提醒，不能只依赖用户点击停止时的清理，否则自动超时后仍会显示失效的授权按钮。其他会话的授权和提醒继续保留；正在停止的会话仍保持忙碌并继续计时，直到收到终止事件。功能模型测试直接注入取消事件，覆盖权限队列清理、迟到权限忽略、取消完成前禁止发送，以及后台会话取消不影响当前会话。

共享 Host 开启官方 SDK 已有的可选 `usage` 解析，并随 `turnFinished` 原样透传。缺失、空值或非法数据不能阻止这一轮结束。输入/输出使用确切上报值，悬停显示总量、推理及缓存明细，没有上报就只显示耗时。

不要用上下文百分比、文字长度或订阅额度推算 token，也不要把不同供应商的报告统一称为单轮累计账单。[固定的 codex-acp 1.13.1](https://github.com/agentclientprotocol/codex-acp/blob/v1.13.1/src/CodexAcpServer.ts) 使用 `lastTokenUsage` 生成完成报告，[ACP 自身也有单轮与会话口径冲突](https://github.com/agentclientprotocol/agent-client-protocol/issues/1860)。正确做法是标注“Agent 上报，统计口径由 Agent 决定”，并保留上游数字；不要跨轮累加或做差来制造总消耗。

每轮回复下方只常驻三项：复制该轮最终回复、用量胶囊（耗时 · 上报 token）、完成时间（当天显示 `HH:mm`，跨天显示 `yyyy-MM-dd HH:mm`）。平均首字延迟、输出速度、输入/输出、缓存、推理、工具与模型调用次数只在悬停胶囊时以状态卡片显示，避免每轮都堆叠一行明细。完成时间用墙钟 `Date` 记录，仅作标签；耗时仍用单调时钟计算。结束消息自己的悬停复制按钮隐藏，避免同一回复出现两个复制入口。

统计仅在会话内存中保存，不新增日志、下载或缓存资源。安装目录和 bundle 继续只读，不影响代码签名和 Sparkle delta。成功重新加载上游历史会重建消息，因此不会把旧本地测量绑定到新回放的消息上。

### 从编辑器和项目树添加文件

两个右键菜单共用 `AgentFileAttachmentMenu`，在打开时读取当前 Agent 和缓存会话，不为罗列候选启动其他进程。快捷项明确写出 Agent 名称；另一入口在同一子菜单内按已配置 Agent 的分组标题列出新建会话和已知历史的标题、短 ID 与当前勾选。共享右键菜单只有一层子列，因此不再嵌套 Agent 子菜单，也不为此扩展共享控件。被右键的编辑标签决定文件，不借用活动编辑器；项目树按当前多选收集普通文件，不展开目录。

应用模型在点击前捕获工作区、Agent 和已有会话标识，模块启动后再次检查工作区与配置。模块负责按 Agent/会话隔离草稿、原子校验和去重；呈现层只负责菜单、附件和聚焦。正确做法是右键 `A.swift`、选择 Claude 的已有会话，再保留其输入文字并加入附件；不要根据当前选中行推测目标，也不要把文件路径拼入提示词或自动发送。

未创建会话的草稿在 `sessionCreated` 时转交新标识；等待期间选择其他历史，迟到的新会话结果也只能带走自己的草稿。加载失败保留目标草稿，正在运行的会话只增加未发送上下文，不停止或续发。绑定附件不再被视图的会话标识变化清空，防止首次启动后把刚附加的文件删除。关闭会话释放它的草稿，位置切换不释放。上游尚未持久化的空会话断连后保留草稿，重连准备时更换会话标识，不能对不存在的 rollout 发起历史加载。附件沿用原本磁盘文件 URI，不新增副本、缓存或发行包写入；脏编辑器内容只提示先保存，不能代用户保存。

放弃两个永远并列的 Codex/Claude 菜单项，因为多个同类 Agent 或多会话时仍然不明确。也不按最后使用的供应商默默转发：显示具体目标多一次选择，但避免把上下文送到错误会话。已知历史来自当前连接，不在右键时联网搜索完整历史；未载入的会话可先从历史页打开，再成为可选目标。

## 考虑过的备选方案

### 始终展示详细统计和重复的 Agent 标题

框外配置栏、统计页签和第二行品牌标题会分散聊天入口，并占用窄面板的正文空间。恢复原单行标题、紧凑活动摘要和框内配置；新增能力放在可点击的上下文与会话详情入口。代价是详细统计需要一次点击，但完整数据及编辑区聊天能力仍保留。

### Codex 直接复制 Claude 重放，或只设置 CODEX_CONFIG

前者会在原生重试之外再增加循环，可能重复工具并放大调用次数；后者被固定
`codex-acp` 1.13.1 的 `mergeGatewayConfig` 覆盖。上游最新公开实现仍覆盖整个
供应商表，单纯升级不能证明预算已生效；点号字段与整个表混用又依赖原生无序
覆盖的应用顺序。隔离或改写用户 `CODEX_HOME` 会改变 Skills、MCP、历史和指令，
手改已安装适配器则破坏安装基线并被重装覆盖，均未采用。

当前复用完整原生 App Server，只在公开配置边界补缺失字段，并保留 AIR 遗失的
结构化错误；代价是每个 API Key 连接多一个 Node 转发进程和独占临时 helper。
普通 429 的原生恢复缺口只在无工作时补齐，已有输出和工具绝不使用此重发。
正确做法是每次升级用本地 Responses 服务核对真实请求次数、流式恢复和清理；
不要仅检查写入了数字五，或把原生重试与 Host 重试分别当成五次。

### Codex 历史上下文由原生恢复通知补齐

`codex-acp` 1.13.1 的历史加载固定传 `thread/resume.excludeTurns: true`，且只在 prompt 开始后安装用量事件处理器。检查上游 v2.2.2 仍没有可供 Lithe 直接调用的历史用量接口；单纯升级不能证明问题解决。Codex App Server 的公开 `thread/resume` 完整恢复路径会发出 `thread/tokenUsage/updated`，其中 `last.totalTokens` 与 `modelContextWindow` 是原生实际报告，累计 `total` 不是上下文占用。

Host 复用既有 `codex-config-relay.cjs` 和当前 Codex 子进程：每次 ACP 加载先创建随机票据，relay 通过连接独占的回环 HTTP 通道取得票据，只对这个已登记的原生恢复取消 `excludeTurns`；收到匹配的恢复响应后，将一次原生用量通知按票据交还 Host。Host 在加载完成前以标准 `usage_update` 事件转给消费端，附 `_meta.lithe.contextUsageSource: history`，界面只显示百分比和已用/容量，不展示“上次上报”后缀或额外标题；来源标记仍留在内部状态用于恢复与回归验证。历史恢复兼容通道不修改模型、审批、路由、用户配置或原生计数；订阅的重试配置和错误保持原生行为。开启模型调用统计时，既有中继另检查原生 account/read 的工作区发现结果，仅普通后台且 NO_CONSTRAINT 允许进程级本机推理地址；受限、未知和失败保留原生直连，账号变更关闭已观察的连接。统计决策见 2026-10-13-agent-model-call-observation.md。普通新建、分叉及未登记的恢复照传。

兼容通道属于单次 Agent 连接：只绑定 IPv4 回环随机端口，路径使用随机能力令牌；只接受 POST、最多 4 KiB JSON、32 个并发加载票据/连接，每个 HTTP 连接最多 2 秒，relay 请求 1 秒。加载完成后最多额外等待 500 毫秒，缺报告继续使用原有未知/缓存策略；失败、取消、替换加载和连接退出都释放票据与监听器。每条报告只可消费一次，过期票据、错误会话、无效容量和新轮次之后的通知不能变为历史用量；标准 ACP 已上报时优先，包含明确无效报告。数据只在内存中存活，临时 launcher 仍走既有系统临时目录生命周期，不写 bundle、已安装适配器、CLI 或新增缓存路径，不影响签名与 Sparkle delta。资源注册继续使用不可复用的 `codex-retry-relay` 排除路由。

不采用第二个 App Server 探测同一线程：它会与现有连接产生 active-writer 锁冲突，也会重复初始化运行时。直接解析私有 rollout 文件、静默发送 `/status` 或再调用模型同样没有必要。代价是旧版历史完整恢复多一次原生历史物化，以及一个短生命周期的回环元数据通道；当适配器提供并验证了完整的 ACP 历史用量恢复，应移除此兼容路径，继续保留标准上游报告优先。

### 两端各用平台语言实现 ACP

界面开发起步更快，但连接、取消、权限和进程树清理都要写两遍，长期维护成本高。社区的 Swift SDK 也会带来第二套协议栈。

### 直接修改 Agent 历史文件来支持收藏、重命名和删除

这样看似能复刻参考项目的全部动作，但会让 Lithe 再实现各 CLI 的私有目录、文件格式、并发写入和索引，绕过 ACP 的所有权边界。当前采用 Lithe 自己的轻量注释以及可恢复隐藏，代价是 CLI 本身的名称和记录不受影响；未来 ACP 提供对应正式能力时再评估迁移。

### 直接读取 `~/.codex/archived_sessions` 或升级 codex-acp 获取归档历史

直接扫描 Codex 私有目录能省掉一个进程，但会让 Lithe 依赖未公开的 rollout 文件格式和索引，也违背“界面不扫描 CLI 文件”的边界；自己移动文件实现取消归档还可能与 Codex 并发写入冲突。升级 codex-acp 暂无可用的归档过滤或取消归档能力。当前使用 Codex 官方 App Server 协议，代价是每次刷新归档列表会短暂启动一个 Codex 进程；若 ACP 或 codex-acp 将来提供正式的归档能力，应迁移到 ACP 并删除该探针。

### 整体复用 Codeg

Codeg 是一个完整的 ACP 产品，可以参考，但它的工作台、状态和发布方式不适合嵌进 Lithe。直接用官方 SDK 可以复用协议实现，同时保留 Lithe 自己的模块生命周期。

### 项目失活时结束会话

这是上一版的做法，但点一下另一个窗口也会结束正在进行的对话。它不符合"会话属于项目"的使用习惯，已经撤回。

### Lithe 自带 Node.js，或用 `npx` 按需拉取适配器

Zed 就是这么做的。但会装 Agent 的用户本机通常已经有 Node。自带 Node 会让安装包变大，也多出一份需要维护更新的运行时。`npx` 会在第一次打开面板时悄悄联网下载，用户不知道装了什么。因此只检测 Node，不自带；适配器由用户点击后才安装，而且固定版本。

### 用户自己用 `npm -g` 装适配器

多数用户不知道"适配器"和 Agent 的命令行工具是两个东西，比如装了 `claude` 不等于装了 `claude-agent-acp`。全局安装还可能碰到权限问题，版本也不受控制。

### 取消超时后结束会话，或定时重发取消

定时重发取消针对单个适配器缺陷，不能成为通用协议策略，因此不采用。单纯超时结束并清空会话会丢上下文，也不采用。当前选择保留记录、显式报错并重连加载的有界恢复：代价是重启连接，但能保证下一轮不与未结束的旧轮混在一起。

曾使用十分钟整轮上限保护完全不返回的请求，但真实编码任务会持续执行超过这个时间，导致正常工作被强制中断，因此已移除。静默只触发提醒；用户停止、上游明确故障、连接退出和会话关闭仍有各自的取消与清理边界。

### Claude 使用通用 gateway、手工修改适配器或另建 HTTP 代理

Claude ACP 0.81.2 的 gateway 模式会将 `ANTHROPIC_AUTH_TOKEN` 设成占位值 `acp-proxy`；0.84.0 仍使用同样逻辑。原生 CLI 请求头实验显示它与真实 `x-api-key` 同时发送，而部分服务商优先校验 Bearer，结果是有效密钥也收到 401。额外自定义 Authorization 未能覆盖占位值，单纯升级同样无法消除此原因。

上游已经公开 `NewSessionMeta.claudeCode.options`，且恢复会话同样接受它。实测不走 gateway、通过这条接口传 SDK 原生 API Key 配置时，同一固定适配器能够完成回复，只发正确的 x-api-key。因此采用此接口完整复用上游 Agent、权限、工具、取消和历史；不修改下载后的第三方文件、不维护供应商专用分支、不增加本地 HTTP 代理。代价是凭据路由需要在每次新建和恢复会话时携带，升级适配器时必须验证这条公开扩展。

正确做法：在共享 Host 的 `session_routing` 中生成两层一致的会话配置，并让新建、历史恢复共用它。不要只清理启动环境或只给 session/new 配置；用户 settings 后加载会覆盖环境，历史恢复也会重新创建 SDK Query。手工修改用户级 npm 包会被重装覆盖，新增代理则增加本可避免的监听端口和生命周期，不采用。

路由仅在连接内存中保存，不产生下载、缓存或生成资源，工作树复用清单无需新增资源；不写发行 bundle 或安装目录，不影响代码签名和 Sparkle delta。

### 环境变量传 Key、或把 `CODEX_HOME` 指到 Lithe 目录

`OPENAI_API_KEY` 这类环境变量只适用于官方地址，也更容易泄露。隔离 `CODEX_HOME` 会让 Agent 读不到用户自己的 MCP 服务器、Skills 和全局指令；而一旦设置了网关，请求本来就不会用到用户的账号登录，所以没有必要隔离。

### 用 npm 日志或另写下载器提供进度

删除一个硬编码的旧模型名无法适应下一次模型变化，按描述为空过滤会误伤合法选项，固定新模型名会绕过上游推荐。上游 [codex-acp 的 AIR 扩展](https://github.com/agentclientprotocol/codex-acp/blob/main/src/AirExtension.ts) 已能提供推荐值，旧式模型目录仍能区分临时补入的配置值，因此复用这些信息并等待 ACP 确认；不修改第三方适配器，也不再另起一个 CLI 进程查询模型。

npm 的进度选项只面向终端，HTTP 日志通常在请求完成后才输出，无法解释长时间下载；轮询用户共享缓存也会把其他 npm 进程的写入误算进来。另写下载器会重复 npm 的代理、重试和缓存边界。因此采用一个只观察实际流字节的 Node 模块，保留 npm 完整安装行为；代价是必须用本地 HTTP 测试保护 Node 观察点和流的背压（消费者来不及处理时暂停接收）语义。

### 不识别来源，失败后给 npm 加 `--force`

这会覆盖 Homebrew 等安装器管理的命令链接，留下两个安装器争用同一文件，也可能让更新的是一份 CLI、PATH 运行的是另一份。统一迁移到 npm 还会改变用户的发布渠道。当前采用文件身份与原安装器记录确认后再更新：查询开销稍大，但能够保留安装方式；未识别的来源宁可显示手动步骤，也不猜测和覆盖。识别规则采用上游公开目录/命令，目录或包管理器输出变化时应补充契约与本地 fixture 测试。

### 可操作的活动栏与文件审阅

活动入口改为按内容出现的紧凑状态区：第一行显示任务已完成数/总数和当前步骤，右侧在存在真实子代理时显示独立入口；第二行显示当前会话待审阅文件数及完整的上游增删行数。任务文字、子代理与文件摘要分别打开原有详情，复用共享 `litheDropdown` 的定位、外部点击与 Escape 关闭，不另写面板样式或键盘事件。窄面板优先保留进度、子代理数量与修改摘要，长任务名称单行省略并保留完整悬停说明。装饰边框不得参与点击检测，只有一行摘要时也必须一次点击即可打开详情。

没有计划、子代理或待审阅修改时隐藏对应入口；全部为空时状态区及其下方间距都归零。例外是审阅仍在执行或失败：保留文件审阅入口，避免把错误一起隐藏。计划清空、保留或回撤最后一个文件、切换会话会关闭失效弹层，后来出现新内容不会重新打开上一次选择。相比常驻的三个等宽按钮，这个布局能直接解释当前步骤；代价是空态不再提供“暂无任务/子代理”的独立入口。普通工具证据仍在转录里，不把工具数量当作任务或子代理。

活动快照按输入更新构造一次，文件统计只采用当前可见、未确认版本；每个文件都必须有完整、已完成的上游统计，否则只显示文件数，求和溢出也保持未知。它不是整个仓库的 Git diff，不新增仓库/分支展示或 Create PR 动作。状态区高度只由可见行数和共享行高推导，同时用于输入区最小高度；不要测量整份转录或把尺寸变化发布到业务模型。数量来自当前会话，不受聊天搜索影响。三项继续使用 Community `915c3c26029bd2f8d35907d6faf43c4a3264c5f7` 的 `expui/build/taskGroup`、`expui/general/refresh`、`expui/general/edit` 明暗 SVG，保持 16pt 和原色。这是 Lithe 的语义映射，不声称复刻专有 AI 插件动作。

“任务”只显示 Agent 通过 ACP 上报的执行计划：非空计划显示已完成数/总数和每条真实状态；没有计划时隐藏任务摘要，计划被清空时同时关闭其旧弹层。比如三步计划完成一步显示 `1/3`；只有五次 `List files`、`cat` 等工具调用时不能显示五个待办。工具证据继续保留在对话记录中，不推断未上报的计划。

任务文字在完成后仍使用正常文字颜色，不加删除线；已完成由绿色勾选表示，待执行用空心圆，执行中保留进度图标。这样保留步骤的可读性，状态由图标及可访问状态标签表达，不靠划掉文字区分。

Codex 的任务清单工具需要显式开启。已核对上游 `rust-v0.156.1` 与 `rust-v0.160.0` 的 [`UpdatePlanToolConfig`](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/config.schema.json)：`tools.update_plan.enabled` 默认是 false；适配器能转发 `turn/plan/updated` 并不代表模型已获得该工具。Host 在 API Key 和官方订阅两条启动路径使用同一进程级 `CODEX_CONFIG` 开启此项，保留各自路由及可选默认模型；不写用户的 `config.toml`，不改变协作模式、权限或模型目录。只有模型实际调用工具并上报 ACP plan 后才显示进度，普通文字计划不作替代。不能通过切换到规划协作模式修复待办，因为上游 [`PlanHandler`](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/plan.rs) 在该模式中禁止执行待办工具。代价是 Lithe 会话显式启用原生任务清单，模型仍可为简单请求不创建计划；收益是计划事实与生命周期继续由 Codex 拥有，不增加一套解析器或任务存储。

“子代理”取代原先列运行工具的“运行中”，参考 [CC GUI 的子代理面板](https://github.com/zhukunpenglinyutong/jetbrains-cc-gui/tree/7bcd6c3803ec44944cef90f5bff0aa666cab99a2/webview/src/components/StatusPanel)。面板显示原生子代理的名称、任务、运行或终止状态，以及已完成数/总数；点击展开上游实际传回的推理、工具和回复，点击详情不会关闭弹层。普通工具调用和异步派发成功都不能证明产生或完成了子代理。失败、取消、断开不计为成功；父代理结束时尚无终态的后代标为“已断开”，不伪造完成。

子代理的执行和历史仍由上游负责。安装版本 Claude ACP 0.81.2 与 Codex ACP 1.13.1 已通过公开 AIR 扩展（适配器协商的附加能力）提供 `nativeSubagentSessions`。因此 macOS 通过可选启动字段协商该能力，只消费明确的子会话创建与状态通知以及子会话的正常 ACP 输出；不复制 CCGUI 的 JSONL 历史轮询，不新增 Agent 进程、缓存、轮询计时器或发行包写入。Windows 目前不启用，不能将普通工具数量标为子代理。

共享 Host 保留直接父会话关系，拒绝循环、跨会话重新绑定和挪用主会话 ID。子代理授权等待记在主轮次中，原始授权请求仍保留子会话 ID；停止主任务、轮次结束或连接退出会收尾所有待定授权。子代理进度能解除静默和禁止整轮重试，但子代理故障不能被当成主代理的模型故障重试。Swift 将子回复和推理单独标记，主回复、历史预览和复制不拼入子回复；工具调用按子会话和工具 ID 区分，文件修改仍使用已有审阅与回撤证据。历史回放先恢复子会话关系，失败回放恢复原会话及路由。

未决授权同时保存来源子会话与所属主轮次。子代理或祖先进入完成、失败、取消、断开状态时，Host 只将该子树的未决请求结算为 `cancelled`；Swift 用同一生命周期通知移除对应卡片并刷新等待计时和注意状态，保留主会话及同级代理的有效授权，主轮次继续运行。来源检查和授权登记共用归属锁，锁顺序为会话归属、未决授权、运行轮次，避免终止通知漏掉刚检查过的请求；终态之后的迟到请求直接取消。只保留根 ID 会丢失清理范围，而终止整条主轮次会误伤其他工作，因此两种做法均不采用。代价是每条未决授权增加来源标识；收益是授权队列和静默计数能及时释放，不新增协议事件或磁盘状态。回归使用受控协议及虚拟时钟覆盖子树终止后主轮次继续、其他授权保留、迟到请求拒绝和静默恢复。

固定 SDK 2.2.0 尚未识别适配器的 `subagent_spawned` 和 `subagent_state_update`。已检查 SDK 3.4.0，其实验性支持采用不同的 `subagent_update` 草案，直接升级不能解码当前适配器。因此 Host 只在通知边界补充这两个已协商的变体，普通更新继续交给 SDK 校验、传输和派发。适配器与 SDK 使用同一草案后应移除这层兼容解析，而不是扩大为另一套 ACP 客户端。代价是未协商或不上报子会话的 Agent 不显示子代理入口；收益是状态有明确来源，生命周期和授权仍在原有连接内。

`AgentActivityPresentationTests` 通过原生鼠标检查三项入口、展开与状态刷新、深浅主题、中英文、长列表末项和编辑操作。该布局不新增下载或运行时磁盘资源，不改变安装包、签名或 Sparkle 增量基线。

“编辑”支持打开文件、复用已有比较界面查看差异、保留单轮文件修改和回撤单个文件或全部文件。Agent 已经保存文件，所以“保留全部”只确认当前版本，不重复写盘。确认保存在该会话的内存里，后续新增工具修改以已确认版本为起点；旧工具的证据若被更新则重新展示，避免旧确认隐藏新内容。同一标签断连、重连和历史回放时继承这些确认；加载失败恢复原会话，加载成功仍核对完整版本或已确认前缀。关闭会话才释放这些状态，Lithe 不新建聊天历史或可复用缓存。行增减数只采用上游版本兼容的统计，缺失时不从字符串或片段估算。

ACP 差异可能是完整文本，也可能是 Claude 上报的片段。界面分开展示每段，标明来源；超出行数比较预算时展示前后文本，超出既有文本上限时标记不完整并禁止回撤。不能把片段拼成虚假的整文件基线。也不能仅凭 `oldText: null` 删除文件，因为上游会用相同值表示插入片段或缺失旧内容；只有显式创建元数据才允许把原创建文件移入废纸篓。Codex 使用差异中的创建类型，Claude 使用固定适配器转发的 SDK `FileWriteOutput`（写文件工具的结构化结果）；它明确区分 `create` 与 `update`，并提供完整的新文本和可用的旧文本。Write 优先用这份完整文本，保留片段会丢掉的末尾换行；旧文本缺失的 `update` 不得被当作创建。新增样例进入共享 fixture，由官方 SDK 往返校验。

回撤由连接模型持有可取消任务，逐个确认成功的文件；失败和较新的版本留在列表。关闭连接会取消并等待任务完成，切换会话不把结果写入新会话。AppModel 在动作前同步原生编辑器的待处理输入，拒绝脏缓冲区和仍在回复的会话；Mac 适配器校验工作区及父目录链接边界，保留末端路径交给文档适配器拒绝符号链接，不能先跟随链接再操作另一个文件。恢复按上报文本逆序处理，片段只允许唯一的非空精确匹配。写盘复用文档适配器的编码、字节身份及原子冲突检查；恢复删除要求路径仍不存在，撤销创建通过携带预期字节身份的受保护废纸篓端口，与原生保存共享同一写入锁。批量回撤不是文件系统事务，发生冲突时停止并保留尚未处理的条目。

外部程序不参与原生保存锁，所以移入废纸篓后还必须核对实际移出的对象类型和字节身份；不匹配时恢复原路径并返回冲突。如果外部程序又创建了同名文件，恢复不能覆盖它，两个版本都保留并提示废纸篓内的恢复路径。废纸篓文件由系统拥有，冲突恢复或用户手动恢复后结束该生命周期；不增加运行时缓存、工作树共享资源或安装包写入，也不改变签名和 Sparkle 增量基线。相比移入前再读一次，提交后的核对能发现最后一次检查与实际移动之间的外部替换；仍不承诺任意外部程序停止写入已打开的文件句柄。没有实现受保护移除的适配器直接拒绝，不能降级为普通 Trash。

正确示例：第一轮修改已保留，第二轮修改后仅撤销第二轮；用户在片段之外追加文字时保留追加内容，片段冲突或出现多个匹配时停止。错误示例：把 Agent 截断的 `newText` 当作磁盘内容直接覆盖，或回撤时删除用户后来新建的同名文件。这些做法会丢失用户数据。

重连也遵守同一个例子：A→B 已保留，回放后 B→C 的回撤只能恢复 B；已回撤的上报记录不会重新出现。创建 a.txt 后若它变成指向 b.txt 的链接，即使 b.txt 内容相同也拒绝，不能把 b.txt 移入废纸篓。原生编辑器先保存了新内容时，移除必须返回冲突，不能把保存成功的用户版本确认成回撤成功。

这里复用已有 ACP Host、文档读写与比较界面，不复制参考项目的桥接协议或另建文件快照服务。代价是证据不足的文件可以打开和确认，但不能自动回撤；多次上报的差异按段审阅，不承诺完整会话净差异；恢复已删除文件只能依据上报文本使用 UTF-8，无法还原未知的原编码或文件元数据。所有写入都来自用户显式回撤，目标仅为工作区；固定资源继续只读，不增加安装目录写入、签名变化或 Sparkle 增量基线变化。Windows UI 仍以功能矩阵中的独立状态为准。

## 后果

### 回复过程中补充指令

用户在 Agent 工作时追加消息，默认是补充当前任务的要求。这里复用固定的
[Codex ACP 1.13.1](https://github.com/agentclientprotocol/codex-acp/blob/v1.13.1/src/CodexAcpServer.ts)
和 [Claude ACP 0.81.2](https://github.com/agentclientprotocol/claude-agent-acp/blob/v0.81.2/src/acp-agent.ts)
已有的 steering 扩展（把消息送入正在执行的任务）。共享 Host 读取初始化响应
顶层的能力声明，再调用 `_session/steering`；不移植 Pi 的模型循环，不启动
第二套 Codex App Server，也不把消息排到整个任务结束后才交给模型。

macOS 输入区只保留一个固定位置的主按钮。运行中且草稿没有有效文字或附件时显示停止；输入有效文字或添加附件后切换为发送，提交消息清空草稿后恢复停止。纯空白仍视为无输入。停止确认中与尚未提交的续发等待阶段继续以停止为优先，避免把待取消操作变成发送；Esc 的取消语义保持。补充消息显示发送中、Agent 已接收
或错误；“已接收”只证明适配器确认收到，不能宣称模型已经阅读。原任务的
计时、工具、授权和停止所有权保持，一个会话一次只等待一个补充发送确认。
正确示例：检查全项目时补充“先只检查登录模块”，把消息交给当前 Agent
调整后续步骤。不要同时再发一个普通 prompt，或把发送失败当作原任务结束。

Claude 明确报告消息未消费时，功能模型等原轮次和预选配置处理完后只续发一次；
用户停止会撤销这次续发。即使原回复已经结束、仍在等待配置确认，也要显示
停止入口并支持 Esc：此时只撤销尚未发送的补充内容，保留配置请求，不向
没有活动轮次的 Agent 发送取消。配置确认之后不能恢复已撤销的消息。

斜杠命令统一等原轮次结束后走普通 prompt（有明确请求响应的消息调用），
命令解析继续由上游负责。固定 Codex 1.13.1 的 `startNewTurnFromSteering`
忽略了 `startNewTurnFromExternalPrompt` 是否真的启动模型轮次的布尔结果，
因此 `/status` 等纯命令完成后也会返回 `startedNewTurn`，却没有新轮的
活跃与空闲事件。正确做法是在发给 steering 扩展之前就报告消息未消费，
原回复结束后只提交一次普通 prompt，以它的响应确认命令完成；带附件或前导
空白的斜杠输入也按此处理，续发时仍只保留原命令文本和有序附件，不追加项目上下文。不按命令名维护第二套目录，不修改第三方适配器，
不凭当前空闲、短暂无事件或延长超时猜测完成。代价是回复期间输入命令会
延后执行，但可确定结束，也能在等待配置时撤销。回归测试控制原回复结束、
纯命令无新轮事件、后续消息，以及配置确认前取消的顺序。

Codex 的固定版本在普通补充消息的结束竞态中可能自行开始内部新轮，
Host 必须继续等待其公开 threadStatus 中的新轮空闲事件，不能用原轮的完成
响应释放忙碌状态。重复空闲通知不能结束下一轮；缺失的续轮 token 用量保持
未知。没有生命周期适配的其他 Agent 若另起分离轮次，或发送确认超时导致
消息是否消费不明，关闭连接并保留输入，不能猜完成或自动重发。

代价是 Codex 这条兼容路径依赖固定上游的状态元数据，需要在适配器升级时
重复验证；静默不能替代结束确认，明确停止仍由现有十秒看门狗限制。
Windows 连接桥已接入共享 Host，面板 UI 也已落地（活动栏入口、右侧工具窗、按窗口与项目隔离的连接单例、会话标签与消息流、权限确认、供应商与适配器设置、CLI 安装升级与配置导入、上下文用量与订阅额度），但订阅登录、供应商切换、CLI 升级与配置导入的真机验收尚未完成，不能把前端代码当作 Windows 已验证。本功能不新增下载、缓存或运行时资源路径，不写安装目录，
不改变代码签名和 Sparkle 增量更新基线。
