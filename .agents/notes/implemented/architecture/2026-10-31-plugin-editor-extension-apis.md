# Agent 笔记：独立的插件高亮、编辑器动作与编辑器 Provider API

状态：已实现

> Viva 迁移状态：当前 Viva 宿主已接通插件静态语法、编辑器动作，以及跳转、悬浮、补全、CodeLens、语义着色、文档链接和前景着色提供者。折叠提供者尚未路由。前景着色随 Core #188 合入，宿主通过固定修订声明该能力。下文旧 Web 编辑器的具体呈现方式仅供历史对照。公共参数、版本和能力以 Core 仓库当前契约为准。

## 先说结论

普通工具插件可以独立提供文本高亮、编辑器配置、位置动作和编辑器语言功能（跳转、悬浮、补全、CodeLens、折叠、语义着色、文档链接），不要求实现 LSP（语言服务器协议）、构建、运行或调试提供者。静态资源使用 `languages:2`；位置动作与语言功能都通过函数协议 3 的独立宿主方法注册，再复用原有函数调用执行；没有 `runMarkers` 清单能力，也不修改 `commands/didRun`。语言功能只“补充”语言服务器：服务器先答，插件的答案只增加不替换。运行和界面验收以功能矩阵为准，不把静态校验当作产品验收。

## 问题

HTTP 工具插件需要高亮和请求旁的按钮。原方案把按钮建模成专用运行标记，并向通用命令通知加入 `runMarker`，扩大了无关领域的兼容面。用户确认[独立能力与领域边界](2026-10-31-plugin-capability-and-domain-boundaries.md)：宿主理解动作的有限展示结构，插件理解 HTTP/SQL 等业务，不能因为按钮像播放图标就归入 Run。

## 决策

### 静态高亮与后端业务分离

语法和注释/括号配置属于安装包内只读资源，通过独立编辑器模块启用；不要求语言服务器或后端。仅配置贡献也应用，编辑器模块不抢占已有语言的运行、调试和服务器所有权。纯静态资源可安装、停用和卸载即时生效，带后端的插件继续遵循既有启动登记规则。

Core 校验资源大小、状态和规则，并拒绝 include 环及展开后超过预算的图。语法的执行放在可终止的隔离执行单元里，超过本地执行期限时该语言退为普通文本，不影响编辑与保存。插件正则不在主线程运行，因为长度限额不能阻止病态回溯。

语法规则按声明顺序执行，不能把语法当成无序字典重建。仅贡献配置的语言保留独立文档身份，但可以借用既有的 tokenizer；撤回配置只释放借用登记，不销毁上游引擎。

### 编辑器动作是小型独立契约

后端先注册普通函数，再通过 `editor/registerActions` 注册上下文、文件选择器和收集函数。宿主返回既有 subscription，由会话、上下文或显式释放共同清理。注册时只记录绑定，下一事件轮才请求解析，避免后端等待宿主注册答复、宿主又等待同一后端的循环。

宿主向收集函数提供公开文档身份、内容版本和当前脏缓冲。返回范围、标题、受限图标和同插件函数绑定；Core 只校验结构和 UTF-16 边界，不解释请求、查询、框架或任务 ID。多个同一行动作进入同一菜单，不制造测试种类或覆盖为只剩一个动作。

正确做法：HTTP 的“发送请求”和 SQL 的“执行查询”都返回同一展示结构，分别绑定自己已有的普通函数。
不要这样做：新增 `http`/`sql` 执行类型、把请求包成假 Build 任务，或者要求工具插件提供 LSP CodeLens。

点击时界面只回传宿主生成的批次和动作键，不能提供函数或业务参数。宿主重新验证内容版本、上下文、注册租约与会话函数，再用已有 invocation 调用；插件收到文档身份、预期版本和自己的不透明数据，执行前核对当前文本。命令通知保持原样，命令面板可调用同一插件业务实现。

### 动作版本 2：同一行的多个图标、替代项与点击后展示位置

同一行可以同时有“运行”“调试”“测试通过/失败”和“跳到父方法/实现”这类图标。版本 2 在不新增方法的前提下表达它们：

- 图标来自宿主声明的图标表（能力发现中列出）。插件不能提供自己的 SVG；表外的图标名由 Core 拒绝。
- 运行类图标画在行号右侧，导航类图标画在行号左侧，两条车道各自排列；同一行的多个动作仍进入同一个菜单。
- 一个标记可以带至多 4 个 `alternatives`（例如“运行 main”旁边的“调试 main”“测试此包”），各有自己的图标、标题和函数绑定。点击回传的仍然只是宿主生成的批次、动作键，外加备选项键。
- 动作函数的返回值可以带 `reveal`（1 到 100 个 LSP 位置），宿主把它展示出来（单个位置直接打开，多个位置用现有的导航列表）。返回值的其他成员属于插件自己，宿主不解释。

测试标记与测试结果不新增任何测试专用契约：插件用 `test`、`test-passed`、`test-failed`、`test-skipped` 图标画状态和入口，点击后执行仍走运行和调试的既有契约。图标只负责画状态，宿主不会因为一个图标自己启动任何东西。

### 语言功能（Provider）：补充语言服务器，不替代它

后端先注册普通函数，再调用 `editor/registerProviders`（权限 `editor.providers`，同时需要 `documents.read`），给一个文件选择器（语言、扩展名、文件名，三者任一命中即可）绑定若干类型的函数：`definition`、`hover`、`completion`、`codeLens`、`foldingRange`、`semanticTokens`、`documentLink`。注册时只记录绑定；询问发生在之后的事件轮，插件通过文档快照读取预期版本的文本再回答。

宿主不认识任何语言，也不解释插件的数据：

- Core 校验注册（选择器必须命中点什么、类型必须是宿主声明的、语义着色必须带 legend）并规范化每种答案的形状。补全只保留展示和编辑信息，丢弃 `data` 和 `command`，因此没有“解析补全”往返，也不会通过补全执行命令；CodeLens 只能带一个同插件的函数；文档链接目标必须是绝对 URL。
- 每种类型的答题期限由宿主决定，插件不能自带预算：悬浮和补全 400 毫秒，跳转 1500 毫秒，其余 2000 毫秒。超时、失败、形状不对、文档已经变化或注册已被撤回的答案一律安静丢弃，只写失败日志。
- 同一个文件上所有匹配的注册并发询问；补全的触发字符只会问到声明过该字符的注册。

**合并规则（语言服务器优先）。**

- 悬浮和补全：宿主把插件当作另一个 Provider，由编辑器自己合并多个来源的结果。宿主自己的悬浮、补全 Provider 注册在同一通配选择器上，插件 Provider 必须先于宿主 Provider 注册，宿主的答案才排第一。
- 跳转：语言服务器先答，插件的位置追加在后；重复位置只保留一个；服务器只指回光标所在符号本身时让位给插件（区间终点不含）。这个规则在 Core 的 `mergeDefinitions` 里。修饰键点击、F12 和原生 Go to Definition 命令走同一个查询和合并；文件没有语言服务器跳转时只展示插件的位置。
- 跳转结果在展示前再核对一次文档版本：查询结束和等待它的调用方恢复是两个事件轮，中间可能有编辑。版本变了就丢弃插件位置，语言服务器的答案照常展示。
- 修饰键悬停判断“是否可点”时，只有语言服务器说没有跳转才问插件；同一个窗口同时最多一组插件跳转查询在跑，新的悬停取消上一组。
- CodeLens、折叠、文档链接：直接追加。
- 语义着色：只在语言服务器没有语义着色的位置生效。通配选择器的注册得分低于具体语言的注册，因此插件的通配注册不会盖过服务器。
- 只读预览不询问插件：预览里只看语言服务器的跳转。

**页面不接触插件的目标。** 界面只收到宿主生成的批次和条目键（UUID），点击 CodeLens 或链接时回传这些键，宿主在自己的表里找到真正的函数、参数和目标。文档链接以不透明的内部地址呈现，由页面先于编辑器的默认处理拦截：编辑器的链接检测会执行 `command:` 链接，如果把插件给的 URL 直接交给它，插件就能让编辑器执行任意命令。宿主只打开 http/https 和工作区内的 `file:`。

**错误码。** 不认识的类型是 `plugin.host.unsupportedOption`（`details.option` 为 `providers.<类型>`，包括 `diagnostics`、`signatureHelp`），其余注册错误都是 `plugin.host.invalidParams`；重复 ID 是 `preconditionFailed`，每个插件最多 32 个注册（`limitExceeded`）。撤回某个函数会使该插件的全部注册失效，插件必须显式重新注册，复用的函数 ID 不会让旧绑定复活。

**不做什么。** 诊断是推送式集合，属于单独设计的诊断 API，不在 Provider 里；符号、格式化、重命名、Code Action、签名帮助、内联提示尚无绑定；运行期传入 JSON 注册高亮也没有。超过 128 Ki UTF-16 单位或 10,000 行的文档保持普通文本，嵌入语言也按普通文本处理。

正确做法：一个“资源 key 在模板和 `.properties` 之间跳转”的插件注册 `definition`、`hover`、`completion` 三个函数，选择器写 `html` 和 `properties`；语言服务器照常提供模板的普通跳转，插件补上 key 的跳转。
不要这样做：在宿主里按语言名加分支，或让插件返回 `command:` 链接让界面去执行。


### 独立前景颜色范围与语言服务共存

颜色范围使用独立的 `colorDecorations` 提供者。它描述“这段文字使用哪个主题颜色”，不冒充变量、类或其他语言语义类别。插件通过现有 `editor/registerProviders` 注册，同一个文件可以接受多个颜色来源；语法和语言服务器仍独立回答原有的语义着色。

Core 校验颜色表、单行 UTF-16 范围（列以 Unicode 的 UTF-16 编码单元计数）和结果上限，并按稳定的来源标识决定重叠优先级。较早的来源保留前景色，后面的范围只覆盖尚未着色的部分。宿主只在后台把这些位置转换成绘制需要的 UTF-8 字节偏移，不再实现第二份排序、裁切或预算规则。调用期限读取 Core 校验后返回的预算；宿主另外限制同时进行的原生调用数量。

绘制时先保留语法与语义着色的字体样式，再用独立范围替换前景色。选区背景、诊断下划线、内联提示、光标和背景主题保留各自的层级。每个颜色同时提供明、暗主题值，切换主题无需重新调用插件。正确做法：两个语义无关的插件都返回同一种范围和颜色标识，由 Core 合并。不要这样做：为了得到多种颜色，把范围伪装成不同的内置语义 token 类型，或在宿主判断某个插件名后改变样式。

每个打开文档只保留当前颜色结果、一次缓存的提供者查询和一个可取消请求。颜色范围以文档绝对字节偏移和颜色表下标保存，同一对明暗颜色只解析一次，所以彩虹括号这类少量颜色循环覆盖上万个括号的结果，每个范围只占 12 字节。

编辑、撤销、重做和后台准备的批量编辑会把编辑点之后的范围整体平移，删除被编辑切开或替换的范围，编辑点之前的范围原样保留。这样在括号前打字时，括号颜色跟着文字走，直到插件对新文本给出答案再整体替换，而不是每次按键都先清空、再在停顿后闪回。平移只遍历编辑点之后的范围，上限是 Core 的 10,000 个。磁盘重新加载替换整个文本，会直接清空。

按键只重新开始一次 250 ms 的停顿计时：不查询提供者，不创建后台任务，也不清空颜色。停顿结束后才创建可取消请求。提供者是否服务该文档按路径、语言和颜色提供者注册变化缓存；提供者注册或撤回、文档改名或换语言时，会重新查询并立即清空旧颜色。每次计划、撤销请求都会递增代数，过期计时器和过期答案直接丢弃；答案应用前还会核对文档版本。提供者撤回、插件停止和文档关闭会取消请求并清空颜色；旧会话释放前，重启的后端可以重新注册相同标识。

绘制时，每个可见行用二分查找取出本行范围，再按语法片段和颜色边界分段解析样式，不逐字符查找，不逐帧解析颜色，也不复制文档。

内置彩虹括号复用同一层绘制和编辑平移。候选直接来自现有 TextMate 后台分词，每 32 行保存一段，只重新计算编辑影响的段；跨行访问符和语法声明的模式绑定状态也参与停止重算的判断。声明名称在后台汇总，语言差异只写成语法元数据，不按语言名分支。正确做法是在分词 worker 产出 token 时收集候选；不要在编辑停顿后从第 0 行再分词一次。

Core 只接收有序括号的位置与类型，返回配对的嵌套深度；候选和开关未变化时直接复用上次 Core 结果。文档最多 1 MiB，整篇缓存最多各 10000 个括号和变量；前段候选数量变化时调整后段配额，删除文本后按需补回。超长行或分词超时保留故障位置前可信的结果，达到数量上限保留有界前缀，并在工作台处理边界记录降级事件。基础语法着色始终沿用原来的分词路径。这些缓存由编辑器标签拥有，关闭时释放，不写发行目录，也不影响签名或增量更新基线。

仅有候选位置改变时，宿主按旧候选的字节位置找到序号，将已有颜色、配对两端和代码块范围投影到新位置；括号类型和变量名序列必须相同。Core 会省略不匹配的闭括号，因此不能把输出序号直接当输入序号，也不能假定所有位置共享一个平移量。宿主不重新配对或计算颜色，投影失败就重新请求 Core，并保持旧结果不可变。

降级日志由文档最近一次被接受的结果持有，只记录新出现的原因；恢复后再次出现仍记录。旧版本或已取消结果不能更新这份状态，避免每次编辑停顿重复消耗后台失败事件的限额。跨过 1 MiB 上限关闭候选收集时，仅清空候选并按编辑范围更新词法检查点；重新启用时才完整重建候选，避免在阈值附近输入触发反复全文分词。

内置开关和明暗色板由 Core 解读，保存到 Lithe 的编辑器偏好。若同一个括号已有扩展提供的前景色，保留扩展的颜色。两种来源都使用紧凑的偏移和颜色表，编辑时只平移受影响的范围。

彩虹变量和彩虹括号分别启用，共用明暗色板。两者同时启用时只分词一次。变量候选基于 TextMate 的变量作用域，Core 按区分大小写的原始拼写选择稳定的颜色，哈希混合后映射到色板；同名声明和用法可以在文件内、跨文件保持同色，但不同名称仍可能碰到同色。这是一种词法配色，语言语义和作用域仍由语言服务负责。

光标附近的配对括号和当前符号引用使用背景高亮，叠加在语法前景色上。括号配对沿用同一次 TextMate 扫描和 Core 配对结果，关闭彩虹前景色仍能查看配对。绘制时读取该版本的配对索引和实际光标，查找跳转同样会更新标记。鼠标点中相邻括号时保留字形命中位置，按住鼠标时只在光标或选区改变后释放该位置。变量、方法等符号由语言服务器的文档高亮请求识别，结果仅用于当前文件。越界范围逐条丢弃。缺少相应能力时，代码里的双击选词与 Core 边界检查使用 Unicode `ID_Continue`、连接控制符及 `$`。Vim Visual 的请求与绘制均核对实际可视选区。关闭标签后拒绝重新为该文档安排高亮任务。绘制只查当前视口。

缩进参考线使用编辑器的缩进宽度和制表位。彩虹参考线按层级循环使用同一套明暗色板，关闭父开关时保留用户保存的子开关值。花括号代码块复用 Core 的配对结果，在开始和结束行之间绘制。闭合括号前另有代码时，以开块行确定线的列。光标所在的最内层代码块加深对比度，同级相邻块单独处理。普通缩进线会穿过位于其内侧的结构线，并依据附近代码衔接空白行。几何坐标在后台准备，视图只绘制可见行。

工作区打开早于后端初始化时，首次上下文通知可能没有接收者。因此宿主在按需启动的后端准备好后补发当前上下文修订，并与后续通知按会话和修订去重、串行发送。初始化期间出现的工作区变化会体现在这次最新修订中；不增加后台轮询。

## 考虑过的备选方案

- 要求工具插件提供 LSP：标准化但无必要地强加语言服务生命周期，拒绝。
- 专用 `runMarkers` 和 `didRun.runMarker`：把展示和执行耦合，新增一种动作就扩张执行通知，拒绝。
- 函数名约定或插件名分支：宿主猜私有协议且无法安全撤回，拒绝。
- 让工具插件把 Provider 注册成一个语言服务器：强加服务器生命周期和文档同步，而且无法表达“只补充”，拒绝。
- 让插件的语言功能答案覆盖语言服务器：会破坏上游语言能力，拒绝；前景颜色覆盖则是明确授权的独立呈现层，不替换语义身份或样式。
- 用彩虹变量的颜色判定同一个符号会混淆同名变量和重载方法。文档高亮请求由语言服务器识别引用，比跨文件查找引用更符合光标移动时的范围。
- 把插件返回的 URL 或命令直接交给编辑器：`command:` 链接会被执行，拒绝；页面只持有不透明键。
- 为测试标记新增测试专用契约：测试发现和运行已经是既有契约的职责，编辑器只需要多种图标，拒绝。
- 允许插件提供自己的图标 SVG 或 CSS：等于向编辑器注入界面，拒绝；改为宿主声明图标表。
- 把诊断放进 Provider 通道：诊断是推送式集合，要有版本、撤回和合并语义，留给单独设计。

## 后果

收益是工具插件不污染领域模型，执行复用现成函数基础设施。代价是增加一个明确授权的独立编辑器贡献契约，需要跨语言校验与生命周期接线。首版不支持远程、只读预览动作，也不承诺任意大型文档的插件高亮。

Provider 通道额外增加一个权限（`editor.providers`）、每次触发后的并发询问成本（由各类型的答题期限限制）和一套页面与宿主的不透明键协议；换来的是 Spring、MyBatis、Go、`.http` 等工具不必为了一个按钮或跳转实现整台语言服务器。
