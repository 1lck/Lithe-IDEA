# Agent 笔记：macOS Monaco 独立可行性实验

状态：已实现

## 先说结论

先用独立原生窗口验证 Monaco 能否在 macOS 的网页容器 WKWebView 中工作，
再通过单独打包的实验版接入 Lithe 工作台。Web 资源位于
`frontend/editor/`，macOS 宿主入口位于 `macos/EditorFrontend/`；
`macos/Experiments/Monaco/` 只保留验证宿主。正式改造已让普通构建打包相同资源。
主编辑区、独立文件窗口和分屏统一使用 Monaco，包含混合换行，已移除原生切换按钮；其他源码预览入口与功能对齐仍在继续。
通过宿主验证仍不代表满足默认替换条件。

## 问题

Issue #687 提议通过 Monaco 减少两端编辑器维护成本，但 Windows 的浏览器
内核与 macOS WebKit 不同。直接复制 Windows 工作台会同时引入 React 状态、
Tauri 事件和语言会话依赖，让宿主问题与业务接入问题混在一起。

## 决策

### 独立宿主

- 原生实验宿主只承载 WebKit、本地资源和临时文本副本。它不启动 LSP，不使用
  正式项目设置，不写传入文件；保存只写实验输出目录中的副本。
- Monaco 使用与 Windows 清单一致的安装版本，通过 Bun 将编辑器和 Worker
  （浏览器后台工作线程）打包为本地文件。页面不访问 CDN，不运行本地 HTTP
  服务；资源路径限制在资源目录，桥接只接受受信主框架消息。
- 实验直接使用 Windows 的纯换行归一化函数，证明这条小范围复用可行。
  当前正式抽取为 `@lithe/editor`，两端共同依赖模型管理、换行、URI 和语义
  token 编码。共享包不导入两端的平台目录，不能往 `shared/` 放编译实现。
- 普通编辑发送 UTF-16 范围增量和版本号。宿主先在副本上校验整个批次，再
  发布文本；旧版本和非法范围显式失败。保存先等待增量队列完成，再核对
  原生文本和磁盘回读。全文只用于打开和保存核验，不在滚动时传输。
- 这是可行性实验专用的镜像协议，不是 Lithe 的第二套生产文档状态机。
  工作台接入必须复用现有 Document、保存冲突、语言路由和 Rust Core。

Windows 的 Vite、TypeScript 和 Bun 测试直接解析 `frontend/editor/src`，
不使用安装时复制到 `node_modules/@lithe/editor` 的源码副本。Bun 的本地文件依赖
可能保留旧副本，导致共享源码已修改而 Windows 仍执行旧逻辑；源码别名消除这条
失效路径。Monaco 在 Windows 宿主中解析为单一安装实例，不能因为共享文件位于
另一个目录就加载第二套模型注册表。依赖清单通过 Bun workspace 引用共享目录，并保留精确版本约束。
Windows 的 Bun 1.3.12 在最小本地 `file:` 包上也会发生 EPERM 复制失败，
workspace 安装可正常建立共享包关系；不通过修改系统权限或发布包副本绕过。
Windows 包使用 Bun isolated 依赖布局，使外层共享目录自身也能解析已声明依赖。
否则 Vite 构建的别名虽然有效，Bun 直接执行共享源码的测试仍会找不到 Monaco。
共享资源构建将 Monaco 包路径解析为真实路径，再处理直接导入；否则 workspace
符号链接路径和相对导入的真实路径可能被打成两份注册表，导致 Java 后台上色失联。

### 工作台实验

Java 继承／实现导航标记独立于 CodeVision，继续调用现有 JDTLS 导航标记与解析
服务。Monaco 左侧 glyph lane 承载方向箭头，同一行双向标记按左右半区选择方向，
并提供 Go to Super Declaration／Go to Implementations 命令入口；断点处理器明确
排除该区域。模型初次显示和语言会话状态变化时请求，输入后沿用 180 ms 合并刷新，
关闭模型清理计时器。请求结果与点击同时检查模型、版本和原生标记 ID；文件改名
为非 Java 时清空。鼠标半区命中、四种原生图标的视觉对齐和真实 JDTLS 跳转仍需
最终原生包检查，不能用桥接固定返回值回归代替。

平台快捷键通过宿主显式注入 Monaco 内置编辑命令。macOS 保留 Lithe 原有的
`⌘D` 复制行或选区、`Option+Shift+↑/↓` 移动行，`⌘/` 使用 Monaco 注释能力。
不能直接采用 Monaco 默认 `⌘D` 多选，否则迁移会改变既有行为；共享包不探测
平台、不改变 Windows 自己的键位配置。回归向实际 Monaco 输入框发送按键，
覆盖 Caps Lock、方向键位置标志、选区、CRLF、撤销和只读保护，替代旧 AppKit
快捷键匹配器测试。缓存模型再次激活时也必须更新显式传入的只读状态，并同步
所有共享该模型的视图；不能只在首次创建时读取权限。

Git 行变更使用 Monaco 的 line decoration 区域，和断点 glyph margin 分开；
增加、修改、删除标记复用现有 Git 行投影。显示装饰不编辑文本、不进入撤销历史。
查看、暂存、取消暂存、丢弃入口发送版本与稳定标记 ID，原生重新确认标记仍存在、
当前 Git 状态允许该动作；丢弃继续经过已有确认流程。共享编辑器在模型改变后拒绝
旧标记动作。宿主观察行标记缓存，只在有效负载变化时推送，关闭文档取消该编辑器
持有的加载任务。真实鼠标命中、右键菜单与未保存文本对应位置仍需最终包验证。

Blame 作者与日期沿用 Git 缓存，显式显示时才补加载；提交详情仍走现有 Git 功能。
Monaco 自定义行号承载紧凑元数据和原始行号，相邻相同提交只在边界和首个可见行
显示标签。该 API 接收 HTML，因此作者、日期、提交标识在文本与 tooltip 中都必须
转义，不能拼入未转义的仓库数据。点击元数据或执行 Show Blame Commit 命令会校验
版本、行号与提交；切换模型、隐藏 blame 或版本过期时恢复普通行号宽度。分屏按
各自模型刷新，不跟随主标签错误地清空。显示和滚动不修改文档，也不请求原生布局。
鼠标命中、长作者截断和实际滚动表现仍属于最终原生包验收范围。

Java CodeVision 通过 Monaco CodeLens 显示引用数、实现数和作者，复用已有原生
提示数据与导航入口。宿主零基行号只在桥接输出时转为 Monaco 一基行号；引用和
实现仅在计数大于零时出现，作者以普通按钮文本显示。数据或设置变化独立触发
CodeLens 刷新，不重新传输文档或重建模型。异步提供器与点击命令都校验模型身份、
版本和关闭状态，旧位置不会在用户输入后继续触发导航。折叠、滚动和布局由
Monaco 的 CodeLens 管理，原生不再给该功能额外挂浮层。真实原生点击导航与视觉
布局仍需在最终包验收；提供器回归不能代替该验证。

图片粘贴沿用原生 `MarkdownImageImportService` 保存资源，共享编辑器只拦截含图片
文件的 paste 事件，普通文本继续交给 Monaco。事件同步捕获不可变 `File`，先由宿主
校验 Markdown 目标、格式和大小，再编码传输快照；不能在异步回调中重新读取系统
剪贴板，否则用户中途复制其他内容会导入错图。100 MB 上限由原生导入端口统一
提供，桥接在 Base64 解码前后校验大小，保存服务继续复核。读取图片有 10 秒截止
时间，失败会提示并清理读取回调。原生基于 LF 坐标计算已有的 Markdown
块间距，返回插入文本；Monaco 通过单个撤销事务应用，源文本镜像保留原始换行。
导入开始前排空增量队列，返回后重新核对模型身份、版本、关闭锁和只读状态；
文档切换或内容变化时放弃过期插入，不修改新文档，也不抢回焦点。
资源已保存而插入取消时明确通知，不自动删除用户可能正在引用的资源。
通知不依赖文档仍然打开，避免关闭文档后连取消原因也丢失。WebKit 回归通过
宿主可控挂起导入，覆盖切换、关闭、继续输入和保存冻结后返回的四种顺序，
检查原模型、新标签与资源保存提示；这些检查不依赖等待若干毫秒猜测竞态。
此入口尚需验证真实系统剪贴板与 Finder 文件复制的 WebKit 事件表现；合成事件
只能验证桥接之后的编辑与撤销，不能据此移除旧剪贴板覆盖或宣称功能完整。

`MonacoWorkbenchEditor` 是 macOS 平台适配器，正式编辑区域只承载 Monaco。
资源缺失时显示构建或安装错误，不创建原生编辑器作为静默回退。
正式 `build-macos.sh` 调用 `build-editor.sh` 生成本地 Web 资源，预览和发布脚本
将其复制到应用的 `MonacoEditor` 目录；当前入口接受所有文本文件。
Monaco 模型统一使用 LF，源文本镜像保留原始 LF、CRLF 和 CR；保存返回源文本，
而非直接取模型全文。不同 Java 标签页复用同一个 WebView 和独立 Monaco 模型；关闭文档
释放对应模型。split 页面已用一个 WebView 承载两份 Monaco 视图；原生切换分支已删除。

分栏中，主标签选中状态与编辑器焦点分别保存。保存、语言编辑与导航命令默认
使用最后聚焦且仍打开的文档；重新选择标签会重置命令目标，即使标签 ID 未变。
例如左侧标签仍选中、光标在右侧 Java 文件时，格式化和保存应作用于右侧文件，
不能将右侧光标位置与左侧文档组合成 LSP 请求。异步结果必须继续使用发起请求时
捕获的文档，不能在回调执行时重新读取当前焦点。补全选择和代码操作入口接受
显式文档，调用方应传入弹出菜单所属的文档；关闭后的文档拒绝再次发起操作。

悬停、补全与格式化在共享工作台中注册到所有语言，由原生宿主检查实际语言
服务器能力。不能只注册 Java：语法高亮正常不代表其他语言的服务器入口可用。
补全类型通过共享映射转换，不能直接把 LSP 数字当作 Monaco 数字；两者枚举
顺序不同。类型、排序与过滤字段保留到编辑器，迟到结果同时检查模型身份、
本地版本和宿主版本，防止关闭或继续输入后呈现旧建议。

候选补全的延迟解析仍由语言服务器负责，宿主按文档保留当前候选列表并返回
不透明列表身份。Monaco 请求详情时必须携带原列表身份和版本；宿主拒绝已替换
列表，前端拒绝编辑后、关闭后或模型替换后的结果。解析返回的额外导入交给
Monaco 补全机制处理，不能绕过编辑器直接覆盖原生全文。新候选请求发出时就使
旧列表失效，不能等新结果返回才替换，否则并发请求乱序完成会恢复旧候选。
共享层也按每个模型的请求身份拒绝旧列表与解析结果，取消请求同样不能带回导入。

LSP 补全的 `insertTextFormat` 必须穿过 Rust 归一化、Swift 解码和网页桥接，
缺省按普通文本处理；值为 2 时交给 Monaco 片段插入机制。只声明服务器能力、
却丢掉格式字段，会把参数占位符直接写进源文件。解析补全和后续 resolve 请求
都保留这个字段，不能在某个中间模型重新退回普通文本。

重命名和代码操作返回范围修改，由 Monaco 的批量编辑服务校验模型版本并维护
撤销历史。宿主先检查所有目标都在当前工作区内，再加载未打开的目标；这些目标
进入文档模型，修改后按正常未保存文档处理。不能在语言服务器回调里直接写盘或
覆盖原生全文。宿主登记文档与网页建立模型是两个时点，未确认初始化的模型在
首次激活时仍须带上原文，避免取消重命名后留下无法打开的标签。

快速修复按文档保存一份带身份的候选列表，用户选中后才解析完整操作。新候选
替换、文档变更或关闭都会使旧操作失效。带服务器命令的操作先经 Monaco 修改
所有目标，再等待文本同步；同步期间继续输入则不执行旧命令。网页只持有不透明
命令标识，宿主校验工作区与版本，并在执行前消费该标识，防止重复提交同一命令。

断点与暂停行使用 Monaco 模型装饰呈现，状态仍由现有调试模块持有，不能再建
一套网页断点存储。左键和 F9 切换断点，右键进入宿主断点编辑；请求携带所属
文档和版本，等待文本同步后执行，分栏不能借用主标签文档。宿主仅订阅断点、
暂停帧、静音和运行状态变化，并比较序列化后的状态，避免控制台输出触发重复
网页刷新。当前执行箭头使用独立标记栏位置，避免遮住同一行的断点。

内联参数和类型提示由 Monaco 按范围请求，复用 Rust 已有的 `inlayHints` 操作，
Swift 会话仅在服务器声明该能力时转发。位置、提示说明、左右间距及接受提示时的
文本修改必须传到网页；展示本身不能修改源文件。响应返回时同时校验模型身份、
本地版本、宿主版本与取消状态，过滤越界位置和修改范围。说明使用不受信任的
Markdown；语言服务就绪或能力变化时通知 Monaco 重新获取提示。

应用退出和项目窗口关闭使用跨越确认、保存与会话清理的关闭锁。先冻结并排空
各文档的网页编辑队列，再依据真实脏状态弹出确认，不能因为存在远程编辑器就
把干净文档当作未保存。关闭锁用独立操作标识持有；普通保存的解锁不能释放它，
重复释放也不能影响另一关闭流程。取消、同步失败、文档集合变化或清理返回时
由持有者释放，避免留下不可编辑窗口。仅登记、尚未激活的网页模型在关闭准备
时仍需初始化；不能因缺少模型而永远拒绝关闭。

单标签、批量标签和项目关闭也必须保留关闭锁，直到保存/丢弃队列结束或取消。
项目关闭最后一步重新检查剩余文档，确认期间新打开的文件不能被直接重置。
磁盘监听先排空远程输入，再决定重载还是显示冲突；同一文档的待同步监听合并，
关闭或重置后的回调作废。异步发现的冲突由文档层通知，不能假装同步返回值已经
包含尚未完成的判断。用户明确选择加载磁盘版或保留编辑版时也需先同步输入。

“全部保存”的取消状态必须传到同步回调。只在等待前检查任务取消是不够的：
用户取消之后，网页仍可能回传最后一笔输入和同步确认；该确认可以更新内存，
但不能再触发这次已取消的磁盘保存，也不能记录保存成功。已经开始的同步磁盘
写入则正常完成，不尝试中断到一半。

Windows 的 Java 上色初始化复用共享 TextMate 实现。共享分词器允许注入语法、
WASM 资源地址和 Worker 工厂：macOS 继续使用本地资源包，Windows 由打包器解析
资源 URL 和模块 Worker。Windows 首次打开 Java 时才动态加载，单个网页运行环境
只注册一次；退出或热更新时释放，初始化中途结束的旧结果也必须销毁。主题颜色
仍从当前 Monaco token theme 读取，不能为 TextMate 建立独立颜色表。

两端共用 `token-theme-roles.ts` 中的语法角色映射和修饰样式，平台只提供颜色及
注释斜体设置。macOS 在边界处转换原生颜色角色名称，例如把共享 `function`
映射到原生 `functionDeclaration`，不另建一份语法规则。这样新增 token 分类时
只需修改共享表，不会出现两端对相同语法使用不同分类的漂移。
颜色查询使用 `Map`；`constructor` 本身是合法的语法 token，不能从普通对象
继承的同名属性取值，否则主题初始化会把函数当作颜色字符串而失败。

调试暂停行的变量值使用 Monaco 行尾装饰展示，不能插入文档文本。宿主只提供
变量名称和值，共享展示层按当前行的完整标识符匹配，最多显示四个变量，并把
多行或过长的值压成简短预览。恢复执行或离开该源文件的暂停帧时清除装饰。
条件断点与日志断点使用不同图标；变量子节点展开和控制台输出不触发装饰刷新。
Java 暂停行的自动求值复用现有有界表达式提取器和调试服务的栈帧去重、检查代次
保护。变量装饰还核对编辑器文档版本，避免输入后收到的旧值贴到新文本上。
“运行到光标”属于各 Monaco 编辑面板的操作，只有暂停且调试器支持跳转目标时
启用。请求携带该面板的文档、版本和一基行列；排空输入后再检查版本及关闭锁，
宿主继续通过已有调试服务解析可执行目标，不能改用全局活动标签的光标。
暂停时的变量悬停与语言文档合并展示，变量内容按纯文本转义，不能解释为链接
或 HTML。求值只接受标识符；结果同时受文档版本、网页调试状态代次和原生调试
检查代次保护，继续运行后再次使用相同栈帧 ID 也不能接纳上一次暂停的结果。
共享分词器使用的 Monaco 内部接口由同目录中的窄范围类型声明约束；升级固定
版本时必须核对这些接口，不能通过关闭 TypeScript 严格检查掩盖变化。

Java 格式化通过 Monaco 的格式化提供器请求宿主，宿主返回 LSP 文本修改范围，
由 Monaco 应用并维护撤销历史。请求前等待文本同步，返回后同时核对原生版本、
Monaco 模型版本和模型身份；请求期间继续输入或关闭文档时丢弃旧结果。
不能由宿主收到格式化结果后直接替换全文，否则会绕过编辑器的撤销边界。

AppModel 不再提供旧原生编辑器直接应用补全、重命名、格式化和代码操作的入口，
也不在功能组合中创建原生工作区文本写入服务。语言请求返回修改描述，由 Monaco
检查模型身份和版本后应用；新增菜单入口也应触发这条路径，不能恢复直接赋值
`document.text` 的旧调用链。旧渲染器的剩余测试辅助代码不代表产品入口。

共享查找接口可以指定文档或视图，并传入查询词、大小写、整词和正则选项。
指定的目标已关闭时不回退到其他文件，防止预览关闭后的迟到请求修改主编辑器。
显式查询暂时关闭 Monaco 从光标单词和全局查找剪贴板填充查询的默认行为，
操作后恢复原选项；否则第一次打开查找会用光标处单词覆盖预览查询。

项目替换的可编辑源码预览使用同一个 Monaco 宿主。原生容器按挂载身份登记，
浮动预览优先取得宿主，主编辑区的更新继续保留但不抢走 WebView；预览卸载时
恢复仍存活的主容器。共享运行时保存主视图的光标和滚动状态，文本模型与撤销
记录始终只有一份。当前取舍是模态预览期间原主容器暂不显示编辑器，避免同时
创建两套 WebView 编辑同一文档；原生布局和交互仍需实机验证。

临时预览也属于正在编辑的文档集合，但干净预览仍不进入标签页。首次输入会
将其转为正式文档；关闭预览先等待编辑队列完成，迟到的输入必须保留。同步
失败时保留可访问的文档并显示错误，不能直接丢弃内存缓冲区。干净预览释放后
也必须发布文档集合变化，让视图更新并回收对应 Monaco 模型。重新打开预览会
使旧关闭回调失效，防止新面板继续使用的缓冲区被旧请求释放。

预览页面通过编辑器视图工厂组合 UI，产品默认只创建 Monaco。Swift 的页面
生命周期测试注入原生编辑器夹具，继续验证输入后的结果失效和视图身份保持；
真实 Monaco 的编辑、跨面板撤销和光标恢复由 WebKit 集成场景验证。两类证据
不能互相替代，也不能据此省略原生 WebView 挂载的人工验证。

### 只读差异视图

历史记录、分支比较、工作区与提交记录的文本差异使用共享 Monaco Diff 渲染器。
原生宿主提供补丁行、真实源文件行号和稳定分块身份；共享前端只负责呈现、折叠、
导航与按钮事件。Git 补丁可能只包含局部上下文，不能把拼接后的显示缓冲区当作
完整源文件，也不能拿 Monaco 重新计算的差异范围生成暂存或丢弃操作。
例如屏幕第 4 行可以对应源文件第 501 行，按钮仍必须回传原始分块身份，
再由现有 Git 功能模型检查当前分块和空白比较模式后执行操作。

只读比较采用独立、非持久化的网页容器，不借用可编辑文档的模型、保存队列或
语言服务器会话。这样打开历史版本不会改变当前文档，也不会向语言服务器发送
历史文本。关闭比较时释放两侧模型和容器；更新期间合并原生刷新，搜索和选择
变化不重复传输补丁全文。异步语法加载按版本拒绝旧结果，旧分块按钮在刷新后失效。
独立比较初始化时普通编辑器可以没有文档，因此显隐操作控制固定宿主容器，
不能假定 Monaco 已创建依赖文档的内部 DOM。

Windows 的单文件和多文件文本比较也使用同一个共享渲染器，原先小补丁的自绘行
列表与大补丁的普通编辑缓冲区不再作为产品入口。比较模型使用独立只读身份，
不会把历史文本登记成当前源文件的可编辑缓冲区。宿主继续负责主题、字体、
源码跳转、图片与二进制预览；多文件区域保留惰性挂载，单个比较区域的高度有界。
源码跳转使用 Ctrl/Cmd 点击，普通点击、双击和拖选保留文本选择能力。
两端通过 `shared/fixtures/editor/diff-review-v1.json` 验证相同的稀疏补丁投影。
搜索保存原始补丁行身份和 UTF-16 匹配范围，同一行多个匹配可以分别定位；
不能用拼接后的显示行号替代搜索结果身份。

预览借用主编辑器时还保存查找栏的查询、选项和显隐状态。关闭预览必须恢复
主编辑器原先的查找状态，不能把替换预览的查询栏留在原文件中。

打开性能测试必须直接进入目标编辑器。正式入口直接启用 Monaco；旧实验的
`--native-editor` 对照开关已经移除。先创建 NSTextView 再切换 Monaco
会混入原生字形布局成本；实际采样已在此路径看到大量 NSLayoutManager 样本。
资源目录只检查一次；已删除按换行格式筛选编辑器的资格检查，避免 LSP 状态
变化触发反复全文复制扫描。切回已有模型只发送身份，不重新传全文；模型和撤销记录仍由 Monaco
维护，光标与滚动状态单独保存。

基础语法注册、语言映射和自定义语法已从 Windows 抽到共享包；两端等待对应
分词器就绪后再建立模型。macOS 按 Monaco 注册表中的文件名/扩展名选择语法，
未知扩展名使用纯文本。Windows 的 TypeScript、JSON 等内置语言服务仍在宿主
注册；共享语法模块不启动这些服务。不能把支持上色等同于支持该语言的 LSP。

Java 基础着色现在使用 TextMate（按语法规则识别颜色的引擎）及 VS Code 的
Java grammar。主线程只保留 Monaco 要求的可见行同步接口，整份文件由独立
Worker 按 8 ms/128 行分片处理；隐藏标签暂停、再次挂载继续，关闭释放镜像。
普通输入只传 UTF-16 增量，合并短时间输入后从失效行重算；主题切换重建颜色。
源文本镜像使用共享片段的不可变平衡树，将 Monaco 的归一化 UTF-16 偏移转换为
原文偏移；撤销版本共享未改动片段，不能每次输入都缓存完整文件。插入换行沿用
首次打开文件的第一个换行样式；未修改的换行保持原样。删除裸 CR 和 LF 之间
的文本时，新连接的 CR 改为 LF，避免两个逻辑行折叠成一个 CRLF；撤销恢复原字节。
此时同步增量覆盖相邻字符，并合并重叠范围；范围不能截断 emoji 的 UTF-16 字符对。
语言同步按 CR、LF、CRLF 计算行号，与 Monaco 的模型坐标一致。
Windows 编辑器也通过共享 `model-source.ts` 为每个模型保留一份原文镜像；
React 各面板观察同一转换结果，不各自猜测 CRLF 偏移。LSP 增量的行列取自
修改前的原文。外部重载会重建源文本版本映射，因为 Monaco 的 `setValue`
清空撤销栈并重置版本；保留旧映射会让新编辑错误命中旧撤销记录。来自其他
面板的相同内容回传不能再次重置模型，否则会丢失新建的撤销记录。
后台响应同时校验模型身份和版本，旧结果不进入当前 token store。
模型构造期间版本号尚未初始化，因此必须等构造结束后再向 Worker 发首份镜像；
否则后台虽然在计算，所有结果都会被版本保护丢弃。此边界由真实 WebKit 测试覆盖。
Worker 异常时记录错误并退回 Monaco 默认后台分词，不能把分词故障当成保存失败。

语义颜色使用现有 JDTLS 会话的标准 `semanticTokens/full`，由 Rust 统一解码
相对位置并携带请求时的 legend（服务器定义的 token 类型表）。动态注册、
取消、超时、文档版本和服务器刷新通知沿用现有会话生命周期；不另起 Java 进程。
Monaco 的原生语义着色调度负责去抖，适配层按文档版本和刷新代数缓存、合并请求。
语言请求错误不再触发编辑同步故障；缓存失效和迟到结果丢弃有受控桥接测试。
目前仍不是 VS Code 的完整工作台、主题体系或所有编辑功能。

### VS Code 源码参考

参照 `microsoft/vscode` 的 `bb000da79d34c2d5baa3b2c26a5cd1012616977b`，
本轮借鉴生命周期设计，复制同提交的 Java grammar，并在 `frontend/editor/` 锁定
`vscode-textmate` / `vscode-oniguruma`。源码出处、许可证和 WASM 随资源打包；
普通 macOS 应用构建现在需要清单锁定的 Bun；纯 Swift 单元测试仍不依赖 Bun。
共享构建器只接收入口和输出路径，不能读取实验或平台实现目录；macOS 在
`macos/EditorFrontend/build.ts` 指定正式入口，实验宿主复用相同打包函数。
CI 的 macOS 打包任务按共享包清单安装 Bun。TextMate 后台接口使用固定版本的 Monaco 内部
API，升级 Monaco 时必须重新跑实际 WebKit 集成测试。

- [TextFileEditorModelManager](https://github.com/microsoft/vscode/blob/bb000da79d34c2d5baa3b2c26a5cd1012616977b/src/vs/workbench/services/textfile/common/textFileEditorModelManager.ts)：复用模型，合并同一资源的并发解析。
- [TextFileEditor](https://github.com/microsoft/vscode/blob/bb000da79d34c2d5baa3b2c26a5cd1012616977b/src/vs/workbench/contrib/files/browser/editors/textFileEditor.ts)：模型挂载与视图状态恢复分离。
- [TextMateWorkerTokenizer](https://github.com/microsoft/vscode/blob/bb000da79d34c2d5baa3b2c26a5cd1012616977b/src/vs/workbench/services/textMate/browser/backgroundTokenization/worker/textMateWorkerTokenizer.ts)：分批处理失效行、约 20 ms 后让出执行、版本化回传。

工作台编辑直接更新现有 `EditorDocument`，并调用现有文档变化与断点重定位
入口。Diagnostics 使用现有诊断存储；Hover、补全和 F12 导航通过 `AppModel`
现有语言能力入口。迟到的语言结果按文档和版本丢弃，不启动第二个语言会话。
高频滚动留在 Web 页面；配置和诊断去重后才跨桥发送。

真实 Java 验证必须先确认 JDTLS 接受增量同步，再观察有意制造的类型错误、
补全和跳转；仅有 Java 进程或桥接调用代码不能证明语言服务已工作。实测曾发现
Swift 同步桥接把内部位置字段编码为 `character`，Rust 要求 `utf16Column`，
导致编辑在进入 JDTLS 前就失败。桥接回归测试经过真实 Rust 解码后检查会话查找，
不启动服务器，防止这类协议错误被空响应夹具掩盖。
语义颜色来自真实 JDTLS，基础颜色来自 TextMate；这与原生 Rust Java 结构分析
的实现不同，不能仅凭两个编辑器的颜色近似就宣称全部功能等价。

原生保存和关闭一个标签页前，通过文档的同步回调冻结对应 Web 模型输入，
排空编辑队列，再核对版本和文本。在这个有界回调范围内才允许同步保存；
失败保留文档和 dirty 状态。文档以强引用保留适配器、适配器以弱引用保留文档，
因此临时切走 SwiftUI 页面不会立即丢失消息处理器，也不形成循环引用。
平台按 `AppModel.id` 用弱注册表复用会话，避免经过 Markdown 或媒体分支后
重新创建一个竞争的 WebView。同步文档时冻结该模型的所有视图，不能只冻结当前有焦点的视图。原生视图宿主
每次挂载取得独立所有权标识；旧视图最后一次更新或卸载只能影响自身，不能
覆盖新分屏布局。缺少资源时不能绕过远程同步保护改用另一个编辑实现。
共享运行时已支持同一页面中的多个 Monaco 视图：视图各自保存光标和滚动位置，
同一文档只创建一个模型、一份源文本镜像和一条同步队列。保存冻结该文档的全部
视图；关闭副视图不释放文档，文档关闭才释放模型。创建视图按激活队列串行执行，
关闭操作使尚未完成的挂载失效，避免异步语法加载结束后复活已关闭的面板。
原生分屏入口已接入该多视图 API，一个 WebView 覆盖两个文本面板；宿主按
面板分别记录激活文档，右侧保存、悬停和补全携带自身文档，定义跳转携带自身
文件位置，不能借用左侧活动标签。共享生命周期已由真实 WebKit 覆盖；原生
菜单保存跟随最近获得编辑焦点的文档，选择标签时重置；直接保存右侧文档和
菜单焦点切换均有存储结果回归测试。导航目标和真实分屏操作仍须进一步验收。
切换期间及禁用后，迟到的 SwiftUI surface 更新不得重新取得文档所有权，
否则界面虽然已显示原生编辑器，保存/退出仍会被远程同步回调拦截。

正式改造已恢复远程文档自动保存，并将 Save All、窗口与应用退出改为异步等待
同步。并发保存与关闭共用一次同步；每轮标识拒绝旧回执，防止误释放下一轮。
批量关标签和项目关闭先同步最后一次编辑，再判断是否提示保存。自动保存的
代次校验使取消或更新后的任务不能保存旧内容；退出期间继续输入的完整事务
保护仍需后续验证，不能仅凭这些回归测试宣称正式替换完成。
外部文件更新会保留撤销历史地传入模型，但若与正在输入的版本冲突，显式失败，
不覆盖较新输入。WebContent 崩溃不自动切换或销毁文档，避免误把旧快照当成最新。

正确做法：先确认真实 Worker 能通过 Monaco RPC 读取同步后的文档镜像，
再记录滚动数据。不要只验证 Worker 可以创建，就声称编辑器没有退回主线程。

正确做法：报告 `requestAnimationFrame` 回调间隔，并注明程序化滚动、窗口尺寸、
构建配置和负载。不要把这个数据称为输入延迟、GPU 帧时间或触控板手感。

自动实验保持窗口可见，并在支持的系统上关闭非活动页面调度限制，避免窗口被
遮挡后暂停动画回调。该设置仅用于有界测试，不是产品后台标签页的调度策略。
单场景及桥接均有 15 秒截止时间，原生宿主另有 120 秒退出保护；手动窗口最多
保留 10 分钟。报告和截图写入 `.artifacts/`，退出时释放页面与消息处理器。
锁屏也会暂停动画帧，因此自动渲染验证要求屏幕解锁并保持点亮。`--logic-only`
可独立验证桥接和 Worker；它跳过渲染、滚动及截图，结果明确记录
`renderingValidated: false`，不会覆盖完整渲染运行的结果。

## 考虑过的备选方案

### 直接接入正式编辑器

可以更快看到工作台效果，但会把原生菜单、未保存文档、跨标签页撤销和异步
语言结果接入同时带入第一轮验证。先用独立宿主隔离这些变量。

### 在 Chrome 或 Safari 网页中测试

可以验证 Web 代码，却无法证明 WKWebView 的资源加载、Worker 和 Swift 桥接
可用。当前实验必须运行真正的原生 WebKit 宿主。

### 建立完整跨平台编辑器包

在宿主是否可用尚不明确时抽取全部 Windows 功能，成本太高。当前复用少量纯函数（包括 Windows 的语义 token 编码），共享语言能力与文档
接口的正式包结构仍属于后续设计工作。

## 后果

收益是获得可重跑的宿主验证和可切换的真实文档实验，并让预览、发布与验证
共用资源构建。代价是新增一条需要逐步收敛的 Web 桥接路径。独立宿主仍仅保存实验副本；
工作台版通过 Lithe 保存真实文件，不能把两者的保存行为混淆。
工作台同步字体大小、字体族、明暗主题及折行。默认语法和语义颜色读取原生
`color-mappings.json`，不复制一套色值；用户自定义主题尚未完整映射。

自动测试中的 Unicode 编辑不等于真实中文或日文组合输入。输入法候选窗口、
触控板动量、VoiceOver、原生快捷键、跨进程总内存、崩溃恢复和 NSTextView
对照采样仍需单独验证。当前文本入口默认使用 Monaco，不代表全量替换已经验收。

## 验证

已打开文档改名时，共享工作台重新确定语言并先加载对应语法，再更新现有模型
的语言，不替换文本或模型。这样从 Swift 改为 Python 后，行注释也随语言改变，
原有撤销历史仍保留。`.env` 注册为 dotenv，复用 Shell 的赋值和注释语法，
不能降级为无注释规则的纯文本。真实 WebKit 回归覆盖改名、注释、撤销及原生同步。

真实工作台已用约 11,200 行 Maven Java 文件验证：JDTLS 发布故意制造的
`int` 到 `String` 类型错误；Monaco 修改后错误变为未使用字段警告；
`toString(): String` 补全可接受并保存，磁盘回读一致；悬停返回完整方法签名，
定义导航定位到声明行；服务保持运行时可长距离滚动。此结果证明真实语言链路
可工作，不是严格的性能对照。本轮最终 Release 副本在同文件收到 7,011 个 JDTLS 语义 token。一次可见窗口
样本中模型建立约 11 ms、挂载约 30 ms、首个动画回调约 47 ms；1.5 秒内记录
87 个动画帧回调、一次超过 50 ms 的间隔（最大 57 ms）。这是一次启动采样，
不是触控板延迟或最终无卡顿证明。前置窗口后确认第 10,000 行附近的语义颜色和
基础颜色正常显示。WebKit 的 9 组集成检查覆盖缓存、
