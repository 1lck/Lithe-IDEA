# Agent 笔记：编辑器查找与恢复副本的职责

状态：已实现

## 先说结论

文件内查找、显示设置默认值、最近访问顺序、快捷键方案转换和恢复冲突判断由 Rust Core 决定。
桌面端只负责原生文本缓冲、绘制和文件读写。恢复副本独立于自动保存，关闭 Scratch 标签会保留内容，
遇到磁盘文件改变时必须由用户明确选择保留编辑器或载入磁盘。

## 问题

Viva（桌面界面框架）的编辑器已经拥有不可变文本树，重新在 Core 维护全文会增加常驻内存。
把全文塞进 JSON 请求也会在每次查找时产生多次转义和复制。另一方面，正常退出时保存标签位置不能
恢复崩溃前尚未写入文件的内容；自动保存关闭时也必须有独立的恢复路径。

## 决策

- 桌面端在窗口线程取得不可变文本快照，后台工作线程经借用式 C ABI（同步调用期间共享字节的跨语言接口）
  提供 UTF-8 数据。Core 只返回有界的原始字节范围和替换计划，不缓存源文件。
  原生文本树、行宽计算和单步撤销的准备在后台完成，回到窗口线程再次检查快照、查询代数和文档归属。
  关闭查找栏、文档或项目会取消查询和定时器，过期结果不得修改编辑器。
- 显示偏好经过 Core 解析后才交给绘制。最近文件的排序、过滤和逻辑顺序不依赖墙上时钟。
  原生工作队列保持同一窗口事件顺序，多个窗口的历史文件读写在原生边界串行完成。
  快捷键方案保存独立绑定，切换方案同时切换实际工作台分发所用的绑定。
- 恢复适配器使用平台用户配置目录下的 `Lithe Desktop/EditorRecovery/`。
  每个 `.draft` 文件包含小型元数据头和原始 UTF-8 内容；后台流式写入私有临时文件、同步后原子替换。
  临时文件与最终文件在同一个目录，既不会混用两个代数，也不需要复制整篇内容到 JSON。
  所有窗口共用原生写入锁，检查 Core 给出的单文档、总字节数和条数限制后再写入。
- 编辑器输入只安排短暂的合并定时器。实际写入由一个有界队列合并同一文档的快照；保存或丢弃操作在旧写入之后执行。
  项目、窗口关闭时先提交最后的快照、停止定时器，再等待所属后台任务结束。
  普通文件保存成功后移除恢复副本；Scratch 关闭时保留，另存为成功或明确丢弃才移除。
- 恢复时比较保存前基线摘要和实际磁盘内容。文件改变或消失时保留冲突；文件监听只比较重启后观察到的
  磁盘基线，不能据此自动确认崩溃前的冲突。用户选择保留编辑器或载入磁盘前，手动保存和自动保存都不得覆盖磁盘。
  更晚的外部修改仍由既有原生受保护写入检查拒绝。

正确做法：查找请求 A 返回前文本发生变化，丢弃 A；后台队列收到新快照后又收到保存成功通知，最终删除副本。
不要这样做：绘制时展开全文并查找、让旧替换结果修改新版本、把文件监听观察到的“未变化”当成恢复冲突已获用户确认。

## 考虑过的备选方案

- 在 Core 保留第二份文本：会重复原生编辑器的文档所有权，拒绝。
- 全文 JSON 请求：会转义和复制整个源文件，拒绝。
- 只依赖自动保存：用户关闭自动保存或发生外部修改时不能保障恢复，拒绝。
- 把草稿放到项目或发行包：会污染工作区，或者改变签名与增量更新基线，拒绝。
- 自建正则引擎：Core 已有成熟 `regex` 依赖，直接使用 Unicode 匹配和捕获组替换。

## 后果

查找需要后台临时连续字节快照，原生文本树仍是唯一长期全文所有者。恢复写入是编辑后短暂合并的检查点，
崩溃发生在检查点完成前时，最后一次检查点之后的按键无法保证恢复。配额满时明确报错并保留编辑器内容，
不静默淘汰未保存的用户数据。恢复文件和最近文件属于可变用户状态，禁止通过工作树资源复用流程共享。
它们始终位于安装目录之外，不影响代码签名和 Sparkle 增量更新。

## 验证

- `desktop/internal/workbench/editor_essentials_test.go`：替换、单步撤销、过期隔离、磁盘冲突保护、草稿持久化与最近访问。
- `desktop/internal/settingswindow/editor_essentials_test.go`：实际设置回显、方案独立、切换、重复名称和默认方案保护。
- `desktop/internal/draftstore/store_test.go`：原子覆盖、重建适配器读取和配额拒绝时原内容保持。
- `editor_essentials_visual_test.go`：以真实 Page 无头渲染深色中文与浅色英文界面。
- Core 的可执行向量为 `rust/fixtures/editor/ide-essentials-v1.json`，借用式 C ABI 测试同时检查空指针和非法 UTF-8。
- 编辑器改动前后各运行六次原有性能基线；原生窗口与 Windows 平台验收独立记录，不能用无头截图代替。

## 适用范围

`desktop/internal/editorview/`、`desktop/internal/draftstore/`、工作台的 `editor_find.go`、`editor_recovery.go`、
`recent_files.go`、`scratch_files.go`，以及设置窗口相应组件。共享规则和正式接口文档属于外部 Core 仓库，
本笔记不作为第二份协议参考。
