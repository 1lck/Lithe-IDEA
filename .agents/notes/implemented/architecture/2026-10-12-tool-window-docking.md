# Agent 笔记：工具窗口停靠与布局保存

状态：已实现

## 先说结论

工具窗口的位置由工作台维护，功能模块继续维护自己的内容、连接和会话。用户可以移动入口、调整组内顺序，并在左侧、右侧和底部的分组中分别打开窗口。模块的默认位置与用户保存的位置分开处理，移动窗口只改变位置，不重建功能内容。编辑器标签分屏由编辑分组维护，见同目录的编辑器标签分屏 Note。

## 问题

工具窗口如果固定分配给某一侧，只移动入口图标并不能改变实际内容的位置；标题栏收起还可能关闭最后选中的侧栏，导航侧栏又另有一套状态。

## 决策

位置包含停靠边缘及主、次分组。一个分组只显示一个窗口，其他分组保持独立。内置窗口使用稳定标识，位置与顺序由工作台的布局状态管理；已有的模块注册表负责动作和内容的查找。

停靠分组包括左侧、右侧和底部，左右两侧各有上下两个分组，底部有左右两个分组，共六组。入口的右键菜单"移动"子菜单按左侧、底部、右侧和前移、后移排列，再用分隔线区分六个精确的分组，避免一级菜单平铺过长。拖到工作区边缘也可以选择实际停靠分组。

入口标识与内容标识分开：入口隐藏只影响入口是否显示；用户主动隐藏才改写保存的展开状态，资源清理不能伪装成用户布局编辑。模块禁用或缺失时关闭其内容和入口，但保留位置与顺序偏好。

布局按工作区保存。旧数据缺少新字段时保留已有尺寸并采用默认位置。恢复时忽略未知或重复的窗口标识，纠正负顺序和同组多个可见窗口。恢复内置或插件窗口时按贡献归属激活所属模块，只打开，不切换关闭。等待激活时用户关闭窗口或选择另一窗口，激活结束后不能重新抢回。

临时显示请求按停靠组记录：首次打开、显示和布局恢复都会产生请求，激活完成时只提交仍属于该组最新请求的窗口。同组 A 等待期间若用户选中 B，A 不能抢回选择；不同组互不取消。用户显隐、移动和布局重置会使相应请求失效，这些请求标记不写入持久布局。

拖动过程只维护局部几何；松开后才原子地移动并保存。Esc、无效落点、窗口失去激活状态和卸载都会清理拖动预览。项目切换时取消未完成的按下和预览，旧项目不能在释放时提交移动。

## 考虑过的备选方案

- 只对图标添加拖动：无法改变窗口实际位置，固定分配仍会把内容送回原区域。
- 直接引入 IDEA Swing 容器：与当前技术栈不同，需要更换整个呈现层。本次参照其状态和提交边界。
- 同时开放插件 UI 和编辑器分屏：涉及外部代码契约、编辑器文档和视图生命周期，独立 PR 更容易验证。

## 后果

现有内容可以在不同区域显示，位置、顺序与尺寸可以在重启后恢复。代价是新增内置工具窗口必须提供稳定标识和默认布局。移动可能重建呈现容器，但功能状态仍归原模块所有；终端和编辑器等原生资源必须遵守既有的挂载生命周期，不能因为移动而重建会话。
