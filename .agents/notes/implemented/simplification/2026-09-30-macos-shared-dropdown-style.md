# Agent 笔记：下拉菜单与列表选中的共享视觉基准

状态：已实现

> Viva 迁移说明：旧 macOS 客户端的 SwiftUI/AppKit 菜单呈现器、测试与截图基线已删除。本文只保留仍约束 Viva 桌面端的共享视觉与交互决策；具体数值以代码常量和主题表为准，不在本文重复。

## 先说结论

Viva 桌面端的产品下拉菜单、右键菜单、分支与搜索等弹层共用一套菜单行样式和行高，调用方只提交条目、动作、可用条件和锚点，不各自绘制外框。树和列表的选中色按“列表有键盘焦点”与“失去焦点”两种状态切换，颜色来自主题表。新增或修改菜单时改共享入口，不在页面里复制行高、留白或颜色。

## 问题

旧 macOS 客户端的下拉框、右键菜单、树和列表样式分散在多个组件里，同一类控件在不同页面外观不一致，且修复一处时其他页面不会同步。Viva 迁移后，工作台和设置窗口仍需要同一个视觉来源，否则菜单行高、选中色和焦点状态会各自漂移。

## 决策

- 菜单行高与内边距由 `desktop/internal/workbench/chrome.go` 的常量统一定义（项目菜单的行高与分支弹窗的行高保持一致），紧凑菜单（`desktop/internal/workbench/compact_menu.go`）与右键菜单属于同一产品菜单族，使用同一组行尺寸。
- 调用方提供条目、动作、禁用条件、子菜单和锚点位置。菜单的外框、行高、留白、选中与悬停色由共享入口负责；页面不另画外框，也不按截图猜测新样式。
- 菜单宽度由各入口自己的常量决定（如项目菜单的 `chromeMenuWidth`），不要求不同菜单同宽。
- 选中色有两种：列表或树拥有键盘焦点时使用活动色，窗口或列表失焦时使用失焦色。颜色定义在 `desktop/internal/workbench/theme.go` 的 `Selection` / `SelectionIdle` 与 `desktop/internal/settingswindow/palette.go` 的 `selection` / `selectionIdle`，页面不写死 RGB。
- 树与列表的行尺寸（行高、缩进、箭头与图标尺寸、两侧留白）由 `desktop/internal/treelist/treelist.go` 统一提供，项目树与 Git 工具窗口的文件列表共用，同一名称在任何列表中外观一致。
- 菜单与列表中的图标使用仓库已导入的官方 SVG 原色资源，不用系统符号近似，也不按菜单文字猜测图标。
- Search Everywhere 的候选枚举、索引和排除规则由 Core 持有（`desktop/internal/core/workspace.go` 说明了发现与排除的归属）；界面只提交用户设置与查询，不在界面层复制排除逻辑。
- 菜单文字与所有用户可见文案走 `shared/i18n/`。

## 考虑过的备选方案

- 每个页面自绘菜单：否决。外框、行高和焦点色会分叉，修复一处无法覆盖其他入口。
- 直接使用各平台原生菜单：否决。原生菜单的行高、选中色与主题无法跨平台保持一致，也无法与工作台的紧凑布局对齐。
- 为每类菜单保留独立的尺寸常量：否决。会让同一类行在不同入口里看起来不同，只保留确有语义差异的常量（如宽度上限）。

## 后果

- 修改菜单外观或选中色只需改共享入口与主题表，调用方不需要同步改动。
- 代价是各平台的原生右键菜单不再保持系统外观，换取跨平台一致的行高和主题色。
- 宽度、行高等数值以代码为准，本文不再记录旧 macOS 版本的像素数值，避免与代码漂移。

## 验证

- `scripts/desktop/desktop-go.sh test ./internal/workbench/...`：覆盖菜单与树行的构建和行为测试。
- `scripts/desktop/desktop-go.sh test ./internal/settingswindow/...`：覆盖设置窗口的选择与列表颜色。
- 在 Viva 桌面端实机检查深色与浅色主题、键盘上下选择、点击外部关闭、窗口失焦后的选中色，以及菜单在窗口边缘的定位。组件测试不替代这项原生验收。

## 适用范围

- `desktop/internal/workbench/`
- `desktop/internal/settingswindow/`
- `desktop/internal/treelist/`
- `shared/i18n/`
