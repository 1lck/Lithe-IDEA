# 日志接入

新增、迁移或审查日志事件、写入器和诊断采集时遵守本页。通用规则见
[Lithe 开发规范](../SKILL.md)；路径均相对于仓库根目录。
事件声明、字段编码、限额、生成器和扫描范围的唯一规则来源是
`shared/logging/README.md`。本页规定开发动作，不另列一套会漂移的语法或参数表。

## 何时记录与如何选择级别

记录能回答“哪个操作、处于什么阶段、结果是什么、耗时多少”的事实：应用或组件的生命周期里程碑、用户操作的终态、功能降级、自动恢复和影响用户的失败。不要把函数调用轨迹当成普通日志，也不要重复 UI 已有状态而不增加排障信息。

| 级别 | 接入规则 |
| --- | --- |
| ERROR | 操作失败且影响用户。在拥有处理决定和足够上下文的边界记录。 |
| WARN | 功能降级，或失败后已自动恢复；结果并未成为影响用户的操作失败。 |
| INFO | 生命周期里程碑和有排障价值的操作终态，不记录每个内部步骤。 |
| DEBUG | 仅用于详细诊断；正常运行不依赖它才能知道关键操作是否失败。 |

级别在事件目录中声明，不能由调用点传任意字符串。是否影响用户取决于处理结果：内部重试后成功可记 WARN，最终无法完成用户请求才记 ERROR。不要把所有上游 ERROR 标签机械地升级成产品 ERROR，也不要用 INFO 掩盖真正失败。

循环、逐按键、逐帧渲染及其他高频路径不得用 INFO 逐项记录。确有诊断价值时使用生成的 DEBUG 事件或发送侧有界汇总，并按目录声明 rate；不要通过提高额度、绕过队列或直接打印解决过载。rate 的运行时执行状态以共享 README 和实际宿主实现为准，声明元数据不等于已限流。

## 只使用目录生成的事件

1. 先调查真实调用和消费者，确定 owner、通道身份与需要保留的事实；没有实际来源不预造事件。
2. 新增事件先修改 `shared/logging/events/<root>.json`，按共享 README 声明稳定 ID、通道模板、英文消息、级别及字段含义。字段说明必须解释本事件中的来源、语义和单位，不能用类型通用短语凑说明。
3. 运行 `node scripts/logging/generate-log-events.mjs`，审查生成的 Swift 类型和 Rust 静态目录。不得手改 `LogEvents.generated.swift` 或 `catalog_generated.rs`。
4. 调用生成的事件类型与 span，把类型化输入交给宿主统一日志入口；Rust 使用生成目录及共享边界。不得手写事件 ID、自由消息或字段字典来规避目录声明，不得自行实现一套序列化或脱敏。

生成事件是尚未脱敏的内存输入。实际落盘必须经过 Core 的目录字段校验、共享脱敏和编码；单独通过类型检查或通用编码器不足以证明隐私安全。路径由平台可写存储适配器提供，不从 bundle、插件安装目录或 Windows 安装目录派生。

消息是供诊断使用的英文事实，沿用共享 README；显示给用户的按钮、提示和错误说明仍走共享 i18n，不把日志消息直接当界面文案。

## 一个操作、一条终态、一个错误处理边界

- 成对操作使用生成的 span（持有开始时间并生成终态耗时的值），由一个调用方拥有。成功调用一次 finish，失败调用一次 fail，生成一条带耗时的终态；不要再手工补“结束”记录。begin 总会产生一条 DEBUG 级别的 started，是否落盘由写入端按级别和详细诊断通道过滤；具体生成行为见共享 README，不另写一套开始日志。
- 不复制 span 以产生多份生命周期，不用墙钟差值计算耗时。跨异步边界保留同一个操作所有者和单调计时上下文。
- 有实际操作上下文时传 `operationID`，让持久化层用 `op` 关联跨模块证据。不要把 op 重新声明为普通字段，不用用户内容作为操作编号，不为每个下层函数重新生成编号切断关联。
- 错误只在处理它的边界记一次。下层把错误及稳定分类返回；上层决定恢复、降级或告知用户时记录。不得“记录后再抛出”，让同一次失败在多层反复出现；span 的 fail 已经记录该操作失败时，不再额外写相同错误。

例如 Git 命令由拥有该命令生命周期的调用方 begin，再按真实结果 finish 或 fail；底层进程适配器返回退出码和结构化错误。不要在进程适配器打印一次、Git 服务 catch 后再打印一次、UI 再记录同一次失败。

## 字段选择与隐私

选择能表达事实的最窄类型，不把结构化信息拼进 message 或自由文本：

| 信息 | 选择原则 |
| --- | --- |
| 计数、开关、耗时、体积 | 使用 int、bool、duration、bytes，单位与编码依共享 README。 |
| 身份、阶段、版本 | 身份用 id；受控短词用 token；版本用 version。id 必须来自已验证的真实身份，字符合法不等于来源可信。 |
| 文件位置 | 使用 path，由共享边界脱敏，不自己拼用户绝对路径。 |
| 失败 | 使用 error，保留稳定 code/domain 等结构化类别，不传未清理的整段错误转储。 |
| 无法结构化的上游诊断 | 仅在必须保留 stderr 行、LSP logMessage 等上游诊断时使用 text。必须在声明中写 reason，说明为什么结构化字段不能代替；“方便调试”不构成理由。 |

不得记录源码、编辑缓冲区、环境变量值、命令输出、凭据、终端历史或协议正文，也不得塞入 text、error、token、路径或消息模板绕过。命令只记录受控名称、阶段、退出码与耗时，不记录完整命令行。stderr 的上游诊断例外不等于允许复制构建输出或协议载荷，仍须按共享规则脱敏和截断。

每个动态通道段必须能追溯到已校验的插件、provider、server 或内部连接 ID。不得使用主机名、显示名称、项目路径和任意用户输入；解析失败按既有错误边界处理，不对未知输入强制解包。

## 用法检查与基线

生产日志不得通过 NSLog、直接 stderr、os_log/Logger、字符串 record 或 Core 的直接打印绕过统一入口。具体可扫描写法、排除范围和检查局限以共享 README 为准；不要利用别名或动态调用逃避门禁。

`log-usage-baseline.json` 只承接 PR2/PR3 待迁移的存量，计数只减不增。修复了某文件某规则的调用，就同步减少或移除对应项；不得给新违规加基线、增大计数、移动旧违规规避比较，或留虚高计数作额度。永久例外写在独立 allowlist，必须给出具体协议或架构理由与精确计数；迁移机器性能标记时同步消费者，不能直接删掉其协议输出。

macOS 从服务构造器、`AppServices.logSink` 或模块激活时的 `ModuleContext.logSink` 获取组合根注入的同一 sink；不得新增全局可变日志单例。`LogScope` 携带同一操作的 op 和可信身份，目录继续决定通道；成对操作在操作前 begin，在拥有操作结果的边界 finish/fail。路径传 URL，错误传 Error，不先拼成字符串。启动早期适配器只有在有界缓存类型化事实后等待注入，不能另建自由字符串通道。

macOS 时间线和导出只向查询提供 v2 会话文件；v1 文件只进入保留清单并按 30 天自然过期。Rust v1 API 与旧命令继续兼容 Windows。剩余 Rust 基线原因使用“PR3：经运行时事件流交给宿主”。

验证入口：

```sh
node scripts/logging/generate-log-events.mjs --check
node scripts/logging/verify-log-usage.mjs
```

修改目录、生成器或门禁本身时，再运行
`node --test --test-timeout=60000 scripts/logging/test-log-events.mjs`，以及直接受影响的 Core 或宿主测试；遵守测试 Skill，不为局部日志改动运行无关全量构建。只读核验只用 `--check`，不执行写生成物的命令。

## 审查清单

- 事件有真实来源和 owner，记录结果所需信息，级别符合用户影响；高频路径没有 INFO 逐项输出。
- 声明先于调用，使用生成类型；没有手写 ID、消息、字段字典、第二套 writer 或直接打印绕过。
- 同一操作只有一个 span 所有者和一条终态；错误只在处理边界记录，已有操作身份通过 op 延续。
- 动态段来源可信且经过校验；字段类型最窄，description 具体，text 的 reason 解释不可替代性。
- 无禁止内容；类型化输入没有直接序列化落盘，目录校验、脱敏与编码的实际边界清楚。
- 生成物检查和用法检查通过，基线只减少；例外有真实理由，协议消费者同步。
- 写入、查询、保留和导出保持有界，文件位于平台可写存储；不把 PR1 元数据、删除计划或组件测试当成运行时验收。
