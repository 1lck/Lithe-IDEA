# 本地代码审查输出格式

始终使用简体中文。

```markdown
## Lithe Review

**结论：** ✅ 未发现明确问题 / ⚠️ 建议修改 / ⛔ 存在阻塞问题 / ❓ 信息不足
**范围：** `目标分支 ← 当前分支` · `commit range 或工作区状态`

### Findings

1. **[P1] 简短且可执行的问题标题**
   `仓库相对路径:行号`

   - 实际影响：
   - 触发条件：
   - 复现步骤：
   - 来源：本次引入 / 本次加剧

### Scope Check

- 关联 Issue 或需求是否完成：
- 已完成范围：
- 未完成范围：
- 是否复用了已有上游能力，或对自研边界给出充分证据：
- 每个 Finding 是否由本次变更引入或加剧：
- 是否属于本次变更职责范围：

### Suggestions

1. 与 Finding 1 一一对应的具体修改建议。

### Summary

简要评价正确性、架构一致性、可维护性、测试充分性和后续扩展成本。

### Verification

- 实际检查的文件、提交和调用链：
- 已提供的测试或 CI 结果：
- 本次未运行的测试：
- 仍存在的非阻塞风险或平台验证缺口：
```

没有实质性问题时必须明确写：

> 未发现需要阻塞合并的问题。

此时省略空的 Findings，保留必要的 Scope Check、Verification 和非阻塞风险。
