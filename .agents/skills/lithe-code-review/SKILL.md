# Lithe 提交前代码审查

这是给开发者在本机提交 Pull Request 前使用的自审 Skill，不替代
GitHub Actions 中的最终 PR 审查。它只在用户明确要求审查时触发，不因为
工作区存在修改就自动启动。

## 触发条件

以下请求应触发本 Skill：

- “提交 PR 前帮我 review 一下”
- “检查当前分支能不能提 PR”
- “审查当前工作区或这次改动”
- “帮我做一次代码自检”
- “检查有没有遗漏的测试、契约或跨平台问题”
- “review 这个 commit range / branch / diff”
- 用户明确输入 `$lithe-code-review`

以下请求不单独触发本 Skill：

- 实现功能、修复 Bug、解释代码、运行测试或普通重构。
- 只要求审查文档、发布说明或视觉材料。
- 只要求提交代码或创建 Pull Request。

如果用户同时要求实现和审查，先完成实现，再对最终变更执行本 Skill。

## 必须遵守的边界

开始前加载并遵守：

1. `.agents/skills/develop-lithe/SKILL.md`
2. 与本次变更相关的 `AGENTS.md`、Agent Notes、共享契约和测试规则。
3. 如果变更涉及测试，再加载 `.agents/skills/write-stable-tests/SKILL.md`。

审查默认只读，不修改文件、不提交、不推送、不创建 PR。除非用户另外明确
要求验证，否则不启动应用、不运行完整测试、不访问网络。

## 确定审查范围

按以下优先级确定范围：

1. 用户明确给出的提交、分支、文件或 diff 范围。
2. 当前分支相对目标分支的差异。
3. 当前分支已提交但尚未合并的提交，加上 staged、unstaged 和 untracked 修改。

先报告实际采用的范围。无法确定目标分支或变更边界时，不得擅自扩大到整个
仓库；将结论标记为“信息不足”并说明缺少什么。

只审查当前范围内的改动，以及这些改动直接影响的调用链、契约、测试和文档。
不要要求本次改动顺手修复历史问题、无关架构债务或未被本次改动恶化的大文件。

## 审查政策与输出

读取并遵循：

- [本地审查流程](references/local-review.md)
- [统一审查政策](references/review-policy.md)
- [严重程度与证据规则](references/finding-severity.md)
- [输出格式](references/output-template.md)

审查结束时，明确区分提交前必须修复的问题、建议修改项、观察项和信息缺口。
没有实质问题时，明确写出“未发现需要阻塞合并的问题。”，并列出仍存在的
测试、平台验证或范围限制。
