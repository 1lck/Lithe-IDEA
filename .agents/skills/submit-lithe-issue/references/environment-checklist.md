# Issue 环境信息核对清单

本清单是 `submit-lithe-issue` 信息采集的必读参考。每次报告都核对基础信息，
再逐类判断下面的条件项是否与现象有关；相关项必须覆盖，不能只记录一个系统名
和几项工具版本就结束。这里只规定采集范围，不增加或替换 GitHub Issue 模板。

## 覆盖与记录方式

- 基础项逐项核对；条件项按涉及的模块、运行边界和故障类型补齐。功能建议记录
  当前工作流的相关环境与目标平台，不要求用户执行与诉求无关的故障诊断。
- 每项区分“已确认”“未采集（原因）”“不适用（依据）”。“未采集”不表示已满足
  必要条件；缺失的信息若影响模板必填或问题判断，必须继续采集或追问。
- 记录信息来源：用户描述、关于页、诊断导出、实际进程/工具输出或配置。日志与
  资源快照写明故障/采样时间和时区；来源冲突时先核实，不擅自选择一个结果。
- 多机器、远程或虚拟化场景分开记录 UI 所在机器、项目/语言服务所在机器、
  构建/运行/调试目标；使用 `<LOCAL>`、`<REMOTE>` 等脱敏标识说明对应关系。
- 不因有清单就转储整个系统。只公开与问题有关的必要信息，遵守 Skill 的脱敏
  规则；设备序列号、凭据、业务数据和完整用户配置都不属于环境必需信息。

## 环境信息的脱敏要求

以下规则适用于采集输出、Issue 草稿、搜索关键词、正文及附件；具体脱敏流程
以 [Skill 的脱敏规则](../SKILL.md) 为准。“完整覆盖环境”不代表公开原始值。

| 环境信息 | 必须脱敏的内容 | 保留的诊断信息 |
| --- | --- | --- |
| 路径与项目 | 用户名、主目录、私人项目/仓库名、客户名、内部包名；统一使用 `<USER>`、`<WORKSPACE>`、`<PRIVATE_PACKAGE>` 等占位符。 | 必要的相对结构、文件类型，以及长路径/空格/中文/大小写等触发条件；必要时用合成示例保留这些特征。 |
| 主机与网络 | 主机名、内网 IP/域名、私有仓库/镜像/代理地址、租户和账户标识；不同对象用 `<HOST_1>`、`<HOST_2>` 区分。 | 本地/远端归属、协议、网络类型、代理模式、必要的端口关系和错误码。 |
| 凭据与配置 | Token、密码、Cookie、Authorization、私钥、连接串中的秘密、签名 URL 参数，环境变量和启动参数中的敏感值；完整替换为 `<REDACTED>` 等标记。 | 配置项名称、非敏感生效值、工具选择关系、鉴权方式和成功/失败状态。 |
| 设备与身份 | 邮箱、真实姓名、设备序列号/UUID/MAC 等唯一标识、组织/客户名称。 | 系统版本、CPU/进程架构、硬件型号、内存等必要规格；避免附带设备身份信息。 |
| 业务与源码 | 真实业务数据、SQL 参数、私有源码、内部类/包/表/分支名，以及日志和 AI 请求/响应中的无关内容。 | 脱敏调用关系、最小合成示例、异常类型、规模统计和复现所需结构。 |
| 版本与指标 | 发布版本、公开构建 SHA、工具版本及资源指标通常保留；私有构建标识、定制版本名若含内部项目/客户信息则替换敏感部分并注明。 | 排障必需的实际版本、兼容关系、时间/时区、耗时、数量、单位及采样范围。 |

同一值跨日志、配置、正文和附件使用相同替代值；不同机器或项目不能全部替换成
同一个名字而丢失对应关系。脱敏副本生成后、对外提供前再次复核，不附原值映射。

## 基础信息：每次问题报告都核对

| 类别 | 核对内容 |
| --- | --- |
| Lithe 身份 | 实际运行的版本、构建号或可验证 SHA；stable/preview/源码构建等渠道；应用进程架构，是否经过 Rosetta 或 Windows 架构模拟。不能用本地源码 HEAD 代替运行版本。 |
| 安装与启动 | 安装来源和包类型、全新安装还是升级、升级前后版本；GUI/命令行/其他入口启动，是否使用自定义数据或配置目录，是否有多个安装实例。源码构建再记录分支/SHA、有无相关本地修改及 debug/release。 |
| 系统与硬件 | macOS/Windows 等具体版本及系统 build、CPU 型号/架构/核数、总内存；明确故障发生在物理机、虚拟机、WSL、远程主机还是容器。与问题有关时补存储和 GPU 信息。 |
| 项目与工作区 | 项目类型、语言及相关框架版本、单项目/多根工作区/多模块/monorepo，受影响文件类型；项目位于本地、外接盘、网络盘、云同步目录还是远程文件系统。 |
| 配置与扩展 | 与问题相关的非默认配置、用户级/项目级/远程级配置及实际生效值，相关插件名称、版本、来源和启用状态；是否刚迁移配置或更新扩展。 |
| 发生条件与变更 | 首次/最近发生时间与时区、触发操作、发生频率、影响范围；冷启动/运行一段时间后出现、最近升级或配置变更、最后正常版本与首次异常版本（如已知）。 |

基础项无法确认时记录缺口，并依据其对报告的影响补采或追问，不能伪造“默认值”。

## 条件信息：逐类判断，相关项全部覆盖

### 1. 语言、构建和测试工具链

- 项目语言/语言级别、框架、SDK、编译器及运行时版本；按实际语言补充 Java、
  Kotlin、Node.js、Python、Go、PHP、Rust、.NET 等相关项，不要求每种都安装。
- Java 问题区分项目 JDK、构建 JDK、语言服务器启动 JDK 和运行/调试 JDK；记录
  供应商、版本、架构、Lithe 实际选择和来源，不能只给终端 `java -version`。
- Maven/Gradle 等构建工具版本，使用系统安装、内置工具还是项目 Wrapper；相关
  插件版本、工作目录、目标任务、构建配置、离线模式、镜像/仓库及依赖缓存状态。
- 相关语言服务器名称、版本、启动参数中的非敏感项、实际使用的运行时；Java
  包括 JDT LS 及相关插件。记录初始化/索引是否完成和同步是否成功。
- 测试问题包括框架/运行器/适配器版本、测试发现方式、执行目标、筛选条件，
  以及命令行和 Lithe 内执行是否存在差异（只记录实际验证结果）。
- 仅源码构建、打包或产品组件兼容问题需要补充相关 Rust/Cargo、Swift/Xcode、
  Node/包管理器、Tauri 等构建信息；不能用本机开发工具版本冒充发布包组件版本。

### 2. 产品运行组件和插件

- 发生问题的插件版本、安装来源、相关依赖以及启用组合；有证据时记录升级前后
  差异或最小触发组合，不能把“尚未禁用其他插件”写成“无插件冲突”。
- Windows 网页界面问题记录实际 WebView2 Runtime 版本和分发方式；Tauri/前端/
  Core 组件信息从运行包元数据或诊断中确认，不靠终端安装的软件推测。
- 插件/语言服务器来源为随包、自行安装还是用户自定义入口，相关组件架构是否
  匹配；仅保留脱敏后的路径关系与必要配置。

### 3. 项目规模、文件和文件系统

- 项目/模块/文件数量、源码总体积、相关单文件大小或行数、目录深度，是否包含
  大量依赖、生成物或 Git 历史；说明统计范围和排除目录，区分源码与缓存体积。
- 相关文件的语言、编码、换行符、是否有 BOM、大文件/长行、只读状态；必要时
  提供不含业务内容的最小示例。
- 文件系统类型、可用空间、大小写敏感性、符号链接、路径长度、空格/中文等路径
  特征，以及项目是否位于外接、网络、云同步或临时目录。实际用户名和项目名脱敏。
- 文件监听、保存、权限或 Git 问题补充同步软件、文件锁、杀毒/索引进程等已知
  相关条件；没有证据时不能把这些条件直接写成根因。

### 4. 性能、资源和会话状态

- 卡顿/慢操作的具体动作、频率、持续时间、可观察延迟；区分冷启动、首次索引、
  缓存命中后、持续使用后以及重启后的结果。
- CPU、内存、内存压力/swap、磁盘 I/O 与可用空间等必要指标；区分 Lithe 主进程、
  语言服务器、构建工具和其他子进程，写明单位、采样时点和范围。
- 打开的窗口/项目/文件数量，是否同时索引、构建、运行测试、搜索或运行其他
  高负载任务；相关缓存和索引是否完成、失效或正在重建。
- 只记录已做过的隔离结果。清缓存、重装、切版本、禁插件或更改电源设置都不能
  当作采集环境信息的默认动作，更不能执行后却仍把修改后的条件当成原始环境。

### 5. UI、编辑器、输入和终端

- 显示器数量、相关屏幕分辨率/缩放/DPI、刷新率、GPU/驱动（相关时），以及
  外接显示器、远程桌面或虚拟显示器条件。
- 系统和应用语言、区域/时区、明暗主题、字体/字号、界面缩放、辅助功能设置；
  输入问题补充输入法、键盘布局、组合键和输入法组合输入状态。
- 终端/进程启动问题记录 Shell 名称和版本、登录/交互模式、PTY、工作目录、
  字符编码，相关 PATH/JAVA_HOME 等生效差异；变量值先脱敏，不转储全部环境。
- GUI 启动和终端启动可能继承不同环境；使用 Lithe 实际进程或诊断确认，不能
  仅凭宿主机终端输出认定应用选中了相同工具链。

### 6. 网络、代理与外部服务

- 本地/公司网络、代理类型、VPN、离线条件；DNS、TLS/自定义证书、企业防火墙等
  与故障有关的配置或已确认现象。记录错误码与失败阶段，内网地址脱敏。
- 受影响服务及协议，例如依赖仓库、Git 托管、插件市场、更新服务或 AI 提供方；
  服务版本/模型标识、相关客户端版本及连接方式按模块记录。
- 鉴权仅记录方式、权限范围和成功/失败状态，不记录 Token、密码、Cookie、
  私钥、完整连接串、带签名 URL 或请求/响应中的业务数据。

### 7. 权限、安全软件和系统策略

- 普通用户/管理员运行、相关目录和可执行文件是否可访问、只读或被占用；涉及
  文件访问时补充已知的系统隐私授权、受保护目录或企业管理策略。
- 安装/启动问题按实际情况记录 macOS Gatekeeper/签名/隔离状态，或 Windows
  Defender、SmartScreen、受控文件夹访问等拦截提示及相关安全软件版本。
- 不为诊断默认提权、关闭安全软件、更改系统策略或写入已发布程序目录。

### 8. 远程、WSL、虚拟机和容器边界

- 本地/远端各自系统和架构、Linux 发行版与内核，WSL 版本/发行版，虚拟化或
  容器运行时版本，CPU/内存/磁盘分配，相关的共享目录和挂载方式。
- SSH/WSL/容器/虚拟机连接方式，UI、文件、语言服务器、构建和目标进程分别
  在哪一侧运行；远端 Shell、相关工具链及路径映射单独记录。
- 只传递必要的脱敏诊断；若实际采集涉及 Parallels Windows 产品，另加载
  `.agents/skills/debug-windows-on-parallels/SKILL.md`。

### 9. 具体模块的服务与数据结构

| 模块 | 相关时补充 |
| --- | --- |
| Git / GitHub | Git/相关客户端版本、HTTPS/SSH、仓库规模、普通仓库/worktree/子模块、浅克隆/LFS、当前操作和冲突状态；服务类型及登录权限状态。远端地址、分支名和业务提交内容按需脱敏。 |
| Run / Debug / Test | 实际运行时、调试适配器与测试框架版本、启动/附加/远程模式、工作目录、必要的脱敏启动配置、构建产物/类路径来源、目标进程状态和端口映射关系。 |
| Database | 数据库类型/服务版本、驱动版本、连接方式、TLS/SSH 隧道、字符集/排序规则、影响问题的 schema 规模；不附生产数据、凭据或完整连接串。 |
| Docker | Engine/Desktop/Compose 等实际版本、客户端与 daemon 所在位置、容器系统/架构、镜像版本、资源限制、挂载及网络模式；私有镜像地址和配置秘密脱敏。 |
| AI | 提供方、模型标识、相关插件/客户端或本地服务版本、接入方式、代理/流式输出/工具调用等相关设置，以及错误码/限流状态；不附密钥和无关对话内容。 |
| Search / Editor / Extensions / 其他模块 | 影响现象的搜索范围/忽略规则/正则/编码、编辑配置、扩展依赖或对应服务版本。清单未列的新模块仍须追问其实际依赖和运行条件，不能默认为无需环境信息。 |

## 放回现有模板，保持结构一致

当前 Bug 模板的字段映射如下；每次仍应读取线上模板确认：

| 模板字段 | 填入内容 |
| --- | --- |
| Platform / 平台、Area / 模块 | 实际故障平台与模块，选择模板允许的选项。 |
| Lithe version / Lithe 版本 | 实际运行版本或可验证构建 SHA，必要时注明渠道。 |
| OS and architecture / 操作系统与架构 | 具体系统版本/build、CPU/进程架构与必要的虚拟化信息。 |
| Environment / 环境信息 | 基础环境和相关条件项，用字段内列表分组说明硬件、工具链、插件、项目规模、配置及本地/远端归属。 |
| Steps to reproduce / 复现步骤 | 实际前置条件、项目/会话状态、触发动作及频率。 |
| Actual behavior / 实际行为 | 观察到的异常、影响、性能测量与已验证的版本/条件差异。 |
| Logs or diagnostic output / 日志或诊断输出 | 与故障时点对应的最小脱敏日志、采样口径及来源。 |
| Screenshots or recordings / 截图或录屏 | 脱敏后的视觉证据，说明对应的操作或显示条件。 |

功能建议把相关环境放在现有“Problem to solve / 要解决的问题”或
“Additional context / 补充信息”字段，目标平台使用对应下拉框。两种报告都
不能因为环境项较多，就增加替代模板、删改字段或改用自由正文提交。
