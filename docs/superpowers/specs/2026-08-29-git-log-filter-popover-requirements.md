# Git Log 筛选器有界下拉需求

对应 Issue：[#302](https://github.com/1lck/Lithe-IDEA/issues/302)（标签：`enhancement`、`macos`）

## 背景

Lithe 0.3.6（macOS）的 Git Log 筛选栏中，「Branch / 分支」「User / 用户」筛选器使用系统
`Menu`（NSMenu）展示候选项。当仓库分支或提交作者数量较多时，NSMenu 会展开成一个几乎铺满
整个窗口的巨型滚动菜单（见 issue 截图），既没有宽度约束，也没有最大高度约束，和锚点控件
毫无位置关联，体验非常差。用户在 issue 中描述为「基于 Webview 的显示」，实际是原生 NSMenu
在大量条目下的默认表现，但无论根因如何，体验问题一致。

期望对齐 IntelliJ IDEA 的 Git Log 筛选交互：筛选弹层锚定在筛选标签正下方，有明确的最大
宽度和最大高度（超出滚动），顶部带搜索框，列表按类别分组展示。

## 问题陈述

1. Branch 筛选下拉在分支较多的仓库中展开为全屏高度的巨型菜单，遮挡整个 Git Log 视图。
2. User 筛选下拉列出全部提交作者，存在同样的无界展开问题。
3. 长分支名 / 长作者名在菜单项中溢出显示，没有稳定的截断与提示规则。
4. 候选列表无搜索能力，在大仓库中无法快速定位目标分支或作者。

## 目标

- Branch、User 筛选器改为有界的锚定弹层（popover），对齐 IDEA 的区域限制交互。
- 弹层必须在固定尺寸约束内展示：宽度有界、高度超过上限时内部滚动。
- 支持在弹层内搜索过滤候选项。
- 保持现有筛选语义不变：选中的筛选条件、清除按钮（×）、与搜索框/日期/路径筛选的组合行为
  均与当前一致。

## 非目标

- 不改变 Git Log 的数据加载、过滤执行逻辑（`AppModel` 侧接口不变）。
- 不改动 Date 筛选器（条目固定且少，无展开问题；是否统一视觉风格留作后续独立小任务）。
- 不涉及 Windows 端（issue 标签为 `macos`；Windows 有独立实现）。
- 不引入分支切换等操作入口（那是 `BranchSwitcherPopover` 的职责，本需求只做筛选）。

## 功能需求

### FR1 Branch 筛选弹层（对齐 IDEA 的两级结构）

- 点击「Branch」筛选标签后，在标签正下方弹出有界弹层，形态对齐 IDEA：
- 一级列为紧凑菜单，自上而下：
  - 固定的「All Branches」重置项（清除引用筛选）；
  - 收藏区：当前分支（⭐）与其 upstream（⭐，若存在）快捷行；
  - 分组行：`Local`、每个远程仓库一行（如 `origin/…`）、`Tags`，行尾带 `>` 指示。
- 点击分组行后，在其右侧展开二级列表（flyout）：列出该分组全部引用，有界高度、
  内部滚动、当前筛选项高亮；二级列表中显示完整引用名（如 `origin/preview`）。
- 顶部提供搜索框：输入后切换为扁平过滤模式（跨所有分组，匹配名称与 upstream，
  不区分大小写），清空后回到两级浏览模式。
- 点击候选行即应用筛选并关闭弹层；当前选中项有明确的选中态标识。

### FR2 User 筛选弹层

- 点击「User」筛选标签后，同样弹出有界弹层（扁平形态，与 IDEA 的用户筛选一致）。
- 首行固定「All Users」，其次「Me」（当前用户），其后按作者名稳定排序列出全部作者。
- 每行显示作者名与邮箱；支持搜索过滤；点击应用筛选并关闭。

### FR3 区域约束与布局

- 弹层宽度有界（扁平模式约 340pt；两级浏览模式一级列约 220pt + 二级列约 330pt）；
  最大高度不超过约 480pt，内容超出时列表内部滚动。
- 弹层必须锚定在触发它的筛选标签下方，不得脱离锚点漂浮。
- 空结果时展示明确的空状态文案（如「No matching branches」）。

### FR4 现有行为保持

- 筛选标签的文案（`Branch: xxx`）、清除按钮、`chevron.down` 指示等现有视觉不变。
- 选中筛选后 Git Log 的提交过滤结果与当前实现完全一致。

## 交互规格

| 交互 | 行为 |
| --- | --- |
| 点击筛选标签 | 弹层在标签下方展开，搜索框自动聚焦 |
| 输入搜索词 | 列表实时过滤（不区分大小写，子串匹配） |
| 点击候选行 | 应用筛选，弹层关闭 |
| 点击弹层外部 / 按 Esc | 关闭弹层，不改变当前筛选 |
| 清除按钮（×） | 行为不变：立即清除对应筛选 |

## 验收标准

1. 在含 100+ 分支的仓库中打开 Branch 筛选，弹层尺寸有界、不遮挡整个窗口，列表可滚动，
   搜索可快速定位分支。
2. 在含大量作者的仓库中打开 User 筛选，表现同上。
3. Branch / User 筛选的组合过滤结果、清除行为与改动前一致（回归现有 Git Log 过滤语义）。
4. `./scripts/test-macos.sh` 通过；涉及视图边界的按 `develop-lithe` 要求补跑
   `./scripts/verify-service-boundaries.sh`。
