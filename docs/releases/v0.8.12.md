## 中文

Lithe Desktop 0.8.12 让插件按需下载固定版本的命令（例如调试器），不必把它们打进插件包；Rust Support 插件 0.1.0 需要这个能力。这一版还修复了四个问题：macOS 上不识别用 rustup 安装的 Cargo；保存工具链后，构建仍用旧环境；Windows 和 Linux 上超长日志行可能让窗口闪退；Linux HiDPI 桌面上的鼠标指针过小。插件详情和全局搜索的排版也更整齐，Viva 同步到了最新上游。

### 重点更新

这一版的重点是插件自己就能装好所需的工具，工具链设置也会立即生效。

#### ✨ 新功能

- 插件可以为缺少的命令指定固定地址的压缩包。在插件能力卡片上点“安装”后，确认对话框会列出版本、下载地址、镜像和 SHA-256。确认后，Lithe 下载并校验压缩包，解压到插件自己的目录，不再需要把调试器这类工具打进插件包。Rust Support 插件用这种方式按需下载 CodeLLDB。

#### ⚡ 改进

- 插件详情的“版本与来源”和“权限与程序”两个页签重新排版：
  - 各项的值对齐，每个权限占一行，常驻说明收进 ⓘ。
  - 每个程序默认折叠成一行，展开后显示带语法高亮的完整 JSON，可以一键复制。
- 全局搜索里，“类型”“符号”页签的 ⓘ 和页签名称放进了同一个页签块。点 ⓘ 也会切到这个页签。
- Viva 图形框架同步到上游 `faaa437`。Windows 终端绘制彩色输出时，排版和绘制调用更少，速度更快。

#### 🛠 修复

- 修复 macOS 上用 rustup 安装的 Cargo 被判为版本不满足的问题。之前它不会出现在工具链页，也无法固定到项目。
- 修复保存工具链设置（例如切换解释器）后，当前窗口的构建和测试仍沿用旧工具链、要重启才生效的问题。
- 修复 Windows 和 Linux 上画不出超长单行文本（例如 LSP 日志里的长行），并可能让窗口闪退的问题。
- 修复 Linux 上 HiDPI 桌面的鼠标指针比系统指针小很多的问题：DEB、RPM 包现在把 `libxcb-cursor` 列为推荐依赖，正常安装会一并装上。

#### 🔌 插件需要的新宿主能力

下面的插件版本需要本版新增的宿主能力，0.8.11 及更早的 Lithe 会拒绝安装：

- [Lithe-IDEA/lithe-plugin-rust](https://github.com/Lithe-IDEA/lithe-plugin-rust) 的 Rust Support 0.1.0（预发布）：需要命令安装器下载固定地址的压缩包（`commandInstallers` 能力版本 1），用来按需下载 CodeLLDB。在 macOS 上用 rustup 安装 Rust 时，它还依赖本版对 rustup 版 Cargo 的识别修复。

### 升级说明

- 已安装 Lithe 的用户，可以从标题栏的更新入口或“设置 → 关于”检查更新，也可以下载完整安装包。
- macOS：打开对应芯片的 DMG，将 `Lithe Desktop.app` 拖入“应用程序”。
- Homebrew：配方更新后运行 `brew update && brew upgrade --cask lithe`。
- Windows：运行 x64 安装程序；Windows 0.8.0 用户需要手动下载安装。
- Linux：全部下载文件中提供 x64、ARM64 的 DEB、RPM 和 tar.gz。

### 兼容性与已知问题

- macOS 最低 13.0；Windows 提供 x64 包；Linux 需要兼容的运行库和图形环境。
- 部分依赖本机交互的 Windows 功能还没有在 Windows 实机上验收，功能矩阵中如实保留为待验证。
- macOS 使用临时签名，没有经过公证；Windows 安装包没有发行者签名。系统可能显示安全提示。

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在“应用程序”中按住 Control 点按应用并选择“打开”；如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 使用 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

## English

Lithe Desktop 0.8.12 lets plugins download pinned commands, such as debuggers, when they are needed, so plugins no longer bundle them; the Rust Support 0.1.0 plugin needs this. It also fixes four problems: Cargo installed with rustup was not recognized on macOS, builds kept the old toolchain after you saved toolchain settings, very long log lines could crash the window on Windows and Linux, and the mouse pointer was too small on HiDPI Linux desktops. Plugin details and Search Everywhere have a tidier layout, and Viva is synced with upstream.

### Highlights

This release lets plugins install the tools they need themselves, and makes toolchain settings take effect right away.

#### ✨ New features

- Plugins can name a pinned archive for a missing command. When you click Install on a plugin's capability card, a confirmation dialog lists the version, download URL, mirrors and SHA-256. After you confirm, Lithe downloads and verifies the archive and extracts it into the plugin's own directory, so plugins no longer have to bundle tools such as debuggers. Rust Support uses this to download CodeLLDB on demand.

#### ⚡ Improvements

- New layout for the Version and source and the Permissions and programs tabs in plugin details:
  - Values line up, each permission takes one row, and the standing explanations moved into ⓘ.
  - Each program is collapsed to one row by default. Expand it to see the full JSON with syntax highlighting, and copy it with one click.
- In Search Everywhere, the ⓘ of the Types and Symbols tabs now sits inside the tab with its name. Clicking ⓘ also switches to that tab.
- Syncs the Viva UI framework with upstream `faaa437`. The Windows terminal now draws colored output with fewer layout and drawing calls, so it is faster.

#### 🛠 Fixes

- Fixes Cargo installed with rustup on macOS being reported as an unsatisfied version. It was missing from the toolchain page and could not be pinned to a project.
- Fixes builds and tests in the current window using the old toolchain after you saved toolchain settings (for example, after switching interpreters) until you restarted.
- Fixes very long single lines of text, such as long lines in LSP logs, not being drawn on Windows and Linux, which could crash the window.
- Fixes a mouse pointer much smaller than the system pointer on HiDPI Linux desktops: the DEB and RPM packages now recommend `libxcb-cursor`, so a normal install pulls it in.

#### 🔌 New host capabilities that plugins need

The plugin versions below need host capabilities added in this release. Lithe 0.8.11 and earlier refuse to install them:

- Rust Support 0.1.0 (prerelease) from [Lithe-IDEA/lithe-plugin-rust](https://github.com/Lithe-IDEA/lithe-plugin-rust): needs command installers that download pinned archives (`commandInstallers` capability version 1) to download CodeLLDB on demand. When Rust is installed with rustup on macOS, it also relies on this release's fix for recognizing rustup's Cargo.

### Upgrade instructions

- If Lithe is already installed, check for updates from the title bar or Settings → About, or download a full package.
- macOS: open the DMG for your processor and drag `Lithe Desktop.app` to Applications.
- Homebrew: run `brew update && brew upgrade --cask lithe` once the cask update is available.
- Windows: run the x64 installer. Windows 0.8.0 users must download and install it manually.
- Linux: the release downloads include DEB, RPM and tar.gz packages for x64 and ARM64.

### Compatibility and known issues

- macOS requires 13.0 or newer, Windows packages target x64, and Linux requires compatible libraries and a graphical environment.
- Some Windows features that depend on native interaction have not been accepted on real Windows hardware yet; the feature matrix still lists them as pending.
- macOS packages use ad hoc signing and are not notarized. Windows installers have no publisher signature. Your system may show security prompts.

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it remains blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
