### 重点更新

本次更新重点完善项目启动、会话恢复和跨平台编辑体验。

#### ✨ 新功能

- macOS 的 HTML 与 HTM 文件支持编辑、分栏和静态预览，两端均可快速用系统浏览器打开。
- macOS 与 Windows 会展示 Java 项目准备进度，构建结论异常时可继续运行或重建 Java 索引。
- Windows 将 Docker 服务与项目应用分开显示，并移除由注释或字符串误识别的 Java 启动项。

#### ⚡ 改进

- Maven 与 Spring Boot 项目会按实际应用模块增量构建，并使用正确的项目 JDK 和依赖运行或调试。
- 大型 Java 项目会协调项目导入与重复构建，并在受支持的 JDK 上处理超长 Windows 类路径。
- Windows 会先恢复标签和布局，再在后台加载文件内容，同时保留光标和滚动位置。
- Windows 打开大型 Maven 工作区时会优先完成 Git 状态读取，减少 Git 与 Java 初始化互相争用。
- Windows 对超大文件默认保留基础高亮并暂停高开销语言功能，加载提示也不再阻挡编辑器交互。
- 使用 Xcode 27 的开发者现在可以在本地构建 macOS 应用，同时继续支持既有发布工具链。

#### 🛠 修复

- Windows 运行面板会正确使用 Maven 面板中已配置的 Maven 路径。
- Windows Java 跳转始终使用当前编辑器位置，并会展示未打开文件中的项目诊断。
- Windows 复制 CRLF 文件选区时不再偏移到上一行，Java 文件变化也不会因计时器错误而丢失。
- Windows 底部右键菜单点击时不再跳动，查找关闭按钮的提示也不再反复闪烁。
- macOS 编辑器现在会正确跟随应用主题和工作台背景，不再显示突兀的独立底色。

### 升级说明

- macOS：打开对应架构的 DMG，将 Lithe.app 拖入“应用程序”。
- Homebrew：新版配方更新后，运行 `brew update && brew upgrade --cask lithe`。
- Windows：下载并运行 x64 安装包。

### 兼容性与已知问题

- macOS 需要 13 或更高版本；Windows 版本仍处于预览阶段，部分平台能力和界面细节可能与 macOS 不完全一致。
- Windows 安装包在未配置 Authenticode 发布者证书时可能显示系统安全提示。
- Windows 的超长 Java 类路径自动缩短需要 JDK 9 或更高版本；JDK 8 仍受系统命令行长度限制。

如果 macOS 提示无法打开 Lithe.app，请在“应用程序”中按住 Control 点按应用并选择“打开”；如果仍被阻止，可在终端执行 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

### Highlights

This release focuses on project launches, session restoration, and cross-platform editing.

#### ✨ New features

- HTML and HTM files on macOS support editor, split, and static preview modes, with quick external-browser actions on both platforms.
- macOS and Windows show Java project preparation progress and let you continue or rebuild the Java index after suspicious build results.
- Windows separates Docker services from project applications and removes Java launch entries falsely detected in comments or strings.

#### ⚡ Improvements

- Maven and Spring Boot projects incrementally build the actual application module and run or debug with the correct project JDK and dependencies.
- Large Java projects coordinate imports and repeated builds, with oversized Windows class paths handled on supported JDKs.
- Windows restores tabs and layout first, then loads file contents in the background while preserving cursor and scroll positions.
- Windows prioritizes initial Git status when opening large Maven workspaces, reducing contention between Git and Java startup.
- Windows keeps basic highlighting for very large files while pausing costly language features, and loading notices no longer block editor interaction.
- Developers using Xcode 27 can now build the macOS app locally while the existing release toolchain remains supported.

#### 🛠 Fixes

- The Windows Run panel now honors the Maven path already configured in the Maven panel.
- Windows Java navigation uses the active editor position and shows project diagnostics from files that are not open.
- Copying selections from CRLF files on Windows no longer shifts to the previous line, and Java file changes are no longer lost to a timer error.
- Windows context menus near the bottom no longer jump when clicked, and the find close-button tooltip no longer flickers repeatedly.
- The macOS editor now follows the app theme and workbench background without an isolated, mismatched surface.

### Upgrade instructions

- macOS: open the DMG for your architecture and drag Lithe.app to Applications.
- Homebrew: run `brew update && brew upgrade --cask lithe` after the cask update is available.
- Windows: download and run the x64 installer.

### Compatibility and known issues

- Requires macOS 13 or later; Windows remains a preview, and some platform capabilities and interface details may differ from macOS.
- The Windows installer may show a system security warning when no Authenticode publisher certificate is configured.
- Automatic shortening of oversized Java class paths on Windows requires JDK 9 or later; JDK 8 remains subject to the system command-line limit.

If macOS says it cannot open Lithe.app, Control-click it in Applications and choose Open. If it is still blocked, run `xattr -dr com.apple.quarantine /Applications/Lithe.app` in Terminal. Use this only for an app from a source you trust.
