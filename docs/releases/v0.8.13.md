## 中文

Lithe Desktop 0.8.13 改善了 Java 项目从首次打开到运行和调试的流程，并加入安全模式、可信位置及 SSH 远程目录浏览。

### 重点更新

打开 Java 工程后，可以从插件推荐直接安装所需工具，并在已打开的编辑器里继续工作。

#### ✨ 新功能

- 用安全模式查看不熟悉的项目时，Lithe 会限制语言服务器、Git 和版本控制的运行。
- 在“设置 → 工具 → 可信位置”中管理可直接打开的位置。
- 在远程开发窗口保存、分组和测试 SSH 连接，可用颜色区分主机并直接回答 SSH 询问。
- 连接 SSH 主机后可选择文件夹并在新标签页浏览目录，状态栏显示连接状态，断线后会尝试重连。
- Git 需要用户名、密码或口令时，可以直接在窗口中输入，也可以取消。

#### ⚡ 改进

- 欢迎页直接显示新建项目、打开项目、克隆仓库和远程开发四种入口。
- 设置窗口记住上次调整后的尺寸，控制台和可信位置归入“工具”，Git 有独立设置页。
- 同步 Viva 后，Windows 拖动缩放减少重复绘制，列表滚动范围和 Linux 长文本绘制也得到修正。

#### 🛠 修复

- 修复首次打开项目时插件推荐不完整，以及从推荐入口打开空白列表的问题。
- 安装语言插件后，已打开的文件可以直接获得语言服务。
- 恢复工具栏的当前文件运行与调试、附加调试，并修复从构建工具发现的入口启动调试。
- 修复多项目工作区中从当前文件运行时选错项目的问题。
- 修复 Windows 无法打开 Linux SSH 主机目录的问题。
- 修复“语言与框架”目录页缺失、语言设置页重复显示目录项的问题。

#### 🔌 插件需要的新宿主能力

以下版本需要本版新增的宿主能力，Lithe 0.8.12 及更早的版本会拒绝安装。

- Gradle 2.0.1需要 `buildSystems` 版本 2 和 `buildProviders` 版本 1，用于按当前 Java 文件所属的源集准备运行和调试。[插件版本](https://github.com/Lithe-IDEA/lithe-plugin-gradle/releases/tag/v2.0.1)
- Maven 1.0.3需要 `buildSystems` 版本 2 和 `buildProviders` 版本 1，用于准备 Maven 应用的调试类路径，并依赖本版对当前文件调试和构建入口调试的修复。[插件版本](https://github.com/Lithe-IDEA/lithe-plugin-maven/releases/tag/v1.0.3)

### 升级说明

- 可从标题栏的更新入口或“设置 → 关于”检查更新，也可以下载完整安装包。
- macOS 用户打开对应架构的 DMG，将 `Lithe Desktop.app` 拖入“应用程序”。
- Homebrew 配方更新后，运行 `brew update && brew upgrade --cask lithe`。
- Windows 用户运行 x64 安装程序，从 Windows 0.8.0 升级时请手动下载安装。
- 全部下载文件中提供 Linux x64、ARM64 的 DEB、RPM 和 tar.gz。

### 兼容性与已知问题

- macOS 最低要求 13.0。Windows 提供 x64 安装包，Linux 需要兼容的运行库和图形环境。
- macOS 安装包使用临时签名，Windows 安装包无发行者签名。系统可能显示安全提示。
- SSH 工作区目前支持浏览目录，打开和编辑文件、远程终端、项目搜索与 Git 仍在开发。[#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- Windows 首次导入 Gradle 项目时，如果 Wrapper 尚未下载且探测超时，可在项目目录运行 `gradlew.bat --version` 等待下载完成，再回到 Lithe 重试。
- 在 Windows 11 ARM64 上运行 x64 版时，Spring Petclinic 的 Gradle 调试因 Java 语言服务器请求超时而未能启动。
- 以 `build.xml` 为根的 Apache Ant 工程仍有项目导入、调试和源码跳转缺口。[#1761](https://github.com/1lck/Lithe-IDEA/issues/1761)

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在“应用程序”中按住 Control 点按应用并选择“打开”。如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 使用 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

Lithe Desktop 0.8.13 improves the path from opening a Java project to running and debugging it. It also adds Safe Mode, trusted locations, and SSH remote folder browsing.

### Highlights

When you open a Java project, you can install the recommended tools and continue working in the files you already have open.

#### ✨ New features

- Safe Mode restricts language servers, Git, and version control when you inspect an unfamiliar project.
- Manage locations you trust to open directly in Settings → Tools → Trusted Locations.
- Save, group, color-code, and test SSH connections and answer prompts in the Remote Development window.
- Choose a folder after connecting to an SSH host, browse its tree in a new tab, and see connection and reconnection status.
- Enter Git usernames, passwords, and passphrases in the window, or cancel the prompt.

#### ⚡ Improvements

- Create, open, clone, and remote development now have their own buttons on the welcome screen.
- Settings remembers its window size, groups Console and Trusted Locations under Tools, and gives Git its own page.
- The Viva update reduces extra redraws during Windows resizing and fixes list scrolling bounds and long text drawing on Linux.

#### 🛠 Fixes

- Fixes missing plugin suggestions when opening projects and an empty list when following a suggestion.
- Files already open can receive language services as soon as you install the language plugin.
- Restores toolbar run and debug for the current file and debugger attach, and fixes debugging from discovered build entry points.
- Fixes run commands for the current file selecting the wrong project in a multi-project workspace.
- Fixes opening Linux SSH host folders from Windows.
- Restores the Languages & Frameworks directory page and removes duplicated directory entries from language settings.

#### 🔌 New host capabilities that plugins need

These plugin versions need capabilities added in this release. Lithe 0.8.12 and earlier refuse to install them.

- Gradle 2.0.1 needs `buildSystems` version 2 and `buildProviders` version 1 to run and debug a Java file with its Gradle source set. [Plugin release](https://github.com/Lithe-IDEA/lithe-plugin-gradle/releases/tag/v2.0.1)
- Maven 1.0.3 needs `buildSystems` version 2 and `buildProviders` version 1 to prepare the Maven debug classpath. It also relies on this release’s current-file and build-entry debugging fixes. [Plugin release](https://github.com/Lithe-IDEA/lithe-plugin-maven/releases/tag/v1.0.3)

### Upgrade instructions

- Check for updates from the title bar or Settings → About, or download a full installer.
- On macOS, open the DMG for your processor and drag `Lithe Desktop.app` to Applications.
- With Homebrew, run `brew update && brew upgrade --cask lithe` once the cask update is available.
- On Windows, run the x64 installer. Windows 0.8.0 users should download and install it manually.
- Linux downloads include DEB, RPM, and tar.gz packages for x64 and ARM64.

### Compatibility and known issues

- macOS requires 13.0 or newer. Windows packages target x64. Linux requires compatible libraries and a graphical environment.
- macOS packages use ad hoc signing. Windows installers have no publisher signature. Your system may show security prompts.
- SSH workspaces support browsing folders. Opening and editing files, remote terminals, project search, and Git are in development. [#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- On Windows, a Gradle project can time out during its first import if its Wrapper distribution still needs to download. Run `gradlew.bat --version` in the project directory, wait for it to finish, and retry in Lithe.
- Gradle debugging for Spring Petclinic could not start in the x64 app on Windows 11 ARM64 because the Java language server request timed out.
- Apache Ant projects rooted at `build.xml` still have gaps in project import, debugging, and source navigation. [#1761](https://github.com/1lck/Lithe-IDEA/issues/1761)

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it is still blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"` in Terminal. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
