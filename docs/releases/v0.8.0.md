### 重点更新

本次重点是 Java 项目配置，以及编辑器和终端中的日常操作。

#### ✨ 新功能

- 无需打开项目，即可自动识别 JDK、手动添加多个版本并选择全局默认版本。
- 项目可单独覆盖全局 JDK，新启动的构建、运行和语言服务使用同一解析结果。
- 配合新版 Java Support、Maven 或 Gradle 插件，设置项目默认及各模块的目标字节码。
- 在配套插件的本地依赖设置中引用 JAR，支持普通 Java、Eclipse、Maven 和 Gradle 项目。

#### ⚡ 改进

- 编译设置显示真实配置来源和继承值，保存时检查外部改动，避免覆盖较新的配置。
- 终端持续输出时保留选区，滚动丢弃旧行后保留仍存在的选中内容。
- Windows 可识别通过 Microsoft Store 安装的 PowerShell 7。

#### 🛠 修复

- 诊断波浪线更细，并正确对齐 Tab、中文和表情后的字符。
- Windows 终端可用 Ctrl+C 中断程序，清除 PowerShell 后正确重绘提示符。
- 自动选择工具链时显示实际生效版本，避免把已有 JDK 显示为未找到安装。

### 升级说明

- macOS：选择对应芯片的 DMG，将 `Lithe Desktop.app` 拖入“应用程序”。
- Homebrew：当前 `lithe` 配方仍指向旧客户端 0.6.7；安装本版请使用上述 DMG。
- Windows：运行 x64 安装程序，或将 ZIP 解压到独立目录后运行 `lithe.exe`。
- Linux：使用对应架构的 DEB/RPM；tar.gz 用户需要自行满足运行库要求。
- 先升级桌面端，再按项目需要更新 Java Support 2.0.0、Maven 1.0.0 或 Gradle 2.0.0；旧桌面端可继续使用原有兼容插件版本。
- 在“设置 → 构建、执行、部署”管理全局 JDK；编译器子页设置字节码，本地 JAR 入口位于对应插件设置中。
- 修改 JDK 后，重启已有语言服务及运行或调试会话；当前没有配置签名更新源，请手动下载安装。

### 兼容性与已知问题

- macOS 最低为 13.0，分别提供 Apple Silicon 和 Intel 包；Windows 桌面端提供 x64 包。
- Linux 提供 x64 和 ARM64 包，需要兼容的运行库和图形环境，未验证所有发行版。
- 配套插件单独安装；更新 Maven 插件后可在 Windows 安装使用，新版编译和 JAR 设置需要本版桌面端。
- 新客户端的功能迁移仍在进行，组件与无头验证不代表旧版功能已全部对齐。
- macOS 使用临时签名且未公证，Windows 安装包没有发行者签名，系统可能显示安全提示。

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在“应用程序”中按住 Control 点按应用并选择“打开”；如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 对应命令是 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

### Highlights

This release focuses on Java project configuration and everyday editor and terminal operations.

#### ✨ New features

- Detect JDKs, add multiple versions manually and choose a global default without opening a project.
- Override the global JDK per project; new builds, runs and language services share the same resolution.
- Set project defaults and per-module bytecode targets with the updated Java Support, Maven or Gradle plugin.
- Reference local JARs through plugin settings for plain Java, Eclipse, Maven and Gradle projects.

#### ⚡ Improvements

- Compiler settings show their real sources and inherited values, checking external changes before saving.
- Terminal output preserves selections, retaining selected content that remains after older lines scroll out of the buffer.
- Windows detects PowerShell 7 installed through Microsoft Store.

#### 🛠 Fixes

- Thinner diagnostic waves align correctly with characters after tabs, Chinese text and emoji.
- Ctrl+C interrupts programs in Windows terminals, and clearing PowerShell redraws its prompt correctly.
- Automatic toolchain selection shows the effective version instead of reporting an existing JDK as missing.

### Upgrade instructions

- macOS: open the DMG for your processor and drag `Lithe Desktop.app` to Applications.
- Homebrew: the `lithe` cask still targets the older 0.6.7 client; use the DMG above for this release.
- Windows: run the x64 installer, or extract the ZIP into its own directory and run `lithe.exe`.
- Linux: use the DEB/RPM for your architecture; tar.gz users must provide the required runtime libraries.
- Upgrade the desktop first, then update Java Support to 2.0.0, Maven to 1.0.0 or Gradle to 2.0.0 as needed; older hosts retain compatible plugin versions.
- Manage global JDKs in Settings → Build, Execution, Deployment; compiler subpages set bytecode, and each plugin provides its local JAR settings.
- Restart existing language services and run or debug sessions after changing JDKs; no signed update feed is configured, so install manually.

### Compatibility and known issues

- macOS requires 13.0 or newer, with separate Apple Silicon and Intel packages; the Windows desktop package targets x64.
- Linux packages target x64 and ARM64, requiring compatible libraries and a graphical environment; not every distribution is verified.
- Install companion plugins separately; updating Maven enables Windows installation, and the new compiler/JAR settings require this desktop release.
- Feature migration continues; component and headless checks do not establish complete parity with the older client.
- macOS packages use ad hoc signing without notarization; Windows installers have no publisher signature and may trigger system prompts.

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it remains blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
