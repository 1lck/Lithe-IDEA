### 重点更新

本次重点是插件托管运行环境、插件自动更新、原生插件视图和设置页重构。

#### ✨ 新功能

- 插件支持受管运行环境（`managedRuntimes`）：安装声明了运行环境的插件时，宿主自动检查本机与缓存，只下载缺失的官方归档并做 SHA-256 校验；运行环境独立缓存，插件升级时复用。
- 插件管理页齿轮菜单新增“自动更新已授权的插件”开关（默认关闭）：开启后定期检查同来源市场，仅对权限与程序声明未变化的新版在后台自动安装，重启后生效。
- 支持插件用 Viva 原生绘制视图：宿主控件、树、画布与自定义设置区域。
- “构建、执行、部署”重构为目录页，以及构建工具、编译器、工具链与调试器四个分栏子页。
- 运行配置支持类型说明提示（ⓘ）、插件包图标、脚本文本自动增高与启动前插件任务（API-29）。

#### ⚡ 改进

- 更新设置并入“关于”页，项目卡片新增 Rust Core 与 Viva 上游信息。
- 三个窗口统一提示气泡样式，浅色主题改为深底浅字；设置窗口的 ⓘ 改为悬停显示。
- 同步 Viva 至 fork `main` `1c0d556`（合入上游 `bd396bc` 及提示边框箭头修复）。

#### 🛠 修复

- 修复 Windows 工具链探测单测参数缺失问题。

### 升级说明

- 已安装 0.8.6：在标题栏的更新入口或“设置 → 关于”中检查更新，即可在应用内更新到本版；更早的版本会下载完整安装包。
- Windows 0.8.0 无法在应用内完成更新，请下载本版安装程序手动安装。
- macOS：也可选择对应芯片的 DMG，将 `Lithe Desktop.app` 拖入“应用程序”。
- Homebrew：配方更新到本版后，运行 `brew update && brew upgrade --cask lithe`。
- Windows：运行 x64 安装程序，或将 ZIP 解压到独立目录后运行 `lithe.exe`。
- Linux：使用对应架构的 DEB/RPM；tar.gz 用户需要自行满足运行库要求。

### 兼容性与已知问题

- Java 插件 4.1.0 的自动准备 JDK 25 与 JDT LS（`managedRuntimes` 0）需要本版或更新的桌面端；更早的桌面端继续使用 Java 插件 4.0.2。
- 插件自动更新默认关闭；旧版已安装的插件需在市场手动更新一次以记录安装来源后才会参与自动更新。
- macOS 最低为 13.0，分别提供 Apple Silicon 和 Intel 包；Windows 桌面端提供 x64 包。
- Linux 提供 x64 和 ARM64 包，需要兼容的运行库和图形环境，未验证所有发行版。
- 自动生成运行配置、调试服务、隐藏 `target`、`node_modules` 等目录需要启用对应的语言或构建插件。
- macOS 使用临时签名且未公证，Windows 安装包没有发行者签名，系统可能显示安全提示。

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在“应用程序”中按住 Control 点按应用并选择“打开”；如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 对应命令是 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

### Highlights

This release focuses on managed plugin runtimes, automatic plugin updates, native plugin views and settings layout.

#### ✨ New features

- Managed plugin runtimes (`managedRuntimes`): when installing a plugin that declares runtimes, Lithe checks local and cached environments, downloads only missing official archives with SHA-256 verification, and reuses them across plugin updates.
- Opt-in automatic plugin updates in the Plugin Management gear menu (off by default): periodically checks approved marketplace sources and installs updates in the background only when permissions and program declarations are unchanged; updates activate on restart.
- Native Viva plugin views: plugins can render host controls, trees, canvases and custom settings regions.
- Build, Execution, Deployment settings are reorganized into a directory page with Build Tools, Compiler, Toolchains and Debuggers split-pane subpages.
- Run configurations add type info tips (ⓘ), plugin package icons, auto-growing script inputs and before-launch plugin tasks (API-29).

#### ⚡ Improvements

- Update settings are now merged into the About page, with Rust Core and upstream Viva project cards.
- Unified tooltip styling across all three windows (dark surface with light text in light theme); settings ⓘ tips show on hover.
- Synced Viva to fork `main` `1c0d556` (incorporating upstream `bd396bc` and tooltip border arrow fix).

#### 🛠 Fixes

- Fixed a missing parameter in Windows toolchain probe tests.

### Upgrade instructions

- From 0.8.6: check for updates from the title-bar update entry or Settings → About to update in-app; earlier versions download the full package.
- Windows 0.8.0 cannot finish an in-app update; download and run this release's installer instead.
- macOS: or open the DMG for your processor and drag `Lithe Desktop.app` to Applications.
- Homebrew: run `brew update && brew upgrade --cask lithe` after the cask is updated to this release.
- Windows: run the x64 installer, or extract the ZIP into its own directory and run `lithe.exe`.
- Linux: use the DEB/RPM for your architecture; tar.gz users must provide the required runtime libraries.

### Compatibility and known issues

- Java plugin 4.1.0's automatic JDK 25 and JDT LS preparation (`managedRuntimes` 0) requires this desktop version or newer; earlier desktop versions keep Java plugin 4.0.2.
- Automatic plugin updates are off by default; previously installed plugins need one manual marketplace update to record their index origin before participating.
- macOS requires 13.0 or newer, with separate Apple Silicon and Intel packages; the Windows desktop package targets x64.
- Linux packages target x64 and ARM64, requiring compatible libraries and a graphical environment; not every distribution is verified.
- Generated run configurations, service debugging and hiding folders such as `target` and `node_modules` need the matching language or build plugin enabled.
- macOS packages use ad hoc signing without notarization; Windows installers have no publisher signature and may trigger system prompts.

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it remains blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
