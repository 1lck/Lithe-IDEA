Lithe Desktop 0.8.16 让你自己选择哪些文件用 Lithe 打开，插件更新更省流量，插件也能完成选题、预览、输出和联网这类常见工作流。

### 重点更新

本次更新集中在文件关联、插件和远程连接。

#### ✨ 新功能

- 「外观与行为 → 通用」新增「文件关联」，勾选由 Lithe 打开的文本格式，并显示系统当前的默认应用。
- 在访达或资源管理器中打开已关联的文件，会直接在 Lithe 的单文件窗口中打开。
- 已安装插件更新时只下载变化的部分，还能在后台提前准备好，下次启动直接用上新版本。
- 插件市场的列表和详情显示插件自己的 SVG 图标。
- 运行窗口的 CPU 和内存图表可以折叠，折叠与否会被记住。
- 插件可以弹出快速选择和输入框，打开 Markdown 或 HTML 预览和只读对比，并在输出、进度和状态栏中显示结果。
- 插件可以读取、搜索和监听项目文件，保存文档，以及新建、重命名、复制文件或移到废纸篓。
- 插件只有后端的命令也会出现在命令面板中，并可以绑定快捷键。
- 构建插件自动找到的运行入口，和手动新建的同类运行配置归入同一分组，使用相同的图标和表单。
- 测试结果中的套件和用例可以右键跳转到源码或重新运行，Build 窗口「已发现的测试」也能跳转到源码。

#### ⚡ 改进

- Build 窗口和插件设置页每次重绘做的工作更少，减少卡顿。
- 打开项目切换菜单时，最近项目的分支名显示更快。
- 设置、日志和插件文件的保存方式更稳妥，断电或崩溃后不再留下空文件或半截文件。
- 英文界面中带数量的文字改用不受单复数影响的写法。

#### 🛠 修复

- 远程连接断线重连时会重新核验主机信任，SSH 别名改指其他主机后不会沿用原主机的信任。
- 远程保存文件只能写入远程工作区内，重新打开容器中的工作树时保留外层连接。
- 单文件模式下跳到其他目录的 Markdown 文件后，图片和链接按当前文件所在目录解析。
- 插件网页打开时，悬停提示、补全和导航弹层不再被网页遮住。
- 插件的工具窗口显示插件声明的图标，网页调用后端失败时能收到插件自己的错误码。
- 引用和问题窗口刷新结果时，选中项不再跳到新增的行。
- 项目的目录排除规则读不出来时，不再用空规则覆盖原文件。
- 插件在重载过程中被更新时，语言、命令和工具窗口不再读到不同版本的配置。
- 调试器设置中的过滤和开关行恢复鼠标悬停高亮。
- 英文界面「新建项目」左栏底部的插件入口在栏内换行，不再压到右侧表单。

#### 🔌 插件需要的新宿主能力

以下插件版本需要本版新增的宿主方法和权限，Lithe 0.8.15 及更早的版本不认识这些权限，会拒绝安装插件。

- [LeetCode](https://github.com/xiaoyumuxi/LeetCode) 0.0.1（预发布）：需要宿主方法 `network/request`（权限 `network.request`）访问题库和判题，`window/showQuickPick` 与 `window/showInputBox`（权限 `window.input`）选择解题语言、关联账号，`preview/openMarkdown` 和内联内容的 `preview/openHTML` 在只读标签页打开题面、题解和讨论，`workspace/create`（权限 `workspace.files.write`）创建解题文件。它还依赖本版插件网页弹层、工具窗口图标和后端错误码的修复。

### 升级说明

- 可从标题栏的更新入口或「设置 → 关于」检查更新，也可以下载完整安装包。
- macOS 用户打开对应架构的 DMG，将 `Lithe Desktop.app` 拖入「应用程序」。
- Homebrew 配方更新后，运行 `brew update && brew upgrade --cask lithe`。
- Windows 用户运行 x64 安装程序，从 Windows 0.8.0 升级时请手动下载安装。
- Linux 用户可以用一行命令安装，也可以在全部下载文件中选 x64、ARM64 的 DEB、RPM 和 tar.gz。

### 兼容性与已知问题

- macOS 最低要求 13.0。Windows 提供 x64 安装包，Linux 需要兼容的运行库和图形环境。
- macOS 安装包使用临时签名，Windows 安装包无发行者签名。系统可能显示安全提示。
- Windows 上勾选文件关联后，需要在系统打开的「默认应用」设置中确认；Windows 11 的右键菜单项可能在「显示更多选项」里。
- 远程开发只支持 x86_64 和 arm64 的 Linux 主机。SSH 连接使用本机的 OpenSSH，WSL 只能在 Windows 上使用，Dev Container 需要本机安装 Dev Container CLI，且只能在本机构建。[#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- 远程工作区暂不启动语言服务器，调试、测试、构建工具以及插件提供的运行配置和执行前任务暂不可用，「在新窗口打开」和「在文件浏览器中显示」也暂不可用。[#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- 远程 Git 推送和拉取时的凭据询问暂不显示在窗口中，仓库根目录位于所打开文件夹上级时暂不支持。
- 单文件模式下，SVG 和 HTML 文件仍然只显示源码。[#2324](https://github.com/1lck/Lithe-IDEA/issues/2324)
- Windows 首次导入 Gradle 项目时，如果 Wrapper 尚未下载且探测超时，可在项目目录运行 `gradlew.bat --version` 等待下载完成，再回到 Lithe 重试。
- 以 `build.xml` 为根的 Apache Ant 工程仍有项目导入、调试和源码跳转缺口。[#1761](https://github.com/1lck/Lithe-IDEA/issues/1761)

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在「应用程序」中按住 Control 点按应用并选择「打开」。如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 使用 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

## English

Lithe Desktop 0.8.16 lets you choose which files open in Lithe, makes plugin updates smaller, and lets plugins handle common workflows such as picking items, previews, output, and network requests.

### Highlights

This release focuses on file associations, plugins, and remote connections.

#### ✨ New features

- Appearance & Behavior → General has a new File associations list. Tick the text formats Lithe should open, and see each format's current default app.
- Opening an associated file from Finder or File Explorer opens it directly in a Lithe single-file window.
- Updating an installed plugin downloads only what changed, and can be prepared in the background so the next launch uses the new version.
- The plugin marketplace list and details show a plugin's own SVG icon.
- The CPU and memory charts in the Run window can be collapsed, and Lithe remembers your choice.
- Plugins can show quick picks and input boxes, open Markdown or HTML previews and read-only diffs, and report results in output, progress, and status bar items.
- Plugins can read, search, and watch project files, save documents, and create, rename, copy, or move files to the Trash.
- Commands that a plugin provides only through its backend appear in the Command Palette and can have shortcuts.
- Run entries a build plugin finds on its own join the same group as run configurations of that kind you create, with the same icon and form.
- Suites and cases in test results can jump to their source or run again from the context menu, and Discovered Tests in the Build window can jump to source too.

#### ⚡ Improvements

- The Build window and plugin settings pages do less work on each redraw, which reduces stutter.
- Branch names of recent projects show up faster in the project switcher menu.
- Settings, logs, and plugin files are saved more safely, so a power loss or crash no longer leaves an empty or partial file.
- Text with counts in the English interface now uses wording that does not depend on singular or plural.

#### 🛠 Fixes

- Reconnecting to a remote host checks its trust again, and an SSH alias pointed at another host no longer reuses the old host's trust.
- Remote saves can only write inside the remote workspace, and reopening a worktree inside a container keeps the outer connection.
- In single-file mode, after you move to a Markdown file in another folder, images and links resolve from that file's own folder.
- Hover tips, completion, and navigation popups are no longer hidden behind an open plugin web page.
- A plugin's tool window shows the icon the plugin declares, and a web page whose backend call fails receives the plugin's own error code.
- When the References or Problems window refreshes, the selection no longer jumps to a newly added row.
- When a project's folder exclusion rules cannot be read, Lithe no longer overwrites the file with empty rules.
- When a plugin is updated during a reload, languages, commands, and tool windows no longer read different versions of its configuration.
- Filter and switch rows in the debugger settings highlight on hover again.
- In the English New Project dialog, the plugin link at the bottom of the sidebar wraps inside the sidebar instead of overlapping the form.

#### 🔌 New host capabilities that plugins need

These plugin versions need host methods and permissions added in this release. Lithe 0.8.15 and earlier do not know these permissions and refuse to install the plugin.

- [LeetCode](https://github.com/xiaoyumuxi/LeetCode) 0.0.1 (prerelease): needs the host methods `network/request` (permission `network.request`) to reach the problem set and the judge, `window/showQuickPick` and `window/showInputBox` (permission `window.input`) to choose a solution language and connect an account, `preview/openMarkdown` and `preview/openHTML` with inline content to open statements, solutions, and discussions in read-only tabs, and `workspace/create` (permission `workspace.files.write`) to create solution files. It also relies on this release's fixes for popups over plugin web pages, tool window icons, and backend error codes.

### Upgrade instructions

- Check for updates from the title bar or Settings → About, or download a full installer.
- On macOS, open the DMG for your architecture and drag `Lithe Desktop.app` to Applications.
- With Homebrew, run `brew update && brew upgrade --cask lithe` after the cask update is available.
- On Windows, run the x64 installer. Upgrading from Windows 0.8.0 needs a manual download.
- On Linux, use the one-line install, or pick a DEB, RPM, or tar.gz for x64 or ARM64 from the downloads.

### Compatibility and known issues

- macOS requires 13.0 or newer. Windows packages target x64. Linux requires compatible libraries and a graphical environment.
- macOS packages use ad hoc signing. Windows installers have no publisher signature. Your system may show security prompts.
- On Windows, after you tick file associations, confirm them in the Default apps settings that Windows opens. On Windows 11 the context menu entry may be under Show more options.
- Remote development supports x86_64 and arm64 Linux hosts only. SSH connections use the OpenSSH on your computer, WSL is available only on Windows, and Dev Containers need the Dev Container CLI installed on your computer and build only there. [#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- Remote workspaces do not start language servers yet. Debugging, tests, build tools, and plugin-provided run configurations and before-launch tasks are not available yet, and neither are Open in New Window and Reveal in File Manager. [#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- Credential prompts from remote Git push and pull are not shown in the window yet, and repositories whose root is above the opened folder are not supported yet.
- In single-file mode, SVG and HTML files still show their source only. [#2324](https://github.com/1lck/Lithe-IDEA/issues/2324)
- On Windows, a Gradle project can time out during its first import if its Wrapper distribution still needs to download. Run `gradlew.bat --version` in the project directory, wait for it to finish, and retry in Lithe.
- Apache Ant projects rooted at `build.xml` still have gaps in project import, debugging, and source navigation. [#1761](https://github.com/1lck/Lithe-IDEA/issues/1761)

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it is still blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"` in Terminal. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
