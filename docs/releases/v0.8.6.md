### 重点更新

本次重点是运行配置、构建选项和项目安全。

#### ✨ 新功能

- 新增“运行/调试配置”对话框，可在一处新建、编辑、复制、排序和删除运行配置，并用文件夹归类。
- 插件可以提供自己的运行配置类型，例如 Go 插件的“Go 构建”和“Go 测试”。
- 运行配置可以勾选“允许多个实例”，再次启动时与正在运行的那份并存。
- 运行控制台新增自动换行开关。
- 项目树右键新增“打开于”和“打开方式”，可用系统关联的应用、文件管理器或终端打开文件。
- 构建窗口和构建选项中，Maven 配置文件（Profile）等多选项可以直接勾选切换，并标出默认生效的项。
- “工具链”设置新增“信任当前项目中的工具环境”，信任前不会运行项目目录里的虚拟环境和包装器。
- 标题栏的调试、搜索、设置按钮可以拖到左右侧栏。

#### ⚡ 改进

- 解释器路径改为下拉选择：自动、终端检测到的同类 shell，或自定义路径。
- 改了插件设置后，下一次构建或运行就用新设置，不用重开项目。
- 构建插件报错时，运行窗口显示插件给出的原因，不再只显示通用错误。
- `.gradle` 和 `.gradle.kts` 文件显示 Gradle 图标。

#### 🛠 修复

- 在标题栏的项目菜单等弹出面板上滚动时，下面的项目树不再跟着滚动。
- 鼠标停留打开“打开于”菜单时会列出应用，不再一直显示“正在查找应用…”。
- 声明了状态或日志目录的调试器可以正常启动。

### 升级说明

- 已安装 0.8.5：在标题栏的更新入口或“设置 → 更新”中检查更新，即可在应用内更新到本版；更早的版本会下载完整安装包。
- Windows 0.8.0 无法在应用内完成更新，请下载本版安装程序手动安装。
- macOS：也可选择对应芯片的 DMG，将 `Lithe Desktop.app` 拖入“应用程序”。
- Homebrew：配方更新到本版后，运行 `brew update && brew upgrade --cask lithe`。
- Windows：运行 x64 安装程序，或将 ZIP 解压到独立目录后运行 `lithe.exe`。
- Linux：使用对应架构的 DEB/RPM；tar.gz 用户需要自行满足运行库要求。

### 兼容性与已知问题

- Go 插件 1.1.0 的“Go 构建”和“Go 测试”运行配置需要本版或更新的桌面端，更早的桌面端继续使用 Go 插件 1.0.1。
- 项目内的工具环境（如项目里的 `.venv`）在信任前不会被探测或运行，会改用本机或系统的工具；信任记录只保存在本机。
- cmd 批处理运行配置在 macOS 和 Linux 上可以编辑，但只能在 Windows 上运行。
- macOS 最低为 13.0，分别提供 Apple Silicon 和 Intel 包；Windows 桌面端提供 x64 包。
- Linux 提供 x64 和 ARM64 包，需要兼容的运行库和图形环境，未验证所有发行版。
- 自动生成运行配置、调试服务、隐藏 `target`、`node_modules` 等目录需要启用对应的语言或构建插件。
- 新客户端的功能迁移仍在进行，部分旧版功能尚未完全对齐。
- macOS 使用临时签名且未公证，Windows 安装包没有发行者签名，系统可能显示安全提示。

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在“应用程序”中按住 Control 点按应用并选择“打开”；如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 对应命令是 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

### Highlights

This release focuses on run configurations, build options and project safety.

#### ✨ New features

- A new Run/Debug Configurations dialog creates, edits, copies, sorts, deletes and groups run configurations in folders.
- Plugins can provide their own run configuration types, such as Go Build and Go Test from the Go plugin.
- Tick Allow multiple instances to start a run configuration again alongside the one already running.
- The run console has a soft-wrap switch.
- The project tree's context menu adds Open In and Open With, to open files in associated apps, the file manager or a terminal.
- In the Build window and build options, multi-choice options such as Maven profiles toggle with checkboxes and mark the default ones.
- Toolchain settings add Trust tool environments in this project; until then, virtual environments and wrappers in the project never run.
- The title bar's Debug, Search and Settings buttons can be dragged to the left or right sidebar.

#### ⚡ Improvements

- The interpreter path is now a dropdown: automatic, a matching shell your terminal detected, or a custom path.
- After you change a plugin's settings, the next build or run uses them without reopening the project.
- When a build plugin fails, the run window shows the plugin's own reason instead of a generic error.
- `.gradle` and `.gradle.kts` files show the Gradle icon.

#### 🛠 Fixes

- Scrolling over popups such as the title bar's project menu no longer scrolls the project tree underneath.
- Hovering to open the Open In menu lists the apps instead of staying on Finding Applications….
- Debuggers that declare state or log folders start correctly.

### Upgrade instructions

- From 0.8.5: check for updates from the title-bar update entry or Settings → Updates to update in-app; earlier versions download the full package.
- Windows 0.8.0 cannot finish an in-app update; download and run this release's installer instead.
- macOS: or open the DMG for your processor and drag `Lithe Desktop.app` to Applications.
- Homebrew: run `brew update && brew upgrade --cask lithe` after the cask is updated to this release.
- Windows: run the x64 installer, or extract the ZIP into its own directory and run `lithe.exe`.
- Linux: use the DEB/RPM for your architecture; tar.gz users must provide the required runtime libraries.

### Compatibility and known issues

- The Go Build and Go Test run configurations of Go plugin 1.1.0 need this desktop version or newer; earlier desktop versions keep Go plugin 1.0.1.
- Tool environments inside a project, such as its `.venv`, are not probed or run until you trust the project; Lithe uses local or system tools instead, and the trust stays on this computer.
- cmd batch run configurations can be edited on macOS and Linux but run only on Windows.
- macOS requires 13.0 or newer, with separate Apple Silicon and Intel packages; the Windows desktop package targets x64.
- Linux packages target x64 and ARM64, requiring compatible libraries and a graphical environment; not every distribution is verified.
- Generated run configurations, service debugging and hiding folders such as `target` and `node_modules` need the matching language or build plugin enabled.
- Feature migration continues; some features of the older client are not yet at full parity.
- macOS packages use ad hoc signing without notarization; Windows installers have no publisher signature and may trigger system prompts.

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it remains blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
