### 重点更新

本次重点是运行配置和多仓库 Git。

#### ✨ 新功能

- 不装插件也能创建并运行 Shell、PowerShell、cmd 脚本和可执行程序的运行配置。
- 多个运行配置可以同时运行，每个都有自己的控制台。
- 运行配置可以设置启动前步骤，先按顺序运行其他配置，全部成功后再启动。
- 打开带 main 方法的 Java 类，选“当前文件”点运行即可运行，并自动保存为运行配置。
- 多仓库文件夹的分支弹窗列出共同分支，可在所有仓库一起检出或新建分支。
- 多仓库检出只在部分仓库成功时，可以一键回滚已完成的仓库。

#### ⚡ 改进

- 控制台里的网址可以点击，在浏览器中打开。
- 运行中的配置在列表和标签上显示运行图标，不再闪动。
- 多仓库合并日志中，每个仓库当前所在的分支都会高亮。
- 侧栏的“…”按钮可以像其他按钮一样拖动和移动，移除没有功能的“更新”入口。
- Windows 上拖动调整窗口大小时界面保持流畅，内容不再被拉伸。

#### 🛠 修复

- 编辑器和行号栏右键菜单的第一项可以正常点击。
- Linux Wayland 下点击界面内容后，键盘和输入法不再失灵。

### 升级说明

- 已安装 0.8.4：在标题栏的更新入口或“设置 → 更新”中检查更新，即可在应用内更新到本版；更早的版本会下载完整安装包。
- Windows 0.8.0 无法在应用内完成更新，请下载本版安装程序手动安装。
- macOS：也可选择对应芯片的 DMG，将 `Lithe Desktop.app` 拖入“应用程序”。
- Homebrew：配方更新到本版后，运行 `brew update && brew upgrade --cask lithe`。
- Windows：运行 x64 安装程序，或将 ZIP 解压到独立目录后运行 `lithe.exe`。
- Linux：使用对应架构的 DEB/RPM；tar.gz 用户需要自行满足运行库要求。

### 兼容性与已知问题

- 运行配置改存为 `.lithe/run/` 下的 YAML 文件，旧的 JSON 在第一次编辑时自动转换；转换后 0.8.4 及更早版本读不到这些配置。
- 运行当前文件里的 Java 类需要 Maven 插件 1.0.1 及以上；该版插件需要本版或更新的桌面端。
- macOS 最低为 13.0，分别提供 Apple Silicon 和 Intel 包；Windows 桌面端提供 x64 包。
- Linux 提供 x64 和 ARM64 包，需要兼容的运行库和图形环境，未验证所有发行版。
- 自动生成运行配置、调试服务、隐藏 `target`、`node_modules` 等目录需要启用对应的语言或构建插件。
- 新客户端的功能迁移仍在进行，部分旧版功能尚未完全对齐。
- macOS 使用临时签名且未公证，Windows 安装包没有发行者签名，系统可能显示安全提示。

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在“应用程序”中按住 Control 点按应用并选择“打开”；如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 对应命令是 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

### Highlights

This release focuses on run configurations and multi-repository Git.

#### ✨ New features

- Create and run Shell, PowerShell, cmd script and executable run configurations without any plugin.
- Run several run configurations at the same time, each with its own console.
- Run configurations can list steps before launch that run other configurations first, in order.
- Open a Java class with a main method, choose Current File and press Run to run it and save it as a run configuration.
- In a folder with several repositories, the branch popup lists common branches to check out or create in all of them.
- When a multi-repository checkout succeeds in only some repositories, roll the finished ones back in one step.

#### ⚡ Improvements

- Web addresses in the console are clickable and open in the browser.
- Running configurations show a steady running icon in lists and tabs.
- The combined multi-repository log highlights the current branch of every repository.
- The sidebar "…" button can be dragged and moved like other buttons; the placeholder Updates entry is removed.
- On Windows, resizing the window stays smooth and no longer stretches the content.

#### 🛠 Fixes

- The first item of the editor and gutter context menus can be clicked.
- On Linux Wayland, the keyboard and input method keep working after clicking content.

### Upgrade instructions

- From 0.8.4: check for updates from the title-bar update entry or Settings → Updates to update in-app; earlier versions download the full package.
- Windows 0.8.0 cannot finish an in-app update; download and run this release's installer instead.
- macOS: or open the DMG for your processor and drag `Lithe Desktop.app` to Applications.
- Homebrew: run `brew update && brew upgrade --cask lithe` after the cask is updated to this release.
- Windows: run the x64 installer, or extract the ZIP into its own directory and run `lithe.exe`.
- Linux: use the DEB/RPM for your architecture; tar.gz users must provide the required runtime libraries.

### Compatibility and known issues

- Run configurations are now stored as YAML files under `.lithe/run/`; old JSON files convert on first edit, after which 0.8.4 and earlier cannot read them.
- Running a Java class from the current file needs the Maven plugin 1.0.1 or later, which needs this desktop version or newer.
- macOS requires 13.0 or newer, with separate Apple Silicon and Intel packages; the Windows desktop package targets x64.
- Linux packages target x64 and ARM64, requiring compatible libraries and a graphical environment; not every distribution is verified.
- Generated run configurations, service debugging and hiding folders such as `target` and `node_modules` need the matching language or build plugin enabled.
- Feature migration continues; some features of the older client are not yet at full parity.
- macOS packages use ad hoc signing without notarization; Windows installers have no publisher signature and may trigger system prompts.

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it remains blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
