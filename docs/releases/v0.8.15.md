## 中文

Lithe Desktop 0.8.15 让插件更快拿到新版本，也让插件能把解释器这类工具的选择直接放进自己的设置页。

### 重点更新

本次更新集中在插件、远程连接和单文件模式。

#### ✨ 新功能

- 「外观与行为 → 编辑器」新增「自动补全」开关，关掉后输入时不再自动弹出补全列表，Ctrl+Space 手动补全仍然可用。
- 插件的设置页可以把工具那一行做成下拉菜单，在原处为项目或全局选择一个已找到的工具，不用跳到「工具链」页。
- 已安装插件的详情新增「更新日志」页签，直接显示插件新版本改了什么。
- 工具链接受链接到主目录外的程序，建在项目外的虚拟环境和 Homebrew 安装的解释器可以选用。
- 单文件模式下打开 Markdown 文件会显示渲染后的页面，可以在编辑和预览之间切换，并用目录按钮跳转标题。
- SSH 身份验证窗口新增「记住」勾选，勾上后密码或私钥口令存入系统钥匙串，下次连接不再询问；验证码从不记住。
- Linux 新增一行命令安装：从应用自己的更新源下载并校验 tar.gz，装到 `~/.local` 并加入应用程序菜单，之后可以用应用内增量更新。

#### ⚡ 改进

- 插件市场的索引改为固定到最新提交读取，设置窗口打开后也会自己刷新过期数据，插件的新版本不用再等几分钟、重开窗口才能看到。
- 插件权限列表为每一项权限补上中英文说明，安装前能看懂插件要什么权限。

#### 🛠 修复

- 改完立即生效的设置后，插件的语言服务器会重新拿到后端算出的配置，不用再重新加载项目。
- 确认删除 Git 分支后工作台立即可用，不再短暂卡住。
- 插件设置页的设置行随页面一起滚动，不再被自己的滚动区域截断。
- 插件设置页的画布上，整行放得下的多段文字不再截断最后一段。
- 「构建、执行、部署」设置页数量为 1 时，英文改用单数。

#### 🔌 插件需要的新宿主能力

以下插件版本需要本版新增的宿主能力，Lithe 0.8.14 及更早的版本不认识这些字段，会拒绝安装或拒绝显示插件的设置页。

- [Python Support](https://github.com/Lithe-IDEA/lithe-plugin-python) 1.2.0（预发布）：需要设置区域工具行的 `choose`（`ui` 能力版本 0 内的补充，让一行工具同时成为该工具的选择器），用于在 Python 设置页原处选择解释器；需要工具定义的 `executableLinksOutsideHome`（`toolDefinitions` 能力版本 0 内的补充，接受链接到主目录外的程序），用于选用建在项目外的虚拟环境和 Homebrew 安装的 Python。它还依赖本版「改完立即生效的设置后语言服务器重新取配置」的修复。
- [Python Support](https://github.com/Lithe-IDEA/lithe-plugin-python) 1.1.0：不需要新能力，支持 Lithe 0.8.9 及以上，但同样依赖本版上述修复，否则改完设置要重新加载项目。

### 升级说明

- 可从标题栏的更新入口或「设置 → 关于」检查更新，也可以下载完整安装包。
- macOS 用户打开对应架构的 DMG，将 `Lithe Desktop.app` 拖入「应用程序」。
- Homebrew 配方更新后，运行 `brew update && brew upgrade --cask lithe`。
- Windows 用户运行 x64 安装程序，从 Windows 0.8.0 升级时请手动下载安装。
- Linux 用户可以用一行命令安装，也可以在全部下载文件中选 x64、ARM64 的 DEB、RPM 和 tar.gz。

### 兼容性与已知问题

- macOS 最低要求 13.0。Windows 提供 x64 安装包，Linux 需要兼容的运行库和图形环境。
- macOS 安装包使用临时签名，Windows 安装包无发行者签名。系统可能显示安全提示。
- 远程开发只支持 x86_64 和 arm64 的 Linux 主机。SSH 连接使用本机的 OpenSSH，WSL 只能在 Windows 上使用，Dev Container 需要本机安装 Dev Container CLI，且只能在本机构建。[#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- 远程工作区暂不启动语言服务器，调试、测试、构建工具以及插件提供的运行配置和执行前任务暂不可用，「在新窗口打开」和「在文件浏览器中显示」也暂不可用。[#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- 远程 Git 推送和拉取时的凭据询问暂不显示在窗口中，仓库根目录位于所打开文件夹上级时暂不支持。
- 单文件模式下，SVG 和 HTML 文件仍然只显示源码。[#2324](https://github.com/1lck/Lithe-IDEA/issues/2324)
- Windows 首次导入 Gradle 项目时，如果 Wrapper 尚未下载且探测超时，可在项目目录运行 `gradlew.bat --version` 等待下载完成，再回到 Lithe 重试。
- 以 `build.xml` 为根的 Apache Ant 工程仍有项目导入、调试和源码跳转缺口。[#1761](https://github.com/1lck/Lithe-IDEA/issues/1761)

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在「应用程序」中按住 Control 点按应用并选择「打开」。如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 使用 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

## English

Lithe Desktop 0.8.15 brings plugin updates to you sooner and lets a plugin put the choice of a tool, such as an interpreter, right in its own settings page.

### Downloads

- [Project homepage](https://github.com/1lck/Lithe-IDEA)
- [macOS Apple Silicon DMG](https://github.com/1lck/Lithe-IDEA/releases/download/desktop-v0.8.15/lithe-0.8.15-darwin-arm64.dmg)

### Highlights

This release focuses on plugins, remote connections, and single-file mode.

#### ✨ New features

- Appearance & Behavior → Editor has a new Autocomplete switch. Turn it off and the completion list no longer opens as you type; Ctrl+Space still asks for it.
- A plugin's settings page can turn its tool row into a drop-down menu, so you choose a found tool for the project or for all projects right there instead of opening the Toolchains page.
- The details of an installed plugin have a new Changelog tab that shows what a new version changed.
- Toolchains accept a program that links outside your home folder, so virtual environments made outside the project and interpreters installed by Homebrew can be used.
- Opening a Markdown file in single-file mode shows the rendered page, with a switch between editing and preview and a button that jumps to a heading.
- The SSH authentication window has a Remember checkbox. Tick it and the password or key passphrase goes to the system keychain, so the next connection does not ask. Verification codes are never remembered.
- Linux has a one-line install: it downloads and verifies a tar.gz from the app's own update feed, installs it under `~/.local`, and adds it to the applications menu, so in-app patch updates work afterwards.

#### ⚡ Improvements

- The plugin marketplace index is now read at its latest commit, and the settings window refreshes stale data on its own, so a plugin's new version no longer takes minutes and a window reopen to appear.
- The plugin permission list explains every permission in Chinese and English, so you can tell what a plugin asks for before installing it.

#### 🛠 Fixes

- After you change a setting that applies immediately, a plugin's language server is given the configuration its backend computes again, so reloading the project is no longer needed.
- The workbench is usable immediately after you confirm deleting a Git branch, instead of briefly freezing.
- Setting rows on a plugin settings page scroll with the page instead of being cut off by their own scroll area.
- On a plugin settings page's canvas, several runs of text that fit on one line no longer lose the last run.
- The Build, Execution, Deployment settings page uses the singular in English when the count is 1.

#### 🔌 New host capabilities that plugins need

These plugin versions need capabilities added in this release. Lithe 0.8.14 and earlier do not know these fields and refuse to install the plugin or to show its settings page.

- [Python Support](https://github.com/Lithe-IDEA/lithe-plugin-python) 1.2.0 (prerelease): needs `choose` on a settings region's tool row (an addition within `ui` capability version 0 that makes a tool row the picker for that tool) to choose the interpreter in the Python settings page, and `executableLinksOutsideHome` on a tool definition (an addition within `toolDefinitions` capability version 0 that accepts a program linking outside your home folder) to use virtual environments made outside the project and Python installed by Homebrew. It also relies on this release's fix for a language server being given its backend's configuration again.
- [Python Support](https://github.com/Lithe-IDEA/lithe-plugin-python) 1.1.0: needs no new capability and supports Lithe 0.8.9 or later, but relies on the same fix; without it, changing a setting means reloading the project.

### Upgrade instructions

- Check for updates from the title bar or Settings → About, or download a full installer.
- On macOS, open the DMG for your architecture and drag `Lithe Desktop.app` to Applications.
- With Homebrew, run `brew update && brew upgrade --cask lithe` after the cask update is available.
- On Windows, run the x64 installer. Upgrading from Windows 0.8.0 needs a manual download.
- On Linux, use the one-line install, or pick a DEB, RPM, or tar.gz for x64 or ARM64 from the downloads.

### Compatibility and known issues

- macOS requires 13.0 or newer. Windows packages target x64. Linux requires compatible libraries and a graphical environment.
- macOS packages use ad hoc signing. Windows installers have no publisher signature. Your system may show security prompts.
- Remote development supports x86_64 and arm64 Linux hosts only. SSH connections use the OpenSSH on your computer, WSL is available only on Windows, and Dev Containers need the Dev Container CLI installed on your computer and build only there. [#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- Remote workspaces do not start language servers yet. Debugging, tests, build tools, and plugin-provided run configurations and before-launch tasks are not available yet, and neither are Open in New Window and Reveal in File Manager. [#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- Credential prompts from remote Git push and pull are not shown in the window yet, and repositories whose root is above the opened folder are not supported yet.
- In single-file mode, SVG and HTML files still show their source only. [#2324](https://github.com/1lck/Lithe-IDEA/issues/2324)
- On Windows, a Gradle project can time out during its first import if its Wrapper distribution still needs to download. Run `gradlew.bat --version` in the project directory, wait for it to finish, and retry in Lithe.
- Apache Ant projects rooted at `build.xml` still have gaps in project import, debugging, and source navigation. [#1761](https://github.com/1lck/Lithe-IDEA/issues/1761)

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it is still blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"` in Terminal. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
