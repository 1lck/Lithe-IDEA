Lithe Desktop 0.8.14 让远程开发可以用于日常工作：在 SSH 主机、WSL 发行版和 Docker/Podman 容器中打开项目后，可以编辑文件、使用终端、搜索、运行 Git 和程序。

### 重点更新

连接 Linux 主机后，项目文件、终端、搜索、Git 和运行都在主机上进行，Lithe 和插件仍在本机。

#### ✨ 新功能

- 在远程工作区打开、编辑、保存和比较主机上的文件，主机上的修改会同步到项目树和已打开的文档。
- 远程工作区的终端在主机上运行。
- 在文件中查找、全局搜索和全部替换直接处理主机上的文件。
- 信任远程文件夹后，Git 在主机上运行，也可以打开和新建 Git 工作树。
- 在主机上运行程序和脚本运行配置及其执行前步骤，断线重连后输出继续显示。
- 关闭远程工作区时，可以把仍在运行的进程留在主机上，下次连接后在运行窗口接回。
- 新增“端口”工具窗口，列出主机正在监听的端口并按需转发到本机，支持主机侧转发规则和反向转发。默认不自动转发，标签、规则和未停止的转发会在重连或重新打开后恢复。
- 在 Windows 上，远程开发窗口列出本机的 WSL 发行版，可直接作为远程工作区打开。
- 进入本机、SSH 主机或 WSL 发行版上正在运行的 Docker/Podman 容器，也可以从本机文件夹中的 `devcontainer.json` 构建并打开 Dev Container。
- 通过状态栏的连接菜单打开工作区以外的主机文件，这些文件以只读方式打开。
- 在“设置 → 工具 → 远程工作区”中指定 SSH 程序、断线重连时长，以及关闭时如何处理主机上的进程。

#### ⚡ 改进

- 远程开发窗口重新设计。没有保存的连接时可以直接快速连接，可从 Motty 或 `~/.ssh/config` 导入主机，连接过程分步显示，SSH 询问直接在窗口中回答。
- 第一次打开远程文件夹时会询问是否信任，“设置 → 工具 → 可信位置”按连接列出远程工作区的信任记录并可删除。
- 连接支持 Windows 域用户（`DOMAIN\name`、`name@domain`），从 Motty 导入时会在对应字段标出不能导入的设置。

#### 🛠 修复

- 修复 Windows 普通账户在只有“修改”权限的项目中保存已有运行配置时提示拒绝访问的问题。
- 设置文件无法读取时，启动后会提示已改用默认设置，并在下次保存时说明原文件的备份位置。
- 修复窗口异常退出后进程无法结束的问题，未保存的编辑会存为恢复草稿。
- 连接未安装的 WSL 发行版时说明无法连接，用户不存在等其他失败会显示 `wsl.exe` 给出的消息。

#### 🔌 插件需要的新宿主能力

以下插件版本需要本版新增的宿主方法及其权限，Lithe 0.8.13 及更早的版本不认识这些权限，会拒绝安装。

- [Gradle](https://github.com/Lithe-IDEA/lithe-plugin-gradle) 2.0.2（尚未发布）需要宿主方法 `build/getOptions`（权限 `build.options.read`）和 `build/watchConfiguration`（权限 `build.configuration.watch`），用于把工具栏的离线模式、Gradle 用户目录和 `gradle.properties` 中的设置交给 Java 导入，并在这些配置变化后刷新导入。

### 升级说明

- 可从标题栏的更新入口或“设置 → 关于”检查更新，也可以下载完整安装包。
- macOS 用户打开对应架构的 DMG，将 `Lithe Desktop.app` 拖入“应用程序”。
- Homebrew 配方更新后，运行 `brew update && brew upgrade --cask lithe`。
- Windows 用户运行 x64 安装程序，从 Windows 0.8.0 升级时请手动下载安装。
- 全部下载文件中提供 Linux x64、ARM64 的 DEB、RPM 和 tar.gz。

### 兼容性与已知问题

- macOS 最低要求 13.0。Windows 提供 x64 安装包，Linux 需要兼容的运行库和图形环境。
- macOS 安装包使用临时签名，Windows 安装包无发行者签名。系统可能显示安全提示。
- 远程开发只支持 x86_64 和 arm64 的 Linux 主机。SSH 连接使用本机的 OpenSSH，WSL 只能在 Windows 上使用，Dev Container 需要本机安装 Dev Container CLI，且只能在本机构建。[#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- 远程工作区暂不启动语言服务器，调试、测试、构建工具以及插件提供的运行配置和执行前任务暂不可用，“在新窗口打开”和“在文件浏览器中显示”也暂不可用。[#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- 远程 Git 推送和拉取时的凭据询问暂不显示在窗口中，仓库根目录位于所打开文件夹上级时暂不支持。
- Windows 首次导入 Gradle 项目时，如果 Wrapper 尚未下载且探测超时，可在项目目录运行 `gradlew.bat --version` 等待下载完成，再回到 Lithe 重试。
- 在 Windows 11 ARM64 上运行 x64 版时，Spring Petclinic 的 Gradle 调试因 Java 语言服务器请求超时而未能启动。
- 以 `build.xml` 为根的 Apache Ant 工程仍有项目导入、调试和源码跳转缺口。[#1761](https://github.com/1lck/Lithe-IDEA/issues/1761)

如果 macOS 提示无法打开 `Lithe Desktop.app`，请在“应用程序”中按住 Control 点按应用并选择“打开”。如果仍被阻止，可执行 `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"`。旧版 `Lithe.app` 使用 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

## English

Lithe Desktop 0.8.14 makes remote development ready for daily work. Open a project on an SSH host, a WSL distribution, or a Docker or Podman container, then edit files, use the terminal, search, and run Git and programs there.

### Downloads

- [Project homepage](https://github.com/1lck/Lithe-IDEA)
- [macOS Apple Silicon DMG](https://github.com/1lck/Lithe-IDEA/releases/download/desktop-v0.8.14/lithe-0.8.14-darwin-arm64.dmg)
- [macOS Intel DMG](https://github.com/1lck/Lithe-IDEA/releases/download/desktop-v0.8.14/lithe-0.8.14-darwin-amd64.dmg)
- [Windows x64 installer](https://github.com/1lck/Lithe-IDEA/releases/download/desktop-v0.8.14/lithe-0.8.14-windows-amd64-setup.exe)
- [All downloads and SHA-256 checksums](https://github.com/1lck/Lithe-IDEA/releases/tag/desktop-v0.8.14)

### Highlights

Once you connect to a Linux host, project files, the terminal, search, Git, and runs all happen on the host, while Lithe and its plugins stay on your computer.

#### ✨ New features

- Open, edit, save, and compare host files in a remote workspace. Changes made on the host update the project tree and open documents.
- Terminals in a remote workspace run on the host.
- Find in Files, Search Everywhere, and Replace All work directly on host files.
- After you trust a remote folder, Git runs on the host, and you can open and create Git worktrees.
- Run program and script run configurations and their before-launch steps on the host. Output continues after a reconnect.
- When you close a remote workspace, you can keep its running processes on the host and take them back in the Run window the next time you connect.
- The new Ports tool window lists the ports the host listens on and forwards them to your computer on request, with host-side forwarding rules and reverse forwarding. Nothing is forwarded automatically, and labels, rules, and active forwards come back after a reconnect or reopen.
- On Windows, the Remote Development window lists your WSL distributions and opens one as a remote workspace.
- Enter a running Docker or Podman container on your computer, an SSH host, or a WSL distribution, or build and open a Dev Container from a `devcontainer.json` in a local folder.
- Open host files outside the workspace from the connection menu in the status bar. These files open read-only.
- Choose the SSH program, the reconnect duration, and what happens to host processes on close in Settings → Tools → Remote Workspace.

#### ⚡ Improvements

- The Remote Development window has a new design. With no saved connections you can connect right away, import hosts from Motty or `~/.ssh/config`, follow each connection step, and answer SSH prompts in the window.
- Opening a remote folder for the first time asks whether to trust it, and Settings → Tools → Trusted Locations lists and removes the trust records of remote workspaces by connection.
- Connections accept Windows domain users (`DOMAIN\name`, `name@domain`), and a Motty import marks each setting it cannot import on its own field.

#### 🛠 Fixes

- Fixes “Access is denied” when a standard Windows account with Modify access saves an existing run configuration.
- When the settings file cannot be read, Lithe now says at startup that it uses the default settings and names the backup of the original file on the next save.
- Fixes the process not exiting after its window loop ends unexpectedly. Unsaved edits are kept as recovery drafts.
- Connecting to a WSL distribution that is not installed now says it cannot be reached, and other failures such as an unknown user show the message from `wsl.exe`.

#### 🔌 New host capabilities that plugins need

These plugin versions need host methods and permissions added in this release. Lithe 0.8.13 and earlier do not know these permissions and refuse to install them.

- [Gradle](https://github.com/Lithe-IDEA/lithe-plugin-gradle) 2.0.2 (not yet published) needs the host methods `build/getOptions` (permission `build.options.read`) and `build/watchConfiguration` (permission `build.configuration.watch`) to pass the toolbar's offline mode, Gradle user home, and `gradle.properties` settings to the Java import, and to refresh the import when they change.

### Upgrade instructions

- Check for updates from the title bar or Settings → About, or download a full installer.
- On macOS, open the DMG for your processor and drag `Lithe Desktop.app` to Applications.
- With Homebrew, run `brew update && brew upgrade --cask lithe` once the cask update is available.
- On Windows, run the x64 installer. Windows 0.8.0 users should download and install it manually.
- Linux downloads include DEB, RPM, and tar.gz packages for x64 and ARM64.

### Compatibility and known issues

- macOS requires 13.0 or newer. Windows packages target x64. Linux requires compatible libraries and a graphical environment.
- macOS packages use ad hoc signing. Windows installers have no publisher signature. Your system may show security prompts.
- Remote development supports x86_64 and arm64 Linux hosts only. SSH connections use the OpenSSH on your computer, WSL is available only on Windows, and Dev Containers need the Dev Container CLI installed on your computer and build only there. [#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- Remote workspaces do not start language servers yet. Debugging, tests, build tools, and plugin-provided run configurations and before-launch tasks are not available yet, and neither are Open in New Window and Reveal in File Manager. [#2231](https://github.com/1lck/Lithe-IDEA/issues/2231)
- Credential prompts from remote Git push and pull are not shown in the window yet, and repositories whose root is above the opened folder are not supported yet.
- On Windows, a Gradle project can time out during its first import if its Wrapper distribution still needs to download. Run `gradlew.bat --version` in the project directory, wait for it to finish, and retry in Lithe.
- Gradle debugging for Spring Petclinic could not start in the x64 app on Windows 11 ARM64 because the Java language server request timed out.
- Apache Ant projects rooted at `build.xml` still have gaps in project import, debugging, and source navigation. [#1761](https://github.com/1lck/Lithe-IDEA/issues/1761)

If macOS cannot open `Lithe Desktop.app`, Control-click it in Applications and choose Open. If it is still blocked, run `xattr -dr com.apple.quarantine "/Applications/Lithe Desktop.app"` in Terminal. For the older `Lithe.app`, use `xattr -dr com.apple.quarantine /Applications/Lithe.app`. Use these commands only for an app from a source you trust.
