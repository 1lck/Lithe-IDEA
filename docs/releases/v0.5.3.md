## 中文

本次更新让大项目打开运行面板更顺畅，修复了 JDK 8 项目无法启动和 Windows 上 Java 无法格式化，并提升 macOS 应用内更新的可靠性。

### 重点更新

本次更新内容如下。

#### ✨ 新功能

- macOS：项目侧栏可切换到“依赖”视图，按运行服务查看源码、构建产物和依赖路径。

#### ⚡ 改进

- 大项目打开运行面板不再长时间等待，只改方法体也不会再误报“配置可能已过期”。
- macOS：大项目中保存或新建运行配置时界面不再卡住。
- 打开项目和普通 Java 文件时，日志中不再出现误导性的 Java 错误。

#### 🛠 修复

- 使用 JDK 8（版本号为 1.8.x）的项目不再被误判为版本不满足而无法启动。
- Windows：Java 文件可用 Ctrl+Alt+L 格式化，不再提示未配置格式化程序。
- macOS 27：应用内增量更新不再偶发失败并改为下载完整更新包。
- macOS：更新弹窗中的更新说明正确显示标题、列表和链接，不再显示原始文本。

### 升级说明

- macOS：打开对应架构的 DMG，将 Lithe.app 拖入“应用程序”。
- Homebrew：新版配方更新后，运行 `brew update && brew upgrade --cask lithe`。
- Windows：下载并运行 x64 安装包。
- 升级后首次打开已识别过的项目时，运行面板可能提示运行配置需要重新生成，按提示重新生成一次即可。

### 兼容性与已知问题

- macOS 需要 13 或更高版本；Windows 仍处于预览阶段，部分功能与 macOS 存在差异。
- Windows 的行号运行图标暂不提供“调试”，macOS 可从同一菜单调试。
- macOS 27 增量更新的修复从 0.5.3 开始生效；从旧版本升级到 0.5.3 这一次仍可能改为下载完整更新包。
- 在已有类中新增 main 方法后，运行列表的“可能已过期”提示需等 Java 语言服务准备就绪后才会出现。
- macOS 安装包尚未使用 Developer ID 签名和公证；Windows 安装包尚未使用 Authenticode 发布者签名，系统可能提示安全警告。

如果 macOS 提示无法打开 Lithe.app，请在“应用程序”中按住 Control 点按应用并选择“打开”；如果仍被阻止，可在终端执行 `xattr -dr com.apple.quarantine /Applications/Lithe.app`。仅对可信来源的应用使用。

## English

This update makes the Run panel responsive on large projects, fixes JDK 8 projects that would not start and Java formatting on Windows, and makes macOS in-app updates more reliable.

### Downloads

- [Project homepage](https://github.com/1lck/Lithe-IDEA)
- [macOS Apple Silicon](https://github.com/1lck/Lithe-IDEA/releases/download/v0.5.3/Lithe-0.5.3-arm64.dmg)

### Highlights

Changes are grouped below.

#### ✨ New features

- macOS: switch the Project sidebar to Dependencies to see each run service's sources, build outputs, and dependencies.

#### ⚡ Improvements

- The Run panel opens without long waits on large projects, and editing a method body no longer marks configurations as out of date.
- macOS: saving or creating a run configuration no longer freezes the window on large projects.
- Opening a project or an ordinary Java file no longer logs misleading Java errors.

#### 🛠 Fixes

- Projects using JDK 8 (reported as 1.8.x) are no longer blocked from starting by a false version mismatch.
- Windows: Ctrl+Alt+L now formats Java files instead of reporting that no formatter is configured.
- macOS 27: in-app delta updates no longer fail occasionally and fall back to a full download.
- macOS: release notes in the update dialog now show headings, lists, and links instead of raw text.

### Upgrade instructions

- macOS: open the DMG for your architecture and drag Lithe.app to Applications.
- Homebrew: run `brew update && brew upgrade --cask lithe` after the cask update is available.
- Windows: download and run the x64 installer.
- The first time you open an already identified project after upgrading, the Run panel may ask you to regenerate run configurations once.

### Compatibility and known issues

- Requires macOS 13 or later; Windows remains a preview, with some features differing from macOS.
- Line-number run icons on Windows do not offer Debug yet; on macOS, the same menu can debug.
- The macOS 27 delta update fix applies from 0.5.3 on; updating from an older version to 0.5.3 may still download the full update.
- After adding a main method to an existing class, the Run list's out-of-date notice appears once the Java language service is ready.
- macOS packages lack Developer ID signing and notarization; Windows installers lack Authenticode publisher signing, so system security warnings may appear.

If macOS says it cannot open Lithe.app, Control-click it in Applications and choose Open. If it is still blocked, run `xattr -dr com.apple.quarantine /Applications/Lithe.app` in Terminal. Use this only for an app from a source you trust.
