# macOS 文件打开与页面切换卡顿归因

## 排查结论

- 排查日期：2026-08-18
- 测试会话：17:46:43–17:58:10
- 日志中出现 66 次 SwiftUI runtime fault：

```text
Publishing changes from within view updates is not allowed, this will cause undefined behavior.
```

卡顿不是单纯因为“没有缓存”，而是界面重复刷新和主线程计算过多共同造成。

| 归因 | 结论 | 处置 |
| --- | --- | --- |
| SwiftUI 更新过程中再次发布状态 | 日志已确认，源码调用链吻合 | **必须修复** |
| 主线程继续高亮不可见的全文 | 源码已确认，开销随文件增大 | **必须修复** |
| Java 结构分析同步且重复 | 源码已确认 | **必须修复** |
| TextKit 创建、全文装载和行号索引 | 部分属于编辑器必要成本 | **测量后权衡** |
| 缓存完整编辑器视图 | 能减少重建，但增加大量内存 | **暂不建议** |
| Git Log 重新计算布局 | 可能影响页面切换，不属于已确认的文件打开根因 | **单独评估** |
| WebKit 和字体首次初始化 | 只解释首次或特定页面额外开销 | **按场景权衡** |
| 文件读取 | 已异步执行，已打开文件也有快速路径 | **当前不处理** |

## 必须修复

### 1. SwiftUI 更新重入

编辑器在 SwiftUI 创建或更新视图时，会同步更新光标、选中文本和 Find 状态，再次触发界面刷新。短时间内重复发布可能造成重复布局和掉帧。

修复方式：

- 不在 `makeNSView`、`updateNSView` 的同步调用链中发布可观察状态。
- 将状态发布延迟到本轮视图更新结束后。
- 合并重复更新，并丢弃旧编辑器排队的状态。
- 避免程序设置选区和 AppKit 回调重复发布。

风险：状态栏可能晚一个事件循环更新，但用户通常无法感知；需重点验证快速切换、输入法、查找和导航。

### 2. 主线程全文语法高亮

原实现显示首屏后，仍在主线程分块扫描全文，对每块执行多组正则并修改 TextKit 属性。文件越大，持续占用主线程的时间越长。

修复方式：

- 首次只高亮可见区域。
- 缓存已高亮的字符区间。
- 滚动时只处理新进入视口的区域。
- 文本或主题变化时正确失效缓存。

风险：快速滚动时语法颜色可能稍晚出现；需避免跨区间注释或字符串出现错误颜色。

### 3. Java 结构分析同步且重复

Java 文件打开时会分析折叠区域和实现标记，原流程可能对相同文本重复计算并占用主线程。

修复方式：

- 非 Java 文件直接跳过。
- 相同文本只分析一次，复用所有结果。
- 放到后台执行，并丢弃过期结果。
- 编辑时增加防抖，避免每个字符都重新分析。

风险：折叠图标可能稍晚出现；必须防止旧结果应用到新文本。

## 需要权衡

### TextKit 和行号索引

创建编辑器、装载全文和建立行号索引有必要成本。先完成上述三项并测量，若仍是主要耗时，再考虑重构或对超大文件限制高级功能。

### 缓存完整编辑器视图

缓存 `NSTextView` 可以加快标签切回，但会长期保存全文、TextKit、监听器和装饰状态。打开文件多时内存增长明显。当前优先缓存轻量状态；如后续确有需要，应使用有限容量 LRU。

### Git Log

Git 提交数据已有缓存，但 View 重建后会重新计算图布局和过滤。应单独测量并单独修复，避免扩大本次编辑器改动范围。

### WebKit 和字体

日志确认首次启动 WebKit 和注册字体存在额外开销，但无法解释连续 20 次 SwiftUI fault。是否预热需要在启动速度、CPU 和内存之间权衡。

## 修复顺序

1. 消除 SwiftUI 更新重入。
2. 改为可见区域按需高亮。
3. Java 结构分析移出主线程并去重。
4. 复测后，再决定是否优化 TextKit、完整视图缓存、Git Log 或 WebKit。

## 验收标准

- 相同操作下 SwiftUI runtime fault 从 66 次降到 0。
- 打开和切换普通文件、大文件、Java 文件时无明显卡顿。
- 输入、输入法、光标、选区、查找和导航正常。
- 滚动和主题切换后语法颜色正确。
- Java 折叠和实现标记正常，且不会应用过期结果。
- 首屏可交互时间不再随文件总长度明显线性增长。
