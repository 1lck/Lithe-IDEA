# macOS 文件打开卡顿：修复与测试

## 修复内容

本轮只处理 macOS 编辑器打开、切换文件时的卡顿，不涉及 Git 窗口。

### 1. 避免 SwiftUI 重复刷新

**问题：** 编辑器刷新界面时，会同步发布光标、选区和查找状态，再次触发 SwiftUI 刷新。日志中出现的 66 次以下错误与该调用链吻合：

```text
Publishing changes from within view updates is not allowed
```

**处理：**

- 将状态更新延迟到当前界面刷新结束后。
- 合并连续更新，只保留最后一次结果。
- 切换文件后丢弃旧编辑器排队的状态。
- 保留右侧分屏编辑器的状态更新能力。

### 2. 语法高亮改为按需处理

**问题：** 原实现显示首屏后，仍会在主线程分块扫描全文，执行多组正则并修改文本样式。文件越大，主线程被持续占用的时间越长。

**处理：**

- 打开文件时只高亮当前可见区域。
- 缓存已经高亮的字符范围。
- 滚动时只处理新进入视口的内容。
- 文本或主题变化时清除旧缓存，避免颜色错误。
- 移除打开文件后遍历全文的高亮任务。

### 3. Java 分析移出主线程

**问题：** 打开 Java 文件时，需要分析代码折叠区域和实现标记。原流程在主线程执行，而且同一份源码可能被重复解析。

**处理：**

- 将 Java 结构分析移到后台线程。
- 一次解析结果同时用于折叠区域和实现标记。
- 输入后等待 80 毫秒再解析，避免每次按键都立即计算。
- 新输入会取消旧任务；完成后再次核对文件和内容，防止应用过期结果。
- 非 Java 文件不执行这项分析。

另外，编辑器初始化时移除了一次不必要的全文装饰刷新，并增加了高亮范围缓存测试。本轮没有缓存完整编辑器页面，是否需要该能力将在本轮效果实测后决定。

## 手动测试

### 1. 普通文件

1. 连续打开 5～10 个普通代码文件。
2. 快速来回切换标签。
3. 输入、选择文本、移动光标并使用文件内查找。

预期：打开和切换无明显停顿；光标、选区和查找结果正常。

### 2. 大文件

1. 打开一个内容较多的代码文件。
2. 在文件顶部、中部和底部快速滚动。
3. 切换到其他标签后再切回。

预期：首屏不等待全文高亮；滚动过程可用，进入视口的内容正常着色。

### 3. Java 文件

1. 打开较大的 Java 文件。
2. 检查折叠图标和实现标记。
3. 连续输入后立即切换文件，再切回检查内容。

预期：输入和切换不被结构分析阻塞；折叠和实现标记稍后出现；旧分析结果不会覆盖新内容。

### 4. 回归功能

检查中文输入法、主题切换、跳转到定义、查找、分屏编辑以及未保存修改。

预期：功能正常，切换标签不会丢失未保存内容。

## 后续判断

如果首次打开已流畅，但切回已打开标签仍有明显卡顿，再测量 `NSTextView` 重建耗时，并评估只缓存最近 3～5 个编辑器实例；不要直接缓存全部标签。
