# Windows Java 集成测试清单

本测试包组合连续补全刷新、Java 服务识别和保存后的 Java 启动准备三项改动。
测试包用于验收，不代表已经通过 Windows 实际操作验证；以随包
`identity-windows-x64.json` 的 `source` 字段确认源码提交，不只看安装器版本号。

## 准备

- 使用 Windows x64 机器，记录 Windows 版本、内存、项目 JDK 和 Maven 版本。
- 解压测试包，在 PowerShell 中执行 `Get-FileHash -Algorithm SHA256 <安装器路径>`，
  与同名 `.sha256` 文件核对后安装。
- 使用可修改的项目副本。建议同时准备若依等 Maven 多模块项目，以及包含
  `library`、`app` 两模块的简单项目：`app` 的 Main 打印 `library` 返回的字符串。
- 首次导入允许下载项目依赖；记录首次导入和后续启动的耗时，区分二者。

## 验收动作

| 项目 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 安装和启动 | 安装后打开应用，再退出重开；打开项目、文件和设置 | 正常显示内容，能输入、切换和关闭；不能仅以出现窗口判定成功，白屏算失败 |
| 连续补全 | Java 文件输入对象名和点号，连续输入几个字母，再删除、重新输入；重复快速输入 | 候选随当前文字更新，不固定在第一批结果；选中候选后插入位置和 import 正确 |
| 服务识别 | 打开包含公共库和 Spring Boot 应用的多模块项目，查看运行配置 | 只有有明确应用入口的模块列为服务；仅继承 Spring 插件的库模块不列为服务；用户自建配置仍保留 |
| 已保存依赖 | 通过命名 Java 项目配置运行，记录输出；修改 library 返回值，保存，再运行 app | 输出新值，不是上次编译结果 |
| 未保存依赖 | 关闭自动保存，修改 library，切到 app 后点击命名配置的运行；另做一次调试 | 启动前保存依赖，运行与调试都使用新值；测试结束恢复自己的自动保存设置 |
| 保存期间编辑 | 编辑多个文件后启动，等待期间继续修改或保存另一个文件 | 不回写旧编辑内容；有未保存修改或保存失败时给出失败，不悄悄运行旧代码 |
| 同名主类 | 两模块各有同名 Main，让它们打印不同标识，分别运行各自配置 | 输出属于所选模块，不误启动另一个 Main |
| 构建失败 | 制造编译错误后运行，再分别测试取消、修复后重试 | 有明确构建结果；取消不启动 JVM，修复后能正常运行 |
| 停止与重启 | 构建期间取消；运行期间停止，然后再运行 | 取消后不突然启动，停止后端口释放；再次运行成功，没有重复服务进程 |
| 项目关闭 | 完成测试后关闭项目并退出应用 | 本次启动的应用、Java 语言服务与测试服务退出，不持续占用内存 |

“当前文件”独立 javac 运行和命名 Java 项目配置是不同入口；上述依赖同步用例必须选择
命名配置。外部工具修改未打开文件的 watcher 同步仍有已知时序限制，应单独记录，
不能用编辑器内保存通过来推断它也通过。

## 反馈格式

每项填写通过、失败或未测。失败时附上：源码 `source`、系统与工具版本、项目类型、
最短复现步骤、期望结果、实际结果、运行输出，以及问题发生时的应用日志。
白屏请记录发生在首次启动还是打开项目后、等待多久、是否能打开菜单，并附截图。
日志中如有凭据或私有地址，分享前移除。

自动安装检查只证明安装成功、进程存活、出现原生窗口及安装目录未被改写，
不能替代这张清单中的编辑器和 Java 功能验收。
