# Lithe 需求开发书

本文定义产品范围、架构目标和验收场景，不维护实时完成状态。当前产品状态
请查看 [`README.md`](../README.md)，跨平台输入输出和错误分类请查看
[`shared/contracts/application-boundary.md`](../shared/contracts/application-boundary.md)
以及 [`shared/contracts/rust-core-api.md`](../shared/contracts/rust-core-api.md)。

## 1. 产品定义

- 产品名：Lithe
- 中文名：轻舟
- 平台：macOS（当前发布产品）；Windows（独立实现中）
- 技术路线：macOS 使用 Swift 6、SwiftUI 与 AppKit；Windows 使用 Qt 6 Widgets、C++23，并通过 Rust Core 复用跨平台行为
- 产品定位：面向 AI 编程时代的本地代码浏览、外部变更观察和 Git 审查工作台

> AI 负责产生和运行代码，Lithe 负责人类阅读、理解并决定是否接受这些改动。

Lithe 借鉴 IntelliJ IDEA 成熟的工作台信息架构和操作习惯，但使用自己的品牌、视觉令牌和原生 macOS 实现。它不是 IntelliJ IDEA 的复制品，也不尝试重新实现一套完整传统 IDE。

## 2. 产品背景

外部 AI 编程工具已经能够完成大量代码生成、修改、运行和测试工作。用户仍需要一个可靠、轻量的本地界面来：

- 打开项目并快速浏览目录和代码
- 及时看到外部工具修改了哪些文件
- 处理外部版本和未保存内容之间的冲突
- 通过并排 Diff 审查每一处改动
- 对修改执行暂存、撤销和提交
- 必要时做少量人工修正

Lithe 不调用 AI 模型，不承载 Agent 会话、聊天或审批系统。它观察同一个本地项目目录，与外部 AI 工具协作。

## 3. 设计原则

1. **审查优先**：Changes 和 Diff 与 Project、Editor 同等重要。
2. **外部变化优先**：文件监听和冲突处理属于基础能力，不是附加功能。
3. **原生 macOS**：使用系统窗口、菜单、快捷键、文件面板和 SF Symbols。
4. **轻量按需**：不常驻 Chromium 或构建进程；Java 语言服务器与终端仅在用户使用时启动。
5. **真实交互**：可见按钮必须真实工作；未接入能力明确显示为空状态。
6. **可恢复开发**：项目使用本地 Git 管理，并按独立功能分段提交。

## 4. 核心用户流程

```text
打开本地项目
    ↓
浏览文件和代码
    ↓
外部 AI 修改项目
    ↓
Lithe 自动发现文件与 Git 状态变化
    ↓
查看修改文件和并排 Diff
    ↓
少量人工修正（可选）
    ↓
暂存、撤销或提交
```

## 5. MVP 功能范围

### 5.1 Welcome Screen

- IDEA 风格的启动页空间结构
- 最近项目列表
- 搜索最近项目
- 打开本地目录
- 识别并弱化已失效路径
- 从最近项目中移除记录

### 5.2 工作台

- 顶部项目与当前 Git 分支信息
- 左侧 Project、Changes、Search 活动栏
- 左侧工具面板
- 中央 Editor / Diff 区域
- Commit、Editor 与 Git 工具窗口支持受约束的拖拽分栏
- 底部轻量状态栏
- IDEA 用户熟悉的高信息密度
- Lithe 自己的色彩、图标和产品文案

### 5.3 Project 与文件

- 打开本地目录
- 文件树展开与折叠
- 目录优先排序
- Finder 中显示文件
- 复制文件路径
- 默认排除 `.git`、`.build`、`node_modules`、`target`、`build`、`dist` 等目录
- 使用 FSEvents 监听整个项目层级
- 外部新增、修改或删除文件后刷新工作区

### 5.4 编辑器

- 多标签浏览
- 原生 AppKit 文本编辑
- 行号、选择、滚动和 Undo
- 保存与未保存状态
- 关闭脏文件前确认
- 当前文件查找由系统文本能力提供
- 基础语法着色
- 路径面包屑

编辑器用于阅读和少量修正，不以大量人工编码为主要目标。首期仅为 Java 接入方法定义跳转和引用查找，不包含自动补全或重构系统。

### 5.5 Java 代码导航

- 使用 Eclipse JDT Language Server
- 光标处方法或符号跳转到定义
- 查找引用并在底部结果列表展示
- 点击结果打开文件并定位到精确行列
- 编辑器右键菜单与 Navigate 主菜单入口
- 打开 Java 项目后后台启动语言服务器，关闭项目时停止
- 接收 JDT LS `textDocument/publishDiagnostics`，显示错误、警告、信息和提示级别
- Problems 工具窗口支持按诊断严重级别筛选，并保留文件、行列、source、code 和关联信息
- 对 JDT LS 标记为 `unnecessary` 或明确未使用的代码范围进行弱化显示，同时保留可点击诊断提示

### 5.6 搜索

- 按文件名和相对路径搜索
- 项目全文搜索，结果显示文件、行号和匹配预览
- 双 Shift Search Everywhere：文件、JDT LS 语义类/符号和文本统一搜索
- 项目搜索和 Search Everywhere 支持大小写、整词和正则表达式匹配选项
- 搜索结果点击后打开文件并定位到命中行
- 项目级替换支持预览、按文件选择和逐文件应用；应用前写入 Local History
- 搜索维护轻量磁盘索引，按文件修改时间增量更新，不建立完整语义索引
- 默认跳过生成目录和超大文件

### 5.7 外部变更与冲突

- 通过 FSEvents 监听外部修改
- 未保存内容没有冲突时自动加载磁盘版本
- 同时存在外部修改和未保存内容时显示冲突提示
- 用户可以选择加载磁盘版本或保留编辑器版本
- 外部变化触发文件树与 Git Changes 刷新

### 5.8 Git 与 Diff

- 使用系统 `/usr/bin/git`
- 当前仓库和分支
- 修改、新增、删除文件列表
- 暂存区与工作区分组
- 并排 Diff
- 文件级暂存与取消暂存
- Diff 内搜索、匹配计数和上下匹配跳转
- 代码块级暂存、取消暂存和确认撤销
- 丢弃修改前确认
- 删除未跟踪文件前确认
- 输入提交信息并提交暂存内容
- 支持 Commit and Push 前确认，并提供 Clone、Fetch、Shelf（Git stash）、分支 Merge、Rebase 和删除
- Git 状态自动刷新
- 本地/远程分支与标签树
- 可搜索的 Git 提交时间线
- 提交作者、时间、引用和详情
- 单次提交的变更文件目录树

代码块操作基于 Git unified patch，只对当前显示的 hunk 生效；当前文件状态变化后自动刷新 Diff 和 Changes 列表。

### 5.9 内置终端

- 底部可拖拽工具窗口
- 默认工作目录为当前项目
- 使用用户默认 Shell 和系统 PTY
- 支持交互命令、历史、清屏、中断与重启
- 切换 Git Log、引用结果和终端时复用底部工具窗口
- 关闭项目时停止终端进程

### 5.10 Maven 与 Java Run

- 在现有底部 Maven 工具窗口内识别 Maven 根项目、模块、Profiles 和 Lifecycle；项目与模块使用轻量树形节点展示
- Profiles 使用复选框选择，Lifecycle 用于执行常用 Maven 构建阶段
- 打开 Maven Spring Boot 项目后，自动识别主类并生成默认运行配置；不维护完整 Maven 有效模型
- 执行 Maven 构建并实时显示 Build Output 与可定位的编译错误
- 支持 Current File、Spring Boot 和 Maven Module 三类基础运行配置
- Spring Boot 运行配置支持 JDK Home、工作目录、VM 参数、程序参数、Maven Profiles 和配置持久化
- Settings → Project 支持项目级 JDK、Maven Wrapper/系统 Maven/自定义 Maven Home 和 Maven 专用 JDK；自动探测 `JAVA_HOME`、macOS `java_home`、标准目录、Homebrew JDK 与 Maven，并显示实际版本
- Maven、Run、Debug 和 JDT LS 统一使用项目运行时；运行配置的 JDK Home 作为单次执行覆盖项
- 对 Spring Boot 默认端口与显式 `server.port` 提供基础冲突提示

### 5.11 Local History

- 项目打开时为可读文本文件异步建立基线
- 保存、外部修改、重命名和删除前自动记录
- 历史内容写入 Application Support，不常驻内存
- 按需查看历史版本与当前文件的并排 Diff
- 支持从项目级入口查看所有文件的历史时间线，并按相对路径查看 Diff
- 恢复前自动保留当前版本
- 默认保留 30 天，每个文件最多 100 条，单文件上限 2 MB
- 不记录构建目录、二进制和不可读文本文件

### 5.12 Java Debug

- 支持当前打开的 Java 文件、Maven/Spring Boot 运行配置和 Remote JVM/Tomcat 三类目标
- 当前文件使用 source-file mode 启动 JVM；Maven/Spring Boot 通过 `spring-boot:run` 注入 JDWP
- Remote JVM/Tomcat 使用 host、port 配置进行 JDWP attach；Tomcat 只要求以标准 JDWP 参数启动，不单独设计调试引擎
- 本地调试会话由独立 `jdb` 进程 attach，远程连接默认提示 JDWP 未加密，优先使用本机或 SSH 隧道
- 支持光标行断点、继续、暂停、单步进入、单步跳过和单步跳出
- 支持通过 `jdb` 查询线程、调用栈和局部变量，并保留原始调试输出
- 在暂停状态下支持输入 Java 表达式并通过 `jdb print` 查看求值结果
- 调试 JVM 和 `jdb` 均在关闭项目或停止会话时释放

### 5.13 数据库工作台与外部 MCP

- 数据库连接按需启动独立 Rust helper，支持 MySQL、PostgreSQL、SQLite、Redis 和 Nacos；未使用数据库功能时不启动数据库进程
- SQL 连接提供连接测试、表和结构查看、分页筛选排序、表格增删改、TSV 批量粘贴、当前分页查找替换、SQL 工作台以及 CSV、JSON、SQL 导入导出
- Redis 提供增量 `SCAN` 键浏览、String/Hash 编辑、TTL 修改、键重命名和删除；不得默认使用 `KEYS *` 或全量加载键空间
- Nacos 提供命名空间下的配置搜索、详情编辑与发布、服务列表、实例及健康状态查看
- 写入操作支持只读连接、生产保护、敏感字段配置、写入前恢复点（适用于 SQL）、审计记录和恢复点回滚
- SQL 备份默认完整导出，不按单表行数截断；恢复 SQL 备份必须经用户确认，先验证内容，再替换当前数据库对象和数据，避免损坏文件导致清库
- `lithe-db-mcp` 是独立的 stdio MCP helper，供外部 Agent 或自动化工具调用数据库能力；它不包含产品内聊天界面、自然语言会话或模型调用

## 6. 当前版本边界

- Windows 当前处于独立实现阶段，不纳入当前 macOS 发布版的功能承诺和验收范围。
- AI、Codex 或其他模型调用
- Agent 会话和聊天界面
- Java 以外语言的 LSP 和代码智能
- 传统代码补全
- 自动导包、快速修复和安全重命名
- 完整代码格式化
- 测试识别、测试树和覆盖率
- 三方冲突解决
- TODO、书签和多根工作区
- 插件市场和远程开发
- 浅色主题和复杂设置系统

AI、插件平台和非 Java 语言能力不进入当前路线。Java 实时分析、运行和调试按需启动，不提高应用空闲状态的基础内存。

## 7. 技术架构

```text
macOS SwiftUI/AppKit Workbench       Windows Qt Widgets Workbench
              │                                  │
       Swift Application                    C++ Qt feature layer
       + macOS adapters                     + Win32 adapters
              └──────────────┬───────────────┘
                     Rust lithe-core
                 JSON C ABI + shared contracts
```

代码模块：

```text
Sources/Lithe/
├── Application/  平台无关的服务图和 UI feature models
├── Core/         ports、Rust bridge 和纯领域逻辑
├── Platform/     macOS composition root 和系统适配器
├── Models/       SwiftUI-facing 状态
├── Services/     产品工作流和领域编排
├── Theme/        Lithe 视觉令牌
└── Views/        Welcome、Workbench、Editor、Diff 等界面
rust/lithe-core/  跨平台命令、模型、错误、事件和 C ABI
windows/core/     C++ Rust C ABI client
windows/adapters/ Win32 ports 和平台适配器
windows/qt/       Qt Widgets 工作台
shared/            跨平台契约和验收 fixtures
```

项目使用 Swift Package Manager 构建，最低支持 macOS 14。

## 8. 性能目标

| 场景 | 目标 |
|---|---:|
| Welcome 空窗口 | 150 MB 以内 |
| 普通项目 | 300 MB 以内 |
| 关闭项目后 | 回落到基础占用附近 |

实施原则：

- 不维护 IntelliJ PSI 或完整语义项目索引；搜索只维护轻量磁盘索引
- Java 语言服务器和终端按需启动，关闭项目时释放；不启动构建进程
- 文件扫描跳过常见生成目录
- 搜索限制单文件大小和结果数量
- Diff 不一次性加载无限历史
- 关闭项目时停止文件监听并释放工作区状态

## 9. 开发阶段

本节定义功能范围和阶段归属，不维护实时完成状态；代码行为以共享契约和验证脚本为准。

### Phase 1：原生可用闭环

- Welcome Screen
- IDEA 风格工作台
- 文件树、多标签和基础编辑
- 最近项目和项目搜索
- FSEvents 外部变化监听
- Git Changes、并排 Diff、文件级暂存/撤销/提交
- Git Log、分支与标签筛选、提交文件和详情
- Local History、设置与原生应用打包

### Phase 2：审查体验打磨

- 代码块级暂存、取消暂存与撤销
- Diff 内搜索和跳转
- 更准确的语法解析与大文件策略
- 标签、面板尺寸和打开状态持久化
- 文件创建、重命名和安全删除
- 稳定的可拖拽布局和窄窗口适配
- 项目级标签、活动文件、侧栏与基础分栏尺寸恢复
- 可访问性、性能和异常恢复

### Phase 3：Java 导航与终端

- Java 方法定义跳转
- Java 引用查找与结果跳转
- 内置项目终端

### Phase 4：轻量生产力增强

- 自定义文件隐藏规则：文件树、搜索索引、外部监听和 Local History 共用规则
- 双 Shift Search Everywhere、项目级替换和轻量磁盘搜索索引
- Java 实时诊断、Problems 和编辑器诊断提示
- Java 实时分析增强：复用 JDT LS 的诊断 code、tags 和 relatedInformation；支持按严重级别筛选、未使用/不必要代码弱化和更完整的原因提示
- Maven 项目模型、Lifecycle 和 Build Output
- Current File、Maven Module 与 Spring Boot 基础运行配置
- JDT LS 实时诊断与 Problems 面板
- 多模块进程管理与本地 Java Debug
- Maven/Spring Boot Debug、远程 JVM/Tomcat JDWP attach
- Java Debug 增强：编辑器 gutter 断点标记与切换、变量按需展开、结构化线程/调用栈和异常提示
- Java Debug 表达式求值
- 项目级 JDK/Maven 运行时设置、自动探测与 Maven/Run/Debug/JDT LS 统一消费

## 10. MVP 验收标准

1. 启动 App 并从 Welcome Screen 打开本地 Git 项目。
2. 在 Project 面板浏览目录并打开多个文本文件。
3. 编辑并保存文件，关闭未保存标签时得到确认。
4. 搜索文件名或文本并从结果打开文件。
5. 外部程序修改文件后，文件树和 Changes 自动刷新。
6. 外部程序修改当前脏文件时，用户可以选择磁盘版或编辑器版。
7. 在 Changes 中查看未暂存和已暂存文件。
8. 在 Git Log 中筛选分支、搜索提交并查看提交文件和详情。
9. 查看文本文件的并排 Diff，并在 Diff 内搜索和跳转匹配。
10. 对单个 Diff 代码块暂存、取消暂存或确认后撤销，也可以对文件执行同样操作。
11. 输入提交信息并提交暂存内容。
12. 关闭项目后回到 Welcome Screen，最近项目仍然存在。
13. 左右或上下拖动工作台与 Git Log 分隔线时，各区域能调整尺寸且不挤压消失。
14. 在 Java 方法上跳转到定义，并从引用结果列表定位到调用处。
15. 打开 Terminal，在项目目录执行命令、中断命令并重启 Shell。
16. 查看文件 Local History、对比历史版本，并在保留当前版本后完成恢复。
17. 从项目级 Local History 时间线查看多个文件的历史记录、Diff，并恢复指定文件版本。
18. 打开 Maven 项目，在现有 Maven 工具窗口查看 Profiles、根项目、多模块及其 Lifecycle，运行构建任务后查看 Build Output 并从错误输出跳转到源码；不要求展示完整 Maven 插件、依赖和仓库模型。
19. 选择 Current File、Spring Boot 或 Maven Module 运行配置，查看输出并停止/重启运行会话。
20. 在 Maven/Spring Boot Debug 中启动 JDWP 调试，并在 Remote JVM/Tomcat 模式下验证 JDWP 连接失败提示。
