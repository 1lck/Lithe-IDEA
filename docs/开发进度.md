# Lithe 开发进度

更新日期：2026-08-04

## 当前状态

当前版本为可安装的原生 macOS Java 项目浏览、构建、运行、Debug 与 Git 审查工具。核心浏览、审查、导航、Maven 构建、项目级运行时选择、基础运行和本地/远程 Java Debug 流程已经形成闭环。仓库同时包含供 Windows 使用的 Rust Core、C++ 适配层和 Qt 工作台骨架；Windows 真实构建、打包和完整功能对齐仍在开发中。

## 已完成

- 项目：Welcome Screen、最近项目、文件树、文件增删改、默认目录排除和外部变化监听。
- 编辑器：多标签、保存、基础 Java 高亮、括号提示、代码折叠、参数提示、实现标记和路径面包屑。
- Java 导航：基于 JDT LS 的定义、引用、实现和 workspace symbol 搜索；编辑器支持 Cmd/Ctrl 悬停链接态和点击跳转，`⌘B` 查询调用位置并排除声明位置，多结果可在可点击结果面板中定位；打开 Java 项目时后台预热，并在关闭项目时停止。
- 搜索：文件名、相对路径和项目全文搜索使用轻量磁盘索引；Java 类/符号通过 JDT LS `workspace/symbol` 查询，结果可定位到文件与行；Search Everywhere 支持双 Shift 打开。
- 项目替换：支持替换预览、文件选择、逐文件写入和 Local History 保护。
- Git：Changes、暂存/取消暂存、撤销、提交、分支操作、提交历史、Blame 和分支比较；提交历史已支持基于真实 parent 拓扑的多 lane Git Graph、Merge 分叉/汇合、HEAD/分支/远程/Tag 标签、搜索保持图结构、悬停路径高亮、提交 Hash 复制、长历史分批加载，以及 Cherry-pick、Revert、Mixed Reset 操作。
- Diff：新增、修改、删除、移动状态区分；新增/删除使用单文件整页显示，修改使用并排对比；支持左右文本搜索、匹配计数和上下跳转；保留 unified hunk，可对当前代码块暂存、取消暂存和确认撤销。
- 工具窗口：内置交互式终端、可拖拽布局、窄窗口适配、设置持久化。
- Maven 管理：在现有底部 Maven 工具窗口内识别 Maven 根项目、Profiles 和多模块，保留 Lifecycle 操作、Build Output 与可定位的编译错误；不维护完整 Maven 有效模型。
- Java 运行基础：Current File 使用 JDK source-file mode；检测到 Maven Spring Boot 主类时自动选择 Spring Boot 运行配置并使用 `spring-boot:run` 启动整个项目，支持 JDK Home、工作目录、VM 参数、程序参数、Maven Profiles、实时输出、停止和重启。
- 项目运行时：Settings → Project 支持选择项目 JDK、Maven Wrapper/系统 Maven/自定义 Maven Home，以及 Maven 专用 JDK；从 `JAVA_HOME`、macOS `java_home`、标准目录和 Homebrew 目录探测实际版本，并将选择按项目保存在本机应用设置中。Maven、Spring Boot Run/Debug 和 JDT LS 统一消费该运行时，运行配置仍可用 JDK Home 覆盖。
- Java 实时诊断：接收 JDT LS `publishDiagnostics`，显示编辑器诊断下划线、Problems 面板和点击跳转。
- Java 实时分析增强：解析诊断 code、tags 和 relatedInformation；Problems 支持按严重级别筛选，编辑器对未使用/不必要代码做弱化并保留诊断提示。
- Local History：磁盘快照、单文件历史、项目级跨文件时间线、历史 Diff 和整文件恢复；默认保留 30 天，不把历史正文常驻内存。
- 文件可见性规则：设置页支持追加隐藏目录名和文件 glob；文件树、搜索索引、外部监听和 Local History 共用规则，规则变更后自动刷新当前项目。
- Java Debug：当前 Java 文件、Maven/Spring Boot 使用本地 JDWP 启动并由独立 `jdb` 会话 attach；Remote JVM/Tomcat 使用 JDWP attach。支持光标行断点、继续、暂停、单步和线程/调用栈/局部变量查询；远程连接默认提醒 JDWP 未加密。
- Java Debug 增强：编辑器 gutter 显示并切换断点；Threads、Call Stack 和 Local Variables 优先结构化展示，变量支持按需展开，异常信息单独提示并保留原始 `jdb` 输出。
- 编辑器交互与视觉对齐：所有文件支持多层级缩进竖线并高亮当前层；Cmd/Ctrl 悬停标识符支持定义跳转；实现标记通过 JDT LS 按需校验并显示实现数量。
- 搜索与 Welcome：Search Everywhere 增加 All / Classes / Files / Symbols / Text / Actions 标签和动作注册表；Welcome 页改为 Projects-only 布局并使用稳定项目徽章与自绘 Lithe Logo。
- 搜索体验：项目搜索和 Search Everywhere 支持大小写、整词和正则表达式选项，两个入口使用同一套匹配规则。
- 文件图标与主题：引入统一的矢量文件/Java 类型图标、标签页/面包屑/项目树复用同一分类入口；统一工具窗口标题栏、弹窗、输入框和按钮样式。
- Git 工作流：支持 Clone Repository、Fetch、真实 Shelf（Git stash）、Commit and Push 二次确认，以及分支 Merge、Rebase、Delete 操作；Git 操作失败会保留命令输出并给出通知。
- 工作台状态：按项目恢复打开标签、活动文件、选中的侧栏和主要分栏尺寸；编辑器支持将文件打开到右侧分栏。
- 外部变化体验：目录监听采用合并、延迟和结构/内容区分刷新，内容变化不再无条件重建整棵项目树，减少文件列表闪烁。
- Git Graph 验收夹具：新增一个 Spring Boot 用户服务示例和 `scripts/create-git-graph-fixture.sh`，可重复生成包含真实 Merge、Rebase、Tag 和远程引用的 Git 历史；`scripts/verify-git-graph.sh` 覆盖线性、Merge、截断 parent 和引用标签布局校验。
- JDK/Maven 专项验收：使用 `Fixtures/lithe-spring-boot-git-graph` 验证项目 JDK 21 选择、Maven compile、Spring Boot Run、JDWP Debug 和 JDT LS 均使用 JDK 21；Spring Boot 日志显示 `Java 21.0.11`，编译产物为 class major version 65。
- 核心验收：`scripts/verify-core.sh` 已覆盖 DiffParser、文件可见性、Git Graph、搜索匹配、Diff whitespace、真实 stash、clone 和 Git whitespace filtering。
- 跨平台核心：`rust/lithe-core` 已建立公共命令、模型、错误、事件和 C ABI；工作区快照、搜索、文件读写、Git 状态/变更/历史、Local History、Maven 解析和 Java 源码解析已接入 Rust，macOS 对已迁移能力保留 Swift fallback；`scripts/verify-rust-core.sh` 覆盖 Rust 单测、Swift 链接、ABI smoke test 和符号检查。
- Windows 实现骨架：`windows/core` 提供 C++ `CoreClient`，`windows/adapters` 提供 Win32 端口与适配器，`windows/qt` 提供工作区树、文件读写、搜索和文件变化刷新的 Qt 工作台；当前只完成边界与最小工作流，不代表 Windows 发布版已完成。
- 交付：应用图标、Release App Bundle、本地签名和 `/Applications/Lithe.app` 安装流程。

- `cargo test --manifest-path rust/Cargo.toml`：15 个 Rust 测试通过。
- `scripts/verify-core.sh`、`scripts/verify-rust-core.sh`、`scripts/verify-service-boundaries.sh` 和 `scripts/verify-windows-boundaries.sh`：均通过。
- macOS CMake Core/adapters 构建通过；Windows CMake 的 Core/adapters 目标可用于边界 smoke build，Qt 目标仍需 Qt 6 和 Windows 工具链。
- Swift/Rust 链接阶段目前会提示 Rust 对象以 macOS 26 为目标、应用链接目标为 macOS 14。这不是当前构建失败，但发布构建需要统一 deployment target，避免产生错误的系统版本要求。

## 性能基线

- 当前开发机使用 macOS `footprint` 的物理内存基线：Welcome 空闲约 44 MB；打开 Java 项目时 Lithe 主进程约 58 MB；JDT LS 约 282 MB；Java 项目空闲总量约 340 MB。
- 主进程仍以低于 150 MB 为目标；JDT LS、Shell、Maven、Run/Debug 等按需子进程单独统计，但不再从用户实际资源成本中隐去。
- 关闭项目后 JDT LS 退出，Lithe 主进程回落到约 56 MB；这是当前没有观察到项目切换后 Java 服务常驻的证据，但仍需在大项目和长时间操作中持续压测。
- Java 服务打开 Java 项目时后台预热，终端和 Run/Debug 按用户触发启动；关闭项目或会话后释放。
- Local History 使用磁盘存储；搜索、Diff 和历史记录均限制读取范围与结果数量；搜索使用轻量磁盘索引并按文件修改时间增量更新。

以上数据是当前开发机单次基线，不替代后续的冷启动、空闲 30 分钟、开关项目、重复操作和大项目压力测试。

## 明确边界

- 当前发布产品面向 macOS 和 Java 项目；Windows 实现处于开发阶段，不纳入当前 macOS 发布版承诺。
- 不内置 AI、Agent 会话或模型调用。
- 不开发传统代码补全、自动导包、快速修复和重型插件平台。
- 不在 Lithe 内重复建立一套 Java 全项目语义索引；语义能力复用 JDT LS。
- 新功能不得阻塞 Welcome 首屏，后台服务不得在未使用时常驻。

## 验收重点

- 启动到 Welcome 可交互的耗时。
- 空闲 30 分钟后的内存是否稳定。
- 打开并关闭项目后内存是否回落。
- JDT LS、终端及未来 Run/Debug 停止后子进程是否退出。
- Cmd/Ctrl 悬停时是否出现链接态和手型光标；`⌘B` 是否只定位调用位置，多结果是否可点击跳转。
- 多次搜索、Diff 和 Local History 查看后内存是否持续增长。
