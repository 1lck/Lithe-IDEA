# Lithe 开发进度

更新日期：2026-08-04

## 当前状态

macOS 版本已经形成可使用的 Java 项目工作流：打开项目、浏览和编辑文件、搜索、Java 导航、Maven 构建、运行与 Debug、查看 Git Diff、Local History 和内置终端。SwiftUI/AppKit 负责界面，Rust Core 负责已经冻结的跨平台数据和命令契约，macOS 适配器负责文件监听、原生文件操作、进程、PTY、运行时发现和持久化。

Windows 已有 Rust Core C ABI 客户端、Win32 适配器和 Qt 工作台骨架，可以验证边界和最小工作流；Windows 实机编译、打包、安装更新和完整功能对齐仍未完成。

本文记录代码现状，不替代产品需求。功能范围和验收目标见 [`docs/需求开发书.md`](需求开发书.md)；公共协议见 [`shared/contracts/rust-core-api.md`](../shared/contracts/rust-core-api.md)。

## 解耦状态

| 范围 | 当前状态 | 说明 |
| --- | --- | --- |
| 公共契约 | 已冻结 | 请求/响应 envelope、命令名、错误码、取消和超时字段，以及共享 JSON fixtures 已建立。 |
| Rust Core | 已完成当前公共能力 | 工作区快照、文件读写、搜索、替换预览、Git 读取和写操作、Local History、Maven 解析、Java 源码解析通过 JSON C ABI 提供。 |
| macOS Adapter | 已完成当前边界 | `Platform/MacOS` 提供文件操作、FSEvents、UserDefaults、进程、PTY、JDK/Maven 发现、原生 UI 和更新能力。 |
| macOS Application | 已完成拆分 | `Application/` 按 Workspace、Document、Git、Search、Java、Terminal、Project History 拆分 Feature Model；`AppModel` 只聚合 UI 状态和导航。 |
| macOS Services | 按边界运行 | Git、Workspace、Search、History 使用 Rust operations；Java LSP、Maven、Run/Debug 的进程生命周期仍由 Swift Service 通过平台端口编排。 |
| Windows | 骨架已落地 | Qt UI 不依赖 Swift 类型，只通过 Windows adapters 和 Rust Core 契约工作；完整产品能力仍在开发。 |

“macOS 解耦完成”在当前阶段只表示公共 Core、Application、Services 和 macOS Adapter 的边界检查通过，不表示所有 Java/终端进程状态机都已经迁移到 Rust，也不表示 Windows 已经可以发布。

## 已实现的 macOS 工作流

- Welcome、最近项目、项目树、文件图标、面包屑和工作台状态恢复。
- 多标签原生编辑器、保存、脏状态、代码折叠、行号和大文件滚动优化。
- Markdown 编辑器、编辑器+预览和仅预览三种视图。
- 文件名、路径、全文、Search Everywhere、正则/大小写/整词搜索和项目替换。
- FSEvents 外部变化监听，以及磁盘版本和未保存内容冲突提示。
- Git Changes、结构化 Diff、hunk 操作、History、Blame、分支、Stash、Commit、Merge、Rebase、Clone、Fetch、Pull 和 Push。
- Local History 快照、单文件和项目级时间线、历史 Diff、恢复和清理策略。
- Maven 项目扫描、Profiles、Lifecycle、Build Output、Current File、Spring Boot 和 Maven Module。
- JDT LS 定义、引用、实现、Workspace Symbol 和实时诊断。
- 本地 JDWP、Maven/Spring Boot Debug、Remote JVM/Tomcat attach、断点、线程、调用栈和变量。
- 内置终端、终端会话生命周期、工具窗口拖拽和布局恢复。

## 可重复验证

在 macOS 上使用完整 Xcode 工具链运行 Swift 测试；只有 Command Line Tools 时可以构建应用，但无法加载 Swift Testing 模块。

```bash
swift test --disable-sandbox
cargo test --manifest-path rust/Cargo.toml
scripts/verify-service-boundaries.sh
scripts/verify-shared-contracts.sh
scripts/verify-windows-boundaries.sh
scripts/verify-rust-core.sh
```

当前验证结果：Swift `LitheTests` 7 个测试通过，Rust Core 15 个测试通过，服务边界、共享 fixtures、Windows 边界和 Rust Core bridge 验证通过。

## 已知限制

- Rust 静态库在当前 macOS 26 开发机上构建时，Swift 链接阶段仍可能提示 Rust 对象目标为 macOS 26、应用最低目标为 macOS 14；发布构建前需要统一 deployment target。
- SwiftUI/AppKit UI、真实项目打开流程、大文件滚动和 Java 导航仍需要持续专项验收；当前 Swift 测试是业务逻辑单测，不是 UI 端到端测试。
- Java 语义能力依赖外部 JDT LS；Maven、JDK、Git 和系统 Shell 依赖本机环境或项目配置。
- Windows 还没有完整的 Windows 工具链、Qt 发布包、安装更新流程和 macOS 功能对齐验收。

## 下一步

4. 在 Windows 实机完成 Rust 库链接、Win32 适配器、Qt 工作台和安装更新验证。

## 维护规则

- 新的跨平台输入、输出、错误或事件必须先进入 `shared/contracts/` 和 fixture。
- Core、Application 和 Services 不得直接依赖 AppKit、SwiftUI、`Process`、`FileManager` 或具体 `Mac*` 类型。
- 平台能力只能通过 `Core/Ports` 注入；macOS 组合根是 `Platform/MacOS/MacServiceContainer`。
- 修改边界后必须运行 `scripts/verify-service-boundaries.sh`；修改 Rust 契约后同时更新 `shared/fixtures/` 和 `scripts/verify-rust-core.sh` 覆盖的验证。
